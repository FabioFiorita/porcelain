## Architecture reviewer rulings

1. **Register the mobile feature boundary.** Add `apps/mobile/src/features/terminal` to the
   Terminal target roots in `scripts/architecture/domains.mjs`. Add its `index.ts` and make every
   caller outside that directory import the public entry. The entry exports the mobile stream
   adapter, recovery bridge, roster hooks, and the five existing Terminal presentation roots used
   by the shell and route. Relative imports remain valid inside the feature directory.

2. **Keep the mobile session seam transport-only.** `apps/mobile/src/lib/daemon/session.ts`
   remains the owner of the singleton session runtime, native socket lifecycle, foreground policy,
   endpoint policy, and credential close callback. Change its public `DaemonSession` shape to the
   following generic surface:

   ```ts
   readonly runtime: SessionClientRuntime
   readonly status: SessionConnectionStatus
   readonly start: () => void
   readonly onTerminalFrame: (listener: (frame: TerminalServerFrame) => void) => () => void
   readonly onDaemonReady: (handler: () => void) => () => void
   readonly onDaemonReconnect: (handler: () => void) => () => void
   readonly onDaemonClose: (handler: () => void) => () => void
   readonly registerWatchInterest: (...)
   readonly selectProject: (projectPath: string) => void
   ```

   Replace `subscribeTerminal`, `onOpen`, and `onReconnect` with the generic names above; remove
   `send` and the generic `request` promise/correlation helper. `onTerminalFrame` forwards the
   already validated `TerminalServerFrame` union without per-kind dispatch. `onDaemonReady` fires
   on every ready transition, including the first, and precedes `onDaemonReconnect`; the latter
   fires only after the first ready. `onDaemonClose` fires whenever the runtime is disconnected,
   including native transport loss, foreground shutdown, endpoint replacement, and protocol
   mismatch. The mismatch observer invokes close listeners before retiring the native adapter so
   Terminal promises reject with `{ reason: 'closed' }` instead of waiting for a deadline. Keep
   `sessionClientRuntime()` and `onSessionClosed()` as provider/test bindings; they are not
   Terminal APIs.

3. **Give one mobile daemon session one cached stream owner.**
   `apps/mobile/src/features/terminal/terminal-stream-adapter.ts` owns one
   `createTerminalStreamState()` instance per `DaemonSession`. The production accessor is
   `mobileTerminalAdapter()`, backed by a `WeakMap<DaemonSession, MobileTerminalAdapter>` so the
   direct adapter tests can create isolated sessions without sharing state. The adapter subscribes
   to `onTerminalFrame`, `onDaemonReady`, `onDaemonReconnect`, and `onDaemonClose`; no component
   subscribes to `DaemonSession` directly.

4. **Use the exact feature adapter surface.** The new adapter exports the following concepts:

   - `TerminalAttachResult` is `{ scrollback, status, exitCode?, epoch, sequence }` from a
     successful `terminal:attached`; it has no `found` member.
   - `TerminalPasteResult` is `{ result: 'ok', path? }` from either paste success. Expected
     failures are rejected as `TerminalAdapterFailure`, never returned as legacy result strings.
   - `TerminalAdapterFailure` is
     `TerminalRequestFailure | { readonly reason: 'not-requestable' }`.
   - `TerminalStreamListeners` receives `onData`, `onExit`, `onScrollback`, and `onRecovery`
     projections in shared-effect order.
   - `MobileTerminalAdapter` exposes `createTerminal`, `attachTerminal`, `detachTerminal`,
     `isTerminalAttached`, `writeTerminal`, `resizeTerminal`, `killTerminal`,
     `pasteImageToTerminal`, `pasteFileToTerminal`, `subscribe`, and `dispose`.
   - `createMobileTerminalAdapter(session, options?)` accepts injectable `requestId`, `now`,
     `requestTimeoutMs`, `schedule`, and `cancel` capabilities. Production defaults use
     `randomUUID` from `expo-crypto`, `Date.now`, `REQUEST_TIMEOUT_MS`, and native timers.
   - `mobileTerminalAdapter()` returns the cached adapter for the configured `daemonSession`.
   - `useMobileTerminalStream(listeners)` is the React boundary for native stream consumers. It
     reference-counts consumers and keeps exactly one adapter subscription while the roster and
     `[id]` route overlap. `terminal-roster.ts` supplies one stable listener object that routes
     data/exit/scrollback to `terminal-engine.ts` and `terminal-store.ts`; the session screen uses
     the same hook without creating another engine subscription.

   `createTerminal` and `attachTerminal` accept the corresponding contract input without `t` or
   `reqId`; paste methods accept `{ id, mime, dataBase64, insert? }` and
   `{ id, filename, mime, dataBase64, insert? }`. The adapter constructs these inputs through
   TRM-003, supplies fresh ids and `now() + REQUEST_TIMEOUT_MS` deadlines, queues strict frames
   until `session.runtime.status()` is `open`, and settles promises only from shared-state
   effects. Each pending request gets one injected timer; expiry calls `state.expire(now())`, and
   close/reconnect clears timers and rejects old requests. Fire-and-forget detach/write/resize/kill
   sends only the strict frame returned by TRM-003 while the runtime is open. Writes are chunked at
   `MAX_TERMINAL_WRITE_CODE_UNITS`; no write, create, or paste is replayed after reconnect.

   On a ready-after-reconnect signal, the adapter calls `state.reconnect()`, emits recovery, and
   issues fresh attach requests with fresh ids and deadlines for `recovery.reattach`. A gap or
   epoch transition follows the same recovery path. `isTerminalAttached` remains true for
   `awaiting-baseline` and `awaiting-reattach`, so roster polling cannot duplicate an in-flight
   attach. Attach scrollback is emitted before the attach promise resolves and before later
   accepted data/exit effects reach the native engine.

5. **Keep recovery and user-facing failure copy in the feature.**
   `apps/mobile/src/features/terminal/terminal-recovery.ts` exports:

   - `applyTerminalRecovery(recovery, { refetchRoster })`, which best-effort refetches the
     authoritative `terminalSessions` query when `refreshRoster` is true and never writes stream
     bytes or mutates the Terminal store; and
   - `useMobileTerminalRecovery(enabled, refetchRoster)`, which mounts one recovery listener for
     the active roster provider and unsubscribes it with the provider; and
   - `terminalPasteFailureMessage(error, kind)`, which maps
     `TerminalAdapterFailure` and contract-owned `terminal.*` codes to the existing image/file
     Alert copy without reviving `no-session`, `too-large`, or `write-failed` result unions.

   Recovery reattachment is owned by the stream adapter; the recovery bridge owns only roster
   freshness. It uses `settleBackground` for refetch failures and accepts the existing query
   refetch promise boundary.

6. **Move roster behavior without moving server truth into a store.**
   `apps/mobile/src/features/terminal/terminal-roster.ts` replaces `use-terminals.ts` and exports
   `useTerminals`, `useRenameTerminal`, `useTerminalActions`, and the stable native stream binding
   used by both Terminal routes. Preserve the five-second `terminalSessions` poll, active-repo
   filter, empty-repo reset, Query-backed loading/error state, store hydration replacement,
   external-exit marking, optimistic rename, action filtering, and trust mutation. Its attach loop
   calls the cached adapter and skips ids already represented by shared desired attachment state.
   `useMobileTerminalRecovery` is enabled only for an active repo and refetches the same roster
   query owned by this hook.

   Replace the local Zod mirrors in
   `apps/mobile/src/lib/daemon/procedures/terminal.ts` with imports from
   `@porcelain/contracts/terminal` and `@porcelain/contracts/actions`: terminal roster and rename
   descriptors use the canonical terminal schemas/types, and actions/trust descriptors use the
   canonical actions schemas/types. The query/mutation descriptor factory remains the mobile
   transport adapter; this unit does not move Actions UI or invent client-runtime action hooks.

7. **Retarget every mobile Terminal caller, then remove the old module.** Change these exact
   files to import the feature adapter or public feature entry:

   - `apps/mobile/src/features/terminal/terminal-engine.ts`, `terminal-input.ts`, and
     `terminal-store.ts` use `mobileTerminalAdapter()` for PTY writes, resize, create, detach, and
     kill. Native xterm/headless buffering, tombstones, selection, spawn sizing, and disposal stay
     in their current owners.
   - `terminal-command-composer.tsx`, `terminal-key-bar.tsx`, and `terminal-composer.ts` use the
     object-shaped paste methods and `terminalPasteFailureMessage`; composer delivery carries the
     typed rejection as an opaque failure value plus the attachment kind and keeps upload-before-
     one-write ordering and the write cap.
   - `terminal-list.tsx`, `terminal-companion.tsx`, and `terminal-session-screen.tsx` use
     `terminal-roster.ts` hooks and the shared stream hook. `terminal-companion.tsx` imports its
     `ActionView` type from `@porcelain/contracts/actions`.
   - `apps/mobile/src/features/shell/surface-slots.tsx` and
     `apps/mobile/src/app/terminal/[id].tsx` import presentation components through
     `@/features/terminal`.

   Delete `apps/mobile/src/features/terminal/use-terminals.ts` and
   `apps/mobile/src/lib/daemon/terminal.ts`. Delete `attachedIds`, `whenOpen`, the old
   `TerminalAttachResult` found sentinel, `PasteImageResult`, local request correlation, raw
   terminal frame dispatch, and the reconnect attach loop with them. The generic
   `apps/mobile/src/lib/daemon/session.ts` frame seam remains; it is not a second stream owner.

8. **Preserve the mobile presentation boundary.** Do not change the native terminal module,
   Ghostty/xterm setup, `NativeTerminalBuffer`, scrollback replacement, OSC52 behavior, input
   encoders, native accessibility/test IDs, route presentation, or the daemon PTY operation. The
   only composer change is replacing legacy paste failure strings with typed adapter failures and
   the existing copy. No stream bytes enter TanStack Query or Zustand as a new cache.

## Objective

The mobile Terminal feature uses TRM-003 for request correlation, attachment intent, scrollback
ordering, epoch/sequence validation, and reconnect recovery. The mobile session module exposes only
generic transport/lifecycle seams, the roster remains Query-authoritative, native presentation
remains platform-owned, and the old mobile Terminal transport module is deleted.

## Why this unit exists

`apps/mobile/src/lib/daemon/terminal.ts` currently owns a second request-id/timeout map,
`attachedIds`, raw frame dispatch, and reconnect attach loop. `use-terminals.ts` adds a separate
subscription lifetime and roster attach loop. TRM-003 and the Web cutover now provide the canonical
state/effect boundary; leaving either mobile fork would preserve divergent stale-reply,
scrollback, and recovery behavior.

## Current behavior and evidence

- `apps/mobile/src/lib/daemon/terminal.ts` creates and attaches PTYs through
  `daemonSession.request`, sends fire-and-forget frames without shared state, and returns old
  `found`/paste failure unions.
- `apps/mobile/src/features/terminal/use-terminals.ts` reference-counts one raw stream listener,
  polls `terminalSessions`, filters by repository path, hydrates `terminal-store`, and attaches
  missing ids.
- `apps/mobile/src/lib/daemon/session.ts` already forwards the complete contract-valid
  `TerminalServerFrame` union from RT-005, but its public request and raw subscription names still
  expose the pre-TRM-005 transport helper.
- `apps/mobile/src/features/terminal/terminal-engine.ts` owns native emulator instances,
  pre-mount buffering, bounded buffers, scrollback replay, and exit presentation; these remain
  outside the stream state owner.
- `apps/mobile/src/lib/daemon/procedures/terminal.ts` still duplicates terminal roster/rename and
  actions schemas even though canonical contract schemas are available.

## Non-goals

## Target ownership and public surface

The target public import is `@/features/terminal`. Its `index.ts` exports
`createMobileTerminalAdapter`, `mobileTerminalAdapter`, `useMobileTerminalStream`,
`useMobileTerminalRecovery`, `applyTerminalRecovery`, `terminalPasteFailureMessage`, the
`MobileTerminalAdapter`/failure/result/listener types, the three roster hooks, and the existing
`TerminalList`, `TerminalPhoneScreen`, `TerminalCompanion`, `TerminalSessionScreen`, and
`TerminalViewer` presentation roots. The only mobile Terminal code that talks to the session
transport is `terminal-stream-adapter.ts`; the only code that turns shared stream effects into
native engine calls is the stable listener binding in `terminal-roster.ts`.

The adapter sends only strict frames returned by TRM-003 through `DaemonSession.runtime.send`.
`terminal-roster.ts` uses TanStack Query for daemon roster truth and Zustand only for the existing
cross-component presentation workflow. `terminal-recovery.ts` refetches the owning roster and
never creates stream data. `terminal-engine.ts` remains the native output/renderer owner, while
`terminal-input.ts`, `terminal-store.ts`, and the composer remain feature-local callers of the
adapter.

## Behavior to preserve

- one inbound stream subscription while roster and session routes overlap;
- daemon-owned PTY lifetime, create auto-attachment, idempotent roster attach, and explicit kill;
- attach scrollback before live data, accepted output ordering, natural exit retention, stale
  output suppression, and gap/epoch recovery;
- foreground/background reconnect, fresh recovery attach ids, no stale request settlement, typed
  close/deadline/server failures, and the five-second roster backstop poll;
- repository filtering, replacement hydration, external exit, tombstones, rename/action UI,
  spawn sizing, write chunking, paste upload ordering, accessibility labels, and existing native
  rendering/input behavior.

## Legacy behavior to delete

- `apps/mobile/src/lib/daemon/terminal.ts` and `apps/mobile/src/features/terminal/use-terminals.ts`;
- `attachedIds`, `whenOpen`, `daemonSession.request`, `daemonSession.send`,
  `daemonSession.subscribeTerminal`, `daemonSession.onOpen`, and `daemonSession.onReconnect`;
- mobile-local `TerminalAttachResult.found`, `PasteImageResult`, and the
  `no-session`/`too-large`/`write-failed` paste result union;
- direct Terminal frame switches and reconnect attach sends outside
  `terminal-stream-adapter.ts`;
- external deep imports such as `@/features/terminal/<module>` outside the Terminal feature root.

The contract-owned `terminal:*` names remain in the adapter's strict input construction and in
contract fixtures; no component, session test, or presentation module may construct or match them.
