## Behavior to preserve

- Strict envelope: only `{ version: 1, value }` is adopted; unversioned JSON, a malformed
  file, and a value the caller schema rejects are all renamed to an exclusive
  `*.corrupt-<timestamp>` backup preserving the original bytes, and the original path is
  removed. Any other finite numeric version is left untouched as `incompatible-version`.
- Oversize is decided from the byte length before decoding and never rewrites the source.
- Writes are atomic in the same directory: `.tmp-` file, fsync, rename, fsync parent; no
  `.tmp-` entry survives a successful or failed write; a rejected write does not block the
  next one; the FIFO chain preserves caller order.
- `ensureRoot` writes the default manifest only for `missing`, never for `corrupt`,
  `incompatible-version`, or `too-large`, and never mutates any other companion file.
  Concurrent callers for one `repoPath` share one in-flight run and produce one manifest.
- Existing unversioned companion bytes (`board.json`, `notes.md`, `layers.json`,
  `scope.json`, `actions.json`) stay byte-identical when the root is ensured.
- `notes.md` stays raw markdown and is unlinked when cleared to empty; `layers.json` stays
  an unversioned array whose uncompilable patterns are dropped on read, with absence
  meaning `DEFAULT_LAYERS`.
- Companion policy keeps the managed `.gitignore` block rewrite-only, preserves human
  lines outside the markers, and keeps `/project-manifest.json`, `*.tmp`, and
  `*.corrupt-*` in `ALWAYS_IGNORED`; disposition flips untrack without deleting on-disk
  files; publishing re-includes exactly one review.
- `projectDataFilesForDomain(...).path()` refuses a file the named domain does not claim.
- Project Data reads no home companion path and no `porcelainHome` record.
