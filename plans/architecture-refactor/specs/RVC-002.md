## Architecture reviewer rulings

- Copy the landed Board client-runtime exemplar `BRD-003` / `packages/client-runtime/src/board/` exactly for layout, naming symmetry, export map, test shape, and package-export registration. This unit does not invent a second client-runtime pattern.
- Place the slice under the canonical domain path `packages/client-runtime/src/review/` (Decision 013 / domain registry). File names stay comment-scoped (`comment-*.ts`); the package subpath is `./review`. Do **not** create a top-level `review-comments/` domain folder.
- Wire still uses `repoPath` on comment procedure inputs (RVC-001). The typed query identity uses product language `projectPath` (Board pattern). `affectedQueries` maps `input.repoPath` → `reviewCommentsQuery(input.repoPath)`. The notification already carries `projectPath`.
- This unit owns **only** the comments query identity among Review server state. `reviewCommentNotificationEffects` maps a validated `review.changed` to **only** that comments identity. Coarse multi-query Review invalidation remaining in Web `use-session-runtime` / mobile event maps is intentionally left for later Review client-runtime units and the RVC-003/RVC-004 adapters; this unit must not broaden or invent a full-Review invalidation map.
- Clean pre-launch cutover (Decision 015): no dual optimism models, no raw procedure-string cache identities, no `AppEvent` / legacy `comments` event branches, no ambient `Date.now` / random ids inside client-runtime, no compatibility shim that re-exports app-local transition code.

## Objective

`@porcelain/client-runtime/review` owns one typed Review-comments query identity, five reversible mutation consequence definitions (add / edit / delete / setResolved / clearResolved), pure optimistic apply / rollback / add reconciliation, and the typed `review.changed` → comments-identity notification effect used by both clients.

## Why this unit exists

Web `apps/web/src/hooks/use-comments.ts` implements temporary ids, cache snapshots, five optimistic mutations, rollback, and invalidate-on-settle against tRPC. Mobile `apps/mobile/src/features/comments/use-comments.ts` is invalidate-only (`COMMENT_INVALIDATIONS = ['reviewComments']`) over local procedure descriptors. RVC-001 stabilized server procedures, authoritative add output, typed failures, and post-write `review.changed`. BRD-003 proved the shared client-runtime pattern; this unit is the Review-comment primary exemplar before either app adapter (RVC-003 / RVC-004) changes UI.

  readonly domain: 'review'
  readonly name: 'comments'

### Optimistic transitions (`comment-reconciliation.ts`)

```ts
export type ReviewCommentOptimisticContext = {
  readonly temporaryId: string
  readonly now: number
}

export type ReviewCommentOptimisticSnapshot = {
  readonly comments: readonly ReviewComment[]
}

export type ReviewCommentMutationKey =
  | 'add'
  | 'edit'
  | 'delete'
  | 'setResolved'
  | 'clearResolved'

export type ReviewCommentOptimisticTransitionResult = {
  readonly comments: readonly ReviewComment[]
  readonly snapshot: ReviewCommentOptimisticSnapshot
}

export function applyReviewCommentOptimisticTransition<K extends ReviewCommentMutationKey>(
  comments: readonly ReviewComment[],
  mutation: K,
  input: /* input type for K */,
  optimistic: ReviewCommentOptimisticContext,
): ReviewCommentOptimisticTransitionResult

export function rollbackReviewCommentOptimisticTransition(
  snapshot: ReviewCommentOptimisticSnapshot,
): readonly ReviewComment[]

export function reconcileReviewCommentMutation(
  comments: readonly ReviewComment[],
  mutation: ReviewCommentMutationKey,
  options?: {
    readonly temporaryId?: string
    readonly result?: ReviewComment // add output only
  },
): readonly ReviewComment[]
```

**Transition rules** (pure; no ambient clock/id; adapter supplies `temporaryId` + `now`):

| Mutation | Next collection |
| --- | --- |
| `add` | **Prepend** `{ id: temporaryId, path, body, resolved: false, createdAt: now, …optional startLine/endLine/anchorText }` so newest-first order matches daemon list order. Omit undefined optionals (no `undefined` fields). Never invent `agentReply`. |
| `edit` | If `id` present: map that comment to `{ …comment, body: input.body }` only (preserve `path`, anchors, `resolved`, `createdAt`, `agentReply`). If absent: leave collection unchanged. |
| `delete` | If `id` present: filter it out. If absent: unchanged. |
| `setResolved` | If `id` present: map that comment to `{ …comment, resolved: input.resolved }` only. If absent: unchanged. |
| `clearResolved` | Filter to `comment.resolved === false` (remove every resolved comment). Empty result is success. |

- Snapshot is always an exact copy of the pre-mutation `comments` array reference contents (`comments.slice()` into `snapshot.comments`).
- `rollbackReviewCommentOptimisticTransition` returns `snapshot.comments` **exactly** (same reference as stored in the snapshot).
- `reconcileReviewCommentMutation`:
  - For `mutation === 'add'` when both `temporaryId` and `result` are supplied: map the temporary card to the authoritative `result` (replace that element; do not re-sort). If either option is missing, return the optimistic collection unchanged (same reference acceptable).
  - For every other mutation: return the optimistic collection unchanged.
  - Authoritative refetch remains required for every mutation (`requiresAuthoritativeRefetch: true`); reconciliation never clears that flag.

## Behavior to preserve

- Newest-first list semantics for optimistic add (prepend with adapter `now` as `createdAt`).
- Anchor/range/body/`agentReply` fields survive local edit and setResolved transitions.
- Daemon results remain authoritative; every mutation still declares authoritative refetch.
- Comment server data stays in TanStack Query ownership (semantic definition only here); line selection, composer draft, and marker presentation stay application state.
- Live refresh after agent/CLI/Web/mobile comment writes remains available via `review.changed` → comments identity (adapters apply invalidation later).
- Missing-id local transitions are no-ops on the collection (rollback still restores snapshot if an adapter applied a no-op patch).
