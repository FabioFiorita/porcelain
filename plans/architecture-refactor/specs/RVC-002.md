- Primary exemplar: yes

## Objective

Client-runtime owns the Review-comment query identity, five reversible mutation consequences, reconciliation, and the typed Review notification effect.

## Why this unit exists

Web `hooks/use-comments.ts` implements temporary ids, cache snapshots and five rollbacks; mobile `features/comments/use-comments.ts` has only `COMMENT_INVALIDATIONS = ['reviewComments']`.

## Current behavior and evidence

- Web reads `trpc.reviewComments`, optimistically adds/edits/deletes/resolves/clears, then refetches.
- Mobile imports comment descriptors and `ReviewComment` from `lib/daemon/procedures/review.ts` and invalidates by procedure string.
- RT-001 replaces coarse `comments` with project-scoped `review.changed`; RVC-001 supplies the canonical comment contracts and successful-write notification.

## Scope

Add `packages/client-runtime/src/review-comments/{comment-queries,comment-mutations,comment-reconciliation,comment-notifications,index}.ts`, colocated tests, and `./review-comments` export only.

## Non-goals

Do not create React hooks, alter comment operations/contracts, move comment presentation, change line-index rules, or bind a QueryClient.

## Target ownership and public surface

- Export `reviewCommentsQuery(projectPath)`, returning `{ domain: 'review', name: 'comments', projectPath }`; it is the only comment server-state identity.
- Export `reviewCommentMutations` keyed `add`, `edit`, `delete`, `setResolved`, and `clearResolved`. Each names exactly one RVC-001 procedure, affects `[reviewCommentsQuery(input.projectPath)]`, and sets `requiresAuthoritativeRefetch: true`.
- Export `applyReviewCommentOptimisticTransition`, `rollbackReviewCommentTransition`, and `reconcileReviewCommentAdd`. Add prepends an adapter-provided temporary id and `now`, edit changes body only, delete removes id, setResolved changes only `resolved`, clearResolved removes resolved comments; missing ids leave the list unchanged.
- Export `reviewCommentNotificationEffects`; a validated `review.changed` maps to its project comments identity and no raw event/default branch exists.

## Behavior to preserve

Comments remain newest-first; anchor/range/body fields survive local transitions; daemon results remain authoritative; comment data stays in Query, while line selection/composer state stays local.

## Legacy behavior to delete

Delete no app hook or descriptor here. RVC-003 and RVC-004 delete their respective optimistic code and string invalidations.

## Ordered implementation

1. Verify RVC-001 exposes canonical list/add/edit/delete/resolve/clear descriptors, `ReviewComment`, fixtures, and `review.changed`.
2. Implement the one identity, five consequence records, pure transitions/snapshots, add reconciliation, and exhaustive notification mapping.
3. Export only the documented public surface and package subpath.

## Tests

- Query tests prove equal project inputs and distinct project identities.
- Reconciliation tests prove all five transitions, exact rollback, temporary-add replacement, newest-first order, and absent-id no-op.
- Mutation/notification tests use TST-001 fixtures and prove exact procedure/effect identities and invalid notification rejection.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../../packages/client-runtime/src/review-comments`.
- Run `pnpm lint`.
- Run `rg -n "react|@trpc|QueryClient|zustand|AppEvent|reviewComments'|reviewComments\"" packages/client-runtime/src/review-comments`; it returns no result.

## Forbidden shortcuts

Do not use ambient clocks/ids, framework imports, broad Review invalidation, raw procedure strings, or a mock that implements daemon comment behavior.

## Completion criteria

- [ ] One typed comments identity, five consequences, reversible transitions, reconciliation, and notification map exist.
- [ ] Direct contract-valid tests prove each behavior and client-runtime remains framework-free.
- [ ] Lint and the deletion-baseline search pass; the unit is committed.

## Handoff

RVC-003 and RVC-004 bind these definitions to their own transports and Query caches.
