# CON-002 — Move Remote procedure schemas into the Remote contract module

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: `remote`
- Depends on: `CON-001` (Landed)
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

`packages/contracts/src/remote/remote.procedures.ts` owns exact query/mutation schemas for all 12
current Remote procedures and removes exactly those entries from the transitional ledger.

## Why this unit exists

Remote combines daemon/network routers and has only two refined entries; protocol/error work needs a
complete Remote wire surface.

## Current behavior and evidence

Current names are `daemonInfo`, `accessStatus`, `issuePairingLink`, `revokePairingLink`,
`revokeAuthorizedClient`, `revokeCurrentClient`, `tailnetStatus`, `setTailnetBind`, `lanStatus`,
`setLanBind`, `funnelStatus`, `setFunnelBind` in `router/{daemon,network}.ts`.

## Scope

Create `remote.contract.ts`, `remote.procedures.ts`, and Remote contract tests; update the ledger and
lint record only.

## Non-goals

Do not change routers, pairing behavior, errors, protocol headers, client adapters or Remote storage.

## Target ownership and public surface

Export `remoteProcedures` as a `satisfies Record<RemoteProcedureName, ProcedureContract>` record.
Use `kind: 'query'` for `daemonInfo`, `accessStatus`, `tailnetStatus`, `lanStatus`, `funnelStatus`;
use `kind: 'mutation'` for the other seven names. `remote.contract.ts` owns strict schemas for daemon
identity, access snapshot/grants, listener status and Funnel status, inferred types and fixtures.

## Behavior to preserve

Preserve every current Zod bound/default and the exact current serializable result shapes.

## Legacy behavior to delete

Delete only the 12 Remote items from `unmigratedProcedureLedger`; keep old horizontal catalog files
until `CON-012`.

## Ordered implementation

1. Transcribe each router input/output into exact strict Remote schemas.
2. Add the kind-aware Remote record and export it from `remote/index.ts`.
3. Remove the 12 ledger entries and update lint/test expectations from 113 to 101 unmigrated names.

## Tests

Add `packages/contracts/src/remote/remote.procedures.test.ts` with valid/invalid fixture parsing for
all 12 entries and a ledger test that Remote has no remaining items.

## Validation and evidence

```text
pnpm --dir apps/desktop test -- ../../packages/contracts/src/remote/remote.procedures.test.ts ../../packages/contracts/src/procedure-ledger.test.ts
node scripts/lint-procedure-contracts.mjs
git diff --check
```

## Forbidden shortcuts

Do not use `z.unknown`, `AppRouter` types, a generic network module, or a second Remote name.

## Completion criteria

- [x] All 12 names have exact schemas and declared kinds.
- [x] Remote ledger items are gone and unmigrated count is 101.
- [x] Tests, lint script and diff check pass.

## Handoff

`ERR-001` and `PRO-001` may import Remote schemas from one domain entry point.
