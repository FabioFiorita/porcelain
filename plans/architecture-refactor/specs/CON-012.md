# CON-012 — Compose the canonical procedure catalog and router-validation gate

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: contract catalog cutover
- Depends on: `CON-011`, `ERR-003`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

Compose one exact 113-entry catalog from the ten landed domain records and make router input/output
adoption mechanically measurable without changing any daemon procedure yet.

## Why this unit exists

The former `CON-012` combined catalog composition, 113 router edits, legacy deletion, and lint
replacement in one commit. This foundation makes the subsequent router-file cutovers mechanical and
independently reviewable; `CON-021` is the named no-fallback deletion unit for the temporary bridge.

## Current behavior and evidence

- Ten `packages/contracts/src/<domain>/<domain>.procedures.ts` records contain all 113 procedures.
- `packages/contracts/src/procedure-ledger.ts` is empty, while
  `procedure-ledger-baseline.ts` and `procedures/{names,io,refined}.ts` remain transitional truths.
- Nine production files under `apps/daemon/src/router/` define the 113 flat procedures: 105 have
  local `.input(...)` middleware, eight have none, and all 113 lack `.output(...)` middleware.
- `scripts/lint-procedure-contracts.mjs` proves name/domain/kind coverage but explicitly leaves full
  input/output exhaustiveness to this batch.

## Scope

Add `packages/contracts/src/procedure-catalog.ts` and its test, export `procedureCatalog` from the
package root, and extend `scripts/lint-procedure-contracts.mjs` plus its fixture tests with a
shrink-only router-file validation ledger. Do not edit production routers.

## Non-goals

Do not delete the horizontal catalog or ledgers, change package subpath exports, edit clients,
attach router input/output middleware, alter runtime behavior, or classify additional errors.

## Target ownership and public surface

`procedureCatalog` is a flat frozen object composed in this exact order from `remoteProcedures`,
`projectsProcedures`, `filesProcedures`, `searchProcedures`, `gitProcedures`, `reviewProcedures`,
`boardProcedures`, `actionsProcedures`, `terminalProcedures`, and `projectDataProcedures`. Its keys
are exactly the 113 baseline names; every value retains required `kind`, `input`, `output`, and
`errors`. It contains no copied schema, fallback, `unknown`, or locally manufactured entry.

In `lint-procedure-contracts.mjs`, define the temporary exact remaining-file set:

```text
board.ts, daemon.ts, files.ts, git.ts, network.ts, repos.ts, review.ts, settings.ts, terminal.ts
```

For a router file absent from that set, lint requires every procedure block to contain exactly one
`.input(procedureCatalog.<name>.input)` and one
`.output(procedureCatalog.<name>.output)`, with the existing query/mutation kind. Files still in the
set remain governed by the existing name/domain/kind checks. Unknown, duplicate, missing, or
non-production filenames fail. The set is enforcement-only and is deleted by `CON-021`.

## Behavior to preserve

Preserve all inputs, outputs, names, kinds, errors, defaults, package root exports, daemon behavior,
authentication, tRPC formatting, and client imports. Catalog construction must not mutate or clone
domain records.

## Legacy behavior to delete

Delete only lint's inability to distinguish validated from unvalidated router files. Keep every
transitional file and root export until `CON-021`; the bridge is dependency-bounded, not permanent.

## Ordered implementation

1. Compose and freeze the flat catalog from the ten domain records; export it from `src/index.ts`.
2. Add a catalog test comparing exact names/kinds/domain ownership to
   `initialProcedureOwnershipBaseline`, asserting 113 unique entries and no missing record fields.
3. Refactor lint's router extraction to retain filename and complete procedure block text.
4. Add the exact nine-file remaining set and pure checks for canonical input/output references on
   files removed from it; report the remaining and validated procedure counts.
5. Add fixture failures for an unknown ledger file, missing/wrong/duplicate input, missing/wrong/
   duplicate output, and kind drift. Keep every existing fixture passing.

## Tests

Add `packages/contracts/src/procedure-catalog.test.ts`. Extend
`scripts/lint-procedure-contracts.test.mjs` using synthetic router source blocks, never production
filesystem mocks. Prove the current nine-file ledger passes before any production router migration.

## Forbidden shortcuts

Do not import the horizontal `procedureIo` into the catalog, copy schemas, use `z.unknown`, accept a
pattern looser than the exact catalog member name, infer migration from formatting alone, edit a
router early, or omit the final deletion dependency.

## Completion criteria

- [ ] One frozen catalog composes exactly 113 entries from the ten domain records.
- [ ] Lint distinguishes the exact nine unvalidated router files and rejects every named drift.
- [ ] No runtime router/client behavior changes and all transitional files remain for the batch.
- [ ] Focused tests, lint fixtures, repository lint, full verify, and diff check pass.
- [ ] One commit lands only `CON-012`, marks recipe/catalog Landed, leaves a clean worktree, provides
      the README review packet, and finishes without pushing.

## Handoff

`CON-013` through `CON-020` may remove only their owned router files from the lint ledger after every
procedure in those files uses its exact catalog input and output. `CON-021` deletes the bridge and
horizontal catalog only after the remaining-file set is empty. Those router units intentionally
adopt strict/void canonical input acceptance. If a canonical output rejects a documented valid
current handler result, the executor stops with the exact procedure/value evidence; it must not
widen the contract or alter the handler under a binding-only recipe.
