# CON-012 — Cut over to domain procedure records and enforce output exhaustiveness

- Status: Draft
- Batch: 0 — architecture and contract foundations
- Domain: contract catalog cutover
- Depends on: `CON-011` (Draft), `ERR-001` (Draft)
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Replace the old horizontal procedure catalog with the ten complete domain records, then make router
inputs and runtime outputs exhaustive against those `ProcedureContract` records.

## Why this unit exists

The ledger is intentionally temporary. Once it is empty, retaining fallback schemas would leave two
authoritative contract surfaces and permit a router result to drift from its declared output schema.

## Current behavior and evidence

Current schema discovery is horizontal under `packages/contracts/src/procedures/`, with partial
coverage in `refined.ts`. The authoritative procedure/name inventory and source routers are in
[`backend.md`](../inventory/backend.md); `CON-002` through `CON-011` supply the replacement records.

## Scope

Own the one-time cutover in `packages/contracts/src/{procedure-catalog,index}.ts`, delete
`packages/contracts/src/procedures/`, `procedure-ledger.ts`, and the stale app-type tombstone
`packages/contracts/src/router.ts`, and update every daemon router
registration to use the named domain record's `input` and parse each result through its `output`.
Extend `scripts/lint-procedure-contracts.mjs` so every router procedure has one domain-record entry,
its declared `kind` matches query/mutation construction, no fallback export is imported, and every
declared output is runtime-validated.

## Non-goals

Do not change request/response semantics, rename procedures, introduce an aggregate generic domain,
or modify Web, mobile, session, persistence, or command behavior.

## Target ownership and public surface

`procedureCatalog` composes exactly `remoteProcedures`, `projectsProcedures`, `filesProcedures`,
`searchProcedures`, `gitProcedures`, `reviewProcedures`, `boardProcedures`, `actionsProcedures`,
`terminalProcedures`, and `projectDataProcedures`. It is the sole lookup used by router builders.
`ProcedureContract.kind`, `input`, and `output` remain required; a router may not manufacture a local
input/output schema or return an unparsed result.

## Behavior to preserve

For every one of the 113 names, preserve its current procedure kind, validation acceptance/rejection,
defaulting, result shape, error mapping, and serialization. Output parsing reports boundary failures
through the `ERR-001` public-error path rather than leaking raw validation internals.

## Legacy behavior to delete

Delete `packages/contracts/src/procedures/**`, `packages/contracts/src/router.ts`, all root exports
that expose them, the empty `unmigratedProcedureLedger`, and any router fallback to a
local/horizontal input or output schema.
There must be no compatibility re-export or dual catalog.

## Ordered implementation

1. Assert the ledger is empty and compose the ten domain records into one exact catalog.
2. Convert every router registration to consume its record, including the `kind`-appropriate builder.
3. Wrap each successful router result with that record's `output.parse` at the daemon boundary.
4. Delete the horizontal catalog and ledger in the same change.
5. Make the lint rule fail for missing, duplicate, wrong-kind, fallback-imported, or unparsed-output
   procedures; add a fixture for each failure mode.

## Tests

Add a catalog test that the 113 inventory names occur exactly once with their expected kinds. Add
router tests that a malformed mocked handler output is rejected through the public boundary and that
all current good outputs still serialize. Add lint fixtures for every exhaustiveness violation.

## Validation and evidence

```text
pnpm --dir apps/desktop test -- ../../packages/contracts/src/procedure-catalog.test.ts ../daemon/src/router/procedure-output-validation.test.ts
node scripts/lint-procedure-contracts.mjs
pnpm lint
git diff --check
```

## Forbidden shortcuts

Do not leave a compatibility barrel, use `z.any`/`z.unknown`, infer a procedure kind from a name,
disable validation for streaming-adjacent procedures, or whitelist uncovered routers.

## Completion criteria

- [ ] All 113 router names resolve once to a kind-aware domain `ProcedureContract`.
- [ ] Every daemon result is parsed by its declared output before crossing the tRPC boundary.
- [ ] The old catalog and transitional ledger are deleted with no imports or aliases left.
- [ ] Exhaustiveness tests, lint, and diff check pass.

## Handoff

Protocol, runtime, and client recipes may now import only domain-owned contract entry points.
