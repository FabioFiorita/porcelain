# RT-002 — Build daemon real-time publisher, gateway, and watch management

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: real-time daemon runtime
- Depends on: `RT-001`, `PRO-003`
- Governing decisions: [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Prepare the daemon's target session publisher, authenticated gateway, and bounded file-watch interest
manager as unactivated modules using the shared RT and handshake contracts.

## Why this unit exists

All daemon event sources need one sequenced, project-scoped publisher; session authorization and
watch ownership cannot remain scattered across old WebSocket handlers. Activation waits for the final
atomic client/daemon switch in `RT-005`.

## Current behavior and evidence

Daemon event sources are `apps/daemon/src/app-events.ts`, file-watch, review-watch, terminal code,
and the existing `apps/daemon/src/net/session.ts`. They currently fan out through legacy frames.
`apps/daemon/src/session/` already exists and owns `session-handshake.ts` (`PRO-003`'s pure
`decideSessionHandshake`); the gateway consumes that decision rather than reimplementing it. The
watch-interest cap and frame schemas are `RT-001`'s `@porcelain/contracts/session` exports
(`SESSION_WATCH_INTEREST_LIMIT = 128`).

## Scope

Create `apps/daemon/src/session/{change-publisher,session-gateway,session-watches}.ts` with injected
source/transport interfaces and focused tests. Define, but do not wire, source-to-category adapters.
The gateway uses `PRO-003`'s pure handshake decision before registration and accepts watch interests
only after ready. The watch manager canonicalizes paths, scopes them to the authorized project,
deduplicates, and caps combined files/directories at 128. `RT-005` activates these modules atomically
with both client adapters.

## Non-goals

Do not wire daemon construction, implement client reconnect/replay, change event sources, implement
Web/mobile adapters, UI invalidation, or delete legacy transport files. `RT-005` owns activation and
final deletion.

## Target ownership and public surface

The publisher assigns a monotonic `sequence` per `epoch` to each `session:change`. The gateway owns
authorization, hello/ready/mismatch, subscriber lifecycle, and terminal stream forwarding. Watches
are advisory interests: excess/invalid/out-of-project paths are rejected without expanding daemon
watch scope. These interfaces do not import current daemon construction or old transport files.

## Behavior to preserve

Preserve authentication requirements, current file/review/git trigger coverage, terminal's separate
ordered stream, and existing watcher lifecycle cleanup on repository/session close.

## Legacy behavior to delete

Delete no old files and add no activated dual publisher. The prepared modules remain unused until
`RT-005` migrates both adapters and performs the single switch/deletion.

## Ordered implementation

1. Implement publisher sequencing and contract parsing at the daemon boundary.
2. Integrate the versioned handshake and authorized subscriber gateway.
3. Add bounded watch-interest canonicalization and source-to-category adapter interfaces.
4. Keep modules unreferenced by daemon construction; document `RT-005` as sole activation owner.

## Tests

Test ordered sequences/epochs, unauthenticated and mismatch rejection, source-to-category mapping,
watch deduplication/cap/out-of-project rejection, cleanup, and terminal forwarding separation.

## Forbidden shortcuts

Do not broadcast unscoped events, accept watches before ready, create unlimited watchers, use a second
event bus, or delete the legacy gateway before clients migrate.

## Completion criteria

- [x] Prepared modules emit valid sequenced domain changes and separate terminal streams in tests.
- [x] Gateway enforces auth and protocol hello/ready/mismatch.
- [x] File interests are canonical, project-scoped, deduplicated, and capped at 128.
- [x] Focused tests, repository lint, full verify, and diff check pass.
- [x] One commit lands only `RT-002`, marks recipe/catalog Landed, leaves a clean worktree, provides

single daemon + Web + mobile activation.
