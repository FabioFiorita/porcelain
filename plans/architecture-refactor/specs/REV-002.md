## Architecture reviewer rulings

These bind the executor and supersede every conflicting sentence in the tracked
Draft. They are decisions already made; the executor does not reopen them.

1. **No target router. The relocated procedures keep their live wire names.**
   The Draft's "target review router" is not buildable: `lint-architecture.mjs`
   (registered-root → registered-root deep imports, lines 405-412) rejects any
   `apps/daemon/src/features/review/*` import of
   `packages/contracts/src/review/review.target-procedures.ts`, and REV-001
   reserved `packages/contracts/src/review/index.ts` for REV-009 alone. Verified
   by probe at `c938eae1`:
   `apps/daemon/src/features/review/<probe>.ts deep-imports packages/contracts/src/review/review.target-procedures.ts across the packages/contracts/src/review domain boundary; only its index.ts is public`.
   This unit therefore follows the unanimous landed daemon-feature idiom (Board,
   Files, Git, Projects, Search, Actions, Terminal, Remote, Project Data,
   RVC-001's `comment-router.ts`): a feature router binds **live**
   `procedureCatalog` names, is registered in `PRODUCTION_ROUTER_FILES`, is
   mounted in `create-daemon-router.ts`, and its procedures leave the legacy
   router in the same commit. The target catalog stays unimported outside its own
   test. REV-009 renames the wire.

2. **Publish's force-stage becomes a narrow Review-owned capability.**
   `ProjectGit` (`apps/daemon/src/features/git/git-ports.ts:40-58`) has no
   `forceStage` and does not grow one: publish must stay the app's only
   force-stage, and Decision 006 wants the capability narrow and explicit. This
   unit declares `ReviewPublication` in the Review feature and implements it with
   the existing `gitForceStage` (`apps/daemon/src/git/git.ts:412`) plus
   `recordPublishedReview` (`apps/daemon/src/features/project-data/index.ts:2`).

3. **This unit is lifecycle-only.** `createReadActiveReview` is dropped. The
   `featureView` read and every `apps/daemon/src/review/feature-*.ts` builder
   belong to REV-003 and are not touched here. Exactly six live procedures move:
   `clearFeatureReview`, `publishReview`, `reviewPublishCost`, `archivedReviews`,
   `restoreArchivedReview`, `deleteArchivedReview`.

4. **No new public error code.** REV-001 ruling 6 permits this unit to add codes;
   it declines. Current wire failure semantics are preserved exactly: an empty
   `id` is rejected as `request.invalid` by the catalog input schema before the
   handler runs, a contract-violating archive row serializes as
   `internal.unexpected`, and a missing archive stays a thrown adapter error. The
   target entries' public error codes belong to REV-009's activation.

5. **One Review key in `DaemonOperations`.** The existing `reviewComments` key is
   widened, not joined by a second key. `ReviewOperations` carries the comment
   operations and the lifecycle operations, the key is renamed `review`, and both
   routers receive `operations.review` — the landed Remote precedent, where
   `createRemoteRouter` and `createRemoteNetworkRouter` both take
   `operations.remote` (`create-daemon-router.ts:38,43`).

## Objective

The six Review lifecycle procedures are served by bound operations under
`apps/daemon/src/features/review/`, over narrow archive-store, publication, clock,
and id capabilities, with identical wire names, schemas, and failure semantics —
and `apps/daemon/src/stores/review-store.ts` no longer reaches Git or Project Data.

## Why this unit exists

`review-store.ts` mixes active reads, archive copy/delete, metadata, cost walking,
Git force-staging, and direct file I/O in one module, and `router/review.ts` calls
it directly. Nothing between the wire and the filesystem can be tested or replaced.
REV-003 (reading) and REV-009 (cutover) both need the lifecycle already owned by
operations before they run.

## Target ownership and public surface

### `review-lifecycle-capabilities.ts`

Domain-prefixed names, error shapes written locally. It imports
`ReviewUnavailableError` from `./comment-capabilities` (an internal import inside
the same registered root) rather than redeclaring it.

```ts
export type ArchivedReviewMeta = {
  id: string
  name: string
  thesis?: string
  archivedAt: string
}
export type ReviewPublishCost = { bytes: number; files: number }
export type ReviewPublishOutcome = { id: string; cost: ReviewPublishCost }

export type ReviewLifecycleResult<T> =
  | { ok: true; value: T }
  | { ok: false; error: ReviewUnavailableError }

/** Active-review directory and `.porcelain/reviews/<id>/` effects. */
export type ReviewArchiveStore = {
  /** Copy the active review to a new archive and clear the active slots; null when nothing is active. */
  archiveActive(repoPath: string, id: string, archivedAt: string): Promise<string | null>
  /** Recursive byte/file cost of the active review; a missing directory is zero. */
  activeCost(repoPath: string): Promise<ReviewPublishCost>
  /** Newest first; unreadable or contract-violating `meta.json` entries are skipped. */
  list(repoPath: string): Promise<ArchivedReviewMeta[]>
  restore(repoPath: string, id: string): Promise<void>
  remove(repoPath: string, id: string): Promise<void>
  /** Relative path of an archive inside the repo, for publication staging. */
  archiveRelativePath(repoPath: string, id: string): string
}

/** The product's only force-stage, plus its durable gitignore negation. */
export type ReviewPublication = {
  recordPublished(repoPath: string, id: string): Promise<void>
  forceStage(repoPath: string, relativePath: string): Promise<void>
}

export type ReviewClock = { now(): number }
export type ReviewArchiveIds = { create(): string }
```

### Operations

Each is a `create*` factory taking an explicit dependency object and returning one
async function, exactly like `createAddReviewComment`. No operation calls another
operation.

| Operation | Live procedure | Signature |
| --- | --- | --- |
| `createArchiveReview` | `clearFeatureReview` | `({ projectPath }) => ReviewLifecycleResult<void>` |
| `createPublishReview` | `publishReview` | `({ projectPath }) => ReviewLifecycleResult<ReviewPublishOutcome \| null>` |
| `createPublishCost` | `reviewPublishCost` | `({ projectPath }) => ReviewLifecycleResult<ReviewPublishCost>` |
| `createArchivedReviews` | `archivedReviews` | `({ projectPath }) => ReviewLifecycleResult<ArchivedReviewMeta[]>` |
| `createRestoreArchivedReview` | `restoreArchivedReview` | `({ projectPath, id }) => ReviewLifecycleResult<void>` |
| `createDeleteArchivedReview` | `deleteArchivedReview` | `({ projectPath, id }) => ReviewLifecycleResult<void>` |

`createPublishReview` owns the ordered effects and nothing else: `activeCost` →
`archiveActive` → return `{ ok: true, value: null }` when the archive id is `null`
→ `recordPublished` → `forceStage(archiveRelativePath(...))` → `{ id, cost }`.
`createArchiveReview` and `createRestoreArchivedReview` each call `ids.create()`
and `clock.now()` for the archive they create, so both archive paths produce the
same metadata.

### Router and composition

`review-lifecycle-router.ts` imports `procedureCatalog` directly from
`@porcelain/contracts`, binds `.input(procedureCatalog.<name>.input)` and
`.output(procedureCatalog.<name>.output)` for the six live names, calls exactly
one operation each, and maps `{ ok: false }` through
`toTrpcError(expectedFailure('review.unavailable'))` — the same `throwIfFailed`
shape as `comment-router.ts:13-23`.

`review-operations.ts` exports
`type ReviewOperations = ReviewCommentOperations & ReviewLifecycleOperations` and
`createReviewOperations(options)`, which builds both families and returns one
`Object.freeze({...})`. `DaemonOperations.reviewComments: ReviewCommentOperations`
becomes `review: ReviewOperations`; `createReviewCommentRouter(operations.review)`
and `createReviewLifecycleRouter(operations.review)` are both mounted, the
lifecycle router immediately after `createReviewCommentRouter` so the flat merge
order stays stable. `index.ts` exports `createReviewOperations`,
`ReviewOperations`, `createReviewLifecycleRouter`, and the capability types any
other module needs — nothing else becomes public.

## Behavior to preserve

- Every wire name, kind, input schema, and output schema is unchanged, and
  `procedureCatalog` still reports 113 names.
- Archive-before-clear: the active directory is removed only after the copy and
  `meta.json` land, and a failed removal still reaches the caller.
- No-active is `null`, never an error: `publishReview` returns `null` and
  `clearFeatureReview` is a silent no-op when there is no active review.
- A corrupt or partial archive is skipped by the list, never deleted and never
  surfaced as data loss; a missing archive root lists as `[]`.
- Archive ids stay unique and keep the
  `<base36 millis>-<8 hex chars>` format; `archivedAt` stays an ISO string.
- Publication stays deliberate and human-initiated: cost first, then archive,
  record, and force-stage — the product's only force-stage, and still a stage and
  never a commit.
- `restoreArchivedReview` still archives the current active review first, restores
  into the **active** paths (not the companion root), and drops the source entry.
- Id containment (`/`, `..`, `''`) is still refused before any filesystem write.
- Failure semantics on the wire: `request.invalid` for an empty id from the input
  schema, `internal.unexpected` for a contract-violating archive row.
- `review-watch.ts` remains the only publisher of `review.changed`.
