# REV-002 — Build active Review and archive operations, rules, stores, and composition

- Status: Draft
- Batch: 5
- Domain: Review
- Depends on: REV-001, DAE-001, PDT-002, TST-002
- Governing decisions: 003, 004, 006, 009, 015
- Primary exemplar: yes

## Objective

Move active Review/archive lifecycle from store/router helpers into bound Review operations with narrow persistence, Git publication, disposition, clock, and ID capabilities.

## Why this unit exists

`review-store.ts` mixes active reads, archive copy/delete, metadata, disposition, force-stage Git, migration, and direct file I/O. `router/review.ts` exposes that behavior with Feature-era procedures.

## Current behavior and evidence

- `review-store.ts` calls `ensureProjectCompanion`, copies active directories, archives metadata, `recordPublishedReview`, and `gitForceStage`.
- Archive IDs use time/random bytes; list skips corrupt partial archives; publication force-stages only after deliberate human action.
- Current clear means archive then clear active slots.

## Scope

- Create `apps/daemon/src/features/review/{operations,adapters,review.router.ts,index.ts}` and required `DaemonOperations.review` binding.
- Implement active read, archive, publish, delete archive, restore, and clear through target contracts.

## Non-goals

- Do not change Git's no-auto-stage rule except explicit `publishReview`; do not delete real archives, migration code, or Evidence compatibility here.

## Target ownership and public surface

`createReadActiveReview`, `createArchiveReview`, `createPublishReview`, `createDeleteArchivedReview`, and `createRestoreArchivedReview` are bound operations. They receive `ReviewStore`, `ProjectDataDispositions`, `ProjectGit`, `Clock`, and `ReviewIdGenerator`; router maps one procedure to one operation.

## Behavior to preserve

Preserve no-active null, archive-before-clear, corrupt archive metadata skip, unique archive IDs, explicit human publication, cost estimate, shared/local disposition, and force-stage only on publish.

## Legacy behavior to delete

Delete direct router imports of review-store and store-owned Git/disposition calls after operations are proven. Keep old vocabulary adapters until REV-009; keep migrations until PDT-005.

## Ordered implementation

1. Add typed capability interfaces and real adapters around active/archive layout, Git stage, disposition, clock/ID.
2. Implement operations with ordered effects: validate/read, archive copy, disposition, force-stage; return public result/failure.
3. Bind required Review operations in daemon composition and make target review router call exactly one operation per procedure.
4. Move direct router/store callers; leave old procedure adapters isolated for REV-009.
5. Test operation success/expected failures with fakes and adapter archive/corrupt-meta behavior on temporary project roots.
6. Delete direct store-to-Git/disposition imports only after operation and router tests pass.

## Tests

- Operation fake tests for order/failure and publication stage boundary.
- Real temporary filesystem archive/restore/corrupt-meta adapter tests.
- Central Vitest focus, `pnpm test`, and lint pass.

## Validation and evidence

Record effect order and no-active/archive/publish results; verify no target router imports a store or Git adapter.

## Forbidden shortcuts

- Do not call an operation from another operation, mutate Git from a router, or make publication automatic.
- Do not collapse corrupt/partial archive into data loss.

## Completion criteria

Lifecycle behavior is bound operations with narrow capabilities; target router has one-operation procedures; retained archive/publication resilience tests pass.

## Handoff

REV-005 migrates direct CLI writers; REV-009 removes legacy Feature wire names.
