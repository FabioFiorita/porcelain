   parenthetical statuses.

3. **Public errors stay exactly as declared. No `remote.*` wire codes.**
   `packages/contracts/src/remote/remote.errors.ts` must not be created.
   Procedure `errors` arrays stay:

   | Procedure | errors |
   | --- | --- |
   | `daemonInfo` | `[]` |
   | `accessStatus` | `['auth.forbidden']` |
   | `issuePairingLink` | `['auth.forbidden', 'request.invalid']` |
   | `revokePairingLink` | `['auth.forbidden']` |
   | `revokeAuthorizedClient` | `['auth.forbidden']` |
   | `revokeCurrentClient` | `['auth.forbidden']` |

   The Draft phrase “typed pairing invalid/expired/not-found/current-admin
   failures” means operation-internal result unions mapped onto those existing
   public codes — not new members and not a behavior change:

   - bad pairing URL / structural URL refusal → `request.invalid` (same checks
     as today's `issuePairingLink`)
   - non-client `revokeCurrentClient` → `auth.forbidden`
   - admin-only procedures stay on `adminProcedure` (`auth.forbidden` from
     middleware; operations do not re-check admin)
   - unknown revoke pairing/client ids stay silent no-ops (`revoke*` returns
     void; authorized-client revoke closes sessions only when the store
     returned `true`)
   - expired pairings stay a store prune (`accessSnapshot` omits them; exchange
     of an expired grant still returns `null` for HTTP). There is no public
     `expired` or `not-found` code on these six procedures.

4. **Ports / adapters. Do not re-home `net/` or session transport.** Access
   persistence moves from `stores/access-store.ts` into the feature as
   `access-store.ts`, keeping the same module-singleton shape (process-wide
   cache + serialized `mutationChain`). Do not convert it to a second
   `createAccessStore()` instance factory — two chains on one file would race.
   Preserve: v1 `{ version: 1, pairings, clients }` at
   `PORCELAIN_ACCESS_FILE` or `porcelainHomePath('access.json')`; atomic
   tmp+rename; `mode: 0o600`; SHA-256 hex `secretHash`; 15-minute pairing TTL
   (`PAIRING_TTL_MS = 15 * 60 * 1000`); `TOKEN_SECRET_BYTES = 32`;
   `timingSafeEqual` compare; oversized (`> 1_048_576`) treated as empty;
   unparseable renamed to `${path}.corrupt-${Date.now()}` then empty; missing
   file → empty; tokens `pc_pair_${id}_${secret}` / `pc_client_${id}_${secret}`.
   The store has **no** grant-issuance rate limiter today — do not add one.
   HTTP `POST /pair` rate limits stay in `net/daemon-http.ts` (REM-002).
   Inject as explicit ports (composition binds the current modules):

   - identity: `daemonIdentity` from `net/daemon-identity.ts`
   - build version: `daemonVersion` from `net/daemon-version.ts`
   - admin token display path: `displayAdminTokenPath` from `net/admin-token.ts`

     `session/live-session.ts`

   `https:` only; empty username/password/search/hash; then `pathname = '/pair'`

## Objective

The six host Remote wire procedures (`daemonInfo`, `accessStatus`,
`issuePairingLink`, `revokePairingLink`, `revokeAuthorizedClient`,
`revokeCurrentClient`) each invoke exactly one bound Remote operation over
injected identity, version, admin-token display, session, and v1 access-store
ports; pairing URL policy and current-client revocation live in operations;
legacy `router/daemon.ts` and `stores/access-store.ts` are gone; public error
codes are unchanged.

## Why this unit exists

Decision 013 assigns daemon identity, pairing, and access to `remote`. CON-002
already owns the twelve wire schemas, but `router/daemon.ts` still orchestrates
pairing URL policy, access-store secrets, and session close inside the
transport, and `DaemonOperations` has no `remote` slice. That blocks REM-002
from composing HTTP/listeners against a domain-owned access capability.

Bound intentions (names exact):

| Operation | Result | Behavior |
| --- | --- | --- |
| `daemonInfo()` | `DaemonInfoOutput` (always succeeds) | `{ version: version(), protocolVersion: PROTOCOL_VERSION, ...identity() }` |
| `accessStatus()` | `Promise<AccessStatusOutput>` (always succeeds) | `{ ...snapshot(), connected: clientSessionCount(), adminTokenPath: displayAdminTokenPath() }` |

URL policy (operation-owned; same as today's router):

1. `new URL(baseUrl)` — constructor throw → `{ ok: false, error: { code: 'request.invalid' } }`
2. protocol not `http:` / `https:` → `request.invalid`
3. `username`, `password`, `search`, or `hash` non-empty → `request.invalid`
4. `pathname = '/pair'`
5. grant = `access.issuePairingGrant(label)`
6. `hash = new URLSearchParams([['token', grant.credential]]).toString()`
7. `{ ok: true, value: { ...grant, url: base.toString() } }`

## Behavior to preserve

- `daemonInfo` announces `PROTOCOL_VERSION` from `@porcelain/contracts`, never
  derived from the build string; `version` is `daemonVersion()`;
  `host`/`platform`/`arch` come from `daemonIdentity()` (`PORCELAIN_DAEMON_HOST`
  override still honored inside that function).
- Access file: v1 only, `0600`, atomic tmp+rename, SHA-256 secret hashes,
  15-minute pairing TTL, prune expired on snapshot/issue/exchange, constant-time
  compare, oversized → empty, corrupt → `${path}.corrupt-${Date.now()}` then
  empty, missing → empty.
- Issued pairing credential never written in plaintext; token prefixes
  `pc_pair_` / `pc_client_`.
- Pairing URL is `${origin}/pair#token=<credential>` with no userinfo, query,
  or pre-existing hash.
- Admin procedures reject non-admin via `adminProcedure` (`auth.forbidden`).
- `revokeCurrentClient` as admin or unpaired public identity is
  `auth.forbidden`; as a client it revokes that client and closes its sessions.
- Unknown pairing/client revoke is void success; session close runs only when
  `revokeAuthorizedClient` returned `true`.
- `exchangePairingGrant` remains one-shot; expired/unknown/mismatch still
  `null` for HTTP pairing (server.ts still passes the same functions).
- HTTP pairing rate limit, CORS, protocol header, and listeners unchanged.
- Flat wire names and input/output shapes unchanged.
