# CON-011 — Move Project Data procedure schemas into the Project Data contract module

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: `project-data`
- Depends on: `CON-010`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Create the final domain-owned procedure record for the six Project Data procedures and reduce the
shrink-only transitional ledger from six entries to zero.

## Why this unit exists

Repo notes and companion dispositions are repository data, not Review, Git, or the generic settings
bucket. They complete the ten canonical product domains before the fallback catalog can be removed.

## Current behavior and evidence

`repoNotes` and `setRepoNotes` are in `apps/daemon/src/router/repos.ts`; `companionDispositions`,
`companionGitVisibility`, `setCompanionGitVisibility`, and `setCompanionDisposition` are in
`apps/daemon/src/router/settings.ts`. The exact procedure inventory is in
[`backend.md`](../inventory/backend.md). Authoritative return shapes live in
`apps/daemon/src/stores/notes-store.ts`, `apps/daemon/src/project/companion-disposition.ts`, and
`apps/daemon/src/project/git-exclude.ts`. The mobile schemas in
`apps/mobile/src/lib/daemon/procedures/{notes,companion}.ts` are useful comparison evidence but do
not own the contract and are not changed here.

## Scope

Create `packages/contracts/src/project-data/{project-data.contract,project-data.procedures,index}.ts`,
its tests, and remove only these final six entries from `unmigratedProcedureLedger`.

## Non-goals

Do not move routers, alter repository storage, merge this surface into Projects, or delete the
horizontal catalog. `CON-021` performs that final cutover.

## Target ownership and public surface

`projectDataProcedures` is a `satisfies Record<ProjectDataProcedureName, ProcedureContract>` record.
Its exact surface is:

- `repoNotes`: input `string`; output `string`.
- `setRepoNotes`: strict `{ repoPath: string; notes: string }`; output `void`.
- `companionDispositions`: input `string`; output strict
  `{ key; label; hint; disposition: shared | local; trackedPaths: string[] }[]`.
- `companionGitVisibility`: input `string`; output strict `{ hidden: boolean }`.
- `setCompanionGitVisibility`: strict `{ repoPath; hidden: boolean }`; output strict
  `{ changed: boolean }`.
- `setCompanionDisposition`: strict
  `{ repoPath; key: non-empty string; disposition: shared | local }`; output strict
  `{ untracked: string[]; revealed: boolean }`.

Export all schemas, inferred types, and the procedure record through the Project Data entry point.

## Behavior to preserve

Preserve missing-notes behavior as the empty string—notes are not nullable. Preserve unbounded
repository paths and notes, the non-empty disposition key constraint, `shared | local`, tracked path
reporting, visibility `changed`, disposition `untracked`/`revealed`, and all current success shapes.
Do not expose `.gitignore` parsing records or add validation for channel keys that the router does
not currently impose.

## Legacy behavior to delete

Delete only the six Project Data entries from the ledger. Keep all `procedures/` files and their
exports until `CON-021` verifies every router uses the complete domain records.

## Ordered implementation

1. Read both routers, the three authoritative implementation modules, mobile comparison schemas,
   baseline, and the landed Terminal/domain contract exemplars.
2. Transcribe the exact inputs and outputs as strict Project Data schemas and synthetic fixtures.
3. Export the kind-aware procedure record and inferred types from the domain entry point.
4. Remove exactly the six Project Data ledger entries; update composition tests and assert the
   transitional ledger and flattened names are empty without deleting either file.

## Tests

Add `packages/contracts/src/project-data/project-data.procedures.test.ts` covering valid and invalid
inputs/outputs for every procedure, exact kinds, strict nested/object rejection, empty notes,
non-empty disposition keys, both dispositions, visibility results, untracked/revealed results, and
the empty-ledger assertion.

closed enum of current companion channel keys, or treat a zero ledger as permission to delete
fallback files in this recipe.
