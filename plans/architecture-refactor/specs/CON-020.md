# CON-020 — Bind Actions and Terminal router procedures to canonical contracts

- Status: Queued
- Batch: 0 — architecture and contract foundations
- Domain: Actions / Terminal contract boundary
- Depends on: `CON-019`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

The six Actions and two Terminal procedures in `router/terminal.ts` use their exact canonical
contracts without changing trust, CRUD ordering/defaults, terminal roster, or rename behavior.

## Why this unit exists

The historical Terminal router also owns Actions CRUD. One file-owned unit completes the last
production router migration while later ACT/TRM specs separate application ownership.

## Current behavior and evidence

Actions names: `actions`, `trustActions`, `addAction`, `updateAction`, `moveAction`, `deleteAction`.
Terminal names: `terminalSessions`, `renameTerminal`. Local schemas enforce trimmed titles/commands,
where values, non-empty trust IDs, directions, and terminal rename input. Handlers call Actions
store/trust helpers and the terminal manager directly.

## Scope

Edit `apps/daemon/src/router/terminal.ts`, add its focused contract test, and remove only
`terminal.ts` from the temporary lint remaining-file set after all eight procedures pass.

## Non-goals

Do not move Actions/Terminal code, alter trust hashes or persistence, CRUD ordering/defaults,
terminal lifecycle/session protocol, rename semantics, PTY behavior, or clients.

## Target ownership and public surface

Bind each exact name to `procedureCatalog.<name>.input` and `.output` on its existing public
query/mutation. Actions use Actions entries; roster/rename use Terminal entries. Preserve all helper
arguments and return values; tRPC output middleware performs the only wire parse.

## Behavior to preserve

Preserve trusted decoration, stored versus wire Action shape, exact Action defaults
`order = 0`/`createdAt = 0`/`trusted = false`, trim/minimum rules, primary/local `where`, move
directions, void CRUD results, Terminal `createdAt = 0`, roster status/exit fields, rename void
result, and absence of new terminal stream behavior.

Deliberately replace Actions object-input unknown-key stripping with strict rejection and give
`terminalSessions` its canonical void parser; incompatible supplied input maps to
`request.invalid` with no fallback.

## Legacy behavior to delete

Delete the seven existing local inputs, add `terminalSessions`' missing canonical void input, and
delete all eight unvalidated outputs. Remove `zod` if unused and remove `terminal.ts` from the lint
remaining set, which must then be empty.

## Ordered implementation

1. Bind all six Actions procedures in source order.
2. Bind `terminalSessions` including explicit void input and bind `renameTerminal`.
3. Remove obsolete schema/type imports only when canonical inference replaces them safely.
4. Add tests for trust/add/update/move/delete, exact Action/Terminal output defaults, roster/rename
   valid outputs, unknown-key/supplied-void and other invalid input, and malformed output rejection.
5. Remove `terminal.ts` from lint's set and assert zero remaining files and 113 validated procedures.

## Tests

Add `apps/daemon/src/router/terminal.contract.test.ts`; use temporary Action storage and the existing
terminal-manager test seams. Do not spawn a PTY for request/response schema proof.

## Forbidden shortcuts

Do not spawn PTYs, weaken trim/minimum/trust rules, copy Action/Terminal schemas, change store or
manager behavior, retain local Zod, or leave the lint set non-empty.
