## Objective

The shared client runtime owns typed Project query identities and the open/remove mutation effects;
Web and mobile bind those definitions through feature adapters while their existing selection state
stores contain only the currently selected Project presentation value, not a server list or a
procedure-name cache.

## Why this unit exists

Web `apps/web/src/hooks/use-repo.ts` and `apps/web/src/stores/repo.ts` expose recent/open/remove
Project behavior through tRPC procedure hooks and vanilla procedure-name calls. Mobile
`apps/mobile/src/features/shell/use-workspace.ts` owns recent and browse `useDaemonQuery` calls,
the `['recentRepos']` invalidation, and the open action alongside the shell's presentation logic.
The two clients therefore have different cache identities and different places that decide what an
open or remove does to the selected Project.

PRJ-001 now supplies the stable Projects contract and daemon operation boundary. This unit is the
client-side seam: the same typed identities and mutation consequences must feed both clients, while
the shell keeps only the selected Project and its existing surface transitions.

## Current behavior and evidence

- `packages/client-runtime/` has landed Board, Files, Git, and Review runtime conventions but no
  Projects entry or package export. The Projects contract already owns the strict four wire
  procedures and `ProjectInfo` (`RepoInfo` remains an external compatibility alias until PRJ-003).
- `recentRepos` has two real result sets: the Web switcher and mobile Project sheet request the
  default `includeWorktrees: false`, while Web restore and mobile daemon bootstrap request
  `includeWorktrees: true`. A query identity that omits this boolean can return the wrong list from
  a shared cache.
- `openRepoPath` returns the validated Project summary and records the recent on the daemon. Web
  `useRepoStore.openRepoPath`/`switchTo` additionally update selected state; `switchTo` closes local
  tabs and resets the local terminal roster. Mobile `lib/daemon/repo.ts` updates the active
  environment path and selects the Project on the live session. Those lower-level compatibility
  seams are still used by bootstrap and Git worktree flows; this unit changes the Project
  switcher/picker data path only and PRJ-003 owns their final vocabulary removal.
- Web `components/shell/project-switcher-menu.tsx`, `welcome.tsx`, and
  `repo-picker-dialog.tsx` consume `useRecentRepos`, `useRemoveRecentRepo`, `useRepoStore` actions,
  and `useBrowseDirs`. `components/shell/project-switcher.test.tsx`, `hooks/use-repo.test.ts`,
  and `stores/repo.test.ts` provide the current focused proof.
- Mobile `features/shell/project-sheet.tsx` renders the Project sheet, while
  `features/shell/use-workspace.ts` owns its recent/browse queries, `runUserAction` open flow,
  active path, and error/loading surface. `workspace-lists.test.ts` proves the shell's pure picker
  derivations; the Project data path has no feature-owned validating adapter test yet.
- There is no `projects.changed` member in `sessionChangeSchema`; the session contract currently
  composes Files, Git, Review, Board, and Actions changes. Project open/remove are client mutation
  effects, not a reason to add a no-op notification module or a second session bridge.

## Target ownership and public surface

### Shared runtime identities

`packages/client-runtime/src/projects/project-queries.ts` exports:

```text
ProjectSummary = ProjectInfo

ProjectsQuery =
  | { domain: 'projects'; name: 'recent'; includeWorktrees: boolean }
  | { domain: 'projects'; name: 'directories'; path: string | null }

recentProjectsQuery(includeWorktrees = false): RecentProjectsQuery
projectDirectoriesQuery(path: string | null): ProjectDirectoriesQuery
projectsQuerySchema: strict discriminated union on name
```

The constructors preserve the input path verbatim, including a nullable directory root. Their
schemas are strict and their inferred types are readonly. `recentProjectsQuery(false)` and
`recentProjectsQuery(true)` are distinct identities; `projectDirectoriesQuery(null)` is distinct
from every non-null directory identity.

`packages/client-runtime/src/projects/project-mutations.ts` exports two exact definitions:

```text
openProject:
  procedure: projectsProcedures.openRepoPath
  procedureName: 'openRepoPath'
  affectedQueries: [recentProjectsQuery(false), recentProjectsQuery(true)]
  optimistic: false
  requiresAuthoritativeRefetch: true
  selectionEffect: 'select-result'

removeRecentProject:
  procedure: projectsProcedures.removeRecentRepo
  procedureName: 'removeRecentRepo'
  affectedQueries: [recentProjectsQuery(false), recentProjectsQuery(true)]
  optimistic: false
  requiresAuthoritativeRefetch: true
  selectionEffect: 'clear-if-selected-input'
```

The definitions describe consequences; they do not call a daemon or mutate selection. The runtime
does not export raw cache strings, local wire schemas, React hooks, or a notification mapper.
`index.ts` exports only the Project identities, schemas, summary type, mutation definition types,
and the two definitions. Add `"./projects": "./src/projects/index.ts"` to the package exports.

### Web adapter

`apps/web/src/features/projects/project-data.ts` owns the Web binding over the existing tRPC
client and React Query cache. Its exact public hooks are:

```text
useRecentProjects(enabled = true): readonly ProjectSummary[]
useOpenProject(): {
  open: (path: string, options?: { resetPresentation?: boolean }) => Promise<void>
  isPending: boolean
}
useRemoveRecentProject(): {
  remove: (path: string) => Promise<void>
  isPending: boolean
}
useProjectDirectories(path: string | null, enabled: boolean): {
  result: BrowseDirsOutput | undefined
  error: { message: string } | null
  isFetching: boolean
}
useSelectedProject(): ProjectSummary | null
```

Use a strict Web key `[ProjectsQuery, DaemonScope]` with `{ host, version }` from
`useDaemonIdentity`; no tRPC procedure-name key may be written by the adapter. Query functions use
the vanilla `trpc.useUtils().client` bound to the canonical runtime `procedureName` and preserve
wire inputs: false recent queries send `undefined`, true recent queries send
`{ includeWorktrees: true }`, and directory queries send the nullable path.

`useRecentProjects` reads the false identity, returns `data ?? []`, and preserves the current
welcome/switcher empty-on-unloaded or failed read surface. `useProjectDirectories` uses
`keepPreviousData`, preserves the current `useBrowseDirs` return shape and error message, and is
disabled without a picker request. Both hooks parse output through the canonical Projects
procedure descriptors before Query data is exposed.

`useOpenProject` binds `openProject`. On the successful daemon result it applies the selected
Project to the existing Web selection boundary, invalidates exactly both identities in
`openProject.affectedQueries`, and resolves. When `resetPresentation` is true it closes tabs and
resets the local terminal roster before the daemon call, preserving `switchTo`; picker/welcome
opens leave those caller surfaces unchanged. A failed mutation does not select the result or
invalidate recents. No open optimism is allowed.

`useRemoveRecentProject` binds `removeRecentProject`, invalidates exactly its two declared recent
identities only after success, and clears Web selection only when the removed path equals the
currently selected path. An unrelated removal never changes selection. Keep the active selection
action small and presentation-only in `stores/repo.ts`; it must not store the recent query list.

Move `useRecentRepos` and `useRemoveRecentRepo` responsibility out of `hooks/use-repo.ts`; retain
only its unrelated Electron new-window hook. Retarget `project-switcher-menu.tsx`, `welcome.tsx`,
and `repo-picker-dialog.tsx` to `@renderer/features/projects`. The switcher passes
`resetPresentation: true`; welcome and picker opens use the default. Replace `useBrowseDirs` with
`useProjectDirectories`, remove the obsolete hook after its callers move, and retain all current
copy, remote wording, dialog behavior, row removal affordances, and tests.

### Mobile adapter

`apps/mobile/src/features/projects/project-data.ts` owns the mobile binding over the existing
`QueryClient`, `getDaemonClient`, and `callDaemon` transport. It binds the canonical
`projectsProcedures` through `namedContractProcedure`; it does not import the legacy local
connection descriptors for the Project sheet. Its public surface is:

```text
useRecentProjects(active: boolean): {
  projects: readonly ProjectSummary[]
  isLoading: boolean
  loadError: string | null
}
useOpenProject(): {
  open: (path: string) => Promise<void>
  isPending: boolean
}
useRemoveRecentProject(): {
  remove: (path: string) => Promise<void>
  isPending: boolean
}
useProjectDirectories(path: string | null, active: boolean): {
  result: BrowseDirsOutput | undefined
  isFetching: boolean
  isLoading: boolean
  error: string | null
}
useSelectedProject(): ProjectSummary | null
```

Use the exact mobile key `['daemon', environmentId, ProjectsQuery]`, with
`environmentId = environment?.id ?? 'none'`. Query hooks are enabled only when the sheet is
active and the environment is paired. Recent and directory reads use the typed identities and
canonical descriptors; they must not call `useDaemonQuery`/`useDaemonInvalidate` or write
`['recentRepos']`.

`useOpenProject` validates and calls `openRepoPath` through the canonical descriptor, updates the
existing environment selection path, and selects the Project on the existing live session using
the same order as `lib/daemon/repo.ts`. It then invalidates exactly the two identities declared by
`openProject`. A failure leaves the current selection and cache untouched. The compatibility
`openRepo` seam may delegate to this shared canonical lower-level helper so Git worktree and
bootstrap callers do not acquire a second Project transport implementation; its repo/workspace
name remains until PRJ-003.

`useRemoveRecentProject` invalidates the two exact recent identities after success and clears the
active environment path only when the removed path is selected. A different path leaves selection
untouched. There is no optimistic cache or selection update.

Move the Project-sheet data hook out of `features/shell/use-workspace.ts`; keep
`useWorkspaceHeader` and `workspace-lists.ts` presentation derivations in Shell, but obtain the
selected Project through the Projects public entry. Retarget `features/shell/project-sheet.tsx`
to the Projects public entry without changing its rows, test IDs, loading/empty/error copy,
directory navigation, or open-current-folder behavior. The Projects public `index.ts` is the only
outside import path for the adapter.

### Selection boundary

Web and mobile must expose a `ProjectSummary | null` view to their Project callers without moving
server lists into selection state. Web may keep the current `repo` field and mobile may keep the
persisted `activeRepoPath` compatibility field; the adapter derives the summary and PRJ-003 later
renames these product-boundary aliases. Selection removal is conditional and exact: only a removal
whose path equals the selected path clears it. Open selects the daemon's returned summary, not a
client-computed basename.

## Behavior to preserve

- `recentRepos` wire input/output and all four wire names remain unchanged. The default recent list
  hides linked worktrees; restore/bootstrap may still request and receive them.
- Stored recent ordering, Project summaries, nullable browser root, directory filtering, and typed
  `projects.*` failures remain daemon-authoritative and are not recreated in client state.
- Web daemon/environment scoping stays in every Project Query key. Mobile environment scoping stays
  in every Project Query key. A Project path or daemon/environment change cannot reuse another row.
- Open remains a non-optimistic mutation. Successful open selects the returned Project, refreshes
  both recent identities, and retains the current switcher tab/terminal reset distinction.
- Remove remains a non-optimistic mutation. Successful remove refreshes both recent identities and
  clears selection only when the removed path is selected.
- Browse keeps current path text, parent navigation, stale-result handling, remote daemon wording,
  and error/loading/empty distinctions on both clients.
- Mobile Project sheet and Web welcome/switcher/picker copy, controls, accessibility/test IDs,
  selection checks, new-window behavior, and route/sheet transitions remain unchanged.
- Existing bootstrap, pairing-group, Git worktree, Files/Git/Review consumers, and compatibility
  `repo`/`workspace` vocabulary remain operational for their current owners until later recipes.

## Legacy behavior to delete

- Direct Project procedure-hook and procedure-name cache ownership from the named Web and mobile
  switcher/picker adapters: `useRecentRepos`, `useRemoveRecentRepo`, `useBrowseDirs`, mobile
  `useDaemonQuery` Project calls, mobile `useDaemonInvalidate(['recentRepos'])`, and their local
  procedure bindings in the migrated data path.
- The Web `hooks/use-browse.ts` module and the old Web recents/removal hook exports after all listed
  callers move.
- Any new adapter use of `trpc.*`/`useDaemon*` procedure-name cache identities, broad invalidation,
  local Project Zod schemas, or a second Project list store.

Do not delete the lower-level compatibility aliases or legacy descriptor declarations still used by
bootstrap/pairing/Git worktree flows; PRJ-003 owns their product-boundary vocabulary and the
corresponding final search.
