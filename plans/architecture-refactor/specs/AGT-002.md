# AGT-002 — Remove mandatory Companion Review lifecycle and migration guidance

- Status: Ready
- Batch: 8
- Domain: Agent foundations and launch
- Depends on: AGT-001
- Governing decisions: 014, 015
- Primary exemplar: no

## Objective

The authored Companion procedure describes Review as explicit-only, scopes evidence validation to
an intentionally published Review, and contains no obsolete home-to-project migration instructions;
the foundation sync gate rejects a return to the mandatory lifecycle or stale migration wording.

## Why this unit exists

Decision 014 keeps the product Review optional while the current Companion source still tells every
session to clear, create, and complete one. Decision 015 and landed PDT-005 removed the daemon's
home-to-project migration modules, but the authored Companion references still teach that deleted
path. This unit removes those instructions without mutating companion data or deleting the product
surface procedure.

Companion is explicit product-surface procedure, not an automatic session lifecycle.

Ordinary code edits follow root AGENTS.md and do not create, clear, or complete a Review.
For an intentionally published Review, complete Execution and real Evidence, then run

## Behavior to preserve

- The Review remains the Intent · Execution · Evidence product surface and can be authored when the
  human requests it or the agent deliberately publishes a unit for review.
- A prior active Review is never cleared automatically. Explicit clear/set commands remain in the
  CLI manual for an intentional replacement and the human-controlled app flow.
- Evidence checks, Results documents, local assets, sandbox/CSS rules, size caps, and
  `check-evidence.mjs` behavior remain unchanged; only the trigger that calls them changes.
- Board stays a queue, Actions remain human-executed definitions, Notes remain read-only human
  scratchpad, and project-relative scope/worktree/environment guidance remains available.
- Repo-local current-format companion data and the `/.migrated-from-home` disposable marker remain
  intact. The no-missing-repo safety behavior remains intact.

## Legacy behavior to delete

- Mandatory session language in the authored Companion skill and Review/Board references.
- The deleted home-channel migration paragraph in `references/sync-environments.md`.
- The deleted daemon-config import sentence in `references/scope.md`.
- Migration rationale in the git-visibility explanation is replaced with the current disposable
  marker disposition; the marker itself is retained.

The worktree PR-body fallback and current reset classification are explicitly retained, so their
remaining tokens are not misreported as deleted product migration instructions.
