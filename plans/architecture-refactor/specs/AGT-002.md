# AGT-002 — Remove mandatory Companion Review lifecycle and migration guidance

- Status: Draft
- Batch: 8
- Domain: Agent foundations and launch
- Depends on: AGT-001
- Governing decisions: 014, 015
- Primary exemplar: no

## Objective

Make Porcelain Companion an explicit product procedure: never clear/create a Review automatically, publish only at human request or deliberate publication, and remove home-to-project migration guidance when that migration is deleted.

## Why this unit exists

Current Companion guidance conflicts with Decision 014 because it requires session Review clear/create/complete behavior, while the product Review is optional. Its migration guidance also cannot survive the clean v1 cutover.

## Current behavior and evidence

- The inventory identifies mandatory review clear/set in Companion's When→what, Standing rules 1/4, and Lifecycle.
- It requires `check-evidence.mjs` only before claiming a published Review complete.
- `migrate-home.ts`, migration marker, home evidence paths, and Companion migration guidance are historical deletion items; real current-format environment seeding may remain product behavior.

## Scope

- Edit `.agents/skills/porcelain-companion/SKILL.md`, its directly referenced companion docs, `scripts/check-evidence.mjs` references, and foundation sync tests.
- Remove migration guidance only in the same clean-cutover change that deletes the underlying migration paths.

## Non-goals

- Do not clear active Reviews, delete project data, or reset/export user data.
- Do not remove Companion's explicit support for Review, Board, Actions, comments, reviewed marks, notes, layers, scope, evidence, or project-companion data.

## Target ownership and public surface

Companion is invoked only when the human explicitly requests product-companion work or the agent deliberately publishes a Review. It never creates/clears a Review by default. `check-evidence.mjs` runs before a claim that an intentionally published Review is complete. Current-format seed instructions name only surviving roots and never infer/delete old data.

## Behavior to preserve

Preserve explicit Companion commands, version sync, evidence validation for published Reviews, Board/action/comment operations, and never-create-a-missing-repo safety.

## Legacy behavior to delete

Delete mandatory lifecycle language and the home-to-project migration section only after `migrate-home.ts`, `migrate-active-review.ts`, their tests/callers, migrated-from-home entries, and old home evidence readers are removed by authorized clean cutover.

## Ordered implementation

1. Locate and remove mandatory session wording from the exact SKILL sections: When→what, Standing rules 1 and 4, and Lifecycle.
2. Add exact replacement language: do not clear another active Review; create/clear only at human request or intentional publication; check evidence only before completing a published Review.
3. Update direct Companion references so none asks for `review clear`, `review set`, or check-evidence on ordinary code edits.
4. Add a foundation-sync assertion that the Companion skill contains the explicit-only rules and no mandatory lifecycle phrase.
5. When the Project Data clean cutover has deleted migration code, remove Companion migration guidance and assert no reference to home migration/migrated-from-home/loop evidence root remains.
6. Keep deliberate current-format environment seed guidance only if its owning product spec retains it.

## Tests

- `pnpm agents:check` and `pnpm agents:doctor` pass.
- New foundation-sync fixtures fail for mandatory lifecycle or stale migration wording.
- `scripts/check-evidence.mjs` remains tested through explicit published-Review evidence paths.

## Validation and evidence

Run exact searches for `review clear.*session`, `review set.*session`, `migrate-home`, `migrated-from-home`, and `loopEvidenceRoot`; retain only intentional current behavior. Record a fresh-agent read showing no Review action is mandatory.

## Forbidden shortcuts

- Do not replace mandatory lifecycle with an implicit 'normally create a Review' rule.
- Do not delete migration guidance before its code/callers are gone.
- Do not treat ordinary code evidence as authorization to mutate a Review.

## Completion criteria

Companion is explicit-only, evidence checks are publication-scoped, foundation sync enforces that language, and migration wording is absent only after its underlying cutover. Foundation gates pass.

## Handoff

AGT-003 includes the final adapter/skill removal after this text and the clean-data deletion gates are satisfied.
