# REM-005 — Make mobile environments strict version 1

- Status: Draft
- Batch: 3 — remaining domain cutovers
- Domain: remote
- Depends on: REM-003, REM-004, PRO-004, RT-005, TST-001
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Mobile persists only strict version-1 Remote environments and provider/session health uses REM-003 with no version-3 or icon coercion.

## Why this unit exists

`lib/daemon/environment.ts` accepts version 3, defaults omitted fields and converts `box` to `desktop`; provider/client/errors duplicate session decisions.

## Current behavior and evidence

Environment storage, pairing and active selection live in `lib/daemon/{environment,environments-store,pairing,client,provider,errors}.ts(x)` and Settings environment screens consume them.

## Scope

Replace those Remote data/session adapters with `features/remote/` and strict v1 Secure Store adapter; update Settings callers; delete version-3 readers/writers/defaults/icon conversion and mobile `DaemonError` classification.

## Non-goals

Do not delete user data, add migration reading, alter pairing/auth, change UI copy, or move Secure Store into client-runtime.

## Target ownership and public surface

`MobileEnvironmentStore` reads/writes only REM-001 strict v1 values; malformed/incompatible persisted values become a visible safe reset-required state without coercion. `RemoteProvider` binds platform foreground/socket lifecycle to REM-003/RT-005 and exposes health/update-required. Settings imports `useRemoteEnvironments` and typed actions from the feature index.

## Behavior to preserve

Keep paired endpoint choice, token secrecy, active selection, foreground reconnect, pairing flow, endpoint failure feedback and native Settings controls.

## Legacy behavior to delete

Delete version `3`, `box`→`desktop`, missing-icon/default coercions, old environment aliases, local `DaemonError`, and raw provider invalidation/error paths.

## Ordered implementation

1. Verify REM-003/004, protocol and realtime cutover.
2. Add strict v1 storage/provider adapters and update Settings callers.
3. Delete every legacy reader/writer/coercion and compatibility test.

## Tests

Test valid v1 round trip, malformed/incompatible diagnostic, no coercion, selection, foreground reconnect, update-required and typed public errors; retain pairing/settings presentation tests.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../mobile/src/features/remote ../mobile/src/lib/daemon/environment.test.ts ../mobile/src/lib/daemon/provider.test.ts` after relocation.
- Run `pnpm --dir apps/mobile typecheck` and `pnpm lint`.
- Run `rg -n "version: 3|\bbox\b|DaemonError|icon.*desktop|procedures/connection" apps/mobile/src`; it returns no result.

## Forbidden shortcuts

Do not preserve an old-format reader, silently reset/delete storage, parse error messages, or add a mobile retry fork.

## Completion criteria

- [ ] Strict v1 environment storage/provider uses shared Remote/session semantics.
- [ ] All v3/icon/error compatibility is deleted with safety tests.
- [ ] Typecheck, lint and searches pass; the unit is committed.
