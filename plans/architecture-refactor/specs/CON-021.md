# CON-021 — Delete horizontal contracts and make domain catalog exhaustiveness permanent

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: contract catalog cutover
- Depends on: `CON-020`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [012](../decisions/012-enforce-the-target-architecture.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Delete every horizontal/fallback procedure contract and temporary migration ledger so the ten domain
records and their composed catalog are the only 113-procedure wire truth.

## Why this unit exists

All nine production router files now consume exact catalog inputs and outputs. Keeping the former
horizontal schemas, empty ownership ledger, baseline, tombstone, or validation ledger would preserve
two architectures after their sole migration purpose ended.

## Current behavior and evidence

- `CON-020` leaves the lint remaining-file set empty and all 113 routers contract-validated.
- `packages/contracts/src/procedures/{names,io,refined,index}.ts` still owns duplicate names and
  partial/copied schemas plus `z.unknown` fallback I/O.
- `procedure-ledger.ts`, `procedure-ledger-baseline.ts`, and `procedure-ledger.test.ts` are temporary.
- `packages/contracts/src/router.ts` is a stale `AppRouter = never` tombstone.
- Ten domain procedure files still import the horizontal `ProcedureName` only to constrain keys.
- `apps/mobile/src/lib/daemon/procedures/connection.ts` imports three horizontal root leaf exports:
  `daemonInfoOutputSchema`, `browseDirsOutputSchema`, and `repoInfoSchema`.
- `packages/contracts/src/project-data/project-data.procedures.test.ts` still imports the temporary
  ledger solely for the empty-ledger assertion alongside its durable Project Data contract tests.
- `packages/contracts/README.md` and `docs/internals/architecture.md` still describe
  `PROCEDURE_NAMES`, `procedureIo`, 63 refined schemas, and 50 unknown fallbacks as current truth.

## Scope

Delete the exact legacy files above, remove their root/package exports, make catalog-owned names and
domain subpath exports permanent, update the one mobile connection import to canonical Remote/
Projects entry points, remove obsolete `ProcedureName` imports from all ten domain procedure files,
replace migration-aware procedure lint/tests with permanent catalog/router exhaustiveness, and
remove the obsolete foundation-to-app import exception from architecture lint. Update the two
current-truth docs above and add a focused mobile connection contract test.

## Non-goals

Do not rename wire procedures, move routers, replace `AppRouter` inference in Web, migrate other
mobile-local schemas, change runtime request/response behavior, retain aliases/fallbacks, or begin
protocol/domain application migrations.

## Target ownership and public surface

- `procedureCatalog` remains the flat frozen 113-entry catalog; export
  `ProcedureName = keyof typeof procedureCatalog` from `procedure-catalog.ts` and the package root.
- Package `exports` exposes `./remote`, `./projects`, `./files`, `./search`, `./git`, `./review`,
  `./board`, `./actions`, `./terminal`, and `./project-data`, each resolving to its domain `index.ts`.
- Mobile connection imports daemon info from `@porcelain/contracts/remote` and browse/repo schemas
  from `@porcelain/contracts/projects`.
- Each domain's `*ProcedureName` is `keyof` its own definition object; it no longer extracts from a
  horizontal name union.
- Permanent lint derives names/domain/kinds from the ten records, requires exactly 113 unique catalog
  entries and router procedures, and requires exact same-name input/output middleware for every
  router. It explicitly enumerates exactly `board.ts`, `daemon.ts`, `files.ts`, `git.ts`,
  `network.ts`, `repos.ts`, `review.ts`, `settings.ts`, and `terminal.ts` so test/support `.ts` files
  are never mistaken for production routers. There is no remaining-file set, baseline, waiver, or
  fallback branch.
- `packages/contracts/src/router.ts:@backend/api` is removed from
  `LEGACY_FOUNDATION_APP_IMPORTS`; with no remaining exception, architecture lint rejects every
  foundation-package import from an application unconditionally and deletes its stale-entry loop.

## Behavior to preserve

Preserve all 113 names/kinds/schemas/errors, runtime output validation, root exports unrelated to the
horizontal procedures, Web `AppRouter` imports from `@backend/api`, mobile connection parsing,
serialization, authentication, error formatting, and all application behavior.

Delete with no replacement alias:

PROCEDURE_NAME_SET, and horizontal copied leaf schemas

No compatibility barrel, deprecated re-export, copied schema, `unknown` I/O, or tombstone remains.

## Ordered implementation

1. Export catalog-derived `ProcedureName`; update ten domain procedure-name types and remove their
   horizontal imports.
2. Add ten domain package subpath exports and move the one mobile connection import to Remote/
   Projects entry points; ensure needed schemas are exported by those domain indexes.
3. Remove horizontal procedure/root exports, then delete `procedures/**`, both ledgers, their tests,
   baseline, and `router.ts`; remove only the temporary ledger import/assertion from the Project
   Data procedure test while preserving all of its durable contract cases.
4. Rewrite procedure lint and fixtures around permanent ten-domain/catalog/router exhaustiveness;
   delete the now-empty router migration set and every migration-only parser/branch.
5. Delete the contracts-router foundation import exception and simplify architecture lint to reject
   every foundation-to-application import; retain its existing failure coverage.
6. Replace the stale contracts/architecture prose with the ten-domain, 113-exact-schema truth; add
   `apps/mobile/src/lib/daemon/procedures/connection.test.ts` proving the canonical subpath schemas
   accept representative daemon-info, recent/open repo, and browse results, and separately proving
   the connection module's local void descriptors still parse `undefined`.
7. Rename/retain the catalog test as the permanent exact 113-name/kind/contract proof and run all
   client/build gates to catch stale imports.

## Tests

`packages/contracts/src/procedure-catalog.test.ts` becomes self-contained and asserts exact catalog
count, unique keys, ten-domain coverage, kinds, schemas, and errors without a baseline. Lint fixtures
must reject duplicate/missing catalog names, wrong kind, missing/wrong/duplicate input/output, and
any import/reference to deleted horizontal paths. The new mobile connection test proves canonical
subpath imports parse the same structured wire values and its local void descriptors remain exact.

## Forbidden shortcuts

Do not keep a re-export, alias, deprecated file, `z.unknown` fallback, migration ledger, root copied
schema, mobile local replacement, foundation-import exception, or lint whitelist. Forbidden-path
fixture strings may remain only in lint test files and are excluded from the production deletion
search. Do not delete a canonical domain schema merely because its horizontal copy had the same name.

## Completion criteria

- [ ] Ten domain records and one composed catalog are the only 113-procedure schema/name truth.
- [ ] Every router permanently uses exact catalog input/output and matching kind.
- [ ] Every named horizontal/ledger/tombstone/fallback path and export is absent.
- [ ] Mobile connection uses canonical domain entry points with unchanged behavior.
- [ ] Catalog tests, lint fixtures, deletion searches, repository lint, full verify, and diff pass.
- [ ] One commit lands only `CON-021`, marks recipe/catalog Landed, leaves a clean worktree, provides
      the README review packet, and finishes without pushing.

## Handoff

Protocol, realtime, daemon-composition, and domain migrations may assume there is no horizontal
contract fallback and every daemon procedure validates both sides of the wire through its domain
record.
