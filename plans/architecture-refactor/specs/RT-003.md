# RT-003 — Build client real-time recovery and file-interest runtime

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: real-time client runtime
- Depends on: `RT-001`, `RT-002`, `PRO-003`
- Governing decisions: [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Create a transport-neutral client runtime that performs hello/ready, tracks epochs and sequences,
recovers through authoritative invalidation, and sends bounded file interests.

## Why this unit exists

Recoverability belongs below Web/mobile adapters. A shared runtime prevents each client from inventing
its own reconnect, sequence-gap, and watch-interest semantics.

## Current behavior and evidence

Existing client session handling is embedded in Web/mobile-specific daemon modules; the shared
legacy helper is flat `packages/client-runtime/src/session-protocol.ts` (backoff, WS URL, token
subprotocol, legacy 4001 revoked close), which stays untouched until `RT-005`. `RT-002` (Landed)
provides the unactivated daemon modules and binds this runtime to two obligations: the daemon
sequences per subscription, so every reconnect resets `sequence` and is itself a recovery point
(epoch alone does not capture this); and a session that never sends `session:watches` receives no
change frames, so the runtime must send watches after ready even when interests are empty. The
interest cap is `SESSION_WATCH_INTEREST_LIMIT` from `@porcelain/contracts/session`, never a literal.
`RT-002` also reserved close codes 4401 (unauthenticated) and 4402 (protocol mismatch) beside the
legacy 4001.

## Scope

Create `packages/client-runtime/src/session/{client-runtime,recovery,interests}.ts` (and focused
tests) as the only shared session state machine. It receives an injected transport, sends hello then
watches after ready, exposes parsed change/terminal frames, tracks epoch/sequence, and emits
authoritative refresh requirements on reconnect, mismatch, epoch change, or sequence gap. It remains
unbound to application transports until `RT-005` activates all runtime sides together.

## Non-goals

Do not bind React Query, browser WebSocket, React Native WebSocket, screens, cache keys, or legacy
file deletion. `RT-004` and `RT-005` own concrete adapters.

## Target ownership and public surface

Recovery is conservative: it never reconstructs missed mutations from signals. A gap or reconnect
marks affected project data stale for the adapter to refetch. Interests are merged/deduplicated,
limited to the daemon's 128 combined paths, and sent only after ready. Mismatch is terminal until a
compatible client is installed.

## Behavior to preserve

Preserve terminal frame order, project scoping, no-change behavior for contiguous signals, and the
existing rule that authoritative RPC reads—not push payloads—provide fresh UI data.

## Legacy behavior to delete

Delete no app-local adapter here. `RT-005` removes legacy real-time code only after both concrete
adapters use this runtime.

## Ordered implementation

1. Define transport-neutral state and lifecycle interfaces.
2. Implement hello/ready, strict frame parsing, epoch/sequence tracking, and mismatch state.
3. Implement recovery/invalidation and interest aggregation with cap enforcement.
4. Add deterministic fake-transport tests.

## Tests

Cover normal ready/contiguous change, reconnect, epoch change, sequence gap, mismatch, invalid frame,
interest merge/removal/cap, and terminal ordering.

## Forbidden shortcuts

Do not expose raw socket events, replay guessed missed mutations, add React dependencies, or let a
client submit more than 128 interests.

## Completion criteria

- [ ] Interests are ready-gated, merged, and bounded.
- [ ] Runtime tests, repository lint, full verify, and diff check pass.

may duplicate recovery logic.
