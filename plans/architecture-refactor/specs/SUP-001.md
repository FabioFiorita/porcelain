## Objective

Web and mobile shell, settings, and viewer production files compose
canonical domains only through each domain's public `index.ts`; a
permanent lint rejects transport, daemon, `@backend`, procedure-schema,
and deep target-root imports from those files; the Review feature owns
`formatBytes`; and landed FIL-005 / REM-004 / PDT-003 / REV-007
presentation stays where those units left it.

## Why this unit exists

REV-007 and the domain cutovers already moved product data out of
supporting regions. Leaving that seam unratcheted lets `lib/trpc`, a
daemon type, or a deep feature import re-enter shell/settings without a
gate. Decision 012 puts that ratchet in a script rather than prose.
Decision 013 forbids turning shell/settings into an eleventh domain, so
the lint must allow public-index composition and must not demand a
relocation that reverses landed stay-rulings.

Import specifier extraction matches `lint-cli-boundary.mjs`
`importSpecifiers` (the `from` / `import(` / `import` regex).

A specifier is forbidden when any of these hold. Import
`DOMAIN_KEYS` from `./architecture/domains.mjs`.

1. It equals or starts with `@renderer/lib/trpc`, `@/lib/trpc`,
   `lib/trpc`, or the same four forms with `daemon` instead of `trpc`.
2. It equals or starts with `@backend/`.
3. It is a deep import into a canonical domain feature:
   - `@renderer/features/<domain>/…` or `@/features/<domain>/…`
   - `<domain>` is a `DOMAIN_KEYS` entry
   - the remainder after `<domain>/` is not `index` or `index.ts`
   Barrel imports `@renderer/features/<domain>` and `@/features/<domain>`
   are legal. `@/features/changes/…`, `@/features/history/…`,
   `@/features/diff/…`, `@/features/shell/…`, and `@/features/settings/…`
   are legal because those names are not in `DOMAIN_KEYS`.
4. A named import from `@porcelain/contracts` or
   `@porcelain/contracts/…` matches `/(Query|Mutation)Schema$/`.
   `commitModelSchema`, `endpointKind`, and type-only contract imports
   are legal.

`describeDisposition` as a settings import). Do not forbid
