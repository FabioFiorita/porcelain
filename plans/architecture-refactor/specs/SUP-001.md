# SUP-001 — Remove product ownership from global Web/mobile shell/settings regions

- Status: Draft
- Batch: 7
- Domain: Shell and Settings supporting regions
- Depends on: ARC-002, CON-001
- Governing decisions: 003, 004, 006, 013, 014
- Primary exemplar: no

## Objective

Make Shell, Settings, Viewer, and UI presentation-only supporting regions. Move product reads, mutations, schemas, and feature state from global regions into the canonical domain feature paths that own them.

## Why this unit exists

The registry reserves `shell`, `settings`, `viewer`, and `ui` as supporting regions, but current Web/mobile shell and settings files still contain Projects, Remote, Review, Files, Git, Board, and Actions behavior.

## Current behavior and evidence

- Web global regions are `apps/web/src/components/{shell,settings,viewer}` and `apps/web/src/lib/responsive-shell.ts`.
- Mobile global regions are `apps/mobile/src/features/{shell,settings}`; they currently include workspace/project, environment, Review layers/editor, and presentation state.
- The domain registry assigns those product concerns to Projects, Remote, Review, Files, Git, Board, and Actions; supporting regions may compose but not own policy.

## Scope

- Inventory every product import/state/procedure in the exact Web/mobile regions above.
- Move each to the matching `apps/web/src/features/<domain>/` or `apps/mobile/src/features/<domain>/` migration root when that domain's contract/runtime slice exists.
- Leave layout, navigation, window/tab/sheet orchestration, visual primitives, and settings assembly in supporting regions.

## Non-goals

- Do not create empty feature folders, duplicate a domain hook/store, change a public procedure, or complete a domain before its own cutover specification.
- Do not move Viewer rendering resilience; SUP-002 owns that proof.

## Target ownership and public surface

Shell owns navigation, panes, tabs, sheets, windows, and composition. Settings owns controls that assemble owner-provided views. `ui` owns generic visual primitives. Product behavior is imported only through each domain's public `index.ts`; no Shell/Settings module exports a domain schema, domain store, or domain mutation hook.

## Behavior to preserve

Preserve current shell navigation, phone/tablet layout, settings navigation, accessibility labels, and domain-visible behavior while ownership moves. Keep mobile NativeWind and 450-line constraints.

## Legacy behavior to delete

Delete only the moved product-specific hooks/stores/procedure calls from `apps/web/src/components/{shell,settings}` and `apps/mobile/src/features/{shell,settings}` after the canonical domain import replaces every caller. Do not delete a supporting layout component.

## Ordered implementation

1. Add an exact per-file ownership ledger to this spec's implementation evidence: source path, exported product behavior, canonical owner, target public import, and retained supporting responsibility.
2. For one canonical domain at a time, move its behavior with that domain's migration and replace global-region imports with the domain public entry.
3. Keep Shell/Settings components declarative: accept domain view models/callbacks or render the domain feature component; they do not issue tRPC calls or persist state.
4. Add `scripts/lint-supporting-regions.mjs` to reject imports of `lib/trpc`, `lib/daemon`, daemon clients, contract procedure schemas, and canonical domain stores from the listed supporting directories, except explicit domain public `index.ts` imports.
5. Add fixture tests for each rejected import and one legal composition import; add the script to root `lint`.
6. Remove ledger entries and old imports only after the owning domain test proves the relocated behavior.

## Tests

- Focused Web/mobile feature tests retain the moved product behavior using contract-valid mocks.
- Supporting-region tests cover composition and navigation only.
- `node scripts/lint-supporting-regions.mjs` and `pnpm lint` pass.

## Validation and evidence

For each moved behavior, record the old path, canonical owner, new public import, focused domain test, and passing supporting-region lint. Run `pnpm test` and `pnpm lint` before declaring the ledger entry removed.

## Forbidden shortcuts

- Do not make Shell/Settings an eleventh domain or allow a direct deep feature import.
- Do not move business rules merely by renaming a global store.
- Do not add a lint exception instead of completing the ownership move.

## Completion criteria

Every listed global product import has a canonical owner/public entry, supporting regions have no product policy or direct transport, and the lint has no exception. Focused tests, `pnpm test`, and lint pass.

## Handoff

Domain cutover specs consume the ledger one owner at a time. SUP-001 completes only after the final global-region product behavior is relocated; SUP-002 separately owns Viewer resilience.
