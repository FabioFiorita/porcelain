## Architecture reviewer rulings

These bind the executor and supersede every conflicting sentence in the tracked Draft.
They are decisions already made; the executor does not reopen them.

1. **Four Review identities already exist — in the Git slice — and they move here.**
   `packages/client-runtime/src/git/git-queries.ts` defines `reviewReadingQuerySchema`
   (line 173), `reviewViewQuerySchema` (181), `reviewedPathsQuerySchema` (189) and
   `worktreeInboxQuerySchema` (197), plus the constructors `reviewReadingQuery` (399),
   `reviewViewQuery` (403), `reviewedPathsQuery` (407) and `worktreeInboxQuery` (411) —
   all already stamped `domain: 'review'`. Defining them a second time under
   `review/` would give one cache key two constructors, which Decision 008 forbids.
   They are therefore **relocated**, not duplicated, and the Git slice imports them
   back through the public package subpath `@porcelain/client-runtime/review` — the
   landed cross-slice door `git-mutations.ts:1-7` already uses for
   `@porcelain/client-runtime/files`. No re-export shim is left in `git/index.ts`.

2. **`gitWorkspaceQuerySchema` keeps its exact membership.** It is the union both app
   query-key parsers validate against (`apps/web/src/features/git/git-query-key.ts:7`,
   `apps/mobile/src/features/git/git-query-key.ts:11`), so its four Review members stay
   in it — now imported from `../review`'s public index rather than declared locally.
   The new REV-006 identities are **not** added to it: they get their own Review key
   namespace in REV-007 and REV-008.

3. **`reviewWorkspaceQuerySchema` and `ReviewWorkspaceQuery` are deleted, not moved.**
   They have no consumer anywhere (`git/index.ts:60,64` export them and nothing
   imports them); the REV-006 `reviewQuerySchema` supersedes them.

4. **The wire stays live-named.** Identities, mutations and effects bind the live
   `reviewProcedures` catalog (`packages/contracts/src/review/review.procedures.ts`).
   `review.target-procedures.ts` — including `REVIEW_TARGET_STALE_ON_REVIEW_CHANGED`
   (line 196) — stays unimported outside its own test; REV-009 alone activates it. That
   constant is the reviewed **judgment source** for this unit's staleness set, and this
   recipe transcribes it into live names below so the executor never reads it at runtime.

5. **Reviewed marks are optimistic today and stay optimistic — as pure shared behavior.**
   `apps/web/src/features/git/git-reviewed.ts:51-56` cancels, snapshots, and patches the
   reviewed-paths cache, and rolls back at `:48`; mobile
   (`apps/mobile/src/features/changes/use-changes.ts:69`) is invalidate-only. The Draft's
   "no Review mutation is optimistic except RVC comments" is false against this tree.
   This unit owns the three pure reviewed-marks transitions and their rollback, following
   the landed `comment-reconciliation.ts` idiom. Every other Review mutation stays
   non-optimistic: publish, archive, restore, delete and clear-evidence perform Git and
   filesystem effects Decision 008 explicitly excludes from optimism.

6. **No intent mutation exists.** The live catalog has `reviewIntent` as a query only;
   Intent is authored through the CLI (REV-005). The Draft's "intent" mutation is
   dropped. The eight non-comment mutations are exactly `markReviewed`,
   `unmarkReviewed`, `setReviewed`, `clearFeatureReview`, `publishReview`,
   `restoreArchivedReview`, `deleteArchivedReview`, `clearLoopEvidence`.

7. **Review mutations declare Review identities only.** Web's publish today also
   invalidates `gitStatus` (`apps/web/src/hooks/use-review-intent.ts:53`) and
   `review.changed` today also refreshes `repoLayers`
   (`apps/web/src/hooks/use-session-runtime.ts:84`). Those cross-domain refreshes belong
   to the Git and Project Data bridges — the landed `project-data-mutations.ts:20-22`
   precedent — and are not encoded here.

8. **Comments stay RVC-002's.** `reviewNotificationEffects` does not return the comments
   identity: `reviewCommentNotificationEffects` already maps `review.changed` to it and
   both are mounted separately in each client. `reviewQuerySchema` composes
   `reviewCommentsQuerySchema` by importing it from `./comment-queries` so one Review key
   namespace parses, without redeclaring the comments identity or its constructor.

## Objective

`@porcelain/client-runtime/review` owns every canonical Review server-state identity
outside comments, the exact consequences of the eight non-comment Review mutations, the
pure reviewed-marks optimistic transitions, and the exhaustive `review.changed` staleness
set — and no Review identity is declared anywhere else in client-runtime.

## Why this unit exists

Review cache identity is currently split three ways: four typed identities inside the Git
slice (ruling 1), tRPC's implicit per-procedure keys in Web
(`apps/web/src/hooks/use-{feature-view,feature-reading,review-intent,evidence,explore}.ts`),
and procedure-name strings in mobile (`apps/mobile/src/features/review/use-review.ts:42-52`,
`apps/mobile/src/lib/daemon/provider.tsx:63-70`). The two clients' `review.changed` sets
already disagree, and each mutation caller invalidates a different collection. REV-007 and
REV-008 cannot bind a boundary that does not exist yet.

### `reviewed-marks-reconciliation.ts`

Pure, framework-free, and total over the three mark procedures — the
`comment-reconciliation.ts` idiom without temporary ids, because the server assigns
nothing here.


## Behavior to preserve

- Every relocated identity keeps its exact object shape, so existing Web and mobile Git
  workspace cache keys, `parseGitQueryKey`, and `isGitQueryKey` behave identically.
- `gitWorkspaceQuerySchema` still accepts and rejects exactly what it does today, and
  `gitNotificationEffects` / `gitMutations` still declare the same Review consequences of
  Git writes — including `worktree-inbox` after `gitAddWorktree`.
- `gitReviewNotificationEffects` stays the owner of `review.changed`'s Git consequences.
- Reviewed marks stay instant: a pure transition, a snapshot, an exact rollback, and an
  authoritative refetch afterwards.
- Archive, publish, restore, delete and clear-evidence stay non-optimistic: they perform
  Git, filesystem and process effects whose success the client cannot predict.
- Publishing still makes the archive list, the whole Review canvas and the publish cost
  stale; deleting an archive still makes only the archive list stale.
- Evidence clearing still leaves the rest of the active review alone.
- Comments keep their separate reversible behavior and their own notification mapping.
- An empty project path stays a programmer error (a thrown identity error), never a public
  error code, and identity construction never performs I/O.
