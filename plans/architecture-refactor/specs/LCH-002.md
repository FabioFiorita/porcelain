# LCH-002 — Remove final ledgers and prove canonical/fresh-agent discoverability

- Status: Draft
- Batch: 9
- Domain: Agent foundations and launch
- Depends on: AGT-003
- Governing decisions: 013, 014, 015
- Primary exemplar: no

## Objective

Remove every completed migration ledger/exception and prove canonical vocabulary, target ownership, and agent discovery from a clean checkout.

## Why this unit exists

A completed domain cannot retain a legacy waiver, alias, or stale foundation instruction. Launch needs machine-readable absence proof as well as passing product behavior.

## Current behavior and evidence

- Architecture target requires completed-domain legacy baselines to shrink to zero and no waiver.
- Inventory completion searches name migrations, Evidence legacy paths, Feature/Project aliases, Ship/Audit refs, and completed-domain ledger entries.
- AGT-003 removes retired foundation surfaces; LCH-002 proves no new hidden authority remains.

## Scope

- Remove only registry `legacyPaths`, compatibility exceptions, and migration-ledger rows whose owning cutover completion criteria are met.
- Add final exact searches/gates and fresh-agent discovery proof.

## Non-goals

- Do not delete non-completed paths, real data, resilience tests, or an owner doc merely to satisfy a zero-hit search.

## Target ownership and public surface

`DOMAIN_MIGRATIONS` lists every domain `complete` with target roots and no existing legacy path. Architecture, support, CLI, Desktop, and foundation lint gates have no compatibility exception. Root plus focused procedures are sufficient for a fresh agent to discover delivery loop, domain boundaries, proof surface, and optional Companion.

## Behavior to preserve

Preserve current canonical docs, targeted owner tests, resilience/security gates, and explicit Companion procedure.

## Legacy behavior to delete

Delete exact ledger entries only after their named target caller/contract/test replacement passes. Delete stale plan references only when they describe already-landed work; retain historical decision/inventory evidence.

## Ordered implementation

1. For each completed domain, run its cutover search and prove all callers use the registered public root.
2. Remove its `legacyPaths` and temporary exception only in the same commit as the last old path/alias deletion.
3. Run exact searches for `ensureProjectCompanion|migrateActiveReviewLayout|migrated-from-home|loopEvidenceRoot`, evidence legacy names, Feature/Project boundary aliases, and Ship/Audit active references; classify every hit before deletion.
4. Add `scripts/lint-launch-cleanup.mjs` that rejects remaining completed-domain ledger entries and known forbidden active paths; test it with fixtures and add to root lint.
5. Perform fresh-agent review from a clean checkout using root and focused procedures only; record discovered loop, gate, browser/mobile proof, domain rule, and Companion optionality.

## Tests

- Launch-cleanup fixtures cover remaining ledger/alias/path failures.
- `pnpm lint`, `pnpm agents:check`, `pnpm agents:doctor`, and `pnpm verify` pass.

## Validation and evidence

Attach zero-hit/classified-search report, registry output, lint result, and fresh-agent walkthrough. Exclude historical plans/inventory from active-source zero-hit checks explicitly by path.

## Forbidden shortcuts

- Do not remove a ledger entry before the old caller is gone.
- Do not use a global rename or ignore to create a misleading zero-hit result.
- Do not treat an approved real-data reset as implied by ledger cleanup.

## Completion criteria

All completed domains have no legacy ledger/waiver, active source has canonical vocabulary, foundation discovery succeeds fresh, and full gates pass.

## Handoff

LCH-003 performs the clean-checkout assembled launch evidence after this canonical/ledger proof.
