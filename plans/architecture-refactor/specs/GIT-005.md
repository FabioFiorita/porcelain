## Objective

Move the remaining Git working-tree, commit, branch, status, suggestion, and model-generation procedures into bound Git operations over explicit capabilities, leaving only the GIT-006 flow/diff/history reads and the Review Inbox on the residual router.

## Why this unit exists

apps/daemon/src/router/git.ts still owns complete workflows: it calls Git helpers directly, clears the working-tree cache, moves discarded files to Trash, clears Review marks after commits, and invokes commit-generation CLIs. The feature boundary created by GIT-002 currently binds only checkout and add-worktree.

## Target ownership and public surface

### Capabilities and adapters

ProjectGit is a fixed-command project capability, not a generic run(args) port. It exposes only the named Git intentions required by this unit: quick command, push, stage/unstage all and one path, file-in-HEAD probe, restore/reset path, commit, committed-file listing, status, suggestions, head, branches, create branch, worktrees, and bounded log. The adapter preserves the existing helper argv, gitEnv scrubbing, caller cwd, max buffer, path behavior, and unexpected exceptions.

The three declared read failures use this exact internal shape:

    type GitProjectError = { code: 'git.not-a-repository' }
    type GitProjectResult<Value> =
      | { ok: true; value: Value }
      | { ok: false; error: GitProjectError }

Only status, branches, and worktrees return that result shape. The adapter recognizes the native repository-discovery outcome at its boundary and rethrows every unmatched exception. Other operations return their contract value and let unexpected defects reach centralized mapping; no operation or router matches stderr.

The remaining capability seams are narrow and named for their effects:

- CommitGeneration exposes generateMessage and generateGroups over the contract inputs.
- WorkspaceTrash exposes only moveToTrash(path) for the new-file discard branch.
- ReviewMarks exposes only clear(repoPath, paths) for the explicit post-commit cleanup.
- WorkingTreeCache exposes only clear(repoPath).
- GitChanges exposes publishWorkingTreeChanged(projectPath), with a feature publisher mapping it to the existing typed git.working-tree-changed session fact.

The production composition root constructs these adapters once and passes them to createGitOperations. Tests inject narrow fakes; no module mocks or process-global Git singleton are introduced.

### Operations

GitOperations retains the existing checkoutGit and addGitWorktree operations and adds one operation for each moved intention: quickCommand, push, stageAll, unstageAll, stageFile, unstageFile, discardFile, commit, generateCommitMessage, generateCommitGroups, commitConventions, status, suggestions, head, branches, createBranch, and worktrees.

The operation ordering is explicit:

1. staging, unstaging, discard, and working-tree-changing quick commands perform Git work, clear the snapshot, then publish the typed working-tree fact; failed work performs neither effect;
2. gitQuickCommand preserves the current cache clear for every successful quick command, but publishes only for commands that can change the working tree (pull, stash, and stash-pop); status, fetch, and push do not claim a working-tree change, and the dedicated gitPush keeps its current no-clear behavior;
3. discardFile probes fileInHead, restores a tracked path or resets then sends a new path to Trash, and publishes only after the complete branch succeeds;
4. commit calls Git, clears the snapshot, lists HEAD files, clears Review marks, then publishes; this preserves the existing commit cleanup order and makes the notification observe durable cleanup;
5. commitConventions reads exactly 200 commits through ProjectGit.log and applies the pure parseConventions rule; generation operations return the existing contract-shaped message/group values.

### Router and composition

createGitFeatureRouter(operations) owns exactly the 17 moved public names. It validates directly with procedureCatalog, calls one operation per resolver, maps git.not-a-repository with expectedFailure('git.not-a-repository') and toTrpcError, and lets unexpected exceptions reach the centralized internal.unexpected boundary. The residual createGitRouter() owns only the nine GIT-006 reads plus worktreeInbox; there is no duplicate flat procedure.
