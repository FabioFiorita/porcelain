- Depends on: `GIT-002` (Draft), `CON-012` (Draft), `ERR-001` (Draft), `DAE-001` (Draft), `TST-002` (Draft)

- Primary exemplar: no

## Objective

Move every Git procedure other than checkout/add-worktree and later Changes/History cutover reads into bound Git operations over explicit Git capabilities.

## Why this unit exists

`router/git.ts` still directly orchestrates stage, commit, push, branch, status, models, and cache/review side effects.

## Current behavior and evidence

The exact remaining Git names are the Git rows in `inventory/backend.md`; sources are `router/git.ts`, `git/{git,commit-generation,conventions,working-tree}.ts`, `fs/move-to-trash.ts`, and reviewed marks.

## Scope

Create/extend `apps/daemon/src/features/git/{git-ports,git-operations,git-router}.ts`; move all Git router procedures except `diffReading`, flow/diff/history reads reserved for GIT-006, and replace direct imports with bound operations.

## Non-goals

Do not move Review inbox/layers, Files trash policy, client mutation semantics, or GIT-006/007 deletion.

## Target ownership and public surface

Operations retain one current procedure intention each; `ProjectGit` capability owns fixed git invocation/outcomes, `ReviewMarks` is a narrow foreign capability used only by commit's explicit post-commit clear. Working-tree cache invalidation and `git.working-tree-changed` publish after successful mutations are explicit.

## Behavior to preserve

Preserve all Git arguments, cache clearing, commit reviewed-mark clearing order, model generation, limits, env scrubbing, and unexpected error handling.

## Legacy behavior to delete

Delete direct store/Git/trash/commit-generation imports from `router/git.ts` for these procedures; retain source helpers only until their adapter replacement has zero callers.

## Ordered implementation

1. Split remaining names by direct capability and contract error list.
2. Extract typed adapter outcomes and operation tests.
3. Bind operations, preserve required post-success order, publish facts.
4. Delete router direct behavior and test mapping.

## Tests

Use real disposable Git adapter tests, focused operation fakes for ordering, and router mapping/output tests for every remaining record.

## Forbidden shortcuts

Do not create a god Git port, hide Review effects in notifications, retain router native errors, or change clients.

## Completion criteria

- [ ] Every in-scope Git router procedure invokes one bound operation.
- [ ] Explicit capability/ordering/error tests cover host risk.
- [ ] Direct router behavior is absent and gates pass.

## Handoff
