# PRJ-003 — Complete the Project vocabulary cutover

- Status: Draft
- Batch: 3 — remaining domain cutovers
- Domain: projects
- Depends on: PRJ-002, FIL-006, GIT-004
- Governing decisions: [002](../decisions/002-organize-by-product-domain.md), [005](../decisions/005-contracts-own-the-wire.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Product boundaries use Project vocabulary and no generic repo/workspace alias remains outside Git worktree terminology.

## Why this unit exists

Selected Project state and product APIs still expose `repo`, `repoPath`, `RepoInfo`, `workspace`, and `openRepoPath` even after PRJ-002 owns their behavior.

## Current behavior and evidence

- Web uses `stores/repo.ts`, `useRepoStore`, `use-repo.ts`, and Shell repo picker imports.
- Mobile uses `lib/daemon/repo.ts`, `useActiveRepo`, `features/shell/use-workspace.ts`, and workspace route language.
- Git linked worktrees are a distinct product concept and retain `worktree`.

## Scope

Rename product-boundary project state/hooks/types/paths in Web and mobile to `project`; update contracts/feature adapters/tests; delete old aliases in the same commit.

## Non-goals

Do not rename Git `worktree`, filesystem repository arguments internal to adapters, persisted user data, daemon operations, or historical docs outside exact product imports.

## Target ownership and public surface

`ProjectSummary`, `ProjectPath`, `useSelectedProject`, `useActiveProject`, and `ProjectSelectionStore` are the only client-facing project names. Feature adapters accept `projectPath`; Git worktree APIs retain `worktreePath` only where they identify a linked checkout.

## Behavior to preserve

Keep selected-project scoping, current routes, recent-project UI, project switching and daemon filesystem/Git behavior.

## Legacy behavior to delete

Delete `useRepoStore`, `useActiveRepo`, `repoPath`, `RepoInfo`, `workspace` selection aliases, `openRepoPath`, and their compatibility re-exports from product boundaries.

## Ordered implementation

1. Verify PRJ-002, Files and Git adapters consume Project boundaries.
2. Rename types/stores/hooks/callers atomically, preserving only Git worktree terminology.
3. Delete aliases and update tests/search baselines.

## Tests

Update project picker/switching, Files/Git active-project scoping and mobile route tests; add no compatibility tests.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../web/src/features/projects ../mobile/src/features/projects ../web/src/hooks/use-repo.test.ts` after relocating its assertions.
- Run `pnpm --dir apps/mobile typecheck` and `pnpm lint`.
- Run `rg -n "\b(RepoInfo|repoPath|useRepoStore|useActiveRepo|openRepoPath)\b" apps/web/src apps/mobile/src packages/client-runtime/src`; it returns no result.

## Forbidden shortcuts

Do not preserve alias exports, reinterpret Git worktrees as Projects, or add migration coercion.

## Completion criteria

- [ ] Product boundaries expose Project vocabulary only.
- [ ] Git worktree distinction and all selected-project behavior remain proven.
- [ ] Searches, typecheck and lint pass; the unit is committed.

## Handoff

Later domains may assume one Project vocabulary at every client boundary.
