## Objective

Web and mobile product boundaries expose one Project vocabulary for selected/open Project state and
Project-scoped feature inputs, while Git workspaces/worktrees, daemon wire names, and persisted
storage retain only the names their owners explicitly require.

## Why this unit exists

PRJ-002 made Project query identities and selection effects canonical, but deliberately left the
old selection seams for this atomic cutover. The Web client still imports `useRepoStore` from
`stores/repo.ts`, the mobile client still imports `useActiveRepo` from `lib/daemon/repo.ts`, and
both clients leak `RepoInfo`, `repoPath`, and `openRepoPath` through product-facing adapters.
Mobile's `workspace` wording is also used for both the active Porcelain Project and a real Git
workspace, so a blind repository-wide replacement would corrupt the Git distinction.

## Current behavior and evidence

The current tree confirms these anchors:

- Web selection and picker state are in `apps/web/src/stores/repo.ts` and
  `apps/web/src/stores/repo-picker.ts`; the only logic in `apps/web/src/hooks/use-repo.ts` is the
  Electron new-window adapter. `apps/web/src/features/projects/project-data.ts` still reads the
  old store and calls stable Project procedures directly.
- Web callers include the shell, Viewer, Files, Git, Board, Review, Terminal, hooks, and their
  tests. They read the selected `repo` value or import the old store path; those reads are
  selection-boundary callers, not independent repository concepts.
- Mobile Project data is in `apps/mobile/src/features/projects/`, while
  `apps/mobile/src/lib/daemon/repo.ts` owns `useActiveRepo()` and imperative `openRepo()`. Mobile
  Git, Files, Board, Review, Changes, Diff, History, and Terminal callers import that seam.
- Mobile `apps/mobile/src/lib/daemon/procedures/connection.ts` still owns local Project
  descriptors used by provider bootstrap and pairing. Those descriptors are to be moved to the
  Projects public adapter; daemon-info and revoke remain in the Remote connection adapter.
- `apps/mobile/src/lib/daemon/environment.ts` and `environments-store.ts` persist
  `activeRepoPath` in version-3 environment records. That is existing storage and remains an
  adapter-only key; Project callers use the new active-Project accessors.
- `apps/mobile/src/features/shell/workspace-lists.ts` and the Git sheet types use `workspace` for
  Git branch/worktree UI. That is a real Git workspace concept and remains.

## Scope

The implementation is one atomic client/contract cutover. It may rename files and mechanical
callers listed here, but it does not redesign feature behavior or migrate unrelated domains.

### Reviewer rulings

1. **Wire and storage names are not product aliases.** Keep the existing daemon procedure names
   `openRepoPath`, `recentRepos`, `removeRecentRepo`, and `browseDirs`; contract serialized fields
   such as `repoPath` and `isRepo`; and the version-3 persisted environment key `activeRepoPath`.
   Decision 005 owns those names until an explicit protocol/storage migration. They may occur only
   in the Projects transport binding, daemon/contract definitions, storage adapter, or exact wire
   fixture assertions. Product callers receive Project-named functions and values, and the binding
   maps to the stable names in one place.
2. **Contract schema identifiers are implementation names, not wire names.** Rename
   `repoInfoSchema` to `projectInfoSchema`, remove the `RepoInfo` type alias from
   `packages/contracts/src/projects/projects.contract.ts` and `apps/daemon/src/api.ts`, and keep
   `ProjectInfo` as the contract output type. Do not rename the four procedure keys or their
   serialized input/output fields.
3. **Shared Project identity.** Add
   `ProjectPath = ProjectSummary['path']` to `packages/client-runtime/src/projects/index.ts`.
   The app adapters use this type for selected Project paths; transport input objects still use
   the contract's stable field names at the binding edge.
4. **Web selection boundary.** Rename
   `apps/web/src/stores/repo.ts` to `apps/web/src/stores/project-selection.ts` and export
   `useProjectSelectionStore`. Its state field is `project`; its actions are
   `selectProject`, `resetProjectPresentation`, `boot`, `restoreLastProject`,
   `openProjectPicker`, `openProject`, `switchProject`, and `toggleShowHidden`. The store imports
   `ProjectSummary` from the Projects public feature entry and has no direct stable procedure
   identifiers. Rename `repo-picker.ts` to `project-picker.ts` and export
   `useProjectPickerStore`. The picker dialog becomes `project-picker-dialog.tsx` and
   `ProjectPickerDialog`; its daemon `isRepo` check remains a wire field, while its visible copy
   says Project.
5. **Web Project transport.** Add
   `apps/web/src/features/projects/project-transport.ts`, exported only through the Projects
   `index.ts`. It is a framework-neutral-in-practice Web adapter over the vanilla tRPC client and
   owns the four stable procedure bindings, output parsing, and the mapping from `ProjectPath` to
   contract `repoPath` inputs. `project-data.ts` and `project-selection.ts` call this adapter;
   neither writes `openRepoPath`, `recentRepos`, `removeRecentRepo`, or `browseDirs` directly.
   The adapter accepts `typeof trpcClient`-compatible clients so the store and React Query hooks
   share one transport path.
6. **Web window adapter.** Rename `apps/web/src/hooks/use-repo.ts` to
   `apps/web/src/hooks/use-new-window.ts`. Keep the hook name `useNewWindow`, but its public
   argument is `projectPath?: ProjectPath`; it maps to the existing shell router's technical
   `{ repoPath }` input. The shell router and `WindowInit` are supporting Electron/transport
   boundaries and are not renamed in this unit; no Web product caller may expose that field.
7. **Web selected-Project callers.** Update every production and test importer of the old store,
   picker, and hook paths. Rename selected state reads from `repo` to `project`, and rename
   Project-scoped component props/local path variables from `repoPath` to `projectPath` where the
   value is the currently selected Project. At contract calls, retain the exact wire object field
   `repoPath` and pass the local `projectPath` value. Rename Project-scoped hooks and props such as
   `useRepoNotes`/`useSetRepoNotes` and `NotesCard`'s path prop to Project vocabulary only when
   they are current-selection adapters; leave Project Data storage internals for PDT-002.
8. **Mobile Project selection boundary.** Delete `apps/mobile/src/lib/daemon/repo.ts`. Add the
   public `useActiveProject(): ProjectSummary | null` and imperative
   `openProject(path: ProjectPath): Promise<void>` to `apps/mobile/src/features/projects/`.
   `openProject` must preserve the existing successful sequence: call the canonical open binding,
   persist the selected Project through `environmentActions.setActiveProjectPath`, then call
   `daemonSession.selectProject`. A failure changes neither selection nor session. The mobile
   Projects entry is the only app import surface for these APIs; no compatibility re-export is
   allowed.
9. **Mobile environment storage adapter.** Keep `activeRepoPath` only in
   `environmentRecordSchema`, `EnvironmentRecord`, persistence serialization, and the provider's
   bootstrap adapter where necessary. Add `activeProjectPathOf(environment)` and rename the public
   action to `environmentActions.setActiveProjectPath`; its implementation maps to the existing
   stored key. Rename `repoNameOf` to `projectNameOf`. Project, Git, and shell feature code must
   use the new accessor/action and must not read or write the stored key directly.
10. **Mobile Project procedures.** Move the Project descriptors from
    `apps/mobile/src/lib/daemon/procedures/connection.ts` to a non-React
    `apps/mobile/src/features/projects/project-procedures.ts`, export them through the Projects
    public index, and keep the stable descriptor names private to that binding. Provider
    bootstrap, pairing-group reads, and Project hooks all import the Projects public entry.
    `connection.ts` retains only `daemonInfoQuery`, `revokeCurrentClientMutation`, and their
    Remote-owned schemas. Delete the local Project type/schema exports and their compatibility
    tests; move validating descriptor assertions to the Projects boundary.
11. **Mobile Project callers.** Update every production and test importer of `useActiveRepo` and
    `openRepo` in Board, Changes, Comments, Diff, Files, Git workspace, History, Review, Terminal,
    and Shell to `useActiveProject`/`openProject` from `@/features/projects`. Rename selected
    locals and public feature props to `project`/`projectPath`; at daemon calls retain stable
    contract fields (`{ repoPath: projectPath }`) and technical procedure inputs. Update
    `useWorkspaceHeader`, `workspace-lists.ts`, branch/worktree sheets, and the workspace create
    form so Project identity uses `projectName`/`projectPath`, while `workspace`, `branch`, and
    `worktreePath` retain their Git meanings. The public Git branch/worktree sheet result field is
    `projectPath`; a linked checkout remains `worktreePath`/`Worktree.path`.
12. **No behavior change.** Preserve selected-project scoping, recent/open/remove behavior,
    nullable directory browsing, environment/session selection order, Git worktree navigation,
    Files/Git/Review/Board/Terminal query keys, current routes, test IDs, loading/error surfaces,
    and all existing stable wire inputs and outputs.

## Non-goals

- Do not rename daemon procedure names, contract serialized fields, version-3 storage keys, Git
  `worktree`, `Worktree.path`, or a real Git `workspace`.
- Do not change daemon operations, filesystem repository arguments at the transport edge, recent
  ordering, linked-worktree filtering, bootstrap semantics, pairing semantics, or session
  recovery behavior.
- Do not relocate Files, Search, Git reads, Review, Board, Actions, Terminal, Project Data, or
  Viewer ownership; later specifications own their remaining procedure and storage vocabulary.
- Do not rename all historical prose, test fixture path literals, Git repository terminology, or
  repository-containment security helpers merely because they contain the English word repository.
- Do not add migration coercion, compatibility re-exports, a second Project transport, a second
  selection store, optimistic open/remove behavior, or broad cache invalidation.
- Do not run a production daemon, open a real repository, use a browser/device runtime proof, push,
  or start another architecture recipe in this unit.

## Behavior to preserve

- Web restore and mobile bootstrap may still request recents with `includeWorktrees: true`; the
  Project switcher/sheet continues to use the default false result.
- Open remains authoritative and non-optimistic: the daemon's returned Project summary becomes the
  selection, the live mobile session is selected after persistence, and both recent query
  identities are invalidated after success.
- Remove remains non-optimistic and clears selection only when its input equals the selected path.
- Browse preserves nullable roots, parent navigation, stale-result behavior, remote daemon error
  wording, and current loading/empty/error presentation.
- Switching a Project in Web still resets local tabs/terminal presentation only for the in-place
  switch; opening from welcome/picker keeps its existing presentation behavior.
- Mobile Git branch and worktree sheets continue to route blocked branches to the worktree sheet,
  open linked worktrees in the active daemon session, and show the same shell chrome.
- Contract and storage tests continue to assert the exact stable `openRepoPath`, `recentRepos`,
  `removeRecentRepo`, `browseDirs`, `repoPath`, `isRepo`, and `activeRepoPath` shapes at their
  owning boundaries.
