# SUP-002 — Preserve Viewer virtualization, large-input, and plain-text behavior

- Status: Draft
- Batch: 7
- Domain: Viewer and Web build support
- Depends on: SUP-001
- Governing decisions: 004, 006, 009, 011, 014
- Primary exemplar: yes

## Objective

Retain Viewer performance and safe degradation while feature ownership moves: virtualized source/diff rendering, bounded large inputs, and plain-text fallback remain Viewer support behavior with focused proof.

## Why this unit exists

The audit inventory identifies virtual viewer, lazy tree, and Vite prebundle as earned performance invariants. A product-ownership cleanup must not turn a source viewer into eager DOM rendering or make unsupported content fail instead of degrading.

## Current behavior and evidence

- Current Viewer paths are `apps/web/src/components/viewer/{text-file-view,editor-source,source-view,file-content,html-view,markdown-view}.tsx` with focused tests.
- Mobile Files Viewer paths include `apps/mobile/src/features/files/{file-viewer,file-viewer-body,source-rows,source-lines,preview-view}.tsx`.
- Audit classifies bounded symbol slicing and plain-text/highlight degradation as permanent Viewer resilience.

## Scope

- Document and test the Viewer boundary in the exact Web/mobile paths above.
- Move only domain-owned file selection/query behavior to Files; retain rendering, virtualization, bounded slicing, and degradation in Viewer support.
- Add a Viewer performance/behavior gate to the focused tests.

## Non-goals

- Do not change Files wire contracts, implement a new editor, remove existing content-type support, or introduce benchmark infrastructure.
- Do not remove a fallback because it is named fallback; remove only historical representation compatibility owned by a later Review/Files cutover.

## Target ownership and public surface

Viewer owns rendering an already-authorized content model: virtualization/windowing, bounded line/token work, syntax-highlighting failure disposition, and plain-text presentation. Files owns reads, path safety, file metadata, and selection intent. Viewer receives no daemon/store import.

## Behavior to preserve

Preserve viewport-relative rendering for long text/diff, safe binary/oversize behavior, highlighting failure fallback, HTML containment, and mobile source-row behavior.

## Legacy behavior to delete

Delete no resilience path. Delete only domain selection/transport imports from Viewer after Files supplies the target view model.

## Ordered implementation

1. Extract a Viewer input model at `apps/web/src/components/viewer/viewer-content.ts` and mobile equivalent `apps/mobile/src/viewer/viewer-content.ts`; it contains already-bounded content, mode, and selection metadata, not a path or daemon client.
2. Refactor listed Viewer components to consume that model; move Files fetch/selection hooks to canonical Files feature roots.
3. Add focused tests with a large synthetic line set proving rendered row count stays bounded by viewport plus overscan, not total input.
4. Add tests proving oversized/binary/unsupported highlight inputs choose the current safe plain-text or unavailable state and never throw.
5. Add tests proving selection, anchor scrolling, and mobile source-row indexing remain correct at first/middle/last windows.
6. Keep Vite prebundle configuration unchanged; add a source assertion that Viewer has no import from daemon/tRPC or a Files store.
7. Run browser E2E only for assembled viewer boot/selection wiring; move branch-level rendering assertions to focused tests.

## Tests

- Existing `text-file-view`, `editor-source`, and `html-view` tests gain large-input/degradation assertions.
- Mobile `source-rows` and preview tests cover the same input-model dispositions.
- `pnpm test`, `pnpm --dir apps/desktop test:e2e -- --project=browser` for retained assembled viewer wiring, and `pnpm lint` pass.

## Validation and evidence

Capture the focused test's bounded rendered-row assertion and fallback disposition cases. Browser proof is against the dev daemon-served client, never the installed/prod app.

## Forbidden shortcuts

- Do not render every line/token to satisfy a test fixture.
- Do not pass a filesystem path, tRPC client, or raw daemon response into Viewer.
- Do not classify a real degradation/security limit as migration compatibility.

## Completion criteria

Viewer has a transport-free input boundary, the listed real resilience cases have focused tests, and no moved Files behavior remains in Viewer. Tests and lint pass.

## Handoff

Files and Review cutovers consume the Viewer content model. E2E-001 retains only startup/assembled selection wiring after these focused assertions exist.
