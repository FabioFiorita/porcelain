# REV-003 — Build Review reading, explore, and inbox operations over Git and Files capabilities

- Status: Draft
- Batch: 5
- Domain: Review
- Depends on: REV-001, REV-002, GIT-001, FIL-001
- Governing decisions: 003, 004, 006, 009, 015
- Primary exemplar: yes

## Objective

Move Review reading, explore, and inbox intentions into Review operations coordinating narrow Git and Files capabilities, preserving cache/recovery rules without locating Review behavior in the Git router.

## Why this unit exists

Current `feature-build`, `feature-explore`, `feature-view`, `flow*`, and `git/worktree-inbox.ts` split one Review intention across Review and Git modules; router handlers call stores/Git/builders directly.

## Current behavior and evidence

- Existing reading paths are `apps/daemon/src/review/{feature-build,feature-explore,feature-view,feature-slice,flow,flow-build}.ts` and `git/worktree-inbox.ts`.
- `router/review.ts` builds Feature reading, drops vanished files to empty hunks, and reads Evidence fresh outside the feature key.
- Inventory assigns Review Inbox to Review, not Git.

## Scope

- Create canonical Review reading/explore/inbox operation modules and `ReviewGit`/`ReviewFiles` capability interfaces.
- Relocate `worktree-inbox.ts` into the Review feature during its target cutover.

## Non-goals

- Do not move low-level Git diff/log/status algorithms out of Git or Files containment/slicing out of Files.
- Do not remove cache/recovery behavior because it is currently labeled feature.

## Target ownership and public surface

`createReadReview`, `createExploreReview`, and `createListReviewInbox` own Review intentions. `ReviewGit` supplies flows/diffs/worktree facts; `ReviewFiles` supplies safe file/symbol content; `ReviewEvidence` supplies current Evidence descriptor. Cache keys are Review-owned derived state and Evidence refresh is an explicit dependency.

## Behavior to preserve

Preserve agent-curated ordering, sections/anchors, vanished/renamed file recovery, bounded slicing, empty active Review, fresh Evidence attachment, and Review Inbox worktree facts.

## Legacy behavior to delete

Delete Feature builder/router names and Git-located inbox export only in REV-009 after target operations/clients use canonical names. Keep low-level Git helpers with Git.

## Ordered implementation

1. Map each current reading/inbox function to Review operation, Git capability, Files capability, or derived cache.
2. Define capability methods with contract-shaped inputs/outputs; no capability exposes raw store or router.
3. Implement operations and explicit cache invalidation/refresh rules; retain fresh Evidence read and vanished-file result disposition.
4. Bind target router procedures to operations and move inbox source from `git/worktree-inbox.ts` to Review feature.
5. Add operation fake tests for ordering and vanished-file/Evidence-freshness cases; retain real Git/Files adapter tests at their owners.
6. Remove direct router calls only after client contract tests pass.

## Tests

- Review pure operation/cache tests plus fake Git/Files/Evidence capability tests.
- Existing Git/Files real-resource tests continue as adapter proof.
- `pnpm test` and lint pass.

## Validation and evidence

Record source ownership map and test evidence for no-active, vanished file, fresh Evidence, and inbox result.

## Forbidden shortcuts

- Do not pull Git algorithms into Review or use broad Git facade.
- Do not silently omit a failure that contract requires to expose.

## Completion criteria

Reading/explore/inbox intents have canonical operations, narrow capabilities, cache/recovery proof, and no target Git-router ownership.

## Handoff

REV-006/007/008 bind client semantics/presentation; REV-009 removes Feature names.
