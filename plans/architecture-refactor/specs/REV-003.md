## Objective

`featureView`, `featureReading`, `exploreFeature`, and `worktreeInbox` are served
by bound operations under `apps/daemon/src/features/review/`, over narrow reading,
Git, Files, and Evidence capabilities, with identical wire names, schemas, ordering,
caching, and failure semantics — and no Review reading intention is left in
`apps/daemon/src/router/git.ts`.

## Why this unit exists

The Review reading intentions are spread across two legacy routers and five
`apps/daemon/src/review/` modules: `router/review.ts` calls the build cache, Git
diffs, the layer store, and the Evidence store directly, and `router/git.ts` owns
the Review inbox outright. Nothing between the wire and git/the filesystem can be
faked, so the ordering, cache-invalidation, and vanished-file rules have no test
boundary that owns them. REV-004 (Evidence), REV-006 through REV-008 (clients),
and REV-009 (cutover) all need these intentions already bound to operations.

export type ReviewGatherState = {
  files: ChangedFile[]
  stats: DiffStat[]
  layers: Layer[]
  reviewSet: ReviewSet | null
  key: string
}
export type ReviewBuiltReview = {
  key: string
  view: FeatureView
  sources: Map<string, string>
}

  updatedAt: string
  checks: EvidenceCheck[]
  medium: EvidenceMedium

/** The narrow Git facts Review reading needs; no argv and no Git algorithm crosses it. */
export type ReviewGit = Readonly<{

export type ReviewFiles = Readonly<{

## Behavior to preserve

- Every wire name, kind, input schema, and output schema is unchanged, and
  `procedureCatalog` still reports 113 names. `worktreeInbox` keeps its name,
  its bare-string input, and its row shape while changing router file.
- Agent-curated membership and ordering: Execution is the review set alone, working
  tree changes the agent did not list never appear, and `null` (not an empty view)
  is the answer without a review set.
- The shared build memo: one build per snapshot key per repo path, reused by both
  reading procedures, plus the `writeFeatureSnapshot` app→agent channel write on a
  build miss.
- Evidence freshness: the Evidence summary is read on every `featureReading` call
  and reattached to a cached reading, together with the review set's `canvas`,
  because neither is part of the feature key. The deprecated `medium` field is
  still emitted (installed mobile clients parse it as required).
- Vanished/renamed recovery: a per-file diff failure yields an absent hunk entry
  and `buildFeatureReading` falls back to an empty hunk list; the reading never
  fails because one file moved.
- Bounded reads: the 1 MiB working-tree source cap in both the build and the
  explore walk, and `walkExplore`'s depth (5) and file (60) caps.
- Explore stays read-only and seeded (symbol or file), names itself from the seed,
  and falls back to `DEFAULT_LAYERS` when the project declares none.
- Inbox resilience: the current checkout is excluded, a signal-free worktree is
  excluded, and a broken or deleted sibling checkout that git still lists yields no
  row instead of failing the whole inbox.
- Active-content posture: agent-authored section HTML and inline SVG stay
  self-contained and size-capped (512 KiB) and remain destined only for the
  `<iframe sandbox="" srcdoc>` path — never a `src` URL, which would drop the
  parent CSP. No adapter, operation, or router in this unit rewrites, sanitizes, or
  re-hosts that content.
- Failure semantics on the wire: a Git or filesystem failure that throws today
  still throws and still serializes as `internal.unexpected`; a contract-violating
  row still fails output parsing.
- `review-watch.ts` remains the only publisher of `review.changed`.
