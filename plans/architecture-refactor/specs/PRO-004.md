# PRO-004 — Enforce protocol headers at daemon tRPC and pairing boundaries

- Status: Draft
- Batch: 0 — architecture and contract foundations
- Domain: protocol / daemon HTTP enforcement
- Depends on: `PRO-002` (Draft), `ERR-001` (Draft)
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Require a matching `x-porcelain-protocol-version` before the daemon dispatches tRPC or pairing HTTP
requests, after every repository-owned caller already supplies it.

## Why this unit exists

The header is inert until enforced; enforcing it before `PRO-002` would break existing owned clients.
This is the single acceptance-rule cutover, with no optional or compatibility path.

## Current behavior and evidence

`PRO-001` exposes literal version `1`; `PRO-002` updates the owned Web, mobile, and desktop HTTP
adapters. `apps/daemon/src/net/daemon-http.ts` currently dispatches versionless tRPC/pairing traffic.

## Scope

Own `apps/daemon/src/net/daemon-http.ts` and its HTTP tests. Validate the named header before tRPC or
pairing dispatch, mapping absent, malformed, older, and newer versions through the `ERR-001`
`protocol.update-required` public envelope.

## Non-goals

Do not change daemon-info, client adapters, session hello/ready, authentication grants, endpoint
paths, CORS behavior, or any non-tRPC/non-pairing HTTP route.

## Target ownership and public surface

The accepted header value is `String(protocolVersion)`. Rejected requests retain one request ID and
return only `publicErrorSchema` JSON; rejected handlers are never invoked. Matching requests retain
their existing status/body/authorization behavior.

## Behavior to preserve

Preserve pairing body caps/rate limits, authorization, CORS, static rendering, and normal matching
request behavior. Do not modify ownership of the header-producing adapters.

## Legacy behavior to delete

Delete versionless, malformed, or mismatched tRPC/pairing acceptance. Do not retain a fallback retry
or endpoint-specific plain-text error.

## Ordered implementation

1. Parse the one exact header before tRPC/pairing dispatch.
2. Convert every failed version case through the ERR public-error writer.
3. Prove rejected calls never enter mocked handlers and matching calls retain prior behavior.

## Tests

Add table-driven daemon HTTP tests for missing, malformed, older, newer, and matching versions, both
tRPC and pairing routes, public-error parsing, and handler non-invocation.

## Validation and evidence

```text
pnpm --dir apps/desktop test -- ../daemon/src/net/daemon-http.test.ts ../../packages/contracts/src/errors.test.ts ../../packages/contracts/src/protocol.test.ts
pnpm lint
git diff --check
```

## Forbidden shortcuts

Do not make the header optional, infer an app version, accept a query parameter, or alter client code.

## Completion criteria

- [ ] Only matching-version tRPC and pairing calls reach handlers.
- [ ] Every mismatch is a structured ERR public error with one request ID.
- [ ] HTTP tests, lint, and diff check pass.

## Handoff

The HTTP protocol cutover is complete; `PRO-003`/RT work own the independent session handshake.
