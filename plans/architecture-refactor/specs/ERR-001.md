# ERR-001 — Establish one safe public error envelope and centralized daemon mapping

- Status: Draft
- Batch: 0 — architecture and contract foundations
- Domain: `daemon-composition`
- Depends on: `ARC-002` (Draft), `CON-011` (Draft)
- Governing decisions: [003](../decisions/003-application-operations-own-orchestration.md), [005](../decisions/005-contracts-own-the-wire.md), [006](../decisions/006-compose-explicit-capabilities.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

Every tRPC and authenticated daemon boundary failure carries one contract-validated `PorcelainError`
with a request ID, while unexpected errors are logged once without leaking internal details.

## Why this unit exists

Current routers throw raw `TRPCError` values and ordinary `Error`s, `daemon-http.ts` returns empty
401/500 responses outside tRPC, and clients interpret tRPC classes/messages independently. Later
operations need a single typed boundary for expected failures instead of inventing router-local
messages and transport mappings.

## Current behavior and evidence

- `apps/daemon/src/trpc.ts` creates tRPC with no error formatter; `adminProcedure` throws raw
  `TRPCError({ code: 'FORBIDDEN' })`.
- `apps/daemon/src/router/daemon.ts` throws raw `TRPCError` for pairing URL and current-client
  refusal; other router/native failures escape unchanged.
- `apps/daemon/src/net/daemon-http.ts` writes empty 401 responses before the tRPC adapter and logs
  any outer failure before an empty 500.
- `apps/mobile/src/lib/daemon/errors.ts` creates local `DaemonError` classifications, and Web hooks
  commonly consume tRPC messages/classes.
- `CON-011` supplies all ten complete domain procedure records that this unit augments with declared
  error codes.

## Scope

- Add the composable public-error contract under `packages/contracts/src/errors/` and
  procedure-error declarations in the ten complete domain `*.procedures.ts` modules supplied by
  `CON-011`.
- Add centralized daemon error normalization, request-ID generation, logging/redaction and tRPC
  formatter wiring under `apps/daemon/src/daemon-composition/`.
- Update `apps/daemon/src/trpc.ts` and `apps/daemon/src/net/daemon-http.ts` to use that boundary.
- Replace direct raw expected-error construction in current daemon routers with the central failure
  helpers, preserving each current accepted/rejected behavior.

## Non-goals

- Do not extract router handlers into operations; `DAE-001` establishes operation factories and
  typed operation results.
- Do not add client-runtime parsing or Web/mobile recovery UI; `REM-003` owns client adoption.
- Do not change procedure names, schema catalog structure, authentication policy, pairing rate
  limits, transport protocol version or persisted data.
- Do not classify unexpected defects as not-found, forbidden or a domain-specific expected failure.

## Target ownership and public surface

Create `packages/contracts/src/errors/{define-public-error,system-errors,public-errors,index}.ts` and
export the public boundary from `packages/contracts/src/index.ts`. `define-public-error.ts` builds a
strict member schema from a literal code, category, retryable value, and exact optional/required
details schema. `public-errors.ts` composes the initial system members:

```ts
export const publicErrorCategorySchema = z.enum([
  'invalid-request', 'unauthenticated', 'forbidden', 'not-found', 'conflict', 'unavailable', 'internal',
])
export const systemPublicErrorSchemas = [
  requestInvalidErrorSchema,
  authUnauthenticatedErrorSchema,
  authForbiddenErrorSchema,
  resourceNotFoundErrorSchema,
  stateConflictErrorSchema,
  resourceUnavailableErrorSchema,
  internalUnexpectedErrorSchema,
  protocolUpdateRequiredErrorSchema,
] as const
export const publicErrorSchema = z.discriminatedUnion('code', systemPublicErrorSchemas)
export type PorcelainError = z.infer<typeof publicErrorSchema>
```

Every member repeats the strict common fields `category`, `message`, `retryable`, and UUID
`requestId`. `details` is absent for every initial code except `protocol.update-required`, whose
required strict details are `{ expected: 1; received: nonnegative integer }`. Later domains define
members in `<domain>.errors.ts` and add their schemas to `public-errors.ts`; they never loosen
`details` into an arbitrary record or extend a generic string enum.
`ProcedureContract` gains `readonly errors: readonly PublicErrorCode[]`; each domain procedure record
supplies the exact list for its current procedure. Procedures with no intentional expected failure
declare `[]`.

Create:

- `apps/daemon/src/daemon-composition/request-id.ts` exporting `createRequestId(): string` using
  `randomUUID`.
- `apps/daemon/src/daemon-composition/public-error.ts` exporting
  `type ExpectedFailure`, `expectedFailure`, `toPublicError`, `toTrpcError`, and `writePublicError`.
- `apps/daemon/src/daemon-composition/error-log.ts` exporting `logUnexpectedError` that logs the
  request ID, procedure path and original error once after redacting Authorization, `pc_pair_*`,
  `pc_client_*`, `PORCELAIN_*` values, absolute host paths and evidence/file contents.

`DaemonTrpcContext` becomes `{ auth: AuthIdentity; requestId: string }`. The tRPC error formatter
adds `data.porcelain: PorcelainError` to the existing tRPC error shape. `daemon-http.ts` creates a
request ID before authentication, passes it to the tRPC context, and sends `publicErrorSchema` JSON
for pre-tRPC 401, malformed-pairing 400/413/429, and unexpected 500 responses. Its tRPC `onError`
path delegates to `logUnexpectedError`; it does not double-log an expected failure.

## Behavior to preserve

- Bearer and WebSocket token authentication, constant-time admin comparison, client revocation,
  pairing one-time use/rate limit/body cap, CORS scoping and public static renderer behavior remain.
- `adminProcedure` remains an authorization gate; it now maps to `auth.forbidden`.
- Pairing rejects invalid schemes, credentials/query/fragment and current-client revocation rejects
  administrator identities with safe public errors.
- Unexpected defects still return failure and are logged with diagnostic correlation; no stack,
  native error class, token, environment value, unsafe host path or file content reaches a client.

## Legacy behavior to delete

- Delete direct expected `new TRPCError(...)` construction from `router/daemon.ts` and
  `trpc.ts`; use `expectedFailure` plus the centralized mapper.
- Delete empty pre-tRPC 401/400/413/429/500 bodies from `net/daemon-http.ts`.
- Delete router-local error message matching in daemon tests introduced before this unit.
- Do not retain an old error response envelope. Mobile's local classifier remains only until
  `REM-003` replaces it with the contract parser; it is not a second target model.

## Ordered implementation

1. Read the governing decisions, `target-architecture.md`, `CON-011`, and the current error sites
   in `trpc.ts`, `daemon.ts`, `daemon-http.ts`, mobile errors, and daemon HTTP tests.
2. Create the `errors/` modules, strict discriminated union, and fixtures for every initial code; export all
   schemas/types from the package root.
3. Add the `errors` array to `ProcedureContract` in `procedure-contract.ts`; populate every domain
   procedure record with the exact currently intentional public codes, using `[]` where no expected
   failure is presently modeled.
4. Create the three daemon-composition modules named above. Implement native `TRPCError` mapping,
   expected-failure mapping, centralized safe message selection and one-time unexpected logging.
5. Add `requestId` to daemon tRPC context, configure the tRPC formatter, and map
   `adminProcedure`/pairing-router rejections through the central functions.
6. Change `daemon-http.ts` to produce contract-valid public errors for each pre-tRPC failure and to
   use the same request ID when it delegates to tRPC.
7. Update daemon HTTP/router tests to parse every public error through `publicErrorSchema`; delete
   assertions against raw `TRPCError` messages.
8. Search for raw expected-error construction and remove it from the daemon source. Leave unexpected
   throw sites alone when they represent defects rather than normal outcomes.

## Forbidden shortcuts

- Do not put arbitrary records in `details`, infer retryability from HTTP status, or expose native
  messages/classes/stacks.
- Do not return a business code for an unexpected exception.
- Do not implement one mapper per router or log expected failures as unexpected defects.
- Do not add client fallbacks that parse old error shapes.
- Do not use a non-UUID request ID or generate different IDs for one HTTP request and its tRPC error.

## Completion criteria

- [ ] Every declared procedure error code and every pre-tRPC failure serializes through
  `publicErrorSchema`.
- [ ] tRPC errors expose exactly one `data.porcelain` value with the request ID.
- [ ] Expected failures are centralized; unexpected defects log once and redact unsafe detail.
- [ ] Raw expected-error construction is absent from current routers and middleware.
- [ ] Contract/daemon tests, catalog lint, deletion searches and lint pass.
- [ ] The commit contains no client recovery rewrite, operation extraction or protocol-version change.

## Handoff

`PRO-001` may use `protocol.update-required`; `DAE-001` may return `ExpectedFailure` values from
operations; later domain specs may replace generic initial codes with their declared domain codes
through the same central mapper.
