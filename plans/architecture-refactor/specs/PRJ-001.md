## Objective

The four Project wire procedures use one contract-bound Project operation slice, with typed
`projects.*` failures, a strict version-1 `projects-recents.json` adapter, and no Project code left
in the Files remainder router or mixed Remote config.

## Why this unit exists

`apps/daemon/src/router/repos.ts` currently mixes Project opening and recents with Files scope
procedures, direct filesystem calls, home migration, watcher registration, and Git warmup. The
same handler reads and writes `recentRepos` inside `<userData>/config.json`, while
`review/review-watch.ts` and `dev-config.ts` also consume that mixed record. This prevents the
Project domain from owning its operation, persistence, and expected failures as one boundary.

| Code | Category | Retryable | Meaning |

| `projects.not-found` | `not-found` | `false` | The requested Project path does not exist. |
| `projects.not-a-directory` | `invalid-request` | `false` | The requested path exists but is not a directory. |
| `projects.unavailable` | `unavailable` | `true` | Project filesystem or recents persistence is unavailable. |

### Projects ports

`apps/daemon/src/features/projects/projects-ports.ts` owns the Node filesystem adapter and its
typed host failures. Export:

```text
ProjectsPort:
  inspectProject(path) -> Promise<
    | { ok: true; value: ProjectInfo }
    | { ok: false; error: 'not-found' | 'not-a-directory' | 'unavailable' }
  >
  browseDirectories(path: string | null) -> Promise<
    | { ok: true; value: BrowseDirsOutput }
    | { ok: false; error: 'not-found' | 'not-a-directory' | 'unavailable' }
  >

ProjectsWorktree:
  isLinkedWorktree(path: string) -> Promise<boolean>

ProjectsEffects:
  watchProjectCompanion(path: string) -> void
  warmFileList(path: string) -> void
```

The concrete port uses `stat` to require an existing directory and returns `basename(path)` in the
Project value. It maps `ENOENT` to `not-found`, `ENOTDIR`/an existing non-directory to
`not-a-directory`, and every other host failure to `unavailable` without exposing host text. Its
browser preserves the current `git/browse.ts` behavior exactly: `null` means `homedir()`, directory
names only, dot-directories and files skipped, `.git` directory or file sets `isRepo`, accent-
sensitive locale sort, and `parent: null` only at the filesystem root.

### Strict recents adapter

`apps/daemon/src/features/projects/projects-recents-store.ts` owns one file at
`<userData>/projects-recents.json`, initialized by `server.ts` through
`initProjectsRecentsDir(userData)`. It uses the landed `createStrictJsonDocument` adapter from
`apps/daemon/src/project-data/strict-json-document.ts` with this strict v1 value:

```text
{ paths: string[] }       // strict object; at most 10 paths
```

The persisted envelope is therefore DAT-001's `{ version: 1, value: { paths } }`. Missing files
read as an empty path list without creating the file. Malformed JSON/schema values are backed up by
the strict document and return `projects.unavailable`; future versions remain in place and also
return `projects.unavailable`; oversized or host I/O failures return the same typed failure without
rewriting the source. Writes are mode-0600, fsynced, atomic temp-file/rename writes supplied by the
strict document. The store serializes its own read-modify-write add/remove queue so concurrent
open/remove calls cannot lose an update.

Export a `ProjectsRecentsStore` with `readPaths`, `addPath`, and `removePath` operations returning
`{ ok: true, value }` or `{ ok: false, error: { code: 'projects.unavailable' } }`, plus the
configured-store accessor used only by `dev-config.ts` and `review-watch.ts`. `addPath` prepends,
deduplicates, and caps at ten; `removePath` is idempotent. The production composition passes the
same configured store instance to Project operations that those supporting callers read.

### Project operations and router

`projects-operations.ts` depends only on the named `ProjectsPort`, `ProjectsRecentsStore`,
`ProjectsWorktree`, and `ProjectsEffects` capabilities. Export four operations using Project nouns:

```text
openProject(path: string) -> ProjectOperationResult<ProjectInfo>
listRecentProjects(input: { includeWorktrees: boolean }) -> ProjectOperationResult<ProjectInfo[]>
removeRecentProject(path: string) -> ProjectOperationResult<void>
browseProjectDirectories(path: string | null) -> ProjectOperationResult<BrowseDirsOutput>
```

`ProjectOperationResult<T>` is a closed `{ ok: true, value: T }` / `{ ok: false, error }` union
whose errors are exactly the three `projects.*` codes. `openProject` validates the directory,
adds the exact input path to recents, then invokes `watchProjectCompanion` and `warmFileList` in
that order as deliberately non-required effects; a recents failure prevents both effects and the
success result. `warmFileList` remains fire-and-forget because the current implementation already
settles its refresh in the background and opening must not wait for Git file discovery.
`listRecentProjects` reads stored order, drops paths that no longer validate, filters linked
worktrees only when `includeWorktrees` is false, and maps valid paths to ProjectInfo. A recents
adapter failure is returned as `projects.unavailable`; individual stale paths remain a skipped
row as today. `removeRecentProject` delegates only to the recents store. Browse delegates only to
the filesystem port.

`projects-router.ts` is the sole tRPC boundary for the four procedures. Each procedure imports
`procedureCatalog` directly from `@porcelain/contracts`, binds its exact `.input` and `.output`,
invokes exactly one operation, and maps the closed error union through
`expectedFailure(...)`/`toTrpcError(...)`. It contains no filesystem, config, Git, watcher, or
migration calls and never emits host error text.

`index.ts` exports only the Projects operations, ports/store types and constructors, and router
factory needed by daemon composition. `createDaemonOperations` receives a required `projects`
slice and exposes it on the frozen `DaemonOperations` object. `server.ts` constructs the concrete
filesystem port, configured recents store, existing `isLinkedWorktree`, watcher, and Git warmup
effects, then passes the resulting `createProjectsOperations(...)` value into composition. Tests
use explicit operation/port/store fakes at the composition boundary.
