- Primary exemplar: no

## Objective

Move `openRepoPath`, `recentRepos`, `removeRecentRepo`, and `browseDirs` into contract-backed Project operations and a version-1 Projects-recents adapter.

## Why this unit exists

`router/repos.ts` mixes opening, recents, home migration, Git warmup, Files scope/watch registration, and direct filesystem behavior under historical repo vocabulary.

## Current behavior and evidence

The four procedures live in `apps/daemon/src/router/repos.ts`; `git/browse.ts` owns `browseDirs`; `stores/config-store.ts` persists mixed recents/listener config at `<userData>/config.json`; `project/migrate-home.ts` is historical companion migration.

## Scope

Create `apps/daemon/src/features/projects/{projects-ports,projects-operations,projects-router,projects-recents-store}.ts` and tests; move those four router bodies, Project recents storage, and directory discovery. Update daemon composition and contracts only for the existing four Project records.

## Non-goals

Do not move Files tree/scope/watches, Git worktrees, Remote listener flags, client selection semantics, or any home/active-review migration behavior.

## Target ownership and public surface

`ProjectsPort` validates an opened directory as a Project; `ProjectsRecents` owns a strict version-1 `projects-recents.json` record separate from Remote configuration. `openProject`, `listRecentProjects`, `removeRecentProject`, and `browseProjectDirectories` return typed `projects.not-found`, `projects.not-a-directory`, and `projects.unavailable` outcomes. Public wire procedure names remain stable in this recipe; internal operation nouns use Project vocabulary.

## Behavior to preserve

Preserve path expansion, recents ordering/deduplication, optional worktree inclusion, nullable browse root, Git warmup as an explicit awaited or deliberately non-required effect exactly as current behavior proves, and corrupt-record diagnostics/atomic write resilience.

## Legacy behavior to delete

Delete Projects reads/writes from mixed `config-store.ts`, direct router filesystem/config calls, and Project-triggered `migrate-home` calls. Do not retain dual reads/writes or `repo` internal aliases in the target feature.

## Ordered implementation

1. Transcribe current four wire values/errors from contracts and router tests.
2. Extract capability and version-1 recents adapter with temporary-directory proof.
3. Implement four operations and bind them to the Projects router.
4. Remove Projects fields/calls from mixed config/router/migration paths; leave Remote config to REM-002.

## Tests

Test recents adapter ordering/dedupe/corruption/atomicity, operation outcomes and effect order with fakes, browse filesystem integration, and router error/output mapping.

## Forbidden shortcuts

Do not retain mixed config reads, call another domain operation, add migration discovery, or expose host error text.

## Completion criteria

- [ ] Four procedures use bound Project operations and strict version-1 recents storage.
- [ ] Projects no longer read/write mixed config or historical migration paths.
- [ ] Adapter/operation/router tests, lint, and diff check pass.
