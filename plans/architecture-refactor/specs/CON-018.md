# CON-018 — Bind Board router procedures to canonical contracts

- Status: Queued
- Batch: 0 — architecture and contract foundations
- Domain: Board contract boundary
- Depends on: `CON-017`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

All six Board procedures use exact canonical input/output contracts while preserving card
validation, ordering, status transitions, persistence calls, and void results.

## Why this unit exists

Board is a small complete router and provides the clearest low-risk proof that a fully landed domain
record replaces every local procedure schema without moving application behavior yet.

## Current behavior and evidence

`apps/daemon/src/router/board.ts` owns `boardCards`, `addBoardCard`, `updateBoardCard`,
`moveBoardCard`, `deleteBoardCard`, and `clearBoardCards`. It uses local Zod/Card-status inputs,
direct Board store calls, and no output parsers. `boardProcedures` owns all six strict contracts.

## Scope

Edit `router/board.ts`, add a focused router-contract test, and remove only `board.ts` from the
temporary lint remaining-file set after all six bindings pass.

## Non-goals

Do not move Board stores/operations/UI, change card defaults/status/order/timestamps, alter
persistence, add optimism/events, or modify any other router.

## Target ownership and public surface

Each procedure uses `procedureCatalog.<name>.input` and `.output` on its existing public
query/mutation. Store calls and returned objects remain unchanged. Delete the now-schema-only `zod`
and `CARD_STATUSES` imports.

## Behavior to preserve

Preserve non-empty title rules, optional body/status behavior, created card shape, update/move/
delete/clear semantics, card ordering, status vocabulary, and void serialization.

Deliberately replace unknown-key stripping on Board object inputs with strict `request.invalid`
rejection; no compatibility parser remains.

## Legacy behavior to delete

Delete all six local router input schemas and missing output validation; remove `board.ts` from the
lint ledger with no local schema alias.

## Ordered implementation

1. Bind the read/add procedures to same-name catalog schemas.
2. Bind update/move/delete/clear without changing store arguments.
3. Remove obsolete `zod` and `CARD_STATUSES` imports.
4. Add valid card/void, unknown-key and other constrained invalid input, and malformed output tests.
5. Remove `board.ts` from the lint set and prove all six bindings.

## Tests

Add `apps/daemon/src/router/board.contract.test.ts` using a temporary Board store/config location and
synthetic cards; do not mock by recreating Board rules.

## Validation and evidence

```text

node scripts/lint-procedure-contracts.mjs

```

## Forbidden shortcuts

Do not retain `CARD_STATUSES` solely for validation, copy Board schemas, change store behavior,
weaken strictness, or add client/runtime work.

## Completion criteria

- [ ] Six Board procedures use exact catalog input/output middleware and existing kinds.
- [ ] Card/store behavior and serialization remain unchanged.
- [ ] `board.ts` leaves the ledger and lint proves all six bindings.
- [ ] Focused tests, deletion search, repository lint, full verify, and diff check pass.
- [ ] One commit lands only `CON-018`, marks recipe/catalog Landed, leaves a clean worktree, provides
      the README review packet, and finishes without pushing.

## Handoff

Board's wire boundary is exhaustive; BRD specs may later migrate its application/store/client layers.
