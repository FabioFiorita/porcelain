- Status: Landed
- Batch: 2 — focused behavior exemplar

- Depends on: RVC-002, TST-001, RT-005
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Architecture reviewer rulings

- Copy the landed Web Board feature adapter `BRD-004` / `apps/web/src/features/board/` exactly for layout, Query-key composition, cancel/snapshot/apply/mutate/rollback/reconcile/refetch lifecycle, notification subscription mount, validating harness tests, public `index.ts` entry, and architecture registration. This unit does not invent a second Web feature pattern.
- Place the Web slice under `apps/web/src/features/review/comments/` (domain key `review`, comments subdomain). Register `apps/web/src/features/review` on the `review` domain `targetRoots` in `scripts/architecture/domains.mjs` (mirror Board’s `apps/web/src/features/board` registration). Do **not** create a top-level `features/comments/` root on Web.
- Wire still uses procedure names `reviewComments` / `addReviewComment` / `editReviewComment` / `deleteReviewComment` / `resolveReviewComment` / `clearResolvedReviewComments` and wire field **`repoPath`** (RVC-001). The typed query identity remains `{ domain: 'review', name: 'comments', projectPath }` (RVC-002). Adapters map active Project path → identity `projectPath` and mutation inputs use `repoPath: repo.path`.
- **Partial `review.changed` ownership (not a product fork):** `review.changed` is a coarse Review category (feature-view + layers + evidence + comments). RVC-002 maps it to **only** the comments identity. This unit **atomically** (1) mounts a feature subscription that invalidates only the mapped comments Query identity for that Project + daemon scope, and (2) removes comments from session-runtime’s bulk `invalidateReview` list. Other Review query invalidations on `review.changed` stay in `use-session-runtime.ts` until later Review client-runtime units. Do **not** no-op the entire `review.changed` case (that would drop feature-view/evidence refresh). Do **not** dual-invalidate comments from both session-runtime and the feature.
- Recovery and non-comment Review mutations that currently call `trpcUtils.reviewComments.invalidate()` must use the feature’s `invalidateAllReviewComments(queryClient)` (predicate over comments keys), same role as `invalidateAllBoardCards` after BRD-004. Touches: `use-session-runtime.ts` recovery wiring and `use-feature-view.ts` archive/restore invalidation lists only.
- `use-app-events.ts` is already gone (RT-005). The legacy comments path is `hooks/use-comments.ts` + procedure-string keys + bulk `utils.reviewComments.invalidate()` inside `invalidateReview` / feature-view helpers — not a raw `case 'comments'`.
- Clean pre-launch cutover (Decision 015): no dual optimism models, no string/`['reviewComments']` cache identities, no fallback to `trpc.reviewComments.useQuery` / `trpc.*.useMutation` procedure hooks for comments, no compatibility re-export of `hooks/use-comments`, no ambient optimism outside the feature adapter.

## Objective

Web comments consume canonical `@porcelain/contracts/review` and `@porcelain/client-runtime/review` through one React Query/tRPC feature adapter: typed comments query identity, five reversible optimistic mutations with cancel → snapshot → apply → mutate → rollback/reconcile → exact refetch, validated `review.changed` notification effects, and deletion of the hook-local optimism owner.

## Why this unit exists

`apps/web/src/hooks/use-comments.ts` still owns temporary ids, cache snapshots, five optimistic patches, rollback, and procedure-string invalidation against tRPC, while comment UI lives under Git/Shell/Viewer. RVC-002 landed shared semantics; BRD-004 proved the Web adapter pattern. This unit is the Web comments primary exemplar before RVC-004 mobile.

### Mutations (`comment-mutations.ts`)

```ts
export type NewComment = {
  path: string
  startLine?: number
  endLine?: number
  anchorText?: string
  body: string
}

export function useCommentActions(): {
  add: (input: NewComment) => Promise<void>
  edit: (id: string, body: string) => Promise<void>
  remove: (id: string) => Promise<void>
  setResolved: (id: string, resolved: boolean) => Promise<void>
  clearResolved: () => Promise<void>
}
```

Lifecycle for each of the five `reviewCommentMutations` keys (Board `board-mutations.ts` shape):

1. **Cancel** in-flight queries for `reviewCommentsQueryKey(daemon, identity)` with `exact: true`.
2. **Snapshot** current cache: `getQueryData<readonly ReviewComment[]>(queryKey)`.
3. **Gate optimism:** if snapshot data is `undefined`, do **not** `setQueryData` (preserve legacy “no seed from a single write before list load”). Still return a context carrying `queryKey` + empty-or-undefined snapshot so rollback is a no-op and settle still refetches.
4. If data is defined: `applyReviewCommentOptimisticTransition(current, key, wireInput, { temporaryId, now })` then `setQueryData(queryKey, comments)`.
5. **Mutate** via vanilla client (not procedure hooks):
   `client.addReviewComment.mutate` / `editReviewComment` / `deleteReviewComment` / `resolveReviewComment` / `clearResolvedReviewComments`.
6. **onError:** `setQueryData(queryKey, rollbackReviewCommentOptimisticTransition(snapshot))` when a snapshot was taken from defined data; toast via `onMutationError` with exact labels:
   `Add comment` | `Edit comment` | `Delete comment` | `Resolve comment` | `Clear closed comments`.
   Map transport errors with `error instanceof Error ? error.message : 'Request failed'` (Board idiom). Typed public failures (`review.unavailable`, `review.comment-not-found`, `request.invalid`) surface through the existing toast description (message from harness/daemon) — do not invent new UI copy.
7. **onSuccess (add only):** `reconcileReviewCommentMutation(current, 'add', { temporaryId, result })` into the cache when `temporaryId` + authoritative `ReviewComment` result are present.
8. **onSettled:** if `reviewCommentMutations.<key>.requiresAuthoritativeRefetch`, `invalidateQueries({ queryKey: reviewCommentsQueryKey(daemon, identity), exact: true })` for each `affectedQueries(wireInput)` identity — **never** string/`utils.reviewComments.invalidate`.
