## Architecture reviewer rulings (bind the executor; supersede the tracked Draft)

1. **Scope is only the two crossed wire bindings.** Move `diffReading` out of
   `apps/daemon/src/router/review.ts` and `commitModels` out of
   `apps/daemon/src/router/settings.ts` into `apps/daemon/src/features/git`. Do **not** move the nine
   residual Git reads or Review-owned `worktreeInbox` still bound by `createGitRouter()` in
   `apps/daemon/src/router/git.ts`. Do **not** relocate `review/flow-build.ts`,
   `review/flow.ts`, or `review/feature-view.ts`. Do **not** change
   `scripts/architecture/domains.mjs` (Git stays `migrating`; residual router procedures remain).

2. **Public wire is unchanged.** Procedure names stay flat `diffReading` and `commitModels` on the
   composed tRPC surface. Contracts stay in `packages/contracts/src/git` (`gitProcedures.diffReading`,
   `gitProcedures.commitModels`, input/output schemas, fixtures). Clients already use those names via
   GIT-006; this unit changes only server binding location.

3. **GIT-005 operation/capability idiom.** Each procedure invokes exactly one bound Git operation.
   Routers do not orchestrate. New effectful dependencies are capability ports constructed once at
   `createDaemonOperations` and injected into `createGitOperations`. Operations do not import
   concrete adapters, routers, stores, or native error text. Unexpected exceptions continue to the
   centralized `internal.unexpected` mapper; neither procedure declares expected public errors
   (`errors: []` in the contract catalog).

4. **`commitModels` capability extension.** Extend existing `CommitGeneration` with
   `listModels(): Promise<CommitModelOption[]>`. Adapter method delegates to
   `listCommitModels` from `apps/daemon/src/git/commit-generation.ts`. Operation
   `commitModelsGit()` returns `commitGeneration.listModels()` with no extra ordering. Router
   binds `procedureCatalog.commitModels` (void input).

5. **`diffReading` capability + operation orchestration.** Add a narrow `GitDiffReadingSources`
   port (name exact) for flow + hunk + commit-message reads. The operation
   `diffReadingGit(input)` owns the **exact** scope branching, parallel hunk fetch, vanished-file
   empty-hunk recovery, and title rules currently inlined in `router/review.ts` (lines 121–161).
   Pure assembly uses `buildDiffReading` from `apps/daemon/src/review/feature-view.ts` (pure,
   already covered by `feature-view.test.ts`). That pure import is the only Review module the Git
   **operation** may touch; adapters bind effectful flow loaders and Git helpers.

6. **No client, contract, residual-router, or product-behavior change.** Preserve Changes/History
   stacked-diff outputs, commit-model discovery/order, cache behavior of shared flow loaders,
   error mapping, and client query identities. Settings UI and preferences presentation stay put.

## Objective

`diffReading` and `commitModels` are bound only through the Git feature router and Git operations;
Review and settings routers no longer define or import those Git procedures.

## Why this unit exists

Decision 013 assigns Changes/History reading and commit-model inventory to Git. After GIT-005/006 the
contracts and clients already treat both procedures as Git, but the daemon still binds
`diffReading` on `createReviewRouter()` and `commitModels` on `createSettingsRouter()`. That crossed
ownership is the last Review/settings Git transport leak named by the Git campaign.

## Target ownership and public surface

### Ports (`git-ports.ts`)

```ts
// CommitGeneration — extend existing type
export type CommitGeneration = Readonly<{
  generateMessage(input: GitGenerateCommitMessageInput): Promise<string>
  generateGroups(
    input: GitGenerateCommitGroupsInput,
  ): Promise<GitGenerateCommitGroupsOutput['groups']>
  listModels(): Promise<CommitModelOption[]>
}>

// New capability — exact name GitDiffReadingSources
export type GitDiffReadingSources = Readonly<{
  loadWorkingFlow(repoPath: string): Promise<FlowGroup[]>
  loadRangeFlow(repoPath: string): Promise<{ groups: FlowGroup[]; base: string }>
  loadCommitFlow(repoPath: string, hash: string): Promise<FlowGroup[]>
  workingHunks(repoPath: string, path: string): Promise<DiffHunk[]>
  rangeHunks(repoPath: string, base: string, path: string): Promise<DiffHunk[]>
  commitHunks(repoPath: string, hash: string, path: string): Promise<DiffHunk[]>
  commitMessage(repoPath: string, hash: string): Promise<string>
}>
```

Use `FlowGroup` / `DiffHunk` types consistent with what `buildDiffReading` already accepts (the
daemon `review/flow` and `git/diff` shapes the current router uses). Import those types at the port
boundary; do not redefine a second incompatible flow schema.

### Operations (`git-operations.ts`)

```ts
// Add to GitOperations:
commitModelsGit(): Promise<CommitModelOption[]>
diffReadingGit(input: DiffReadingInput): Promise<DiffReadingOutput>

// GitOperationDependencies gains:
diffReadingSources: GitDiffReadingSources
// commitGeneration already present; now includes listModels
```

`commitModelsGit` implementation: `return commitGeneration.listModels()`.

`diffReadingGit` implementation must preserve this exact behavior (ported from review router):

1. Destructure `{ repoPath, scope }` from input.
2. **working:** `groups = await sources.loadWorkingFlow(repoPath)`; `name = 'Changes'`;
   hunks via `sources.workingHunks(repoPath, path)`.
3. **branch:** `range = await sources.loadRangeFlow(repoPath)`; `groups = range.groups`;
   `name = \`vs ${range.base}\``; hunks via `sources.rangeHunks(repoPath, range.base, path)`.
4. **commit:** `groups = await sources.loadCommitFlow(repoPath, scope.hash)`;
   `message = await sources.commitMessage(repoPath, scope.hash)`;
   `name = message.split('\n')[0]?.trim() || scope.hash.slice(0, 12)`;
   hunks via `sources.commitHunks(repoPath, scope.hash, path)`.
5. Flatten `groups` files; `Promise.all` per-file hunk fetch into a `Map<path, DiffHunk[]>`;
   on thrown error for a path, leave that path out of the map (buildDiffReading defaults missing
   paths to `[]`) or set `[]` explicitly — match current empty-hunk recovery.
6. Return `buildDiffReading({ name, groups, diffs })`.

No cache clear, no session publish, no Review-mark side effects.
