# RT-005 — Bind mobile real-time and delete the legacy transport surface

- Status: Draft
- Batch: 0 — architecture and contract foundations
- Domain: real-time mobile adapter / legacy cutover
- Depends on: `RT-004` (Draft), `RT-003` (Draft), `RT-002` (Draft)
- Governing decisions: [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Bind mobile to the prepared shared real-time runtime and atomically switch daemon, Web, and mobile to
the target gateway before removing the old horizontal session/frame/event surface.

## Why this unit exists

The old transport cannot be deleted after only one client migrates. Mobile is the final adapter and
therefore the safe ownership point for the coordinated no-dual-path cutover; preparatory modules are
not activated before this recipe.

## Current behavior and evidence

Mobile daemon/session code is under `apps/mobile/src/lib/daemon/`; the old shared protocol is
`packages/contracts/src/ws-protocol.ts`; daemon compatibility sources include `apps/daemon/src/net/session.ts`
and `apps/daemon/src/app-events.ts`. `RT-002` prepares target modules but does not activate a bridge.

## Scope

Own the React Native transport and mobile cache/lifecycle binding under `apps/mobile/src/lib/daemon/`
and `apps/mobile/src/`; activate the prepared `RT-002` daemon modules and `RT-004` Web binding in the
same change; then delete `ws-protocol.ts`, the old daemon session/app-event path, and all remaining
Web/mobile legacy adapter imports. There is no runtime compatibility parser or bridge.

## Non-goals

Do not change category schemas, publisher semantics, recovery algorithms, project storage, pairing
flow, or invent a mobile-specific fallback protocol.

## Target ownership and public surface

Mobile injects its transport/auth lifecycle into `RT-003`, maps categories to existing authoritative
data refreshes, sends Viewer/file interests only after ready, and reports terminal mismatch/reconnect
state without treating signals as data. Before deletion, an assertion must prove no imports of the old
protocol/event/session modules remain in daemon, Web, mobile, or shared packages.

## Behavior to preserve

Preserve background/foreground lifecycle safety, pairing authorization, existing mobile query/cache
behavior, terminal output order, and the guarantee that reconnection refetches authoritative state.

## Legacy behavior to delete

Delete the old horizontal frame contract, daemon legacy session/app-event bridge, and old Web/mobile
session adapters in this single final cutover. No compatibility export, duplicate publisher, or
unversioned handshake remains.

## Ordered implementation

1. Implement and test the React Native transport/cache adapter using `RT-003`.
2. Activate the prepared daemon publisher/gateway and Web binding with this mobile adapter in one
   change; no old/new frame conversion is permitted.
3. Prove Web and mobile run the target hello/ready gateway and recovery path.
4. Remove old session/frame/event modules and all imports in that same change, then add a static
   legacy-import guard and end-to-end-focused daemon/mobile checks.

## Tests

Cover mobile foreground/background reconnect, hello/ready/mismatch, category invalidation, interest
updates, sequence-gap recovery, terminal ordering, and zero old-protocol imports. Re-run Web adapter
tests while the old bridge is absent.

## Validation and evidence

```text
pnpm lint
git diff --check
```

## Forbidden shortcuts

Do not retain a compatibility frame parser, a second publisher, a mobile-only legacy retry, or bypass
the static no-legacy-import guard.

## Completion criteria

- [ ] Mobile uses the shared runtime for target gateway, recovery, and interests.
- [ ] Both clients work without the legacy session/frame/event path.
- [ ] Old modules/imports are deleted and the guard proves zero remaining uses.
- [ ] Focused tests, lint, and diff check pass.

## Handoff

Real-time architecture is fully cut over; later work changes the named domain contracts rather than
reintroducing a horizontal event protocol.
