# TRM-004 — Move the Web Terminal adapter to shared stream semantics

- Status: Draft
- Batch: 2 — focused behavior exemplar
- Domain: terminal
- Depends on: TRM-003, TST-001, RT-005
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

The Web browser socket/Ghostty adapter consumes TRM-003’s canonical stream state while retaining Web-only terminal registry, clipboard and rendering code.

## Why this unit exists

`lib/daemon.ts` owns browser socket framing, request maps, attached ids and reconnect reattach; `use-terminal-channel.ts` separately hydrates/query-polls and routes stream data to the registry.

## Current behavior and evidence

- `hooks/use-terminal-channel.ts` subscribes `primary`/optional local daemon, filters terminalSessions to the Project, hydrates `stores/terminals`, and attaches missing sessions.
- `lib/terminal-registry.ts` and `terminal/ghostty/*` are Web-only byte/rendering adapters.
- RT-005 provides the single target session; no local legacy protocol may remain.

## Scope

Create `apps/web/src/features/terminal/{terminal-stream-adapter,terminal-roster,terminal-notifications,index}.ts`; update `use-terminal-channel.ts` callers and terminal components; remove terminal request/attachment/correlation code from `lib/daemon.ts` and obsolete hook paths after migration.

## Non-goals

Do not change Ghostty rendering, local-machine terminal mapping policy, PTY lifecycle, terminal roster contracts, terminal keyboard/clipboard UI, or make stream bytes Query data.

## Target ownership and public surface

- `terminal-stream-adapter.ts` exports `createBrowserTerminalAdapter` and `useTerminalStream`; it injects browser WebSocket/session transport, request id/timeout, and registry callbacks into TRM-003.
- `terminal-roster.ts` exports `useTerminalRoster`; it maps canonical `terminalSessions` to the current Project and attaches desired sessions through the shared state machine while retaining five-second authoritative roster polling.
- `terminal-notifications.ts` exports `applyTerminalRecovery`; stream recovery triggers roster/query refetch, never cache byte synthesis.
- `index.ts` is the feature boundary; terminal components import feature functions, not `lib/daemon.ts` stream APIs.

## Behavior to preserve

Keep primary/local roster merging, buffered data before Ghostty mount, scrollback replay, external-kill reconciliation, create/attach/paste error behavior, reconnect reattach, session cleanup and terminal output ordering.

## Legacy behavior to delete

Delete duplicated terminal request maps, attached-id sets, correlation dispatch, reconnect reattach loops and terminal listener APIs from `apps/web/src/lib/daemon.ts`; delete any moved `use-terminal-channel` implementation. Retain non-Terminal daemon session responsibilities until their named owner removes them.

## Ordered implementation

1. Verify TRM-003 and RT-005 are landed and the target session provides canonical frames.
2. Bind browser transport/registry and authoritative roster to the shared state machine.
3. Move terminal component imports, then delete only duplicated Terminal state from the legacy modules.

## Tests

- Adapter tests prove request correlation, close/timeout, reconnect reattach, gap recovery roster refetch and scrollback-before-data with fake browser transport.
- Roster tests retain Project/local filtering, poll and external exit behavior.
- Retain Ghostty key/runtime/surface and terminal component tests; they consume the feature boundary without mock child terminals.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../web/src/features/terminal ../web/src/terminal/ghostty ../web/src/components/terminal`.
- Run `pnpm lint`.
- Run `rg -n "pending(Creates|Attaches|Pastes|Files)|attachedIds|onTerminal(Data|Exit|Scrollback)|attachTerminal|terminal:attached" apps/web/src/lib/daemon.ts`; it returns no result.

## Forbidden shortcuts

Do not retain a second stream state machine, downgrade stream loss to a notification, push bytes into Query/Zustand, or alter Ghostty to compensate for protocol behavior.

## Completion criteria

- [ ] Web uses TRM-003 for all stream correlation/recovery/attachment decisions.
- [ ] Web-only rendering and local-session behavior remain covered; duplicate terminal state is deleted.
- [ ] Focused tests, lint and deletion search pass; the unit is committed.

## Handoff

TRM-005 supplies the final mobile adapter and completes the shared Terminal stream cutover.
