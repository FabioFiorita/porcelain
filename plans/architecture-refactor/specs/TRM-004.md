## Architecture reviewer rulings

1. **Dependencies and target root.** TRM-003, TST-001, and RT-005 are Landed at the review HEAD.
   Register `apps/web/src/features/terminal` as the Terminal Web target root in
   `scripts/architecture/domains.mjs`, and add its public `index.ts` entry. All Web callers in
   this unit import the feature entry; the feature's own modules may use relative imports. Do not
   create a second `packages/client-runtime` or contract Terminal implementation.

2. **The session seam stays transport-only.** `apps/web/src/lib/daemon.ts` remains the owner of
   the single browser socket, shared session runtime, endpoint/reconnect policy, and generic
   change/freshness lifecycle. It adds these two generic lifecycle/transport subscriptions:

   - `onTerminalFrame(listener: (frame: TerminalServerFrame) => void)`: forwards the already
     contract-validated `TerminalServerFrame` received from `SessionClientRuntime`; it performs no
     per-kind dispatch, correlation, attachment bookkeeping, scrollback routing, or request
     settlement.
   - `onDaemonReady(listener: () => void)`: fires after the shared runtime has entered `open` on
     every successful handshake, including the first one, before `onDaemonReconnect` listeners.

   Delete the old `onTerminalData`, `onTerminalExit`, and `onTerminalScrollback` subscriptions,
   all Terminal request methods/types, `pendingCreates`, `pendingAttaches`, `pendingPastes`,
   `pendingFiles`, `attachedIds`, `outbox`, Terminal correlation dispatch, and the reconnect
   attach loop from this file. `onDaemonReconnect` remains the generic subsequent-ready/freshness
   signal used by existing query adapters; the Terminal feature uses `onDaemonReady` to flush its
   queued requests and `onDaemonReconnect` to invoke shared-state recovery. `lib/daemon.ts` must
   not import the Terminal feature.

3. **One Web stream owner per daemon session.**
   `apps/web/src/features/terminal/terminal-stream-adapter.ts` owns one
   `createTerminalStreamState()` instance per `DaemonSession`. The cached production accessor is
   `terminalAdapterForSession(session)`; `terminalAdapterFor(id)` resolves ownership through the
   existing `sessionForTerminal(id)` policy in `apps/web/src/lib/local-daemon.ts`. Primary and
   optional local sessions therefore have separate shared-state instances, while the Web registry
   continues to route by the daemon-minted id. Repointing an existing local `DaemonSession` keeps
   its adapter/state so live PTYs retain their desired attachment set.

4. **Exact Terminal adapter surface.** The feature adapter exports these types and functions:

   - `TerminalAttachResult` is the successful `terminal:attached` value with
     `{ scrollback, status, exitCode?, epoch, sequence }`; it has no `found` member.
   - `TerminalPasteResult` is the successful `{ result: 'ok', path? }` value for either paste kind;
     expected failures are not encoded as old `no-session`/`too-large`/`write-failed` result
     strings.
   - `TerminalAdapterFailure` is
     `TerminalRequestFailure | { reason: 'not-requestable' }`. Server failures preserve the
     contract-owned `TerminalPublicError` inside `{ reason: 'server', error }`; close and deadline
     failures preserve `{ reason: 'closed' }` and `{ reason: 'deadline' }`.
   - `BrowserTerminalAdapter` exposes `createTerminal`, `attachTerminal`, `detachTerminal`,
     `isTerminalAttached`, `writeTerminal`, `resizeTerminal`, `killTerminal`,
     `pasteImageToTerminal`, `pasteFileToTerminal`, `subscribe`, and `dispose`. Its request
     result methods reject with `TerminalAdapterFailure`; fire-and-forget methods return `void`.
   - `createBrowserTerminalAdapter(session, options?)` creates an isolated adapter for direct
     boundary tests. `terminalAdapterForSession(session)` returns the one cached adapter, and
     `terminalAdapterFor(id)` returns the adapter for the existing primary/local ownership rule.
   - `useTerminalStream(session: DaemonSession | null, listeners)` is the React boundary hook. It
     subscribes/unsubscribes Web-only consumers and returns the cached adapter or `null`; it does
     not create a second state machine or copy stream bytes into Query/Zustand.

   `subscribe` listeners receive only ordered effects projected as Web values:
   `onData(id, data)`, `onExit(id, exitCode)`, `onScrollback(id, scrollback)`, and
   `onRecovery(recovery)`. The adapter routes an attach scrollback callback before resolving the
   attach promise; it routes accepted data/exit only after TRM-003 has accepted their epoch and
   sequence.

5. **Ids, deadlines, queues, and effects.** The Web adapter supplies every request id with
   `randomId()` (injectable in tests) and every request deadline as `now() + REQUEST_TIMEOUT_MS`
   using `REQUEST_TIMEOUT_MS` from `@porcelain/client-runtime/session/transport` (injectable clock
   and timer capabilities in tests). It never puts id, clock, or timer behavior in
   `packages/client-runtime/src/terminal`.

   - `createTerminal`, `attachTerminal`, and both paste methods call the matching TRM-003
     `request*` method, register one resolver keyed only by that request's id, and queue its
     strict returned frame until `session.runtime.status()` is `open`; `onDaemonReady` flushes the
     queue. A resolver is settled only by the corresponding TRM-003 effect, never by a second
     frame parser or a guessed error string.
   - The adapter schedules expiry for each pending request and feeds the injected current time to
     `state.expire`. It removes expired/settled requests from the outbound queue and clears timers
     on every settlement. A session close calls `state.close()`, clears unsent frames, and rejects
     pending promises with typed `closed` failures.
   - `writeTerminal` chunks at the contract's `MAX_TERMINAL_WRITE_CODE_UNITS`; every chunk,
     resize, detach, and kill gets a fresh request id through TRM-003. No fire-and-forget frame is
     sent while the runtime is closed, and no create/write/paste is replayed after reconnect.
   - On `onDaemonReconnect`, the adapter calls `state.reconnect()`, emits the typed recovery
     effect, and issues fresh attach requests with fresh ids/deadlines for the sorted
     `recovery.reattach` ids. `isTerminalAttached` is true for known desired attachments,
     including `awaiting-baseline` and `awaiting-reattach`, so roster polling cannot race a
     reconnect attach. `attach` failure removes the desired id through the shared state machine;
     the next authoritative roster can retry it.
   - A gap or epoch change follows the same shared recovery path. `applyTerminalRecovery` asks
     the owning roster query to refetch and never synthesizes or inserts stream bytes into a
     cache.

6. **Roster and dual-daemon ownership.**
   `apps/web/src/features/terminal/terminal-roster.ts` moves the current
   `useTerminalChannel` implementation into `useTerminalRoster`. It keeps the primary
   `terminalSessions` query's five-second polling and current-project filter, the optional local
   query/mapped-path filter, local-id reseeding, store hydration, and external-exit handling. It
   obtains adapters only through `useTerminalStream`; it never calls Terminal methods or listener
   APIs on `DaemonSession`.

   `apps/web/src/features/terminal/terminal-notifications.ts` exports:

   - `applyTerminalRecovery(recovery, { refetchRoster })`, which best-effort refetches the owning
     primary or local roster when `refreshRoster` is true; and
   - the small typed failure-to-copy helper consumed by Web paste UI, which maps contract error
     codes and adapter `not-requestable`/closed/deadline failures without restoring the old result
     union.

   Update `apps/web/src/components/shell/app-shell.tsx` to mount `useTerminalRoster` and delete
   `apps/web/src/hooks/use-terminal-channel.ts`. Keep `apps/web/src/hooks/use-local-terminal.ts`
   and `apps/web/src/lib/local-daemon.ts` as the local-session/query and ownership policy; only
   their callers move to the feature boundary.

7. **Rendering and lifecycle callers.** Keep `apps/web/src/lib/terminal-registry.ts` and
   `apps/web/src/terminal/ghostty/*` as Web-only rendering, buffering, OSC52, clipboard, and
   Ghostty code. Retarget its writes/resizes/kills/pastes to `terminalAdapterFor(id)` and remove
   its `DaemonSession`/legacy paste-result imports. Retarget
   `apps/web/src/lib/terminal-file-attach.ts` and `apps/web/src/stores/terminals.ts` to the same
   feature boundary; preserve file-size checks, tab/store/tombstone behavior, local-vs-primary
   lifecycle routing, scrollback-before-live-data ordering, and existing user-facing copy.
   `apps/web/src/components/terminal/*` must continue importing rendering/file helpers only and
   must not gain raw daemon imports.

8. **Oversized-file ledger and public imports.** The migrated
   `apps/web/src/lib/daemon.ts` must fall below the 450-line architecture ceiling; remove its
   `OVERSIZED_PRODUCTION_FILES` entry in `scripts/architecture/domains.mjs`. Register the Web
   Terminal feature root there with the other Terminal target roots. No external Web caller may
   deep-import a non-`index.ts` module from the new root.

## Objective

Web browser/Electron terminal transport, correlation, attachment ordering, and reconnect recovery
use TRM-003's single shared stream state per daemon session while Ghostty rendering, clipboard, and
primary/local roster presentation remain Web-owned.

## Why this unit exists

`apps/web/src/lib/daemon.ts` currently owns Terminal request maps, an attached-id set, per-kind
listeners, scrollback routing, and reconnect reattachment. `apps/web/src/hooks/use-terminal-channel.ts`
then separately subscribes and polls the roster. TRM-003 now provides the canonical correlation,
attachment, ordering, and recovery semantics that must replace both duplicated responsibilities.

## Current behavior and evidence

- `apps/web/src/lib/daemon.ts` currently defines `AttachResult.found`, old paste-result unions,
  four pending maps, `attachedIds`, `outbox`, per-kind frame dispatch, and direct reconnect attach
  frames; all are still present at the review HEAD.
- `apps/web/src/hooks/use-terminal-channel.ts` subscribes primary/local sessions, routes data,
  scrollback, and exit to `apps/web/src/lib/terminal-registry.ts`, hydrates
  `apps/web/src/stores/terminals.ts`, polls the primary roster every five seconds, and attaches
  missing ids.
- `apps/web/src/lib/local-daemon.ts` is the established second-session owner. Its
  `sessionForTerminal(id)` policy and `localTerminalIds` set must remain the only local-vs-primary
  routing decision.
- `apps/web/src/lib/terminal-registry.ts` owns persistent Ghostty instances, pre-mount output,
  scrollback replay, OSC52, clipboard, and rendering lifecycle; it must not become the stream
  state owner.
- `apps/web/src/stores/terminals.ts` owns only the cross-component roster workflow and tombstones;
  daemon roster data remains authoritative and is hydrated, not copied into a new stream store.
- `apps/web/src/lib/daemon.test.ts` is a characterization suite for the old Terminal behavior and
  must move Terminal assertions to the feature adapter; its retained tests cover only the generic
  socket/session seam. `apps/web/src/lib/session-browser-adapter.test.ts` already proves the real
  shared runtime forwards contract-valid Terminal frames.

## Target ownership and public surface

The target public import is `@renderer/features/terminal` and its exact exports are:

```text
createBrowserTerminalAdapter
terminalAdapterForSession
terminalAdapterFor
useTerminalStream
useTerminalRoster
applyTerminalRecovery
terminalPasteFailureMessage
BrowserTerminalAdapter
TerminalAdapterFailure
TerminalAttachResult
TerminalPasteResult
TerminalStreamListeners
```

The adapter sends only strict frames returned by TRM-003 through the one
`DaemonSession.runtime.send` transport. It never sends a Terminal frame directly, correlates a
server frame independently, or replays a write/create/paste after reconnect. The feature's only
imperative mutable state is the cached TRM-003 state and its effect-settlement bridge; rendering
buffers and roster presentation retain their current owners.

## Behavior to preserve

- One primary session socket shared by change signals and terminal bytes; optional local daemon
  session remains independent and is selected only by `sessionForTerminal`.
- Five-second authoritative primary/local roster polling, current-project/mapped-path filtering,
  local-id reseeding, hydrate replacement, tombstone behavior, explicit kill, and repo-switch
  detach without kill.
- Create auto-attachment, writes chunked at the contract cap, valid resize/kill/detach commands,
  paste byte/name limits, typed daemon failures, and no hung promise after close or deadline.
- Initial attach and reconnect/gap recovery replay scrollback before accepted live data; stale,
  pre-baseline, wrong-epoch, and sequence-gap bytes remain suppressed by TRM-003.
- Ghostty pre-mount buffering, replay reset, OSC52 behavior, selection/clipboard actions, local
  and remote lifecycle routing, and terminal component behavior.

## Legacy behavior to delete

- `AttachResult.found`, old `PasteImageResult`/`PasteFileResult` failure unions, and all Web
  callers of those types.
- `pendingCreates`, `pendingAttaches`, `pendingPastes`, `pendingFiles`, `attachedIds`, `outbox`,
  direct Terminal `switch` correlation, per-kind Terminal listeners, and the reconnect attach loop
  from `apps/web/src/lib/daemon.ts`.
- `apps/web/src/hooks/use-terminal-channel.ts` and its direct subscription/attach implementation.
- Terminal-specific assertions and old `found` frames in `apps/web/src/lib/daemon.test.ts`.

No legacy Terminal result strings may remain in the Web adapter API; mobile's old adapter remains
out of scope until TRM-005.
