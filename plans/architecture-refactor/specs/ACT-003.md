## Architecture reviewer rulings (bind the executor; supersede the tracked Draft)

1. **Dependencies.** Catalog is the source of status. Depend only on `ACT-002`, `TRM-005`,
   `TST-001`, and `RT-005` (all Landed). Do not repeat mutable status beside IDs.

2. **Copy Web Board / Files / Search feature layout; mobile Board / Files non-optimism.**
   | Concern | Copy from | Do not invent |
   | --- | --- | --- |
   | Web query keys | Board/Files: `[identity, DaemonScope]` | tRPC procedure-name keys |
   | Web transport | Board/Files: vanilla `trpc.useUtils().client.<proc>` | `trpc.actions.useQuery` procedure hooks for the Actions feature cache |
   | Web mutations | Files non-optimism: success-only exact invalidation of declared identities | Board optimism / reconciliation |
   | Web notifications | Board `useBoardNotificationSubscription` + `applyBoardNotification` | session-runtime `utils.actions.invalidate()` ownership |
   | Mobile query keys | Board: `['daemon', environmentId, identity]` | procedure-name strings |
   | Mobile transport | Board: `namedContractProcedure` + `callDaemon` + `getDaemonClient` | `useDaemonQuery(actionsQuery)` from Terminal procedures |
   | Mobile notifications | Board/Search bridges in `app/_layout.tsx` | provider `proceduresForChange` returning `['actions']` |
   | Shared semantics | `@porcelain/client-runtime/actions` only | reimplement prepare/cwd/trust policy in UI |

3. **Dual identity → one wire list cache row (ACT-002 ruling 3).** Machine trust is product-distinct
   from the roster, but the only Actions **read** procedure remains flat `actions`
   (`ActionView[]` with derived `trusted`). Adapters:

   - Construct **list** identity `actionsQuery(projectPath)` for the React Query cache row that
     holds `ActionView[]`.
   - When `affectedQueries` / `actionsNotificationEffects` yield **both** list and trust
     identities, invalidate the **list** cache key once per distinct `projectPath` (dedupe by
     project). Do **not** invent a second trust-only wire call or a second cache row.
   - Predicate helpers treat both identity `name` values (`list` | `trust`) as Actions domain
     keys for session recovery (`invalidateAllActionsQueries`), so a trust-shaped key never
     strands if one appears later.

4. **`prepareActionRun` → one Terminal create (not create-then-write).**
   ACT-002 yields plain fields `{ name, cwd, initialInput, where, … }`. Platform create already
   accepts `initialInput` (Web `useTerminalsStore.create` / `spawnLocalTerminal`; mobile
   `useTerminalStore.spawn` → `mobileTerminalAdapter().createTerminal`). **Do not** attach a
   second `terminal:write` for the command. Do not import `@porcelain/client-runtime/terminal`
   into Actions. Do not select an existing session — always create a new one (current product).

5. **`useActionRun` result contract (Web preserves File Finder + ActionsGroup).**

   ```ts
   type RunActionResult = 'ran' | 'needs-local-path' | 'needs-trust'
   ```

   | Outcome | When |
   | --- | --- |
   | `'needs-trust'` | `prepareActionRun` refuses `actions.untrusted` |
   | `'needs-local-path'` | refuses `actions.needs-local-path` |
   | `'ran'` | prepare succeeds and Terminal create (+ Web tab open) completes |
   | throw / reject | Terminal create fails (caller toasts / ErrorNote) |

   After a successful `trustActions` mutation, the initiating UI **must** pass
   `{ ...action, trusted: true }` into `useActionRun` before prepare (list refetch is async;
   command text is unchanged). Do not add a prepare skip-trust flag.

6. **Web local vs primary create paths (preserve `useRunAction` + `spawnLocalTerminal`).**

   | Prepared `where` | Create path |
   | --- | --- |
   | `'primary'` | `useTerminalsStore.getState().create({ cwd, name, initialInput })` then `openTab({ id: tabId('terminal', id), kind: 'terminal', title: name, path: id })` |
   | `'local'` | `spawnLocalTerminal(cwd, { name, initialInput })` from `@renderer/lib/terminal-actions` (already opens tab + sets origin `local`) |

   `cwd` / `name` / `initialInput` come **only** from `PreparedActionRun`. Project path for prepare
   context is `useProjectSelectionStore` project path; local path is caller-supplied
   `opts.localPath` (mapped path or dialog result). No project → no-op return `'ran'` (current
   silent guard).

7. **Mobile run path.** `useActionRun` calls `useTerminalStore.getState().spawn({ cwd, name, initialInput })`
   from prepared fields (selects the new session as today). Filter `where === 'local'` out of the
   list hook (phone has no local daemon) — preserve `useTerminalActions` filter. No CRUD hooks
   on mobile (never existed).

8. **Trust dialog / local-path dialog ownership.** Presentation stays UI-owned:

   - `ActionTrustDialog` moves into the Actions feature (Web).
   - `LocalPathDialog` **stays** at `apps/web/src/components/terminal/local-path-dialog.tsx`
     (also used by Terminal list spawn/edit). ActionsGroup imports it for `mode: 'run'` only.
   - Compose-intent store `useActionRunStore` moves into the Actions feature
     (`action-run-store.ts`). File Finder keeps requesting local runs through the public index.

9. **Session / provider handover (Board/Search pattern).**

   - Web: `case 'actions.changed'` in `invalidateForChange` becomes a no-op
     (`Promise.resolve()`), comment that the Actions feature owns it. Map
     `SessionQueryUtils.actions.invalidate` to `invalidateAllActionsQueries(queryClient)`.
     Mount `useActionsNotificationSubscription` from `app-shell.tsx` beside Board/Files/Search.
   - Mobile: `proceduresForChange` `actions.changed` returns `[]`; mount
     `ActionsNotificationBridge` in `app/_layout.tsx`. Project-scoped recovery that previously
     bulk-listed `'actions'` must not leave Actions stale — the bridge's
     `applyActionsFreshnessRequirement` (project-scoped) and session `invalidate all` path that
     already clears React Query wholesale remain sufficient; do not reintroduce procedure-name
     `'actions'` invalidation for the new identity keys.

10. **ACT-004 boundary.** This unit **stops all production callers** of Terminal-owned Action
    hooks/descriptors **and deletes** the dead descriptor definitions
    (`actionsQuery`, `trustActionsMutation`, `TerminalAction` type) from
    `apps/mobile/src/lib/daemon/procedures/terminal.ts` in the same commit (file retains only
    true Terminal procedures: `terminalSessionsQuery`, `renameTerminalMutation`, and related
    Terminal types). ACT-004 still owns architecture-gate zero-assertions and any residual
    Terminal vocabulary elsewhere; do **not** add those gates here.

11. **Naming (draft → Ready).** Draft names `useActionEditor` / `useActionRun` map to:

    | Public name | Role |
    | --- | --- |
    | `useActions` | list read |
    | `useActionMutations` | Web CRUD only (composer / row menu) |
    | `useTrustAction` | trust mutation |
    | `useActionRun` | prepare → Terminal create (replaces `useRunAction`) |

    Export alias **not** required for `useRunAction` — update all callers in this unit.

## Objective

Actions UI becomes an Actions feature in both clients, consumes ACT-002 identities/mutations/
notifications/`prepareActionRun`, and executes the explicit prepared Action → Terminal create
workflow without Terminal-owned Action descriptors or facades owning list/trust/CRUD/run.

## Why this unit exists

Web action controls live under Terminal; mobile list/trust/run live in the Terminal feature and
local procedure descriptors, obscuring Action ownership and allowing the two clients to drift from
shared prepare semantics.

## Behavior to preserve

- Trust is by command fingerprint on this machine; accept-and-run still runs immediately after
  successful trust with `{ ...action, trusted: true }`.

  input = command text (typed into shell, not auto-executed beyond Terminal create's existing
