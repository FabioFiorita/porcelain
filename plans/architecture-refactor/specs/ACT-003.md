# ACT-003 — Relocate Actions UI and execute through Terminal

- Status: Draft
- Batch: 3 — remaining domain cutovers
- Domain: actions
- Depends on: ACT-002, TRM-005, TST-001, RT-005
- Governing decisions: [004](../decisions/004-keep-cross-domain-workflows-shallow.md), [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Actions UI becomes an Actions feature in both clients and invokes the explicit prepared Action → Terminal workflow without Terminal-owned descriptors/facades.

## Why this unit exists

Web action controls live under Terminal; mobile splits commands between Changes and Terminal, obscuring Action ownership.

## Current behavior and evidence

Web uses `components/terminal/{actions-group,action-composer,action-trust-dialog}.tsx`; mobile uses quick-command and terminal composer surfaces. Current run state is local UI state.

## Scope

Create `apps/web/src/features/actions/` and `apps/mobile/src/features/actions/`; move action controls/hooks; bind ACT-002 to TRM-005 create/write through a narrow `runPreparedAction` adapter; update Shell/Terminal placement imports only.

## Non-goals

Do not change terminal rendering/lifecycle, action persistence rules, visual placement, or make terminal execution a daemon Actions mutation.

## Target ownership and public surface

Each feature exports `useActions`, `useActionEditor`, `useActionRun`, and presentation components. `useActionRun` obtains `prepareActionRun`, asks the platform Terminal adapter to create/select a session, then writes the prepared initial input once; it exposes preparation/terminal failures to the initiating UI. Components import the Actions feature, never Terminal daemon descriptors.

## Behavior to preserve

Keep trust dialog, action ordering/editor copy, local-only filtering, selected terminal behavior, pending/failure UI, accessibility and no automatic execution from notifications.

## Legacy behavior to delete

Delete action data hooks/types from Terminal/Changes feature boundaries and all direct `procedures/terminal` action/trust imports; retain Terminal’s generic render/input APIs.

## Ordered implementation

1. Verify ACT-002, TRM-005 and RT-005.
2. Create feature adapters/components and route current placements through their public entry point.
3. Delete Terminal-owned action facades and descriptor imports after all callers move.

## Tests

Test valid mock list/trust/CRUD, run preparation refusal, one terminal create/write invocation, terminal failure recovery, and retained action composer/trust visible behavior.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../web/src/features/actions ../mobile/src/features/actions ../web/src/components/terminal/action-composer.test.tsx ../web/src/components/terminal/action-trust-dialog.test.tsx`.
- Run `pnpm --dir apps/mobile typecheck` and `pnpm lint`.
- Run `rg -n "procedures/terminal.*(actions|trust)|useActions|ActionTrust" apps/web/src/components/terminal apps/mobile/src/features/{changes,terminal}`; it returns no result.

## Forbidden shortcuts

Do not reimplement terminal streams, run actions from notifications, retain a Terminal Actions store, or mock the workflow boundary.

## Completion criteria

- [ ] Both apps present Actions through domain features and execute the named workflow.
- [ ] Terminal-owned Action facades are absent and behavior tests pass.
- [ ] Typecheck, lint and search pass; the unit is committed.
