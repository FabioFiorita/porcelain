# CLI-001 — Gate the direct CLI's build, dependency, and channel boundary

- Status: Ready
- Batch: 0
- Domain: CLI delivery and agent channel
- Depends on: ARC-002
- Governing decisions: 003, 004, 006, 009, 014
- Primary exemplar: no

## Objective

Add a repository lint gate that locks the agent CLI to a built-in-plus-shared direct filesystem
channel: no daemon client, no listener, no `run` command, no new runtime dependency, and atomic
same-directory JSON replacement. The gate lands before any noun/verb ownership cutover.

## Why this unit exists

The CLI is intentionally a fresh synchronous direct writer for agent companion channels, not a daemon
RPC client. Its current traits are documented in comments/tests but not protected against a command
change importing a network client, adding a listener, or weakening the durable JSON write path.

## Current behavior and evidence

- `apps/cli/src/cli.ts` imports Node built-ins/local helpers; its comment declares a dependency-free
  direct project-channel CLI.
- `apps/cli/package.json` has exactly one runtime dependency, workspace `@porcelain/shared`; its
  build runs `scripts/build-node.mjs cli`.
- `apps/cli/src/project-io.ts` writes `${path}.tmp` then `renameSync(tmp, path)`.
- `scripts/build-node.mjs` bundles `apps/cli/src/porcelain.ts` to
  `apps/desktop/out/main/cli/porcelain.js`.
- The CLI inventory has 11 nouns/41 verbs; none is `run`. Terminal execution is not this channel.

## Scope

- Add `scripts/lint-cli-boundary.mjs` and `scripts/lint-cli-boundary.test.mjs`.
- Add root `lint:cli`; invoke it from root `lint` after `pnpm lint:architecture`.
- Add focused `COMMANDS` invariant assertions to `apps/cli/src/cli.test.ts`.
- Export `COMMANDS` for its focused invariant test; do not change parsing or dispatch.

## Non-goals

- Do not change a noun, verb, output shape, channel file name, or data schema.
- Do not replace direct filesystem I/O with tRPC, HTTP, WebSocket, IPC, or daemon client.
- Do not change `apps/daemon/src/cli-install.ts` or Project Data versioning/adoption.

## Target ownership and public surface

`lint-cli-boundary.mjs` exports `checkCliBoundary(root: string): string[]`; direct execution
prints violations and exits non-zero. `lint:cli` runs its fixture test before the repository check.

The gate scans production `.ts`/`.tsx` below `apps/cli/src`, excluding test files. It allows only
relative imports, `node:` imports, and exact workspace imports from `@porcelain/shared`. It rejects
other bare specifiers including `@porcelain/contracts`, `@daemon/`, `@backend/`,
`@client-runtime/`, `@web/`, `@mobile/`, and relative imports resolving outside `apps/cli/src`.

It requires `apps/cli/package.json` to have exactly one runtime dependency,
`@porcelain/shared: workspace:*`. It requires `scripts/build-node.mjs` to retain the
exact CLI entry/output, `bundle: true`, and `packages: 'bundle'`.

## Behavior to preserve

- The CLI remains a direct synchronous companion-file channel.
- `COMMANDS` remains help/dispatch registry and keeps its existing parity test.
- JSON writes remain same-directory temporary write followed by `renameSync`.
- The bundled output remains the daemon installer's source.

## Legacy behavior to delete

Delete no command or data compatibility in CLI-001. This gate replaces the unenforced assumption
that the CLI stays dependency-light and non-listening.

## Ordered implementation

1. Implement `checkCliBoundary(root)` and collect all violations before return.
2. Parse static import/export specifiers with the deterministic textual approach already used by
   `lint-architecture.mjs`; apply the exact allowlist and outside-root resolution rule.
3. Reject imports of `node:http`, `node:https`, `node:net`, `node:dgram`, `ws`, and
   `@trpc/client`; reject source calls matching `.listen(`, `createServer(`,
   `createConnection(`, and `WebSocket(`. Existing `execFileSync('git', ...)` remains permitted.
4. Enforce the package dependency rule without constraining dev dependencies.
5. Inspect `project-io.ts` and require a temporary path in the final directory, `writeFileSync`
   to that temporary path, and `renameSync` from it to final path; reject final `writeFileSync(path,`.
6. Inspect the CLI build configuration for exact entry/output/bundle/packages and reject an
   `external` option in the CLI build configuration.
7. Export `COMMANDS`. In `cli.test.ts`, assert every command verb differs from `run`
   and every noun/verb pair is unique; retain the current help/dispatch parity assertion.
8. Add controlled fixtures proving failure for daemon import, HTTP listener, non-workspace runtime
   dependency, direct final-file write, `run` registry entry, and external CLI package; prove a
   valid fixture passes.
9. Add `lint:cli` as `node scripts/lint-cli-boundary.test.mjs && node scripts/lint-cli-boundary.mjs`
   and call it in root `lint` immediately after `pnpm lint:architecture`.

## Tests

- `scripts/lint-cli-boundary.test.mjs` covers every violation and a valid fixture.
- `apps/cli/src/cli.test.ts` asserts no `run` verb and unique noun/verb pairs.
- `pnpm lint:cli`, `pnpm --dir apps/desktop test ../cli/src/cli.test.ts`, and `pnpm build:cli` pass.

## Validation and evidence

Run `pnpm lint:cli`, `pnpm --dir apps/desktop test ../cli/src/cli.test.ts`, `pnpm build:cli`, and
`node apps/desktop/out/main/cli/porcelain.js --help`; then run `pnpm lint`, `pnpm verify`, and
`git diff --check`. Record the output path and no-`run` registry assertion. Anchor note (verified
2026-08-10): `COMMANDS` is already exported at `apps/cli/src/cli.ts:193` — step 7's export half is
done; add only the invariant assertions. `scripts/build-node.mjs` gained a `buildProtocol` target in
PRO-004; the gate locks the CLI entry/output/bundle options and must not reject that daemon-side
protocol target.

## Forbidden shortcuts

- Do not allow a generic third-party runtime-package exception or accept daemon code because bundle.
- Do not accept a renamed command if it opens a listener or executes user-supplied shell commands.
- Do not weaken atomicity to a direct final-path write or silence lint with an inline ignore.

## Completion criteria

- The self-tested CLI gate is part of root lint.
- Source has only permitted imports and no listener/client construction.
- Runtime dependencies, build output, command registry, and atomic JSON replacement are locked.
- CLI tests, CLI build, repository lint, full verify, and diff check pass.
- One commit lands only `CLI-001`, marks recipe/catalog Landed, leaves a clean worktree, provides
  the README review packet, and finishes without pushing.

## Handoff

Later CLI noun/verb cutovers preserve this gate. A command requiring process execution belongs to
Actions plus a visible Terminal capability; it does not become an agent CLI `run` verb.
