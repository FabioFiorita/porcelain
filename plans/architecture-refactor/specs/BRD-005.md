# BRD-005 — Complete the mobile Board cutover

- Status: Landed
- Batch: 1 — Board primary exemplar
- Domain: board
- Depends on: BRD-002, BRD-003, BRD-004, TST-001
- Governing decisions: [002](../decisions/002-organize-by-product-domain.md), [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

The mobile Board feature will consume canonical Board contracts and `@porcelain/client-runtime/board`, apply validated Board notifications once, preserve mobile Board presentation workflows, delete Board descriptors from the Review-local procedure module, and satisfy the completed Board client gate.

## Why this unit exists

Mobile is the last remaining Board client path. `features/board` is already colocated but reaches generic daemon descriptors under Review, has a mobile-only string invalidation list, and applies the raw `board` event in the global provider. Completing this cutover removes both client-local wire ownership and the last Board semantic divergence from Web.

## Current behavior and evidence

- `apps/mobile/src/features/board/use-board.ts` imports Board types/descriptors from `@/lib/daemon/procedures/review`, calls `useDaemonQuery`/`useDaemonMutation`, and owns `BOARD_INVALIDATIONS = ['boardCards']`.
- `apps/mobile/src/lib/daemon/procedures/review.ts` owns `boardCardSchema`, Board inferred types, `boardCardsQuery`, and five Board mutations after Review comment descriptors.
- Anchor update (2026-08-11, post-RT-005/BRD-004): mobile `app-events.ts` no longer exists. The
  session-native adapter (RT-005) delivers validated `SessionChange` facts to
  `lib/daemon/provider.tsx`, which today hard-codes a `case 'board.changed'` invalidating the
  `['boardCards']` key (~lines 92 and 115) — that Board case is the raw mapping this unit deletes
  in favor of `BoardNotificationBridge` over `boardNotificationEffects`. The daemon serves ONLY the
  six canonical Board names since BRD-004's swap, so mobile Board is currently broken at runtime by
  design; this unit restores it on the canonical wire.
- Board presentation is already in `apps/mobile/src/features/board/{board-column,board-companion,board-list,board-phone-screen,board-viewer,card-composer,card-row,board-store,review-handoff-store}.ts(x)`.
- `board-store.ts` correctly owns unpersisted focus, phone column and card draft. `review-handoff-store.ts` correctly owns a one-use unpersisted local Board → Review suggestion.
- No Board-specific mobile test exists. Existing mobile tests under `features/board` are absent; the current shared behavior is instead characterized in Web `hooks/use-board.test.ts`.

## Scope

- Replace `apps/mobile/src/features/board/use-board.ts` with `board-data.ts` and `board-notifications.tsx`, plus their `.test.ts`/`.test.tsx` files.
- Update every Board component in `apps/mobile/src/features/board/` to import Board types, columns and actions from the Board feature boundary rather than Review-local descriptors.
- Update `apps/mobile/src/app/_layout.tsx` to mount `BoardNotificationBridge` once inside the existing daemon/query provider tree.
- Remove the Board descriptors, schemas and inferred exports from `apps/mobile/src/lib/daemon/procedures/review.ts`.
- Remove only the Board `case 'board.changed'` mapping from `apps/mobile/src/lib/daemon/provider.tsx`;
  retain all non-Board change handling.
- Change `apps/mobile/src/lib/daemon/{procedure,queries}.ts` only to accept the canonical structural procedure descriptors exported by BRD-001; do not change callers outside Board.

## Non-goals

- Do not change Board daemon operations, contract schemas/errors/notification names, client-runtime Board semantics, Web Board, Review operations, Review UI, shell navigation, native terminal, endpoint/session recovery or the non-Board provider mappings.
- Do not persist Board focus/draft/handoff state, store cards in Zustand, or turn Board → Review into a daemon operation.
- Do not add mobile E2E or a second mock framework.

## Target ownership and public surface

- `apps/mobile/src/features/board/board-data.ts` will export `BOARD_COLUMNS`, `boardStatusLabel`, `cardsInColumn`, `useBoardCards`, `useBoardCardActions`, `useBoardFailure`, `useFocusCard`, and `useSelectedCardId`.
- Its `useBoardCards(active)` maps `boardCardsQuery(projectPath)` from `@porcelain/client-runtime/board` to the mobile Query key with the active environment identity and invokes the BRD-001 `listBoardCards` contract descriptor through the mobile transport adapter.
- Its `useBoardCardActions()` binds all five BRD-003 mutation definitions, applies the same cancel → snapshot → pure transition → mutation → rollback/reconcile → exact invalidation lifecycle as Web, and supplies temporary id/timestamp values only at the mobile adapter boundary.
- `board-notifications.tsx` will export `BoardNotificationBridge`. It subscribes once to the configured mobile daemon session, accepts only validated BRD-001 Board notifications, maps them through `boardNotificationEffects`, and invalidates exactly the resulting active-environment Query identities. It will be mounted once from `app/_layout.tsx`.
- `apps/mobile/src/lib/daemon/procedure.ts` will accept the BRD-001 contract descriptor structural type for `callDaemon`, `useDaemonQuery`, and `useDaemonMutation`; it will not declare Board schemas, procedure names, output schemas, or local Board types.
- `apps/mobile/src/features/board/board-store.ts` continues to export `useBoardStore`, `draftFromCard`, `resolveBoardFocus`, `ComposerHost`, and `CardDraft`; its `BoardCard` and `CardStatus` imports come from `@porcelain/contracts/board`.
- Board components import from `@/features/board` or local Board files only. No Board component imports `@/lib/daemon/procedures/review`, `@/lib/daemon/queries`, or `@/lib/daemon/repo` directly.

## Behavior to preserve

- A focused Board reads only when its screen/panel is active; an empty loaded Board is distinct from a loading or failed Board.
- Existing phone one-column navigation, tablet three-column Board, Focus companion, board list, composer host coordination, confirmation dialogs, accessibility/test IDs, error copy and Board → Review handoff remain unchanged.
- Focus is Project-scoped and falls back Doing → To do → Done; draft, focus, column and handoff state remain unpersisted.
- Board changes from the mobile client, Web, CLI or agent refresh Board cards through the one daemon session. Reconnect and active-environment behavior remain owned by the Remote provider.
- All five writes gain the same immediate reversible feedback already preserved by BRD-004, followed by authoritative Board refetch; failure remains visible at the initiating mobile surface.

## Legacy behavior to delete

- Delete Board `boardCardSchema`, `BoardCard`, `CardStatus`, `boardCardsQuery`, `addBoardCardMutation`, `updateBoardCardMutation`, `moveBoardCardMutation`, `deleteBoardCardMutation`, and `clearBoardCardsMutation` from `apps/mobile/src/lib/daemon/procedures/review.ts`.
- Delete `BOARD_INVALIDATIONS` and every `['boardCards']` Board invalidation declaration from mobile Board source.
- Delete the Board `case 'board.changed'` / `['boardCards']` handling from
  `apps/mobile/src/lib/daemon/provider.tsx` and no other change handling.
- Delete `apps/mobile/src/features/board/use-board.ts` after every caller moves to `board-data.ts`.
- Delete no Review API except those Board-local declarations and delete no protocol compatibility behavior outside the Board cutover.
