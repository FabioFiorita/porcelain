## Architecture reviewer rulings (bind the executor; supersede the tracked Draft)

1. **Copy the landed Board/RVC daemon dual-writer exemplar.** Physical shape and test boundaries
   follow `BRD-002` / `apps/daemon/src/features/board/` and `RVC-001` /
   `apps/daemon/src/features/review/` (comments slice). Do **not** invent a third architecture,
   keep a Terminal façade, or leave the CLI on a second storage semantics.

2. **Contracts already land (CON-009).** Do not re-home schemas or rename the six public
   procedure names (`actions`, `trustActions`, `addAction`, `updateAction`, `moveAction`,
   `deleteAction`). Extend only with `actions.*` public errors, per-procedure `errors` arrays,
   fixtures, and tests. Notification `actions.changed` already exists and stays.

3. **Atomic daemon + CLI cutover to one strict version-1 actions document.** Disk shape is
   `{ version: 1, actions: ActionRecord[] }` at `<project>/.porcelain/actions.json`. Top-level
   arrays and incompatible versions are rejected without coercion, dual-read, or migration
   fallback (Decision 015). Shared pure model lives in `@porcelain/shared/actions-file`.

4. **Machine-local trust is a distinct version-1 home document.** Path remains
   `PORCELAIN_ACTION_TRUST_FILE` or `~/.porcelain/action-trust.json` (same env/fileName as today).
   On-disk shape is `{ version: 1, projects: Record<projectPath, fingerprint[]> }` where each
   fingerprint is the existing 32-hex SHA-256 prefix of the command text. Unversioned
   `Record<path, string[]>` is rejected without coercion — re-trust is the clean cutover cost.

5. **Public failures (exact).**

   | Code | category | retryable | details |

   | `actions.unavailable` | `unavailable` | true | none |

   | `actions.untrusted` | `conflict` | false | strict `{ actionId: z.string().min(1) }` |

   Compose all three into `publicErrorSchema` / `publicErrorFixtures`. Procedure `errors`:

## Objective

The six existing Actions wire procedures each invoke exactly one bound Actions operation over
injected version-1 project-actions and machine-trust adapters; the daemon and CLI share one strict
v1 actions document; successful mutations publish exactly one operation-owned `actions.changed`
after the durable write; Terminal no longer defines or imports any Action procedure; and
`prepareActionRun` is a directly tested internal operation that refuses missing or untrusted
commands without calling Terminal.

## Why this unit exists

Decision 013 assigns saved Actions, ordering, trust policy, and run preparation to `actions`.
CON-009 already moved the wire schemas, but `router/terminal.ts` still binds the six procedures
through unversioned `stores/actions-store.ts` + `stores/action-trust-store.ts`, and the CLI
dual-writes a permissive array. That crossed ownership blocks client-runtime and UI cutover.

## Target ownership and public surface

### Shared actions file (`@porcelain/shared/actions-file`)

Exports (dependency-free; no Zod; CLI-safe), mirroring `board-file` / `comments-file`:

```ts
export const ACTIONS_FILE_VERSION = 1 as const
export const ACTIONS_FILE_MAX_BYTES = 512 * 1024
export const ACTION_TITLE_MAX_LENGTH = 240
export const ACTION_COMMAND_MAX_LENGTH = 20_000

export type ActionsFileWhere = 'primary' | 'local'
export type ActionsFileAction = {
  id: string
  title: string
  command: string
  where?: ActionsFileWhere // omit or never persist 'primary'
  order: number
  createdAt: number
}
export type ActionsFileV1 = { version: 1; actions: ActionsFileAction[] }

export function emptyActionsFileV1(): ActionsFileV1
export function parseActionsFileV1(value: unknown): ActionsFileV1 // throws ActionsFileParseError
export function serializeActionsFileV1(value: ActionsFileV1): string // JSON + trailing newline
export function sortActions(actions: readonly ActionsFileAction[]): ActionsFileAction[]
// pure planners used by daemon ops + CLI:
export function planCreateAction(...)
export function planUpdateAction(...) // not-found when id missing
export function planMoveAction(...) // not-found when id missing; no-op result when at end
export function planDeleteAction(...) // not-found when id missing
```

Parse rejects: top-level arrays, non-object roots, `version !== 1`, malformed/unknown fields,
duplicate ids, blank/too-long title or command after trim, negative/non-safe-integer order or
createdAt, invalid `where`. UUID form for new ids matches Board (`randomUUID()`); parsers accept
any non-empty string id already on disk so CLI/daemon do not reject historical non-UUID ids
created before this unit (contracts use `z.string()`, not `z.uuid()`).

Title/command max lengths apply at pure plan + shared parse boundaries. **No clamp and no
`actions.invalid-title` code.** Over-length title or command from `planCreateAction` /
`planUpdateAction` is a plan failure; the operation returns
`{ ok: false, error: { code: 'request.invalid' } }` and the router maps it with
`expectedFailure('request.invalid')` (declared on `addAction`/`updateAction` in ruling 5).
Blank title/command is rejected at the wire Zod boundary before the operation runs.

### Ports (`actions-ports.ts`)

```ts

export type ActionsStoreResult<T> =

export type ActionsChangeResult =
  | { ok: true; value: ActionsChange }
  | { ok: false; error: ActionsNotFoundError }

  | { kind: 'delete'; file: ActionsFileV1; actionId: string }

export type ActionsStore = {

    projectPath: string,

    | { ok: false; error: ActionsUnavailableError | ActionsNotFoundError }

}

/** Machine-local trust. Keys are absolute project paths. */

  trustCommands(projectPath: string, commands: readonly string[]): Promise<ActionsStoreResult<void>>
}

export type ActionsClock = { now(): number }
export type ActionsIds = { create(): string }
export type ActionsChanges = {
  publish(change: { type: 'actions.changed'; projectPath: string }): void

export type ActionsOperationResult<T> =

      ok: false
```

**Move-at-end:** when the action is already first (`up`) or last (`down`), the operation returns
void success, does **not** call `transact`, and does **not** publish `actions.changed`. Missing id
still `actions.not-found`.

### Trust adapter (`json-action-trust-store.ts`)

- `commandFingerprint(command: string): string` — identical algorithm to current store
  (`sha256` hex, first 32 chars); export from the feature index for tests.
- Document path: `process.env.PORCELAIN_ACTION_TRUST_FILE ?? porcelainHomePath('action-trust.json')`.
- Strict v1: `{ version: 1, projects: Record<string, string[]> }`. Missing file → empty projects.
- Corrupt/malformed/unversioned/incompatible: rename the unreadable file to
  `${path}.corrupt-<UTC ISO with colons replaced by dashes>` (collision suffix `-1`, `-2`, …)
  exactly as `json-board-store.ts` does, then:
  - `readFingerprints` returns `{ ok: true, value: empty Set }` so list views render every action
    as `trusted: false` (fail closed on trust, not on listing);
  - `trustCommands` after a failed read of a present unusable document returns
    `{ ok: false, error: { code: 'actions.unavailable' } }` and does not create a new document
    over an unrestorable path; when the path is missing (`ENOENT`), `trustCommands` creates a
    fresh v1 document and writes the fingerprints.
- Oversized file (`> 512 * 1024` bytes): leave the file untouched; `readFingerprints` returns
  empty set success; `trustCommands` returns `actions.unavailable`.
- Atomic temp+rename, serialized mutations per process, no `ensureProjectCompanion`.
- `trustMigratedCommands(projectPath, commands)` — same semantics as today (no-op on empty list);
  exported for `migrate-home.ts`.

### Actions adapter (`json-actions-store.ts`)

Copy `json-board-store.ts` / `json-comment-store.ts` guarantees: absolute project path required,
absent → empty v1, strict parse, incompatible version untouched + unavailable, malformed → corrupt
backup + unavailable, size bound `ACTIONS_FILE_MAX_BYTES`, temp+rename, fsync, serialized
per-project chain, companion shell (gitignore + hide + `watchProjectCompanion`) without home
migration.

### Operations (`createActionsOperations`)

Bound intentions (names exact):

| Operation | Behavior |
| --- | --- |
| `listActions({ projectPath })` | Read actions + fingerprints; return `ActionView[]` sorted by `order` ascending (then `createdAt`, then `id` for ties). `trusted` = fingerprint set has `commandFingerprint(command)`. |
| `trustActions({ projectPath, ids })` | Load actions; for each id present, collect command text; `trustCommands` those texts; publish `actions.changed` after durable trust write. Unknown ids ignored. If store/trust unavailable → error. |
| `addAction({ projectPath, title, command, where? })` | Plan create with injected clock/ids; persist; **auto-trust** the new command text (human-authored through the app); publish after both durable writes succeed; return stored `Action` (no `trusted` field). |
| `updateAction({ projectPath, id, title?, command?, where? })` | Plan update; not-found if missing; if `command` changed, auto-trust the new command text after actions write; publish after durable success; void. |
| `moveAction({ projectPath, id, direction })` | Plan swap with neighbour by sorted order; not-found if missing; end-of-list → void success, no write, no notify; else write + notify; void. |
| `deleteAction({ projectPath, id })` | Plan delete; not-found if missing; write + notify; void. |
| `prepareActionRun({ projectPath, actionId })` | Load action; not-found / untrusted / success payload per ruling 6; **no** notify, **no** Terminal. |

Publish **only** after durable success; never on reject or adapter failure. Never import concrete
adapters inside operation factories — only ports. `Date.now` / `randomUUID` only via injected
clock/ids (defaults at composition).

### Router (`createActionsRouter(operations)`)

Six procedures, each: contract input → one operation → `throwIfFailed` mapping:

- `actions.unavailable` → `expectedFailure('actions.unavailable')`
- `actions.not-found` → `expectedFailure('actions.not-found', { actionId })`
- `actions.untrusted` → not used by wire procedures (prepare only)
- `request.invalid` → `expectedFailure('request.invalid')` when add/update plan rejects length

`actions` query input is the bare project path string (existing contract). Mutations keep
`repoPath` field names from CON-009.

## Behavior to preserve

- Human-only execution: neither Actions nor CLI runs a command.
