# CON-017 — Bind Review router procedures to canonical contracts

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: Review / Git contract boundary
- Depends on: `CON-016`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

The 26 Review procedures and Git-owned `diffReading` in `router/review.ts` use their exact canonical
input/output contracts without changing review content, evidence safety, comments, or exploration.

## Why this unit exists

`review.ts` is the largest source router and contains one Git procedure for historical layout
reasons. One file-owned recipe avoids overlapping edits while later REV/GIT specs relocate behavior.

## Current behavior and evidence

Review names: `markReviewed`, `unmarkReviewed`, `reviewedPaths`, `setReviewed`, `featureView`,
`featureReading`, `clearFeatureReview`, `reviewIntent`, `reviewEvidenceDocs`,
`reviewEvidenceAssets`, `reviewEvidenceAsset`, `reviewPublishCost`, `publishReview`,
`archivedReviews`, `restoreArchivedReview`, `deleteArchivedReview`, `loopEvidence`,
`loopEvidenceHtml`, `clearLoopEvidence`, `reviewComments`, `addReviewComment`, `editReviewComment`,
`deleteReviewComment`, `clearResolvedReviewComments`, `resolveReviewComment`, and `exploreFeature`.
`diffReading` belongs to Git. The file reads bounded Review/Evidence content, constructs working/
branch/commit readings, and performs comment/archive/review mutations through existing helpers.

## Scope

Edit `apps/daemon/src/router/review.ts`, add its focused contract test, and remove only `review.ts`
from the temporary lint remaining-file set after all 27 procedures pass.

## Non-goals

Do not relocate the file, change active/archive/evidence formats, file containment or caps, HTML
inlining/sandbox assumptions, Git flow construction, comments, publishing, exploration, or clients.

## Target ownership and public surface

Every named procedure uses exact same-name `procedureCatalog` input/output middleware on its current
public query/mutation. `diffReading` uses the Git catalog entry; the other 26 use Review entries.
Handler mappings and return annotations remain unless made redundant without changing types.

## Behavior to preserve

Preserve scope discriminators, review/read shapes, nullable/void behavior, Evidence document/asset
limits and containment, publish-cost/result behavior, archive identity, comment validation and
mutation semantics, exploration seeds/results, ordering, and ERR-002 safe unexpected failures.
`featureReading` and the named Evidence/publish lookups retain their current nullable contracts;
`exploreFeature` remains non-null and `loopEvidenceHtml` retains its exact non-null union member.

Deliberately replace object-input unknown-key stripping with strict `request.invalid` rejection;
there is no compatibility strip, alternate schema, or fallback.

## Legacy behavior to delete

Delete all 27 local input definitions and absence of output validation in `review.ts`; remove `zod`
only when unused and remove only `review.ts` from lint's remaining set.

## Ordered implementation

1. Bind `diffReading` to its Git entry, preserving its scope-to-flow orchestration.
2. Bind all 26 Review procedures in source order to exact catalog entries.
3. Remove obsolete schema imports only; do not move helper or content logic.
4. Add tests for strict unknown-key rejection, representative reading/document/asset/comment/archive/
   void outputs, other invalid input, and deliberately malformed output using synthetic temp data.
5. Remove `review.ts` from the lint set and prove all 27 exact bindings.

## Tests

Add `apps/daemon/src/router/review.contract.test.ts`; reuse test-owned temp Review fixtures and narrow
helper mocks. Never read real project companion content or reduce safety caps.

## Forbidden shortcuts

Do not replace strict output with unknown, expose raw file/native values, weaken content limits,
reimplement helper behavior in mocks, retain local Zod, or skip `diffReading` because its domain
differs.
