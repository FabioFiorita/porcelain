## Objective

The Terminal domain has one contract/daemon/client surface for roster and rename, no residual
`apps/daemon/src/router/terminal*` or mobile `procedures/terminal` ownership, shared roster
identity/mutation consequence under `@porcelain/client-runtime/terminal`, and the architecture
registry marks Terminal `complete`.

## Why this unit exists

TRM-001..005 moved stream vocabulary, PTY operations, shared stream state, and Web/mobile stream
adapters into the Terminal target roots. ACT-001 stripped Action procedures off the Terminal
router; ACT-004 completed Actions. What remains is request/response debt: the thin Terminal
router still lives under legacy `router/`, client-runtime has stream state but no roster
identity, Web still binds `terminalSessions`/`renameTerminal` through raw tRPC procedure hooks
and `trpcClient`, and mobile still hosts a `defineQuery`/`defineMutation` mirror under
`lib/daemon/procedures/terminal.ts`. Leaving Terminal `migrating` without zero-import gates lets
that debt re-expand.

## Behavior to preserve

- Daemon roster returns every live/exited PTY with `id`, `name`, `cwd`, `status`, optional
  `exitCode`, and `createdAt` (default 0) through contract output validation.
- Rename mutation returns void; empty/whitespace names remain no-ops inside operations; unknown
  ids are silent no-ops (current product behavior).
- Web primary roster: five-second poll, enabled only with a selected project, project cwd filter
  including nested paths, merge with local twin rows, hydrate into `useTerminalsStore`, attach
  missing ids through the stream adapter, recovery refetch on `refreshRoster`.
- Web local twin: five-second poll scoped to mapped local path; technical dual-daemon query key
  remains distinct from primary identity keys.
- Web rename: optimistic store update + write-through to the owning daemon (primary vs local);
  no required query invalidation.
- Mobile roster: five-second poll, active-project filter via `terminalSessionsForRepo`, store
  hydration, attach loop, recovery refetch, optimistic rename then authoritative mutation.
- Stream create/attach/write/resize/kill/paste, epoch/sequence recovery, and Actions → Terminal
  create remain unchanged.
- Composition merge order keeps Terminal last among current routers (same call site; only import
  path changes).
