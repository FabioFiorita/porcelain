# FIL-003 — Connect Files operations to bounded declarative watches

- Status: Draft
- Batch: 2 — focused behavior exemplars
- Domain: files
- Depends on: `FIL-002` (Draft), `RT-005` (Draft)
- Governing decisions: [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Publish typed successful Files change facts and replace per-window legacy file watchers with the RT declarative, bounded interest manager.

## Why this unit exists

Files is the real-time exemplar: existing `file-watch.ts` owns Electron-shaped senders, old event strings, separate caps, and no recovery-aware session interests.

## Current behavior and evidence

`apps/daemon/src/fs/file-watch.ts` has `setWatchedFiles/setWatchedDirs`, 128 directory cap, non-recursive directory watchers, debounce, and `app-event` `working-tree`/`file-tree` sends. RT-005 has deleted the old session/app-event surface and activated the target gateway.

## Scope

Replace `apps/daemon/src/fs/file-watch.ts` with `apps/daemon/src/features/files/files-watches.ts`; connect FIL-002 operations and current readDir/pin/scope mutations to RT-001 `files.content-changed`, `files.tree-changed`, or `files.scope-changed`; use only `apps/daemon/src/session/session-watches.ts` for interests.

## Non-goals

Do not alter client query mapping (FIL-004), recursive-watch policy, Git status publication, Search results, or a second socket/event path.

## Target ownership and public surface

Each successful text write creates `files.content-changed` for its relative path; create/rename/duplicate/trash creates `files.tree-changed` with affected paths; hide/unhide/pin/unpin/scope creates `files.scope-changed`. `files-watches.ts` watches only accepted session interests, uses one non-recursive directory watch per canonical directory, ignores `.git` churn, debounces to typed facts, and relies on RT's combined 128-interest limit rather than a second cap.

## Behavior to preserve

Preserve atomic-rename detection by watching parent directories, targeted project scope, watcher cleanup on session/repository close, unsupported-filesystem degradation to stale-until-refetch, `.git` suppression, and burst coalescing.

## Legacy behavior to delete

Delete `FileWatchSender`, `setWatchedFiles`, `setWatchedDirs`, `clearWatchedFiles`, `clearWatchedDirs`, `app-event`, `working-tree`, and `file-tree` from this module and all imports; retain no Electron `send` adapter.

## Ordered implementation

1. Map each Files mutation to its exact post-success fact.
2. Implement the RT-interest-backed adapter with canonical project-relative paths and debounce.
3. Wire operations/watch sources to the RT publisher after success only.
4. Delete legacy watcher/event exports and test target session cleanup.

## Tests

Test operation facts, filename-less atomic changes, `.git` rejection, debounce, directory/file interest reconciliation, cap delegation, session cleanup, and no event on failed mutation.

## Forbidden shortcuts

Do not recursively watch a repository, send raw paths outside the project, retain Electron senders, duplicate RT caps, or publish before the mutation commits.

## Completion criteria

- [ ] Files mutations and external changes emit only typed project-scoped facts.
- [ ] Watches are declarative, bounded, cleanup-safe, and non-recursive.
- [ ] Legacy FileWatch/app-event APIs have zero imports; tests/lint pass.
