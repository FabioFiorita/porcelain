### `createFilesChangesPublisher` (exact — Board shape)

```ts
// files-notifications.ts
import type { SessionChange } from '@porcelain/contracts/session'
import type { FilesChanges } from './files-ports'

export function createFilesChangesPublisher(
  publish: (change: SessionChange) => void,
): FilesChanges {
  return {
    publish(change) {
      if (change.type === 'files.content-changed') {
        publish({
          kind: 'files.content-changed',
          projectPath: change.projectPath,
          paths: [...change.paths],
        })
        return
      }
      publish({
        kind: 'files.tree-changed',
        projectPath: change.projectPath,
        paths: [...change.paths],
      })
    },
  }
}
```

Do not wrap in try/catch unless `publish` is known to throw; `publishSessionChange` / publisher `publish` return outcomes and do not throw on invalid (invalid → `{ ok: false }`). Match Board: no try/catch.

### Successful mutation facts (exact — success only)

Paths are the **wire project-relative** strings from the operation input (and duplicate’s returned relative path). Order is stable as listed; **dedup consecutive/identical entries** with a simple unique pass preserving first-seen order (required when `renamePath` `from === to`).

| Operation | On `ok: true` publish | On `ok: false` / throw |
| --- | --- | --- |
| `readFile` | **nothing** | nothing |
| `previewHtml` | **nothing** | nothing |
| `writeTextFile` | `{ type: 'files.content-changed', projectPath, paths: [path] }` | nothing |
| `createFile` | `{ type: 'files.tree-changed', projectPath, paths: [path] }` | nothing |
| `createFolder` | `{ type: 'files.tree-changed', projectPath, paths: [path] }` | nothing |
| `renamePath` | `{ type: 'files.tree-changed', projectPath, paths: unique([from, to]) }` | nothing |
| `duplicatePath` | `{ type: 'files.tree-changed', projectPath, paths: [value] }` where `value` is the **returned** new relative path | nothing |
| `trashPath` | `{ type: 'files.tree-changed', projectPath, paths: [path] }` | nothing |

**from/to semantics:** both sides are project-relative wire fields; publish both on rename so consumers can drop the old identity and load the new. Duplicate publishes only the new path (source content unchanged). Do **not** also publish `files.content-changed` for structural ops in this unit (FIL-004 mutation effects / later mapping may refine client recovery; draft FIL-003 structural → tree only).

### Operations factory (exact)

```ts
export function createFilesOperations(options: {
  workspaceFiles?: WorkspaceFiles
  changes?: FilesChanges
  publishSessionChange?: (change: SessionChange) => void
} = {}): FilesOperations {
  const workspaceFiles = options.workspaceFiles ?? createNodeWorkspaceFiles()
  const changes =
    options.changes ??
    createFilesChangesPublisher(options.publishSessionChange ?? (() => undefined))

  return Object.freeze({
    readFile: (input) => workspaceFiles.readFile(input),
    previewHtml: (input) => workspaceFiles.previewHtml(input),
    async writeTextFile(input) {
      const result = await workspaceFiles.writeTextFile(input)
      if (!result.ok) return result
      changes.publish({
        type: 'files.content-changed',
        projectPath: input.projectPath,
        paths: [input.path],
      })
      return result
    },
    // createFile / createFolder / trashPath: same pattern with tree-changed + [path]
    // renamePath: tree-changed + unique([from, to])
    // duplicatePath: on ok, tree-changed + [result.value]
  })
}
```

### `createSessionFilesWatches` (exact)

```ts
// features/files/files-watches.ts
import { watch as defaultWatch, type FSWatcher } from 'node:fs'
import { basename, dirname, relative, resolve, isAbsolute, sep } from 'node:path'
import type { SessionChange } from '@porcelain/contracts/session'

export const FILES_TREE_DEBOUNCE_MS = 200

export function isGitChurn(filename: string | null): boolean {
  return filename === '.git' || (filename?.startsWith('.git/') ?? false)
}

export type FilesWatchHost = {
  readonly watch: typeof defaultWatch
  readonly setTimeout: typeof setTimeout
  readonly clearTimeout: typeof clearTimeout
}

export type SessionFilesWatches = {
  readonly apply: (interests: {
    readonly projectPath: string
    readonly files: readonly string[]
    readonly dirs: readonly string[]
  }) => void
  readonly clear: () => void
}

export function createSessionFilesWatches(options: {
  publish: (change: SessionChange) => void
  host?: Partial<FilesWatchHost>
}): SessionFilesWatches
```

**Rules (bind the executor):**

1. **One instance per session** (constructed in `live-session.createSession`). **Cross-session watchers are intentionally separate** (no process-wide sharing). Within one session, keep one map keyed by canonical absolute directory. Each entry holds one `fs.watch`, a mutable file-basename set, and a `treeInterested` flag. A directory that is both an expanded-directory interest and the parent of one or more file interests therefore has **one** host watcher whose callback may emit an immediate content fact and enqueue a tree fact from the same event — never two watchers.
2. **No second interest cap.** Do not reintroduce `MAX_WATCHED_DIRS`. Bounding is solely `session-watches` + `SESSION_WATCH_INTEREST_LIMIT`.
3. **Non-recursive only.** Call `host.watch(dir, listener)` with **no** `{ recursive: true }`.
4. **File interests:** group by `dirname(file)`; store basename set; watch the parent directory; on event, if `filename` is null/empty **or** `entry.files.has(filename)`, schedule/publish **content** facts. Atomic rename survives because the parent is watched (preserve file-watch comment intent).
5. **Dir interests:** one watcher per accepted dir path; on event, if `isGitChurn(filename)` return; else debounce **tree** publish.
6. **Debounce:** tree events coalesce with `FILES_TREE_DEBOUNCE_MS` (200) after the last event per session-watches instance. Maintain one insertion-ordered pending tree-path set for the whole instance: every qualifying event adds its watched-directory path first and then its child path (when known); resetting the timer does not discard earlier paths. On expiry, publish one tree fact with the accumulated first-seen order, then clear the timer and set. Content events publish **immediately** (legacy file path had no debounce). `clear()` and a project-root change cancel the timer and empty the pending set, so facts from one project can never publish under another project.
7. **Fact translation (external events):**
   - `projectPath` = last successful `apply.projectPath` (canonical absolute from session-watches `resolve`).
   - Convert absolute host path → notification path:
     ```ts
     function toNotificationPath(projectPath: string, absolute: string): string | null {
       const rel = relative(projectPath, absolute)
       if (rel === '') return '.'
       if (rel === '..' || rel.startsWith(`..${sep}`) || isAbsolute(rel)) return null
       // normalize to POSIX-ish: Node relative on POSIX already uses '/'
       if (!isFilesNotificationPath(rel)) return null
       return rel
     }
     ```
   - **Content:** for a parent-dir event with basename `filename`:
     - if `filename` is null/empty: `paths` = all currently interested files under that parent, converted to notification paths (min 1 after filter; if empty after filter, publish nothing).
     - if basename matches an interested file: `paths` = `[toNotificationPath(project, join(parent, filename))]` (drop if null).
   - **Tree:** `paths` = `[toNotificationPath(project, watchedDirAbsolute)]`; if filename is a non-git non-null string, **also** include `toNotificationPath(project, join(watchedDir, filename))` when non-null; then unique preserving order. If the only path would be null, publish nothing.
   - Publish via `publish({ kind: 'files.content-changed'|'files.tree-changed', projectPath, paths })` where `projectPath` is the watch frame’s project root string (the absolute project path sessions already use for change scoping — **unchanged**: notifications keep absolute `projectPath` field; only `paths[]` are relative).
8. **`.git` suppression:** tree listeners only (content basename `.git` is not a normal open document; if it appears as filename under a parent watch, content filter won’t match ordinary interests).
9. **Unsupported / error:** `try/catch` around `watch` — skip that path (stale-until-refetch). `watcher.on('error', …)` — `close()`, remove map entry, clear pending debounce if that was the last dir (mirror legacy).
10. **Directory disappears:** handled by `error` path; no process crash.
11. **Teardown / idempotence:** `clear()` closes every watcher, clears timers and pending tree paths, and empties maps; second `clear` is no-op. `apply` is one complete desired-state reconciliation, not a transactional guarantee over host `fs.watch`: close removed directory entries, update the shared entry's basename set / `treeInterested` flag in place, and open one watcher for each new directory key. Reapplying the same frame creates no watcher. If `projectPath` changes, clear the old frame completely before installing the new one. A synchronous unsupported-watch failure skips only that directory; a later `apply` retries it because no live map entry exists.
12. **Symlink/canonical assumptions:** do **not** re-`realpath` interest paths; trust session-watches `resolve()` canonical strings. Publish containment uses `relative(projectPath, absolute)` only.
13. **No `FileWatchSender`, no `isDestroyed`, no `app-event` channel.** Lifecycle is session close → sink.clear / watches.clear.
