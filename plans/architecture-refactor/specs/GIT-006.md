## Objective

Git Changes, Diff, History, Commit, branch, status, suggestion, and model reads use shared typed identities and mutation consequences in both clients, with only presentation state remaining in app stores.

## Why this unit exists

The Web horizontal hooks in `apps/web/src/hooks/{use-git-flow,use-branch-flow,use-diff,use-diff-reading,use-history,use-commit,use-reviewed}.ts` and the mobile hooks in `apps/mobile/src/features/{changes,use-commit,diff,use-diff,history,use-history,use-commit-actions,settings}/` independently bind the same Git procedures. Mobile also keeps a second wire schema in `apps/mobile/src/lib/daemon/procedures/changes.ts`; Web still imports daemon Git models and both clients retain separate invalidation maps. GIT-003/004 already prove the shared workspace pattern and its temporary legacy bridge. This unit completes the bounded client cutover before GIT-007 moves the two crossed server router procedures.

## Current behavior and evidence

- `packages/client-runtime/src/git/git-queries.ts`, `git-mutations.ts`, and `git-notifications.ts` already own the GIT-003 workspace identities, non-optimistic checkout/create-branch/add-worktree consequences, and `git.working-tree-changed` mapping. Extend those files and their direct tests; do not add a parallel `git-reading.ts` semantic layer.
- `packages/contracts/src/git/git.procedures.ts` is the authoritative catalog for the remaining public reads (`gitStatus`, `gitFlow`, `gitRangeFlow`, `gitRangeDiffFile`, `gitDiffFile`, `gitHead`, `gitBranches`, `gitWorktrees`, `gitLog`, `gitCommitMessage`, `gitFileLog`, `gitCommitDiff`, `gitCommitFlow`, `diffReading`, `commitModels`) and writes (`gitQuickCommand`, `gitPush`, staging, discard, commit, and generation). `gitProcedures.diffReading` and `gitProcedures.commitModels` already have refined Git contract schemas even though their daemon bindings remain in `router/review.ts` and `router/settings.ts` for GIT-007.
- The Web adapter currently lives under `apps/web/src/features/git/workspace/`; it keys four workspace reads and bridges every GIT-003 effect through `workspace/git-legacy-cache.ts`. `apps/web/src/hooks/use-session-runtime.ts` still has Git-specific invalidators and excludes `git.working-tree-changed` from its global branch. `apps/web/src/features/files/files-mutations.ts` still maps Files' Git foreign token to raw tRPC invalidators.
- The mobile adapter has the same bounded bridge under `apps/mobile/src/features/git/workspace/`, while `apps/mobile/src/lib/daemon/provider.tsx` still owns Git procedure-name recovery for `review.changed` and skips Git notifications. `apps/mobile/src/features/files/files-foreign.ts` still constructs `['daemon', environmentId, 'gitDiffFile']` keys.
- `apps/mobile/src/lib/daemon/procedures/changes.ts` duplicates Git output schemas, query descriptors, mutation descriptors, and the `DiffReadingScope`; only its Review mark descriptors are a presentation-adjacent concern that must remain supported until the Review recipes move them. The Git portion of `changes.test.ts` is therefore deleted or moved to contract-backed Git adapter tests, while Review-mark coverage is retained through `reviewProcedures`.
- The current Web and mobile behavior is concrete: working flow polls at 3 seconds, suggestions poll at 5 seconds, mobile history polls at 15 seconds, branch and commit reads are immutable, diff prefetch preserves the last data, staging/discard/commit failures reject to the user-action owner, and Git writes never use optimistic server-state painting. These rules are preserved in the feature adapters.
- The current mutation sets are split across Web and mobile: staging refreshes flow (and mobile also refreshes diff, reading, and suggestions), discard refreshes Git plus Files tree/pins, commit/push refresh the working/range/history/conventions/suggestion/review-mark surfaces, and quick commands currently use a broad tRPC flush. The new typed table must preserve the visible results while replacing the flush with command-specific effects.

## Scope

### Shared Git client-runtime

Extend only `packages/client-runtime/src/git/git-queries.ts`, `git-mutations.ts`, `git-notifications.ts`, `index.ts`, and their tests. Keep the existing `gitProjectKey` validation and workspace capabilities. Replace the workspace-only identity union with exact query identities plus explicit family effects; update GIT-003/004 consumers in the same unit and leave no compatibility type alias.

The exact query constructors and identity dimensions are:

| Procedure | Runtime identity | Dimensions |
| --- | --- | --- |
| `gitHead`, `gitFlow`, `gitRangeFlow`, `gitStatus`, `gitBranches`, `gitWorktrees`, `gitCommitConventions`, `gitSuggestions` | existing names | `projectPath` |
| `gitDiffFile` | `diff-file` | `projectPath`, `filePath` |
| `gitRangeDiffFile` | `range-diff-file` | `projectPath`, `base`, `filePath` |
| `gitCommitDiff` | `commit-diff` | `projectPath`, `hash`, `filePath` |
| `diffReading` | `diff-reading` | `projectPath`, discriminated `scope` (`working`, `branch`, or `commit` plus `hash`) |
| `gitLog` | `log` | `projectPath`, `limit` (default constructor value `200`) |
| `gitFileLog` | `file-log` | `projectPath`, `filePath`, `limit` (default constructor value `50`) |
| `gitCommitMessage` | `commit-message` | `projectPath`, `hash` |
| `gitCommitFlow` | `commit-flow` | `projectPath`, `hash` |
| `commitModels` | `commit-models` | daemon scope only; no `projectPath` |

All exact identities are strict Zod-described values. Family effects are separate typed values used when a notification or mutation lacks a file, hash, limit, or scope: working diff, range diff, log, file log, diff reading, and commit/history families each retain the project dimension. Query-key adapters match a family effect to every exact identity in that family and match an exact effect only to the same complete identity. Session recovery includes daemon-scoped `commit-models`; project-gap recovery selects only identities with that project path.

Add the following shared exports:

- `GitQuery`, `GitQueryEffect`, strict schemas, and constructors for every exact identity above;
- `gitQueryEffectMatchesQuery`, effect deduplication, and family constructors used by both adapters;
- `gitMutations` definitions bound to the exact `gitProcedures` records, with `optimistic: false` and `requiresAuthoritativeRefetch: true` on every state-changing Git definition;
- exact `affectedQueries(input)` tables for staging, discard, commit, push, generation, and quick command. `gitQuickCommandEffects` has explicit rows for `status` (no state effect), `fetch` (remote/head/history/suggestions effects), `pull` (working-tree plus history effects), `push` (push/remote suggestion effects), and `stash`/`stash-pop` (working-tree effects); no mutation calls a broad invalidation;
- a discard `filesEffects(input)` set containing the Files tree subtree for `input.path` and the project Pins identity, so the Web/mobile adapters can invalidate Files through the existing typed Files filter rather than a Git-to-Files procedure string;
- `gitNotificationEffects` for `git.working-tree-changed` covering head, flow, range-flow, status, working/range diff families, working/branch diff reading, log/file-log families, conventions, suggestions, Review reading/view/reviewed paths, and no immutable commit identity; a separate `gitReviewNotificationEffects` for `review.changed` covering only the Git flow/range/diff-reading consequences of changed Review layers.

The shared mutation and notification tests must assert procedure-object identity, every dimension, family matching, exact effect order/deduplication, no optimism, authoritative refetch, daemon-scoped model identity, and contract-valid output/error handling through the landed validating mock.

### Cross-domain and state boundaries

- `apps/web/src/features/files/files-mutations.ts` and `apps/mobile/src/features/files/files-foreign.ts` remain Files-owned adapters; they consume typed Git effects and never import Git transport internals.
