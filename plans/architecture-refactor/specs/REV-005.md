# REV-005 — Write canonical Review CLI nouns and version-1 documents

- Status: Draft
- Batch: 5
- Domain: Review
- Depends on: REV-001, REV-002, REV-004, CLI-001
- Governing decisions: 003, 005, 006, 009, 015
- Primary exemplar: no

## Objective

Replace the agent CLI's Feature-era Review vocabulary and ad-hoc document writers with canonical Review nouns that write only validated version-1 Review documents.

## Why this unit exists

The dependency-light CLI is a direct channel, but `review-file.ts`, `evidence-file.ts`, `feature-view-file.ts`, and help/dispatch still duplicate schemas and expose Feature/root-index compatibility.

## Current behavior and evidence

- CLI Review files are `apps/cli/src/{review-file,evidence-file,reviewed-file,comment-file,layers-file,feature-view-file}.ts`.
- `cli.ts` currently registers `review`, `feature`, `comments`, `reviewed`, `intent`, `evidence`, and `layers`; `review-file.ts` supports HTML canvas/legacy terminology.
- CLI must remain Node-builtins/no listener and atomic direct project writer.

## Scope

- Create canonical Review CLI nouns/procedures and strict v1 document validation matching contracts.
- Move CLI document layout helpers to named Review/Project Data shared leaf modules where dependency direction permits.

## Non-goals

- Do not add a CLI `run`, daemon client, network listener, legacy Feature alias, root-index writer, or data migration.
- Do not change Board/Actions/Files CLI nouns.

## Target ownership and public surface

CLI exposes `review`, `comments`, `reviewed`, `intent`, `evidence`, and `layers` under canonical verbs from contracts. `feature` noun is absent. Each writer validates v1 schema, writes only active/archive/intent/evidence target paths atomically, and prints contract-shaped output/errors. CLI depends only on Node builtins, contracts/shared.

## Behavior to preserve

Preserve direct synchronous channel, `--repo` absolute validation, atomic temp rename, caps, check semantics, Results/Assets preparation, ordered docs, and clear user-facing validation errors.

## Legacy behavior to delete

Delete Feature noun/helper and legacy root-index write behavior only in REV-009 after daemon/Web/mobile/Companion/worktree consumers are target-only. Do not retain a spelling alias.

## Ordered implementation

1. Derive CLI validation from contract/shared leaf schemas without importing daemon source.
2. Rename commands/help/dispatch/tests to canonical Review nouns and exact procedures; remove target Feature documentation.
3. Ensure `evidence prepare/set/check/results-*` writes only v1 meta/results/assets and validates caps before write.
4. Update review/intent/reviewed/comments/layers writers to strict v1 envelopes and canonical filenames.
5. Add CLI fixture tests for valid write, invalid/version failure, no listener/import boundary, and atomic temp replacement.
6. Coordinate the one atomic Feature/root-index deletion with REV-009 after every consumer is moved.

## Tests

- `pnpm --dir apps/desktop test ../cli/src/cli.test.ts ../cli/src/review-file.test.ts ../cli/src/evidence-file.test.ts`.
- `pnpm lint:cli`, `pnpm build:cli`, `pnpm test`, and lint pass.

## Validation and evidence

Record help output noun/verb inventory, clean temporary project document bytes, invalid-shape errors, and absence of Feature/root-index target writer.

## Forbidden shortcuts

- Do not duplicate a daemon schema or preserve an old command spelling.
- Do not make a CLI read mutate/migrate a document.

## Completion criteria

CLI writers are canonical/v1/atomic and target-only; CLI boundary and focused tests pass.

## Handoff

REV-009 removes all transitional server/client/Companion root-index and Feature readers in one cutover.
