## Objective

Every Review document the agent CLI authors — the Intent and Results tab
manifests, and the evidence checks list — is produced from a shared strict
version-1 module the daemon reads back, with no second hand-rolled schema and no
duplicated cap in `apps/cli/src/`; and a CLI write into a companion root whose
`project-manifest.json` declares an unsupported version fails with a clear
message instead of writing anyway.

## Why this unit exists

`apps/cli/src/doc-set-file.ts:16-17,41,70-73` and
`apps/daemon/src/review/doc-set.ts:36,67-80` are two hand-written descriptions of
one file: the CLI writes `{ tabs }` with a 12-entry cap and its own extension
regex, the daemon parses `{ tabs }` with a 12-entry cap, a 60-character label
cap, and its own extension map. `apps/cli/src/evidence-file.ts:79-92,106-110`
re-declares the check shape, the three check caps, and `evidenceOverallStatus`
that `packages/shared/src/evidence-check.ts:12-30` already owns. Each pair is one
edit away from silent drift, and one already drifted: a CLI-generated label over
60 characters makes the daemon drop the whole manifest and fall back to name
order, so the tab order an agent pinned disappears without an error anywhere.
REV-004 recorded the evidence half of this debt for this unit in its Handoff;
PDT-001 recorded the manifest half.

## Target ownership and public surface

`packages/shared/src/doc-set-file.ts` is the single owner of the document-set
manifest format, written in the exact idiom of `comments-file.ts` (no zod, no
Node API, pure functions, an error class carrying a code):

- `export const DOC_SET_FILE_VERSION = 1 as const`
- `export const MAX_DOC_SET_TABS = 12`
- `export const MAX_DOC_SET_LABEL = 60`
- `export type DocSetTab = { file: string; label?: string }`
- `export type DocSetFileV1 = { version: typeof DOC_SET_FILE_VERSION; tabs: DocSetTab[] }`
- `export type DocSetFileParseErrorCode = 'incompatible-version' | 'malformed'`
- `export class DocSetFileParseError extends Error` with a readonly `code`
- `export function emptyDocSetFile(): DocSetFileV1`
- `export function parseDocSetFile(value: unknown): DocSetFileV1` — throws
  `DocSetFileParseError`; rejects a top-level array, a missing or non-finite
  `version`, a `version` other than 1, an unknown top-level key, a non-plain file
  name (containing `/`, `\`, or a leading `.`), an empty `file`, and a `label`
  longer than `MAX_DOC_SET_LABEL`; caps `tabs` at `MAX_DOC_SET_TABS`
- `export function serializeDocSetFile(tabs: readonly DocSetTab[]): string` —
  caps and emits `JSON.stringify({ version, tabs }, null, 2)`
- `export const DOC_SET_MEDIUM_BY_EXT: Record<string, 'markdown' | 'html'>` with
  the four current entries, and
  `export function docSetMediumFor(file: string): 'markdown' | 'html' | null`
- `export function docSetLabelFor(file: string): string` — the current derivation,
  truncated to `MAX_DOC_SET_LABEL`

`packages/shared/src/project-porcelain.ts` gains
`export const PROJECT_COMPANION_LAYOUT = 'project-companion-v1' as const` and
`export const PROJECT_COMPANION_FORMAT_VERSION = 1 as const`, documented as the
literals the Project Data manifest writer and the CLI's read-only guard share.

`apps/cli/src/project-io.ts` gains
`export function assertCompanionRootVersion(repoPath: string): void`, called at
the top of `ensureProjectDir`. It reads `.porcelain/project-manifest.json`; an
absent or unreadable file is a no-op, and a parsed file whose `version` is not
`PROJECT_COMPANION_FORMAT_VERSION` or whose `value.layout` is not
`PROJECT_COMPANION_LAYOUT` throws
``Error(`<path> declares an unsupported companion layout — upgrade Porcelain (this CLI writes version ${PROJECT_COMPANION_FORMAT_VERSION} ${PROJECT_COMPANION_LAYOUT})`)``.
The CLI never creates, repairs, or backs up that file.

`apps/daemon/src/review/doc-set.ts` keeps its public surface (`readDocSet` and
its options) and its zod use for everything else; only `manifestSchema`,
`MAX_DOCS`, and `MEDIUM_BY_EXT` are replaced by the shared module.

## Behavior to preserve

- The CLI stays a direct synchronous companion channel: Node builtins plus
  `@porcelain/shared` only, no listener, no daemon client, no `run` verb, exactly

  `not inside a git repository` message.
- Atomic same-directory temporary write followed by `renameSync` on every write.
- `intent prepare` never overwrites an existing manifest; `evidence prepare`
  wipes the previous pack; `evidence check` appends or replaces by label, carries
  the existing title forward, and creates the pack when absent.
- Existing check caps and their exact user-facing messages, the HTML payload cap
  (`MAX_HTML_BYTES = 1_572_864`) and the viewer-cap warnings, the missing-image
  warning, and the Results/Assets prepare guidance text.
- `readDocSet`'s fallback: a manifest that does not parse leaves tab order at
  name order rather than failing the read.
- Project Data remains the only writer of `project-manifest.json`; a missing
  manifest is still filled in by the next daemon write.
