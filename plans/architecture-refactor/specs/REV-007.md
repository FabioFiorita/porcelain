## Objective

Web Review lives under a Review feature boundary over canonical contracts/runtime with no daemon model import or Feature-named data hook.

## Why this unit exists

Review UI and hooks are scattered under `components/git`, Shell and `hooks/use-{feature-view,feature-reading,review-intent,evidence,reviewed,explore}.ts`.

## Current behavior and evidence

Current components include feature/review list/view/inbox/document/reading/evidence/explore surfaces; `stores/review-focus.ts` and `review-start.ts` are presentation workflow state.

## Scope

Create `apps/web/src/features/review/{review-queries,review-mutations,review-notifications,review-focus-store,index}.ts`; move Review components/callers from `components/git` and Shell; delete raw Review hooks and `@backend/review` imports.

## Non-goals

Do not rename final Feature vocabulary/files reserved for REV-009, change document rendering, move Evidence storage, or alter Shell navigation layout.

## Target ownership and public surface

Feature hooks bind REV-006/RVC-002 identities and mutations to Web Query/transport; `applyReviewNotification` is mounted once and invalidates exact keys. `review-focus-store.ts` keeps only selected Review/document/presentation state. `index.ts` exports UI/hooks needed by Shell; components do not import tRPC, daemon types or cache APIs.

## Behavior to preserve

Keep three-tab canvas, archive/restore/publish controls, Inbox, document reading, Evidence gallery/assets, comments, focus/start drafts, loading/error states and accessibility.

## Legacy behavior to delete

Delete named raw hooks, direct Review tRPC/cache logic, daemon Review model imports and migrated `components/git` Review paths; retain Feature-name file cleanup for REV-009.

## Ordered implementation

1. Verify REV-006 and RT-005.
2. Build feature adapters/stores and move presentation callers without changing copy/layout.
3. Delete raw hooks/imports and add feature-boundary tests.

## Tests

Use TST-001 for query/mutation/notification behavior; retain list/view/inbox/reading/evidence component tests for visible workflows without mocked Review hooks or child surfaces.

## Forbidden shortcuts

Do not retain Feature data aliases, duplicate runtime effects, put Review data in Zustand, or use broad invalidation.
