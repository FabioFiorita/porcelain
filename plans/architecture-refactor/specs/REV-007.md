## Architecture reviewer rulings

These bind the executor and supersede every conflicting sentence in the tracked Draft.

1. **`hooks/use-reviewed.ts` does not exist.** The Draft names it. Reviewed marks live in
   `apps/web/src/features/git/git-reviewed.ts` (101 lines), keyed with `gitQueryKey` over
   `reviewedPathsQuery`, and are exported from `features/git/index.ts:50`. The five raw
   Review hooks that do exist are `use-feature-view.ts` (119), `use-feature-reading.ts`
   (29), `use-review-intent.ts` (61), `use-evidence.ts` (86) and `use-explore.ts` (29).
2. **`reviewed-paths` and `worktree-inbox` stay in the Git key namespace.** REV-006 ruling 2
   froze `gitWorkspaceQuerySchema`'s membership because both app query-key parsers validate
   against it (`apps/web/src/features/git/git-query-key.ts:7`). Re-keying reviewed marks or
   the worktree inbox into a Review namespace would invalidate landed Git cache keys, so
   `git-reviewed.ts` and `features/git/workspace/git-queries.ts` are **not** touched by this
   unit. The new Review key namespace owns the other eleven identities only.
3. **`invalidateReviewEffects` routes each effect to the namespace that owns its key.**
   `reviewNotificationEffects` and the `reviewMutations` definitions return
   `reviewed-paths` among their effects (REV-006 `review-mutations.ts`), and that identity
   is keyed by Git under ruling 2. The Web filter therefore partitions the effect list:
   `reviewed-paths` and `worktree-inbox` are forwarded to the public
   `invalidateGitEffects` from `@renderer/features/git`; every other effect is matched
   against the Review key predicate. Importing another feature's public `index.ts` is legal;
   deep-importing its internals is not.
4. **`review-view.tsx` and `review-all-toggle.tsx` are Git surfaces and do not move.**
   `review-view.tsx` (82) reads `useDiffReading` and `review-all-toggle.tsx` (29) calls
   `useSetReviewed` — both Git-owned reads keyed in the Git namespace. Their Review-sounding
   names are REV-009's vocabulary problem, not this unit's ownership problem. What moves is
   exactly the presentation that reads Review server state.
5. **Comment presentation stays in `components/git`.** `comment-composer.tsx`,
   `comment-marker.tsx`, `diff-view.tsx`, `hunks-view.tsx` and `commit-view.tsx` render
   comments over Git diffs; RVC-003 already gave comments their client slice and left this
   presentation in place, exactly as RVC-004 did on mobile. Relocating it is not in this row.
6. **Daemon Review types have exact contract replacements.** Every type Web Review imports
   from `@backend/review/*` and `@backend/stores/evidence-store` is already declared in
   `packages/contracts/src/review/review.contract.ts`: `FeatureView` (88), `FeatureReading`
   (149), `ReadingFile` (48), `FileSource` (20), `ReviewDoc` (171), `Evidence` (229),
   `EvidenceAsset` (241), `EvidenceAssetBody` (253). CON-017 landed exact contract
   input/output middleware on the Review router, so these are the runtime shapes. The one
   gap is `ReviewCanvas`: `reviewCanvasSchema` is exported (line 111) but its inferred type
   is not. This unit adds `export type ReviewCanvas = z.infer<typeof reviewCanvasSchema>` to
   `review.contract.ts` — a type export beside an already-exported schema, with no schema,
   wire, procedure, or error change.
7. **`@backend/review/flow` stays.** `FlowGroup` is a Git changes-grouping type that happens
   to live under the daemon's `review/` directory. Its five importers
   (`components/git/commit-view.test.tsx:1`, `components/git/changes-list.test.tsx:1`,
   `components/shell/commit-group.test.tsx:1`, `components/shell/glance-home.test.tsx:2`)
   are Git and Shell surfaces. This unit's deletion search excludes it by name; REV-009
   owns the daemon-side move.
8. **`review.changed` loses its `exploreFeature` arm, deliberately.**
   `hooks/use-session-runtime.ts:83` refreshes `exploreFeature` on every review change;
   REV-006's `reviewNotificationEffects` excludes `explore` because an exploration is a
   snapshot of code being read, not of the active review — the behavior
   `hooks/use-explore.ts:6-10` already documents (`staleTime: 60_000`, "A snapshot, not
   live"). REV-006 is the landed authority; this unit follows it and does not re-add the arm.
9. **`repoLayers` stays in the session runtime.** REV-006 ruling 7 assigned the Project Data
   consequence of `review.changed` to Project Data. The minimal landing is to leave the
   `case 'review.changed'` arm in `use-session-runtime.ts` invalidating **only**
   `utils.repoLayers`, which already routes through the feature predicate
   `invalidateProjectDataLayers` (`use-session-runtime.ts:191`). No new Project Data file.
10. **SUP-001's supporting-region lint does not exist.** `scripts/lint-supporting-regions.mjs`
    is unwritten and SUP-001 is Draft. This unit must not pull it forward, must not add a
    region lint, and must not move a Shell file's layout responsibilities. Removing Review
    data ownership from `review-group.tsx`, `publish-review-button.tsx`, `glance-home.tsx`,
    `app-sidebar.tsx`, `viewer.tsx` and `app-shell.tsx` is precisely what makes a future
    SUP-001 tractable; it is a consequence of this unit, never a licence to start it.
11. **Two shrink-only ledgers move with the files.** `OVERSIZED_PRODUCTION_FILES`
    (`scripts/architecture/domains.mjs:132-144`) is keyed by path: the entries for
    `apps/web/src/components/git/feature-view.tsx` (520) and
    `apps/web/src/components/git/reading-surface.tsx` (904) are re-keyed to their new paths

    `TARGET_ROOT_DEEP_IMPORT_BASELINES['apps/web/src/features/review']` (14 occurrences / 14
    files, `domains.mjs:170-173`) must reach zero here and its entry must be **deleted** —
    the gate fails on a zeroed entry that is left behind (`lint-architecture.mjs:508-511`).
12. **`WEB_SERVER_IMPORT_BASELINE` is stale and is corrected here.** It records 106
    occurrences / 86 files (`domains.mjs:146-149`); the tree at `c8649621` actually has 41 /
    35. The gate only fails on growth, so the stale value has been silently inert. This unit
    sets it to the measured post-change value.

## Objective

Every Web surface that reads or writes Review server state does so through
`apps/web/src/features/review`'s public entry over `@porcelain/client-runtime/review` and
`@porcelain/contracts/review`; no Web file imports a daemon Review model, and no Review
procedure is invalidated by name.

## Why this unit exists

REV-006 landed the shared Review identities, mutation consequences and notification effects,
and nothing binds them yet. Web still reads Review through five raw tRPC hooks with implicit
per-procedure keys, types its Review props from `@backend/review/*`, and bulk-invalidates
nine procedure names from the session runtime. REV-008 (mobile) and REV-009 (the Feature-name
cutover) both assume one Web Review owner exists.

## Target ownership and public surface

### `review-query-key.ts`

Follows `features/git/git-query-key.ts` and `features/review/comments/comment-query-key.ts`
exactly: semantic identity first, daemon scope second, parsed rather than pattern-matched.

```ts
const reviewQueryKeySchema = z.tuple([reviewQuerySchema, daemonScopeSchema])
export type ReviewQueryKey = readonly [ReviewQuery, DaemonScope]
export function reviewQueryKey(daemon: DaemonScope, query: ReviewQuery): ReviewQueryKey
export function parseReviewQueryKey(
  queryKey: readonly unknown[],
): { query: ReviewQuery; daemon: DaemonScope } | null
export function isReviewQueryKey(queryKey: readonly unknown[]): boolean
```

`reviewQuerySchema` and `daemonScopeSchema` come from `@porcelain/client-runtime/review` and
`@renderer/lib/daemon-scope`. The comments identity is a member of `reviewQuerySchema`, so a
comments key parses here too; comment invalidation nonetheless keeps flowing through
`comments/comment-query-key.ts` and `invalidateAllReviewComments` — this unit adds no second
owner for comments.

### `review-query-filter.ts`

Copies `features/git/git-query-filter.ts`.

```ts
export function invalidateReviewEffects(
  queryClient: QueryClient,
  daemon: DaemonScope,
  effects: readonly ReviewQueryEffect[],
): Promise<void>
export function invalidateReviewProject(
  queryClient: QueryClient,
  daemon: DaemonScope,
  projectPath: string,
): Promise<void>
```

`invalidateReviewEffects` dedupes with `dedupeReviewQueryEffects`, then partitions

`parseReviewQueryKey` + `reviewQueryEffectMatchesQuery`, which is how the
`evidence-asset-family` effect reaches every per-file asset key of one project.
`invalidateAllReviewQueries` matches on `isReviewQueryKey` alone and is the session-recovery
slot. No procedure-name string appears in this file.
