# PDT-003 — Move Project Data settings to feature adapters

- Status: Draft
- Batch: 4 — Project Data and complete Review
- Domain: project-data
- Depends on: PDT-001, PDT-002, TST-001, RT-005
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Web and mobile Settings consume Project Data contracts/runtime effects while Settings remains an aggregator with no notes/disposition/layer wire ownership.

## Why this unit exists

Web settings hooks import backend Project/Review models and mobile splits local schemas across notes/companion/settings procedures.

## Current behavior and evidence

Web `use-{repo-notes,companion-dispositions,repo-layers}.ts` feed settings sections; mobile `features/settings/{data-panel,review-layers,review-panel,use-review-editor,use-settings}.ts(x)` uses local descriptor modules.

## Scope

Add `packages/client-runtime/src/project-data/{project-data-queries,project-data-mutations,project-data-notifications,index}.ts`; create Web/mobile `features/project-data/` adapters; update named settings sections; delete local wire hooks/descriptors after callers move.

## Non-goals

Do not change v1 manifest/storage, preferences persistence, Review behavior, Settings navigation or perform user-data reset/export.

## Target ownership and public surface

Runtime exports typed project-scoped identities for notes, companion dispositions/visibility and review layers; mutation definitions update only their affected identity and require authoritative refetch; typed `project-data`/Review change effects map explicitly. Feature indexes export notes/disposition/layer hooks and local editor state; Settings imports only those adapters.

## Behavior to preserve

Keep notes editing, disposition/visibility controls, layer editing, current validation/error copy, active Project scoping and notification refresh.

## Legacy behavior to delete

Delete `use-repo-notes`, `use-companion-dispositions`, `use-repo-layers`, mobile `procedures/{notes,companion,settings}` Project Data declarations, and direct backend type imports from Settings.

## Ordered implementation

1. Verify PDT-001/002 contracts/storage/operations and RT-005.
2. Implement runtime identities/effects and app feature adapters.
3. Move settings callers and delete named local paths.

## Tests

Test exact query/mutation effects, typed notifications/failures with TST-001, editor draft behavior, and retained settings section controls.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../../packages/client-runtime/src/project-data ../web/src/features/project-data ../mobile/src/features/project-data ../web/src/components/settings ../mobile/src/features/settings`.
- Run `pnpm --dir apps/mobile typecheck` and `pnpm lint`.
- Run `rg -n "@backend.*(notes|layers|companion)|procedures/(notes|companion|settings)|useRepo(Notes|Layers)" apps/web/src apps/mobile/src`; it returns no result in migrated settings paths.

## Forbidden shortcuts

Do not put data in preferences/Zustand, let Settings select cache keys, or delete persistence/migration behavior outside scope.

## Completion criteria

- [ ] Project Data has shared semantics and both settings adapters.
- [ ] Settings is presentation-only and legacy wires are gone.
- [ ] Tests, typecheck, lint and search pass; the unit is committed.

## Handoff

PDT-004 through PDT-006 govern authorization, migration deletion and durability proof.
