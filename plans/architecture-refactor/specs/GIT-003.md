## Architecture reviewer rulings (bind the executor; supersede the tracked Draft)

1. **Dependencies.** The catalog is the source of dependency status. This recipe depends only on
   `GIT-001`, `GIT-002`, `TST-001`, and `RT-001`; do not duplicate mutable status annotations in
   the recipe.

2. **Semantic identity vocabulary (ruling 1).** The runtime surface uses product-semantic names,
   while adapters later map them to the existing contract procedures. Do not make a cache identity
   out of a wire procedure string:

   | Runtime identity | Domain/name fields | Contract procedure family |
   | --- | --- | --- |
   | `gitHeadQuery` | `git/head` | `gitHead` |
   | `gitFlowQuery` | `git/flow` | `gitFlow` |
   | `gitRangeFlowQuery` | `git/range-flow` | `gitRangeFlow` |
   | `gitStatusQuery` | `git/status` | `gitStatus` |
   | `gitDiffQuery` | `git/diff` | `gitDiffFile` for every open file in the project |
   | `gitBranchesQuery` | `git/branches` | `gitBranches` |
   | `gitWorktreesQuery` | `git/worktrees` | `gitWorktrees` |
   | `gitLogQuery` | `git/log` | `gitLog` |
   | `gitCommitConventionsQuery` | `git/commit-conventions` | `gitCommitConventions` |
   | `gitSuggestionsQuery` | `git/suggestions` | `gitSuggestions` |
   | `reviewReadingQuery` | `review/reading` | `featureReading` |
   | `reviewViewQuery` | `review/view` | `featureView` |
   | `reviewedPathsQuery` | `review/reviewed-paths` | `reviewedPaths` |
   | `worktreeInboxQuery` | `review/worktree-inbox` | `worktreeInbox` |

   `gitDiffQuery` is deliberately a project-scoped semantic family: the current wire operation
   has a `filePath` input, and GIT-004's adapters match every active file-diff key for the
   declared project. `reviewReadingQuery` and `reviewViewQuery` preserve the existing
   `feature*` wire names without copying those names into shared cache semantics. No query
   identity carries a response value, a local app type, or a raw cache-key string.

3. **Identity validation and isolation (ruling 2).** Every identity is a strict object with its
   owning `domain`, semantic `name`, and non-empty `projectPath`; `gitProjectKey` owns the shared
   non-empty project-path check and constructors use it. The `gitQuerySchema`, review workspace
   query schema, and combined `gitWorkspaceQuerySchema` are the executable descriptions consumed by
   tests and future adapters. No absolute-path, host-canonicalization, or empty disabled sentinel
   policy is invented here; active adapters choose their disabled key later.

4. **Exact mutation consequences (ruling 3).** `gitWorkspaceMutations` binds the exact
   `gitProcedures` objects and exposes `procedureName`, `affectedQueries`, `optimistic: false`, and
   `requiresAuthoritativeRefetch: true`. Checkout and create-branch return this exact ordered set:

   `gitHead`, `gitFlow`, `gitRangeFlow`, `gitStatus`, `gitDiff`, `gitBranches`, `gitWorktrees`,
   `gitLog`, `gitCommitConventions`, `gitSuggestions`, `reviewReading`, `reviewView`,
   `reviewedPaths`, and `worktreeInbox`.

   Add-worktree returns only this exact ordered subset:

   `gitBranches`, `gitWorktrees`, and `worktreeInbox`.

   The checkout and create-branch definitions are equal in consequence, and add-worktree is a
   strict subset. No definition cancels a query, writes cache data, applies a host-state patch, or
   chooses a broad cache flush. The definitions bind the existing `gitCreateBranch` contract
   directly; GIT-003 does not add a daemon operation or reopen GIT-002's server boundary.

5. **Failure and authoritative state (ruling 4).** This unit owns semantic declarations, not
   transport lifecycle. The `optimistic: false` field is the proof that dirty/refused Git failures
   leave cached state untouched; the canonical GIT-001 procedure contracts remain the source of
   expected checkout/add-worktree error values, and TST-001's validating mock proves a refused
   request remains an observable public error. Adapters in GIT-004 surface the failure and refetch
   only after a successful mutation.

6. **Working-tree notification mapping (ruling 5).** `gitNotificationEffects` accepts the typed
   RT-001 `GitChange` union and exhaustively maps `git.working-tree-changed` for its project to
   exactly the current-worktree identities:

   `gitHead`, `gitFlow`, `gitRangeFlow`, `gitStatus`, `gitDiff`, `gitLog`, `gitCommitConventions`,
   `gitSuggestions`, `reviewReading`, `reviewView`, and `reviewedPaths`.

   Branch roster, linked-worktree roster, and sibling worktree inbox are not current working-tree
   data and are not included in this notification effect. Their external changes remain covered by
   their declared adapter polling/refetch behavior. The typed effect never names every query in a
   client or a framework cache.

7. **Contract-backed proof (ruling 6).** Direct tests use the TST-001
   `createValidatingDaemonMock` with `gitProcedures`, `gitChangeSchema`, and `publicErrorSchema`.
   Notification tests parse `gitNotificationFixtures['git.working-tree-changed']`; mutation tests
   dispatch the GIT-001 checkout/add-worktree contracts, including a typed refusal, and prove the
   runtime definition does not apply a local optimistic transition. No app transport, React, query
   client, daemon router, or subprocess is imported.

8. **Package boundary (ruling 7).** Add `packages/client-runtime/src/git/index.ts`, export it as
   `@porcelain/client-runtime/git` through the package `./git` map, and register
   `packages/client-runtime/src/git` as the Git target root in `scripts/architecture/domains.mjs`.
   The public index exports only the Git workspace semantic definitions, schemas, types, and
   constructors created by this unit.

## Objective

Client-runtime distinguishes non-optimistic checkout/create-branch effects from narrow add-worktree effects through typed Git identities.

## Why this unit exists

Web `use-worktrees.ts` calls `utils.invalidate()` for checkout; mobile `procedures/workspace.ts` holds two divergent string arrays. The shared layer needs one exact consequence table before GIT-004 replaces either adapter.

## Current behavior and evidence

- Checkout/create branch change HEAD, flow, diff, status, branches, worktrees, log and Review context.
- Add worktree leaves the current checkout unchanged and refreshes only branches, worktrees and inbox.
- Current reads include Git head/flow/range/status/diff/branches/worktrees/log plus Review reading/inbox dependencies.
- RT-001 defines one strict `git.working-tree-changed` notification scoped by `projectPath`; current Web/mobile maps confirm that it refreshes working-tree Git data rather than the branch/worktree roster.

## Scope

Add `packages/client-runtime/src/git/{git-queries,git-mutations,git-notifications,index}.ts`, their direct tests, the package `./git` export, and the Git client-runtime target-root registration. Implement only checkout/create-branch/add-worktree consequences and the typed working-tree notification map.

## Non-goals

Do not implement remaining Git procedures, React hooks, transport adapters, local selection, optimistic host state, notification delivery, local cache matching, or change the operation contracts. Do not change Web, mobile, daemon, or production runtime callers; GIT-004 owns both workspace adapters.

## Target ownership and public surface

- Export the fourteen typed identities listed in ruling 1, each project-scoped, with strict runtime schemas and project isolation.
- Export `gitWorkspaceMutations.checkout`, `.createBranch`, and `.addWorktree`; all are `optimistic: false` and require authoritative refetch.
- Checkout/create-branch affect exactly the fourteen identities in the declared order. Add-worktree affects exactly branches, worktrees, and inbox.
- Export `gitNotificationEffects`; typed `git.working-tree-changed` affects exactly the eleven current-worktree identities in the declared order and never every Query cache.

## Behavior to preserve

Dirty/refused Git mutations leave cached state intact and visible errors surface; branch/worktree external changes self-heal through typed refresh; no host mutation is optimistic.

## Legacy behavior to delete

Delete no app caller here. GIT-004 deletes `utils.invalidate()` and `WORKSPACE_*_INVALIDATIONS` when both adapters consume this module.
