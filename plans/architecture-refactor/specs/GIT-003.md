## Objective

Client-runtime distinguishes non-optimistic checkout/create-branch effects from narrow add-worktree effects through typed Git identities.

## Why this unit exists

Web `use-worktrees.ts` calls `utils.invalidate()` for checkout; mobile `procedures/workspace.ts` holds two divergent string arrays.

## Current behavior and evidence

- Checkout/create branch change HEAD, flow, diff, status, branches, worktrees and Review context.
- Add worktree leaves current checkout unchanged and refreshes only branches, worktrees and inbox.
- Current reads include Git head/flow/range/status/diff/branches/worktrees/log plus Review reading/inbox dependencies.

## Scope

Add `packages/client-runtime/src/git/{git-queries,git-mutations,git-notifications,index}.ts`, tests and `./git` export for only checkout/create-branch/add-worktree semantics.

## Non-goals

Do not implement remaining Git procedures, React hooks, local selection, optimistic host state, or change the operation contracts.

## Target ownership and public surface

- Export typed identities `gitHeadQuery`, `gitFlowQuery`, `gitRangeFlowQuery`, `gitStatusQuery`, `gitDiffQuery`, `gitBranchesQuery`, `gitWorktreesQuery`, `gitLogQuery`, `gitCommitConventionsQuery`, `gitSuggestionsQuery`, `reviewReadingQuery`, `reviewViewQuery`, `reviewedPathsQuery`, and `worktreeInboxQuery`, each project-scoped.
- Export `gitWorkspaceMutations.checkout`, `.createBranch`, and `.addWorktree`; all are `optimistic: false` and require authoritative refetch.
- Checkout/create-branch affect exactly head, flow, range-flow, status, diff, branches, worktrees, log, conventions, suggestions, review-reading/view, reviewed paths and inbox. Add-worktree affects exactly branches, worktrees and inbox.
- Export `gitNotificationEffects`; typed `git.working-tree-changed` affects the current-worktree data identities, never every Query cache.

## Behavior to preserve

Dirty/refused Git mutations leave cached state intact and visible errors surface; branch/worktree external changes self-heal through typed refresh; no host mutation is optimistic.

## Legacy behavior to delete

Delete no app caller here. GIT-004 deletes `utils.invalidate()` and `WORKSPACE_*_INVALIDATIONS` when both adapters consume this module.

## Ordered implementation

1. Verify GIT-001/GIT-002 contracts/results and RT-001 Git notification.
2. Define the exact identities and the two distinct consequence sets.
3. Add non-optimistic mutation and notification definitions with direct tests.

## Tests

Prove identity project isolation, checkout/create equality, add-worktree strict subset, no optimistic patch, expected failure preservation, and typed working-tree notification mapping with TST-001 fixtures.

## Validation and evidence

- Run `pnpm lint`.
- Run `rg -n "react|QueryClient|AppEvent|invalidate\(\)|WORKSPACE_" packages/client-runtime/src/git`; it returns no result.

## Forbidden shortcuts

Do not use a broad cache flush, raw procedure strings, duplicate Review/Git type definitions, or optimistic checkout/worktree state.

## Completion criteria

- [ ] The three mutations have explicit, distinct typed consequences.
- [ ] Runtime tests prove their difference and framework-free ownership.
- [ ] Lint and search pass; the unit is committed.
