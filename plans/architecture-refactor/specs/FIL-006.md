# FIL-006 — Complete the mobile Files cutover

- Status: Draft
- Batch: 2 — focused behavior exemplar
- Domain: files
- Depends on: FIL-004, FIL-005, TST-001, RT-005
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

Mobile Files uses canonical contracts/runtime watches/effects and removes its local Files schemas, daemon-name invalidations, and per-hook legacy watches.

## Why this unit exists

`features/files/use-files.ts` imports `procedures/files.ts`, owns `TREE_INVALIDATIONS`/`WRITE_INVALIDATIONS`, and calls `useDaemonWatch`; presentation is otherwise already colocated.

## Current behavior and evidence

- Reads cover directory, pins, content, preview and File/Search currently mixed together.
- Writes cover create/folder/rename/duplicate/trash and scope pin/hide; `use-files-browser.ts` owns prompts and visible failures.
- `procedures/files.ts` contains duplicate Zod models/descriptors; `app-events.ts` maps `file-tree`/`scope` by strings.

## Scope

Replace `features/files/use-files.ts` with `files-data.ts`, `files-notifications.tsx`, and `files-interests.ts`; update Files components; remove only Files declarations from `lib/daemon/procedures/files.ts`; remove only Files entries from mobile legacy invalidation code after RT-005.

## Non-goals

Do not move Search, change native preview/rendering, persist file data in `files-store`, alter prompts/path helpers, or remove non-Files daemon descriptors.

## Target ownership and public surface

- `files-data.ts` exports `useDirEntries`, `usePinnedEntries`, `useFileContents`, `useHtmlPreview`, `useFileWrites`, `usePathScope`, and contract types used by Files presentation; each maps FIL-004 identity/effect to active environment keys.
- `files-interests.ts` exports `useFilesViewerInterest` and `useFilesDirectoryInterest`, registering active absolute files/directories once through RT-005 rather than sending frames.
- `files-notifications.tsx` exports one `FilesNotificationBridge` mounted in the mobile provider tree; it maps validated typed facts through FIL-004 and invalidates exact environment/project keys.
- Components import the Files feature boundary; `files-store.ts` keeps only show-hidden/navigation/presentation state.

## Behavior to preserve

Keep relative-path UI/absolute daemon boundary conversion, directory ordering, prompt/error behavior, watched visible files/dirs, native preview states, pin/hide behavior, and no optimistic filesystem rendering.

## Legacy behavior to delete

Delete `TREE_INVALIDATIONS`, `WRITE_INVALIDATIONS`, `useDaemonWatch` calls in Files, Files descriptors/schemas/types in `procedures/files.ts`, and Files string entries in `app-events.ts`; retain Search declarations for its later domain cutover.

## Ordered implementation

1. Verify FIL-004, FIL-005 and RT-005 are landed.
2. Bind each Files read/write to the feature adapter and mount the single notification bridge/interests.
3. Move callers, delete named local descriptors/invalidation arrays, and leave Search code untouched.

## Tests

- `files-data.test.tsx` proves active environment keys, disabled reads, non-optimistic write refetch and typed failures with TST-001.
- Notification/interest tests prove file, directory and scope effects, project isolation, dedup and reconnect recovery.
- Retain Files pure tests and add browser/viewer presentation tests for load/empty/error, prompts, actions and accessibility.

## Forbidden shortcuts

Do not keep local Zod schemas, string invalidation, raw socket sends, a Files cache store, or a Search deletion in this unit.

- [ ] Named schemas and invalidations are deleted while Search remains intact.
- [ ] Focused tests, typecheck, lint and searches pass; the unit is committed.

## Handoff

The Files exemplar is complete; Search later owns its currently colocated reads.
