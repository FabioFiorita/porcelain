6. **Exhaustive `FilesQueryEffect` binding (ruling 4)**

Implement in `files-query-filter.ts` (pure; no React). Adapt Web FIL-005 rules to mobile keys:

```ts
export function filesPathIsSelfOrDescendant(candidate: string, root: string): boolean {
  return candidate === root || candidate.startsWith(`${root}/`)
}

export function filesQueryMatchesEffect(
  queryKey: readonly unknown[],
  effect: FilesQueryEffect,
  environmentId: string,
): boolean

export function invalidateFilesEffects(
  queryClient: QueryClient,
  environmentId: string,
  effects: readonly FilesQueryEffect[],
): Promise<void>

export function invalidateFilesProjectQueries(
  queryClient: QueryClient,
  environmentId: string,
  projectPath: string,

```

| Effect | Match on `['daemon', envId, FilesQuery]` |
| --- | --- |
| `exact` | envId equals and identity deeply equals `effect.query` → `invalidateQueries({ queryKey, exact: true })` |
| `tree-family` | envId + tree identity + `projectPath === effect.projectPath` |
| `tree-subtree` | tree identity + same project + env; `effect.path === '.'` matches only `path === '.'`; otherwise segment-safe self/descendant on identity path |
| `content-subtree` | content **or** preview identity + same project + env + segment-safe path |

- Always `dedupeFilesQueryEffects(effects)` before invalidation.
- `invalidateFilesProjectQueries`: parse the key, require `key[0] === 'daemon'`, `key[1] === environmentId`, `isFilesQueryKey(key)`, and `key[2].projectPath === filesProjectKey(projectPath)`. A project-scoped sequence gap must leave another project and another environment untouched; there is no environment-wide Files recovery helper in this unit.
- Tests must prove: `a` does not match `ab`; `src` matches `src`/`src/x` not `src2`; `'.'` tree-subtree is self-only; content-subtree hits content+preview; tree-family hits both showHidden rows.

8. **Notifications + provider cutover (ruling 6)**

### `files-notifications.ts` (QueryClient adapter; no React lifecycle)

```ts
export function applyFilesNotification(
  notification: FilesChange,
  options: {
    queryClient: QueryClient
    environmentId: string
    activeProjectPath: string | null
  },
): void

export function applyFilesFreshnessRequirement(
  requirement: FreshnessRequirement,
  options: { queryClient: QueryClient; environmentId: string },
): void
```

Rules:

- Accept only validated kinds `files.scope-changed` | `files.tree-changed` | `files.content-changed` (bridge kind-guards before cast to `FilesChange`).
- If `activeProjectPath === null` → no-op.
- If `filesProjectKey(notification.projectPath) !== filesProjectKey(activeProjectPath)` → no-op (other-project isolation).
- Else apply `filesNotificationEffects` via `invalidateFilesEffects` **and** `filesNotificationForeignDependencies` via `applyFilesForeignDependencies`.
- Freshness: for a project-scoped requirement, use `requirement.scope.projectPath` and `invalidateFilesProjectQueries` so only that project's Files identities in the matching environment become stale; then apply the union of foreign tokens for all three kinds (working-tree + path-index + content-index). Do not invalidate every Files project in the environment. Session-scoped recovery stays provider-owned (`daemonKeys.environment(id)` covers typed Files keys under that prefix).

`applyFilesNotification` and `applyFilesFreshnessRequirement` are synchronous callback boundaries. They must use `settleBackground(promise, 'notification')` / `settleBackground(promise, 'invalidation')` for invalidation and foreign-dependency promises. They must not use `void`, a bare Promise, or a no-op catch. Mutation promises remain awaited and reject to the existing `guard` / status owner.

### `FilesNotificationBridge`

- Mount once from `app/_layout.tsx` inside `DaemonProvider`.
- `subscribeSessionChanges({ onChange, onFreshnessRequired })` exactly like Board/Comments.
- `onChange`: kind-guard Files three kinds → `applyFilesNotification` with the paired `environment.id` and paired `useActiveRepo()?.path ?? null`; an unpaired environment does not subscribe and cannot call `filesProjectKey`.
- `onFreshnessRequired`: project scope → `applyFilesFreshnessRequirement`; session scope → no-op in the bridge (provider already invalidates the environment prefix). The project helper uses the requirement's project path, not the active repo path, so cached projects recover precisely.
- Cleanup: effect return unsubscribes.
- Double delivery is safe (idempotent invalidation).

9. **Interests (ruling 7) — mobile differs from Web**

Web mounts one AppShell bridge over tabs + expanded tree dirs. Mobile has **no** equivalent global tree-dir/tab interest store: directory watches attach to the **active browser path**, file watches to the **active viewer path**. Implement two hooks over FIL-004 `createFilesInterest` (not `useDaemonWatch`):

```ts
/** Watch one repo-relative directory while active ('' → '.'). */
export function useFilesDirectoryInterest(relative: string, active: boolean): void

/** Watch one repo-relative file while active. */
export function useFilesViewerInterest(relative: string, active: boolean): void
```

Lifecycle for each hook:

1. Read both `useActiveEnvironment()` and `useActiveRepo()`. When `!active`, `!isPaired(environment)`, `repo === null`, or the path is invalid → release any prior handle/facade and register nothing; do not call `filesProjectKey` while unpaired.
2. `const interest = createFilesInterest(repo.path, { registerWatchInterest: (i) => ({ release: daemonSession.registerWatchInterest(i) }) })`. The mobile `daemonSession.registerWatchInterest` returns `() => void`; the adapter must wrap it in the RT-003 `WatchInterestRegistration` object, never pass the bare function to `createFilesInterest`.
3. Directory: `interest.addDirectory(relative === '' ? '.' : relative)`; File: `interest.addFile(relative)` (null handle when invalid).
4. Cleanup: `handle.release()` then `interest.dispose()` (terminal, idempotent).
5. Key the effect on `repo.path`, `relative`, `active` (and environment pairing) so path changes re-register without leaking.

Call sites:

- `useDirEntries` calls `useFilesDirectoryInterest(relative, active && repo !== null && isPaired(environment))` (or equivalent enabled flag) and **must not** call `useDaemonWatch`.
- `useFileContents` calls `useFilesViewerInterest(relative, enabled)` and **must not** call `useDaemonWatch`.

Do **not** delete `apps/mobile/src/lib/daemon/watch.ts` in this unit (generic RT-005 helper; zero Files callers after cutover is enough). No second registry, frame, or 128 cap. RT-003 owns merge/dedup/reconnect replay. The hook test must assert the host receives `{ files, dirs }` and that cleanup calls the wrapped `release` before `dispose`.
