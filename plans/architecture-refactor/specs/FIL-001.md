## Objective

Make Files own exact strict wire contracts, kinds, and expected public failures for its 15 existing tree, pin, scope, read, preview, and mutation procedures.

## Why this unit exists

`CON-004` supplied exhaustive coverage, but Files needs deliberate file-view and failure vocabulary before operations replace direct Node calls.

## Current behavior and evidence

The 15 names and their current router locations are in `inventory/backend.md`: six in `router/repos.ts`, eight in `router/files.ts`, and `repoScope` in `router/settings.ts`. `router/files.ts` has local `FileView`, nullable preview, raw path schemas, and native errors; `read-limits.ts` caps reads at 10 MiB.

## Scope

Refine only `packages/contracts/src/files/{files.contract,files.procedures,files.notifications}.ts` and tests. Cover `readDir`, hide/unhide/pin/unpin, `pinnedEntries`, `readFile`, `previewHtml`, write/create/rename/duplicate/trash, and `repoScope`.

## Non-goals

Do not move router bodies, create filesystem capabilities, change path policy/persistence/watches, change Search, or add client semantics.

## Target ownership and public surface

`FileView` is strict `text | image | binary | too-large | not-found`; image data URLs, byte sizes, and nullable preview are wire values. Records declare current kinds and exact `files.not-found`, `files.already-exists`, `files.path-outside-project`, `files.not-a-file`, `files.unsupported-preview`, and `files.resource-too-large` only where intentional. RT owns the canonical Files notifications.

## Behavior to preserve

Preserve public string inputs, 10 MiB view behavior, image/binary distinction, nullable preview, duplicate target result, and current output defaults/order.

## Legacy behavior to delete

Delete exported local `FileView` and all Files local router Zod fallbacks; retain execution and watch behavior unchanged.

## Ordered implementation

1. Inventory exact current input/output/error behavior for all 15 records.
2. Make strict contract schemas/error arrays the sole Files procedure values.
3. Replace only router type/schema imports with contract values.
4. Add valid/invalid fixtures for every variant and declared error.

## Tests

Test every record, FileView variant, error detail, and RT notification schema; retain current router good-output assertions.

## Forbidden shortcuts

Do not use `z.unknown`, expose native errors, change path shapes, or define another daemon/client FileView.

## Completion criteria

- [ ] All 15 records have strict input/output/kind/error declarations.
- [ ] File view/notification vocabulary has one contract owner.
- [ ] Local router fallbacks are absent and focused tests/lint pass.
