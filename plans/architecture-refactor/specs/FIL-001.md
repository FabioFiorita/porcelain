## Architecture reviewer rulings (bind the executor; supersede the Draft)

1. **Scope shape (catalog + target architecture).** Catalog sequence is contracts (`FIL-001`) → capabilities/operations (`FIL-002`) → watches (`FIL-003`) → shared client semantics (`FIL-004`) → Web (`FIL-005`) → mobile (`FIL-006`). `BRD-001` is the contracts-batch exemplar: wire schemas, domain public errors, fixtures, tests; **no** operation bodies, **no** filesystem adapter, **no** client invalidation work. The tracked Draft’s Scope (“contracts only”) and its Ordered step 3 / completion criteria (“router import cutover / delete local fallbacks”) disagree. **Ruling:** this unit owns **contracts + domain public-error members + composition into the global error union + tests**, plus the **minimal daemon type-ownership cutover** required by Decision 005 (handwritten wire-type duplicates are forbidden). It does **not** move router bodies, native-error mapping beyond what is already live, path policy, watches, or client schemas.

2. **What “local fallbacks” means at HEAD.** CON-014 / CON-015 already bound every Files procedure to `procedureCatalog.<name>.input/output`. There is **no** local Zod left in `router/files.ts`, `router/repos.ts` (Files procedures), or `router/settings.ts` (`repoScope`). The remaining duals are **TypeScript types**, not runtime parsers: `export type FileView` in `router/files.ts` (re-exported by `api.ts`), `export interface DirEntry` in `router/repos.ts`, mobile mirror schemas in `apps/mobile/src/lib/daemon/procedures/files.ts` (FIL-006). This unit deletes the daemon handwritten `FileView` / `DirEntry` wire types and re-exports contract-inferred types from `api.ts`. It does **not** touch mobile mirrors.

3. **Public error vocabulary (do not invent soft failures as errors).**
   - `readFile` soft outcomes stay **success** `FileView` branches: `text | image | binary | too-large | not-found`.
   - `previewHtml` soft outcomes stay **success** `string | null` (missing, over-cap, empty → `null`).
   - **Do not** introduce `files.resource-too-large`, `files.unsupported-preview`, or a public `files.not-found` on `readFile` / `previewHtml` — those contradict live success modeling and Decision 010’s split between expected application failures and ordinary outcomes.
   - **Currently intentional mapped public error:** only `renamePath` → `state.conflict` (no details) via `expectedFailure` + `toTrpcError` in `router/files.ts`.
   - **New domain member in this unit:** `files.already-exists` for the intentional non-clobber of `createFile` (`wx`) and `createFolder` (non-recursive `mkdir`). **Declaration only** in contracts; **native EEXIST → public mapping is FIL-002** (ERR-001 / Decision 010: do not guess native classes in a contracts unit). Until FIL-002 maps it, runtime may still surface those collisions as unexpected defects — that is accepted for this unit, matching Board’s contracts-before-mapping order.
   - **Deferred entirely to FIL-002 (do not declare here):** `files.path-outside-project`, mutation `files.not-found`, `files.not-a-file`, and any other native translation. Public path-mutating procedures lack `projectPath`/`repoPath` on write/read wires; containment semantics are not decidable as a wire error until FIL-002 specifies the adapter boundary. Scope-store already throws a generic `Error` for out-of-repo pin/hide paths — leave unexpected until a later Files operations unit that owns those procedures.

4. **Notifications.** RT-001 / domain modules already own canonical `files.scope-changed` | `files.tree-changed` | `files.content-changed` under `packages/contracts/src/files/files.notifications.ts`, composed into `sessionChangeSchema`. FIL-001 **does not** redefine or re-home them. Publication cutover (delete `file-watch` app-event dual path; operation-owned facts) is **FIL-003**. Intermediate HEAD bridge: `live-session.ts` maps legacy `working-tree`/`file-tree` sender events into the three Files kinds for the session publisher.

5. **Path shapes.** Preserve current public path field shapes and names (`repoPath`, bare `path` strings, absolute/relative acceptance). Do **not** rename to `projectPath`, add `min(1)` path refinements, or change void mutation outputs. Decision 015 clean cutover does **not** require renaming Files paths in this unit.

6. **Dependencies at HEAD.** Catalog shows CON-021, ERR-001, RT-005 all **Landed**. The tracked Draft’s “Draft” annotations beside those IDs are stale. List dependency IDs only (no mutable status).

## Objective

Files owns one strict contract surface for its fifteen live tree/pin/scope/read/preview/mutation procedures: input/output schemas, kinds, fixtures, one contract-owned `FileView`, the three RT Files change notifications (already present), and exact intentional public-error declarations (`state.conflict` on `renamePath`, `files.already-exists` on `createFile`/`createFolder`); daemon no longer authors a second `FileView` or `DirEntry` wire type.

## Why this unit exists

CON-004 / CON-014 / CON-015 exhausted name and schema binding. FIL-002 must implement a project-contained filesystem capability and map native outcomes without inventing wire shapes or public codes. Soft file-view vocabulary and intentional collision errors must be locked in contracts first, following the Board contracts-before-operations order (`BRD-001` → `BRD-002`).
