# CON-015 — Bind Files and Search router procedures to canonical contracts

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: Files / Search contract boundary
- Depends on: `CON-014`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

The eight Files and three Search procedures in `router/files.ts` validate through their exact
catalog entries without changing file safety, limits, mutations, search semantics, or ERR failures.

## Why this unit exists

One legacy router file owns the remaining Files procedures plus all Search procedures. Migrating
the complete file makes the lint boundary binary and leaves domain relocation to later FIL/SEA specs.

## Current behavior and evidence

Files: `readFile`, `previewHtml`, `writeTextFile`, `createFile`, `createFolder`, `renamePath`,
`duplicatePath`, `trashPath`. Search: `searchText`, `searchCode`, `searchFiles`. The file owns binary/
size decisions, evidence HTML inlining, filesystem mutation calls, Git search calls, and the
`state.conflict` expected failure for an existing rename destination.

## Scope

Edit `apps/daemon/src/router/files.ts` and its tests, then remove only `files.ts` from the temporary
lint remaining-file set after all eleven procedures pass.

## Non-goals

Do not change path safety or read limits, rename error meaning, file encodings, asset inlining,
search options/results, filesystem/Git helpers, `FileView` export, or procedures in `repos.ts`.

## Target ownership and public surface

Every exact name above uses `procedureCatalog.<name>.input` and `.output` on the existing
`publicProcedure`, before its unchanged query/mutation resolver. Keep `expectedFailure`/
`toTrpcError` for `renamePath`; output validation defects map through ERR-002 as unexpected.

## Behavior to preserve

Preserve all current file-view discriminators, byte/size values, UTF-8 writes, creation/duplication/
trash results, non-overwriting rename behavior, search minimum/regex/case/include/exclude validation,
result ordering, and safe public errors.

Deliberately replace object-input unknown-key stripping with strict rejection through ERR-002
`request.invalid`; no compatibility input or retry is allowed.

## Legacy behavior to delete

Delete the eleven local input schemas and absence of output validation in this file. Remove its
`zod` import if unused and remove only `files.ts` from lint's remaining set.

## Ordered implementation

1. Bind all eight Files procedures, preserving `renamePath`'s expected failure.
2. Bind all three Search procedures to the Search-owned catalog entries.
3. Remove obsolete imports without changing handler or helper code.
4. Extend the existing router test for strict unknown-key rejection, valid file views/mutations/
   search results, and malformed handler-output rejection using temporary files and mocked helpers.
5. Remove `files.ts` from the lint set and prove all eleven bindings.

## Tests

Extend `apps/daemon/src/router/files.test.ts`; fixtures are temporary directories and synthetic file
content only. Never read a human repository or weaken caps to simplify the test.

## Validation and evidence

```text
pnpm --dir apps/desktop exec vitest run ../daemon/src/router/files.test.ts
node scripts/lint-procedure-contracts.mjs
rg -n "\.input\(z\.|from 'zod'" apps/daemon/src/router/files.ts
pnpm lint
pnpm verify
git diff --check
```

## Forbidden shortcuts

Do not parse outputs manually, convert native failures into new public codes, widen file/search
schemas, bypass the rename collision, retain local Zod, or change filesystem/Git implementations.

## Completion criteria

- [ ] Eight Files and three Search procedures use exact same-name catalog input/output schemas.
- [ ] File safety, mutations, search behavior, exported type, and expected failure remain exact.
- [ ] `files.ts` leaves the ledger and lint proves every binding.
- [ ] Focused tests, deletion search, repository lint, full verify, and diff check pass.
- [ ] One commit lands only `CON-015`, marks recipe/catalog Landed, leaves a clean worktree, provides
      the README review packet, and finishes without pushing.

## Handoff

Every Files and Search wire procedure now consumes its domain-owned contract even though source
relocation remains later domain work.
