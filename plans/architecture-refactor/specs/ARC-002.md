# ARC-002 — Make architecture import checks migration-status aware

- Status: Landed
- Batch: 0
- Domain: Supporting architecture enforcement
- Depends on: ARC-001
- Governing decisions: 001, 003, 004, 006, 013, 014
- Primary exemplar: yes

## Objective

Extend the architecture lint so the canonical-domain registry is the source of truth for migration
state and declared target roots. Legacy domains retain current coarse checks; migrating and complete
domains gain public-entry and cross-domain import checks only for their registered target files.

## Why this unit exists

`DOMAIN_STATUS` currently has ten unconditional `legacy` entries. The linter does not connect that
status to paths, public `index.ts` entries, or deep imports. The first migrated domain otherwise has
no gate preventing private cross-domain reach-through.

## Current behavior and evidence

- `scripts/architecture/domains.mjs` exports `DOMAIN_KEYS`, status-only `DOMAIN_STATUS`,
  `TARGET_DOMAIN_ROOTS`, and legacy compatibility exceptions.
- `scripts/lint-architecture.mjs` enforces current domain, runtime-direction, target-name,
  line-ceiling, and web-server-import-baseline rules.
- It does not resolve imports between domain target roots or require a public entry.
- All ten domains are `legacy`; this unit changes none of their status.

## Scope

- Add registry-backed migration records in `scripts/architecture/domains.mjs`.
- Refactor `scripts/lint-architecture.mjs` into an importable checker and add
  `scripts/lint-architecture.test.mjs` fixture tests.
- Add root `lint:architecture`; route the existing root `lint` through it.

## Non-goals

- Do not move, create, or mark a product domain migrated.
- Do not delete legacy paths, relax a baseline, create an eleventh domain, or add a TypeScript AST
  dependency.

## Target ownership and public surface

`scripts/architecture/domains.mjs` exports the frozen record below for exactly `DOMAIN_KEYS`; every
record initially has the shown legacy values:

```js
export const DOMAIN_MIGRATIONS = Object.freeze(
  Object.fromEntries(DOMAIN_KEYS.map((key) => [key, Object.freeze({
    status: 'legacy', targetRoots: Object.freeze([]), legacyPaths: Object.freeze([]),
  })])),
)
export const DOMAIN_STATUS = Object.freeze(
  Object.fromEntries(DOMAIN_KEYS.map((key) => [key, DOMAIN_MIGRATIONS[key].status])),
)
```

`targetRoots` and `legacyPaths` are unique normalized repository-relative POSIX strings. A target
root begins under one `TARGET_DOMAIN_ROOTS` entry and ends with its own domain key. Its public
`index.ts` is the activation marker: a canonical-named legacy directory remains legacy until that
file lands and the same change registers the root.
`scripts/lint-architecture.mjs` exports `checkArchitecture(root: string): string[]`; direct
execution prints each violation and exits non-zero on any violation.

## Behavior to preserve

- The ten keys, supporting-region exclusion, current import-direction rules, generic-name rule,
  450-line ceiling, legacy feature-directory rule, and shrinking web baseline keep their behavior.
- A repository with all domains legacy and no registered target root passes the new checks.
- `pnpm lint` remains the normal combined gate.

## Legacy behavior to delete

Delete the independent authored status map: `DOMAIN_STATUS` remains only as the derived
compatibility export above; lint logic reads `DOMAIN_MIGRATIONS`.

## Ordered implementation

1. Define `DOMAIN_MIGRATIONS` exactly as the target surface and derive `DOMAIN_STATUS` from it.
2. Validate registry shape before scanning: exactly ten keys; only `status`, `targetRoots`, and
   `legacyPaths`; allowed status; unique normalized repository-relative POSIX paths; each root's
   domain suffix and allowed root.
3. Enforce state: `legacy` has no target roots; `migrating` and `complete` have one or more;
   `complete` has no existing path named in `legacyPaths`.
4. Treat `<TARGET_DOMAIN_ROOTS>/<domain>/index.ts` as the candidate target-domain activation marker.
   Reject that public entry unless its root is registered and its domain is `migrating` or
   `complete`; require `index.ts` for every registered root. A canonical-named directory with no
   public entry remains governed as legacy code.
5. Resolve relative and configured TypeScript alias specifiers using `.ts`, `.tsx`, `/index.ts`, and
   `/index.tsx`. A cross-root import may resolve only to the foreign root's `index.ts`; reject every
   deep foreign target regardless of whether it used a relative path or a configured alias.
6. Preserve same-domain relative imports and leave unregistered legacy paths governed only by the
   existing checks.
7. Extract the checker into `checkArchitecture`; add fixture tests using self-cleaning temporary
   repositories. Cover all-legacy pass, unregistered target failure, migrating root pass,
   cross-domain deep failure, cross-domain `index.ts` pass, and complete legacy-path failure.
8. Add `lint:architecture` as `node scripts/lint-architecture.test.mjs && node
   scripts/lint-architecture.mjs`; replace only the current architecture command in root `lint` with
   `pnpm lint:architecture`.

## Tests

- `node scripts/lint-architecture.test.mjs` covers every registry and import state above.
- `pnpm lint:architecture` proves fixture tests precede the repository check.
- `pnpm lint` proves existing lint lanes still compose.

## Validation and evidence

Run `pnpm lint:architecture` and `pnpm lint`. Record that all ten current records remain legacy and
the fixture suite rejects an unregistered target root before a domain claims it.

## Forbidden shortcuts

- Do not infer status from directory existence or permit deep imports within one app.
- Do not exempt daemon, contracts, runtime, web, or mobile target roots.
- Do not add a broad allowlist, increase `WEB_SERVER_IMPORT_BASELINE`, or change status to pass.

## Completion criteria

- `DOMAIN_MIGRATIONS` is the sole authored migration record with all ten keys.
- A target domain public `index.ts` activation marker cannot land without a same-change registered
  migration root; canonical-named legacy directories without that marker remain allowed.
- Current checks remain active and registered migrated roots receive public-entry checks.
- `pnpm lint:architecture` and `pnpm lint` pass.

## Handoff

Each later domain migration updates only its `DOMAIN_MIGRATIONS[domain]` record in the same change
that adds its target root. No later specification adds a second status list.
