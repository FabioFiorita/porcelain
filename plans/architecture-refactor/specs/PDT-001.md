## Objective

One strict version-1 Project Data manifest owns companion layout/policy, each
canonical domain has explicit per-project file paths via `forDomain`, and
first-write no longer starts home or flat-active-review migration.

## Why this unit exists

Companion first-write is copied across `net/project-channel.ts` and three
feature stores (hide + default `.gitignore` + Review watch). Six remaining
horizontal stores still call `ensureProjectCompanion` on read, which copies and
purges `~/.porcelain` home records via `project/migrate-home.ts`. Decision 015
requires a version-1 root and forbids that discovery path; DAT-001 already
supplies the envelope primitive.

### Manifest document (`project-manifest.ts`)

```ts
export const PROJECT_MANIFEST_LAYOUT = 'project-companion-v1' as const
export const PROJECT_MANIFEST_FILE_MAX_BYTES = 16 * 1024

export const projectManifestValueSchema = z
  .object({ layout: z.literal(PROJECT_MANIFEST_LAYOUT) })
  .strict()
export type ProjectManifestValue = z.infer<typeof projectManifestValueSchema>

export const defaultProjectManifestValue = (): ProjectManifestValue => ({
  layout: PROJECT_MANIFEST_LAYOUT,
})

export function projectManifestPath(repoPath: string): string {
  return projectPorcelainPath(repoPath, PROJECT_FILES.manifest)
}

export function createProjectManifestDocument(
  repoPath: string,
  maxBytes = PROJECT_MANIFEST_FILE_MAX_BYTES,
): StrictJsonDocument<ProjectManifestValue>
```

`createProjectManifestDocument` calls `createStrictJsonDocument` with an
absolute path (the helper must reject a non-absolute `repoPath` by throwing,
same as DAT-001's constructor). It does not seed, migrate, or interpret
unversioned JSON as v1.

```ts
export type ProjectDataRootError =
  | { readonly code: 'project-data.manifest-corrupt'; readonly backupPath: string }
  | { readonly code: 'project-data.manifest-incompatible'; readonly version: number }
  | { readonly code: 'project-data.manifest-too-large'
      readonly byteLength: number
      readonly maxBytes: number }

export type ProjectDataRootResult =
  | { readonly ok: true }
  | { readonly ok: false; readonly error: ProjectDataRootError }

export type ProjectDataStore = {
  ensureRoot(repoPath: string): Promise<ProjectDataRootResult>
  readManifest(
    repoPath: string,
  ): Promise<ReadStrictJsonDocument<ProjectManifestValue>>
  forDomain(domainKey: ProjectDataDomainKey): ProjectDomainFiles
}
```

These `project-data.manifest-*` codes are capability discriminants only. Do
not add them to `publicErrorSchema`.

### Store (`project-data-store.ts`)

`createProjectDataStore()` returns a `ProjectDataStore`.

- `forDomain` delegates to `projectDataFilesForDomain`.
- `readManifest` is `createProjectManifestDocument(repoPath).read()`.
- `ensureRoot` is write-side only (never from domain reads):
  1. Reject a non-absolute `repoPath` by throwing.
  2. Call `ensureCompanionHidden(repoPath)` (existing `git-exclude` helper;
     no-op when `gitCommonDir` is null).
  3. `mkdir(projectPorcelainDir(repoPath), { recursive: true })`.
  4. `applyCompanionPolicy(repoPath)` (see companion-policy).
  5. `readManifest`. Map DAT-001 kinds:
     - `missing` → `write(defaultProjectManifestValue())`, then `{ ok: true }`.
     - `valid` → `{ ok: true }`.
     - `corrupt` → `{ ok: false, error: { code: 'project-data.manifest-corrupt', backupPath } }`.
     - `incompatible-version` → `{ ok: false, error: { code: 'project-data.manifest-incompatible', version } }`.
     - `too-large` → `{ ok: false, error: { code: 'project-data.manifest-too-large', byteLength, maxBytes } }`.
  6. On `corrupt` / `incompatible-version` / `too-large`, `console.error` a
     single diagnostic line (same style as `projects-recents-store`) and do
     **not** write a default, delete the file, or touch any other companion
     file.
- Do **not** import `review-watch`, `migrate-home`, or
  `migrate-active-review`.
- Memoize in-flight `ensureRoot` per `repoPath` (same shape as
  `ensureProjectCompanion` / `ensureCompanionHidden`). Failures are not
  cached. Export `resetProjectDataRootMemo()` as the test seam.

`ensureProjectDataRoot(repoPath)` is a process-wide helper that calls
`createProjectDataStore()` once and delegates to `ensureRoot`. Production
write sites use this helper so there is one memo. Tests that need isolation
call `createProjectDataStore()` plus `resetProjectDataRootMemo()`.

### Companion policy (`companion-policy.ts`)

`applyCompanionPolicy(repoPath): Promise<void>`:

- If `.porcelain/.gitignore` is absent, write `DEFAULT_PROJECT_GITIGNORE`.
- If it exists and its text does not include the line
  `/project-manifest.json`, rewrite only the managed block with
  `renderGitignore(current, parseDispositions(current))` (published-review
  default argument preserved). Channel dispositions and human lines outside
  the managed block stay as they are.
- This is not a second disposition store: it only publishes the new
  always-ignored pattern into an already-managed file.
