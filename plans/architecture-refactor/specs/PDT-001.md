- Primary exemplar: no

## Objective

Create one strict version-1 Project Data manifest that names owned companion layout/disposition policy and gives each domain one explicit per-project file adapter root.

## Why this unit exists

`net/project-channel.ts` currently performs first-read home migration, companion ignore policy, active-layout migration, and review watch registration for every domain record.

## Current behavior and evidence

The data inventory lists companion files under `<repo>/.porcelain`; `project-channel.ts`, `project/migrate-home.ts`, `project/migrate-active-review.ts`, `companion-disposition.ts`, and `git-exclude.ts` mix layout/policy/history. Home records and flat active-review paths are Decision-015 legacy/delete.

## Scope

Create `apps/daemon/src/features/project-data/{project-manifest,project-data-ports,project-data-store,companion-policy}.ts` and tests; provide construction-injected per-domain file adapter factories; update current channel callers only to use the factory boundary, without migrating each domain record's schema/behavior.

## Non-goals

Do not migrate Notes/dispositions/layers (PDT-002), rewrite Review/Board/Actions/Files record schemas, export/reset data (PDT-004), or silently import historical data.

## Target ownership and public surface

`project-manifest.json` is strict `{ version: 1, disposition: ... }` and owns companion layout/policy only, not domain data. `ProjectDataStore` creates one versioned root and exposes `forDomain(domainKey)` capability paths; domain adapters own their own strict envelopes. First target access creates intentional defaults; corrupt/unsupported manifest produces typed Project Data diagnostic and never guesses old data.

## Behavior to preserve

Preserve atomic tmp+rename, serialized writes, permissions, companion `.gitignore` disposition policy, corrupt backup/diagnostics, domain file locations, and CLI-readable companion layout where it is current product behavior.

## Legacy behavior to delete

Delete automatic reads/copies/purges of `~/.porcelain` home records and flat active-review migration from project-channel first access; delete `ensureProjectCompanion` migration side effects and no dual layout discovery remains.

## Ordered implementation

1. Define manifest/schema/default/corruption policy and adapter factory.
2. Test fresh, corrupt, unsupported version, atomic, and concurrent access in temporary projects.
3. Rewire project-channel callers through the factory without changing domain payloads.
4. Delete historical migration invocation/paths and assert old roots are never read.

## Tests

Test manifest strictness/default creation, atomic/corrupt behavior, disposition/gitignore policy, concurrent per-domain access, zero legacy-root reads, and current domain-channel regression fixtures.

## Forbidden shortcuts

Do not reuse public contracts as persistence schemas, dual-read/dual-write, infer old layouts, put domain payloads in the manifest, or add a global project store.

## Completion criteria

- [ ] Strict version-1 manifest and one factory own Project Data layout/policy.
- [ ] Historical migration/home reads are absent while real atomic/corruption resilience remains.
- [ ] Adapter/channel tests, lint, and diff check pass.

## Handoff

PDT-002 may move Notes/dispositions/layers through this Project Data root; PDT-005 later removes all remaining authorized historical state.
