# CON-014 — Bind Projects and repository Files procedures to canonical contracts

- Status: Queued
- Batch: 0 — architecture and contract foundations
- Domain: Projects / Files contract boundary
- Depends on: `CON-013`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

The ten procedures in `router/repos.ts` use their exact Projects or Files catalog input/output
schemas while preserving repository discovery, companion setup, visibility, pinning, and watches.

## Why this unit exists

`repos.ts` is a legacy source grouping containing four Projects procedures and six Files
procedures. Router-file ownership avoids a partial migration ledger and does not endorse that source
grouping as the target domain architecture.

## Current behavior and evidence

Projects: `openRepoPath`, `recentRepos`, `removeRecentRepo`, `browseDirs`. Files: `readDir`,
`hidePath`, `unhidePath`, `pinPath`, `unpinPath`, `pinnedEntries`. The file defines local `RepoInfo`
and `DirEntry` return types used by `api.ts`, performs companion/watch side effects when opening a
repo, and has local Zod inputs with no output middleware.

## Scope

Edit `apps/daemon/src/router/repos.ts`, add its focused contract test, and remove only `repos.ts`
from the temporary lint remaining-file set after all ten bindings pass.

## Non-goals

Do not relocate the mixed router, change exported daemon types, alter filesystem/Git/config stores,
change worktree inclusion defaults, warm/watch timing, paths, hidden/pinned semantics, or any other
router.

## Target ownership and public surface

For each exact name above, replace the local/missing input with
`procedureCatalog.<name>.input`, add `procedureCatalog.<name>.output`, and retain its existing public
builder, query/mutation kind, handler, and return annotation where still useful. The contract schema
is the only runtime parser; no copied adapter schema remains.

## Behavior to preserve

Preserve `recentRepos` optional/default input behavior, repository/worktree filtering, returned path
and name values, browse parent/entry shapes, ignored/hidden/pinned mutations, sorted directory
results, companion migration/watch effects, and void serialization.

Deliberately replace Zod's former unknown-key stripping with the canonical strict object inputs;
extra request fields now fail as `request.invalid`. No compatibility strip or fallback remains.

## Legacy behavior to delete

Delete all ten local router input schemas and unvalidated outputs in `repos.ts`. Remove its `zod`
import if unused and delete only `repos.ts` from lint's remaining set.

## Ordered implementation

1. Bind the four Projects procedures to their same-name catalog entries.
2. Bind the six Files procedures in the same source file.
3. Remove only imports made obsolete by those replacements; preserve exported local type surfaces.
4. Add focused tests for defaulted recent repositories, strict unknown-key rejection, a valid
   directory result, void mutations, and rejection of a deliberately malformed output.
5. Remove `repos.ts` from the lint set and prove all ten exact bindings.

## Tests

Add `apps/daemon/src/router/repos.contract.test.ts` with temporary directories and synthetic config
data only. Do not use the human's repositories or daemon channels.

## Forbidden shortcuts

Do not relocate behavior, mock production parsing, change defaults to satisfy a schema, use unknown
outputs, remove `RepoInfo`/`DirEntry` exports, or touch `router/files.ts` early.

## Completion criteria

- [ ] Four Projects and six Files procedures use exact catalog input/output middleware.
- [ ] Repository discovery, defaults, side effects, types, and filesystem behavior are unchanged.
- [ ] `repos.ts` leaves the ledger and lint proves every binding.
- [ ] Focused tests, deletion search, repository lint, full verify, and diff check pass.
- [ ] One commit lands only `CON-014`, marks recipe/catalog Landed, leaves a clean worktree, provides
      the README review packet, and finishes without pushing.

## Handoff

The remaining Files/Search router may migrate independently; the legacy source grouping is still
deleted only by its later domain relocation specs.
