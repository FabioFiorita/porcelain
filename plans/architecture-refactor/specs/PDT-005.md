# PDT-005 — Delete home and active-layout migrations after authorized clean-state path

- Status: Draft
- Batch: 4
- Domain: Project Data
- Depends on: PDT-004, PDT-002, REV-002
- Governing decisions: 009, 015
- Primary exemplar: no

## Objective

Remove historical home-to-project and flat-active-review migration code, callers, markers, tests, and Companion guidance only after strict v1 roots and authorized clean-state handling are complete.

## Why this unit exists

Current generic reads call `ensureProjectCompanion`, which can migrate/copy/purge historical records and change git visibility. Target reads must not discover or transform old layouts.

## Current behavior and evidence

- Exact legacy paths are `apps/daemon/src/project/{migrate-home,migrate-active-review}.ts` and tests, `review-store.ts` `reviewSetsPath`, `scope-store.ts` `resolveScopePath`, `fs/evidence-paths.ts` `loopEvidenceRoot`, and migrated-from-home patterns.
- `review-store.ts` invokes `ensureProjectCompanion` before reads/archive; `project-channel.ts` carries migration policy.
- Inventory requires current v1 root/authorization before migration deletion.

## Scope

- Delete exact migration modules, import/call sites, markers, old-home readers, and migration-only tests after their target record/Review paths work from clean v1 state.
- Update Companion/worktree guidance in AGT-002's explicit-only rules.

## Non-goals

- Do not delete existing user/home/project data or run a reset.
- Do not remove atomic/corruption/path-containment or visibility resilience.

## Target ownership and public surface

Every Project Data and Review adapter reads one strict v1 project path. Generic document I/O performs no migration, disposition, watcher registration, or historical discovery. Clean seed creation is explicit and owned by the new root manifest.

## Behavior to preserve

Preserve absent-document defaults, never-create-a-missing-repo safety, atomic tmp+rename, corruption backups, containment, and Review watcher behavior relocated to its owner.

## Legacy behavior to delete

Delete `migrate-home.ts`, `migrate-active-review.ts`, their tests, `ensureProjectCompanion` calls, `.migrated-from-home` handling, home evidence root readers, `reviewSetsPath` no-arg alias, and `resolveScopePath` deprecated alias only after target callers are canonical.

## Ordered implementation

1. Require PDT-004 authorization outcome and clean v1 root tests before touching migration modules.
2. Enumerate every import/caller with `rg`; replace each with strict target adapter/operation behavior.
3. Move watcher registration to Review composition and visibility policy to Project Data before deleting generic channel hooks.
4. Delete migration modules/tests/markers/home readers and stale Companion/worktree text in one bounded cutover.
5. Add `lint-project-data-cutover.mjs` checks for forbidden migration identifiers and legacy alias exports; fixture-test it.
6. Run clean v1 startup/read/write/archive tests with no historical files present.

## Tests

- Focused temporary-project clean-v1 tests prove Notes/Layers/Review/Evidence operations without a home path.
- Negative source-lint fixtures prove legacy identifiers fail.
- `pnpm test`, `pnpm lint`, and `pnpm verify` pass.

## Validation and evidence

Record zero-hit search results for each exact legacy identifier and clean-fixture operation results. Record authorization reference, not real-data content.

## Forbidden shortcuts

- Do not remove a migration test before target clean-state proof exists.
- Do not use a runtime fallback or empty default to hide an old-path caller.
- Do not delete user data.

## Completion criteria

No target read/write/archive starts migration; all exact legacy source/test/guidance identifiers are gone; clean v1 tests and full gates pass.
