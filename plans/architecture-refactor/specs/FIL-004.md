## Architecture reviewer rulings (bind the executor; supersede the tracked Draft)

1. **Dependencies.** Catalog shows `FIL-001`, `FIL-002`, `FIL-003`, `TST-001`, `RT-003` **Landed**. List dependency IDs only (no mutable status) when promoting.

2. **Generic identity/effect vocabulary (landed Board/Review only).** Reuse BRD-003 / RVC-002 shapes, extended only where Files needs multi-identity + family effects:
   - Query identity: `{ readonly domain; readonly name; …dimensions }` + builder function — **exactly five** `FilesQuery` variants in **`files-queries.ts`**; no fake sixth query.
   - Mutation / notification **effects** are `readonly FilesQueryEffect[]` (exact query **or** tree-family) owned by **`files-effects.ts`**, not bare identity arrays and not out-of-band adapter rules.
   - Mutation definition: `procedure` pinned to `procedureName`, `affectedEffects(input)`, `foreignDependencies(input)`, `requiresAuthoritativeRefetch: true`. Duplicate alone also has `affectedEffectsForResult(input, output)`.
   - Notification mappers: `filesNotificationEffects` → Files query effects; `filesNotificationForeignDependencies` → Files-owned foreign tokens (both compose helpers from `files-effects`).
   - Package subpath export only (`./files`), named symbols from `index.ts`.
   - **No** `optimistic: false` field (does not exist on landed definitions; decorative flag forbidden). Non-optimism is expressed by **omitting** any reconciliation module and never exporting apply/rollback/reconcile for Files.
   - **No** raw procedure-name invalidation strings, `QueryClient`, React, app imports, or Files-only parallel effect framework.
   - **No** mandatory adapter-only invalidation rules (deleted: `filesTreeProjectPrefix` and every “adapters must also …” prefix step).
   - **No circular imports:** queries ← effects ← mutations/notifications; interests → queries only.

3. **Path alphabet for identities is project-relative (+ `'.'` root), not wire-absolute.** All identity / effect / interest builders normalize absolute `projectPath` through **`filesProjectKey`** (daemon project root string, same as notification `projectPath` / session project): empty-message vs other-invalid via **`isFilesProjectPath`**, then trailing-slash strip matching Web `normalizeProjectRoot` (no invented dot-segment collapse). Where a path dimension exists, **project-relative** paths use FIL-003 notification alphabet: `isFilesProjectRelativePath(path)` **or** `path === '.'` for the project root listing. Content/preview **reject** `'.'` (file targets only: `isFilesProjectRelativePath`). Invalid project or relative paths throw `FilesIdentityError` (programmer error).
   - Remaining `readDir` / pin-hide / `repoScope` **wire** still uses absolute/`repoPath` (FIL-002/003 non-goal). **FIL-005/006 adapters** translate: identity `path: '.'` ↔ mobile `''` / web absolute project root; identity relative ↔ absolute UI paths; scope mutations still submit current wire shapes.
   - Session `session:watches` paths remain **host-absolute**. `createFilesInterest` joins normalized project key + relative (or returns the key for `'.'`) before calling RT-003 — root `/` + `src/a` → `/src/a`, never `//src/a`.

4. **Tree precision without inventing file-vs-dir certainty.** FIL-003 tree facts name operation targets or watched-dir ± child and do **not** encode kind. Safe expansion for a notification/mutation path `P`:
   - Always affect tree identities at `P` and at `parentFilesPath(P)` (see helpers), each with **both** `showHidden: false` and `showHidden: true`, wrapped as **exact** effects.
   - `parentFilesPath('.')` is not defined → only `'.'` trees.
   - `parentFilesPath('foo') === '.'`; `parentFilesPath('a/b') === 'a'`.
   - **No** recursive prefix invalidation of unrelated expanded subtrees via exact identities.
   - **Scope-changed / scope mutations** use one runtime-owned **`tree-family`** effect for the project (subsumes every tree identity including both root trees). Adapters must exhaustively bind `tree-family`; forgetting it is a compile/test failure in FIL-005/006.

5. **Cross-domain Search/Git.** Neither domain exposes client-runtime query identities (GIT-003 / SEA-002 still Draft; no `packages/client-runtime/src/{git,search}`). **Do not** invent Search/Git cache keys, import planned modules, or use raw procedure names in this package. Export Files-owned **foreign dependency tokens** from **`files-effects.ts`** (not query identities, not from `files-queries.ts`):

   ```ts
   export type FilesForeignDependency =
     | { readonly domain: 'git'; readonly name: 'working-tree' }
     | { readonly domain: 'search'; readonly name: 'path-index' }
     | { readonly domain: 'search'; readonly name: 'content-index' }
   ```

   Mutation definitions declare `foreignDependencies(input)` returning these tokens. Notifications declare **`filesNotificationForeignDependencies(notification)`** with the same token type (separate from Files query effects). **Conservative notification foreign recovery:** scope → path-index only; tree-changed and content-changed → working-tree + path-index + content-index. Mutation `writeText` also returns all three. FIL-005/006 map tokens to today’s `gitFlow`/`gitDiffFile`/`searchFiles`/`searchCode`/`searchText` invalidations until GIT/SEA client-runtime land; those later units rebind the **same tokens** to typed identities without changing Files. **No** `exploreFeature` token (Web-only; out of Files runtime).

6. **Interest facade is RT-003 only.** `createFilesInterest(projectPath, host)` receives `{ registerWatchInterest }` from `SessionClientRuntime` (or the same function signature). It does **not** create a second registry, socket, readiness state, or 128 cap. Cap, merge, files-before-dirs, ready-gated send, and reconnect replay stay in `createWatchInterestRegistry` / `createSessionClientRuntime`. Snapshot API is **`held()`** / **`FilesInterestHeld`** (facade-held absolutes only). **`dispose()` is terminal and idempotent.**

## Objective

Client-runtime owns exact Files query identities (`files-queries`), runtime-owned mutation/notification effects and foreign tokens (`files-effects`, including tree-family), typed Files notification→effect mapping, and a declarative Files interest facade over RT-003.

## Why this unit exists

Web `hooks/use-files.ts` and mobile `features/files/use-files.ts` each invent cache strings, mutation invalidation sets, and watch registration; effects diverge (Web ties writes to Git; mobile ties writes to Search strings; both ignore FIL-003 `paths`). Shared semantics must land before FIL-005/006 delete those paths. Every invalidation rule that both clients must share is **runtime-owned** so adapters cannot diverge on mandatory extras.

### Query identities (`files-queries.ts`)

```ts
import {
  isFilesProjectPath,
  isFilesProjectRelativePath,
} from '@porcelain/contracts/files'

/**
 * Programmer error for invalid project or identity paths.
 * Not a domain public error; never mapped to contracts error codes.
 */
export class FilesIdentityError extends Error {
  override readonly name = 'FilesIdentityError'
}

/**
 * Normalize absolute project root for identity / effect / interest dimensions.
 * 1. Empty string → throw non-empty message (distinct from other invalid input).
 * 2. Else validate with landed `isFilesProjectPath` (NUL, backslash, length ≤ 4096,
 *    must start with `/` — same rules as the wire schema).
 * 3. On pass, strip trailing `/` except root `/` itself — same trailing-slash behavior as
 *    Web `normalizeProjectRoot`. No extra dot-segment or host canonicalization here;
 *    daemon/session owns canonical host resolution.
 */
export function filesProjectKey(projectPath: string): string

export type FilesTreeQuery = {
  readonly domain: 'files'
  readonly name: 'tree'
  readonly projectPath: string // filesProjectKey result
  readonly path: string // project-relative or '.'
  readonly showHidden: boolean
}

export type FilesPinsQuery = {
  readonly domain: 'files'
  readonly name: 'pins'
  readonly projectPath: string
}

export type FilesScopeQuery = {
  readonly domain: 'files'
  readonly name: 'scope'
  readonly projectPath: string
}

export type FileContentQuery = {
  readonly domain: 'files'
  readonly name: 'content'
  readonly projectPath: string
  readonly path: string // project-relative only (not '.')
}

export type FilePreviewQuery = {
  readonly domain: 'files'
  readonly name: 'preview'
  readonly projectPath: string
  readonly path: string // project-relative only (not '.')
}

export type FilesQuery =
  | FilesTreeQuery
  | FilesPinsQuery
  | FilesScopeQuery
  | FileContentQuery
  | FilePreviewQuery

export function filesTreeQuery(
  projectPath: string,
  path: string,
  showHidden: boolean,
): FilesTreeQuery

export function filesPinsQuery(projectPath: string): FilesPinsQuery
export function filesScopeQuery(projectPath: string): FilesScopeQuery
export function fileContentQuery(projectPath: string, path: string): FileContentQuery
export function filePreviewQuery(projectPath: string, path: string): FilePreviewQuery

/** Parent of a Files identity/notification path. `'.'` has no parent → null. Bare segment → `'.'`. */
export function parentFilesPath(path: string): string | null

/**
 * Tree path keys made stale by a structural path without knowing file vs directory:
 * `[path]` plus parent when defined. Dedup preserving first-seen order.
 */
export function filesTreePathsAffectedBy(path: string): readonly string[]

export function isFilesTreeQuery(value: FilesQuery): value is FilesTreeQuery
export function isFileContentQuery(value: FilesQuery): value is FileContentQuery
export function isFilePreviewQuery(value: FilesQuery): value is FilePreviewQuery
```

**These five builders are the only Files server-state identities.** Effects live in `files-effects.ts` and wrap these identities or express tree-family — no sixth query.

#### `filesProjectKey` exact behavior

| Input | Behavior |
| --- | --- |
| `''` | throw `FilesIdentityError` message exactly: `files: project path must be non-empty` |
| fails `isFilesProjectPath` after empty check (relative, no leading `/`, NUL, backslash, length > 4096, empty-after-other-checks) | throw `FilesIdentityError` message exactly: `files: project path must be absolute` |
| `'/'` | returns `'/'` |
| `'//'` / `'///'` | `isFilesProjectPath` accepts; strip trailing slashes → `'/'` |
| `'/repo/'`, `'/repo//'` | returns `'/repo'` (strip all trailing slashes) |
| `'/repo'` | returns `'/repo'` |
| `'/a\0b'`, `'/repo\\win'`, `'repo'`, `'./repo'`, string length > 4096 | throw absolute-message (`isFilesProjectPath` false) |

Pin tests for: empty, relative, NUL, backslash, overlength, root, repeated trailing slash. Do **not** invent `.` / `..` segment collapsing beyond trailing-slash strip.

All identity builders, effect builders that take `projectPath`, and `createFilesInterest` call `filesProjectKey` once and store/use the returned key.

#### Relative path validation (builders)

| Builder | Accepted `path` | On invalid |
| --- | --- | --- |
| `filesTreeQuery` | `'.'` **or** `isFilesProjectRelativePath(path)` | `FilesIdentityError` message exactly: `files: invalid tree path` |
| `fileContentQuery` / `filePreviewQuery` | `isFilesProjectRelativePath(path)` only (not `'.'`) | `FilesIdentityError` message exactly: `files: invalid content path` |

**Deleted (do not implement):** `filesTreeProjectPrefix`. Project-wide tree invalidation is `filesTreeFamilyEffect(projectPath)` only (in `files-effects.ts`).

#### Equality / isolation

- Structural deep equality on all fields (same pattern as Board tests: `toEqual`).
- Distinct normalized `projectPath` → distinct identities (cross-project isolation).
- Distinct `path` or `showHidden` → distinct tree identities.
- Distinct `path` → distinct content/preview identities.
- Root listing identity uses `path: '.'` (never `''`).
- Builders always store `filesProjectKey(projectPath)` on the identity.

### Effects and foreign tokens (`files-effects.ts`)

```ts
import {
  type FilesQuery,
  fileContentQuery,
  filePreviewQuery,
  filesProjectKey,
  filesTreePathsAffectedBy,
  filesTreeQuery,
} from './files-queries'

/**
 * Runtime-owned invalidation effect. Not a sixth query identity.
 * Adapters must exhaustively switch on `type` (exact | tree-family).
 */
export type FilesQueryEffect =
  | { readonly type: 'exact'; readonly query: FilesQuery }
  | { readonly type: 'tree-family'; readonly projectPath: string }

/** Files-owned foreign freshness tokens — not query identities and not procedure names. */
export type FilesForeignDependency =
  | { readonly domain: 'git'; readonly name: 'working-tree' }
  | { readonly domain: 'search'; readonly name: 'path-index' }
  | { readonly domain: 'search'; readonly name: 'content-index' }

/** Stable foreign token constants (object identity + structural equality). */
export const FILES_FOREIGN_WORKING_TREE: FilesForeignDependency = {
  domain: 'git',
  name: 'working-tree',
}
export const FILES_FOREIGN_PATH_INDEX: FilesForeignDependency = {
  domain: 'search',
  name: 'path-index',
}
export const FILES_FOREIGN_CONTENT_INDEX: FilesForeignDependency = {
  domain: 'search',
  name: 'content-index',
}

export function filesExactEffect(query: FilesQuery): FilesQueryEffect
export function filesTreeFamilyEffect(projectPath: string): FilesQueryEffect

/**
 * Dedup effects: first-seen order.
 * - exact: structural equality on `query` fields
 * - tree-family: equality on normalized `projectPath`
 * tree-family does not collapse exact tree identities in the same list
 * (callers should not emit redundant root exact trees when family is present;
 * scope helpers emit family only for trees).
 */
export function dedupeFilesQueryEffects(
  effects: readonly FilesQueryEffect[],
): readonly FilesQueryEffect[]

/**
 * Dedup foreign tokens: first-seen order; equality on `{ domain, name }`.
 */
export function dedupeFilesForeignDependencies(
  deps: readonly FilesForeignDependency[],
): readonly FilesForeignDependency[]

/**
 * Exact tree effects: both showHidden variants for each path in `filesTreePathsAffectedBy`.
 * Order: listed paths, then false then true per path. Wrap each as `{ type:'exact', query }`.
 * Dedup via `dedupeFilesQueryEffects`.
 */
export function treeEffectsForStructuralPath(
  projectPath: string,
  path: string,
): readonly FilesQueryEffect[]

/**
 * Exact content + preview effects for one file path (order: content, then preview).
 */
export function contentPreviewEffects(
  projectPath: string,
  path: string,
): readonly FilesQueryEffect[]

/**
 * Destination-only tree effects for duplicate result: self path × both showHidden as exact
 * effects. Does **not** include parent (parent already covered by source structural expansion
 * when destination is a sibling; do not re-emit parent here).
 */
export function treeSelfEffects(
  projectPath: string,
  path: string,
): readonly FilesQueryEffect[]
```

Mutations and notifications **import shared effects from `files-effects.ts`** — they do not reimplement expansion or own the effect/token types. `files-effects` imports identities/path helpers from `files-queries` only; **no circular imports**.

```ts
  type CreateFileInput,
  type CreateFolderInput,
  type DuplicatePathInput,
  type DuplicatePathOutput,
  type HidePathInput,
  type PinPathInput,
  type RenamePathInput,
  type TrashPathInput,
  type UnhidePathInput,
  type UnpinPathInput,
  type WriteTextFileInput,
  filesProcedures,
} from '@porcelain/contracts/files'
import type { FilesForeignDependency, FilesQueryEffect } from './files-effects'
import {
  FILES_FOREIGN_CONTENT_INDEX,
  FILES_FOREIGN_PATH_INDEX,
  FILES_FOREIGN_WORKING_TREE,
  contentPreviewEffects,
  dedupeFilesForeignDependencies,
  dedupeFilesQueryEffects,
  filesExactEffect,
  filesTreeFamilyEffect,
  treeEffectsForStructuralPath,
  treeSelfEffects,
} from './files-effects'
import {
  filesPinsQuery,
  filesProjectKey,
  filesScopeQuery,
} from './files-queries'

type FilesMutationProcedureName =
  | 'hidePath'
  | 'unhidePath'
  | 'pinPath'
  | 'unpinPath'
  | 'writeTextFile'
  | 'createFile'
  | 'createFolder'
  | 'renamePath'
  | 'duplicatePath'
  | 'trashPath'

/**
 * Standard Files mutation: procedure object is pinned to procedureName.
 * Effects are complete from input alone (void-output procedures).
 */
export type FilesMutationDefinition<
  TName extends FilesMutationProcedureName,
  TInput,
> = {
  readonly procedure: (typeof filesProcedures)[TName]
  readonly procedureName: TName
  readonly affectedEffects: (input: TInput) => readonly FilesQueryEffect[]
  readonly foreignDependencies: (input: TInput) => readonly FilesForeignDependency[]
  readonly requiresAuthoritativeRefetch: true
}

/**
 * Result-dependent mutation. Only `duplicate` uses this.
 * `affectedEffects(input)` is the source-only base set.
 * `affectedEffectsForResult(input, output)` is the complete post-success set (base + destination).
 * `output` is required — no optional parameter and no incomplete success fallback.
 */
export type FilesResultMutationDefinition<
  TName extends FilesMutationProcedureName,
  TInput,
  TOutput,
> = FilesMutationDefinition<TName, TInput> & {
  readonly affectedEffectsForResult: (
    input: TInput,
    output: TOutput,
  ) => readonly FilesQueryEffect[]
}
```

#### Adapter success-only call order (bind FIL-005/006)

1. Invoke the bound procedure with wire input.
2. On **failure** / throw: **no** effect invalidation from these helpers.
3. On **success** for non-duplicate keys: invalidate `definition.affectedEffects(input)` (exhaustive effect switch) and map `foreignDependencies(input)`.
4. On **success** for `duplicate`: invalidate **`definition.affectedEffectsForResult(input, output)` only** — never settle on base `affectedEffects(input)` alone. `output` is the successful relative destination string from the procedure. Base `affectedEffects` exists for composition/tests and as the documented source subset inside `affectedEffectsForResult`; adapters do not call it for settle.

Other-project isolation: effects only emit identities/family with `filesProjectKey(notification.projectPath)`. Adapters compare active project before invalidate.

#### Absolute conversion (exact)

```ts
function toAbsoluteInterestPath(projectKey: string, relative: string): string {
  if (relative === '.') return projectKey
  // projectKey is '/' or has no trailing slash — never produce '//'
  if (projectKey === '/') return `/${relative}`
  return `${projectKey}/${relative}`
}
```

No `node:path`. `projectKey` is always `filesProjectKey(projectPath)` from construction.

#### Semantics

| Action | Behavior |
| --- | --- |
| Construction | `projectKey = filesProjectKey(projectPath)` (throws `FilesIdentityError` if invalid). |
| `addFile(rel)` | If disposed → `null`, zero host calls. If `!isFilesProjectRelativePath(rel)` → `null`, zero host calls. Else `abs = toAbsolute…`; `reg = host.registerWatchInterest({ files: [abs], dirs: [] })`; track handle; `release` calls `reg.release()` **once** (second call no-ops). |
| `addDirectory(rel)` | If disposed → `null`, zero host calls. If `rel !== '.' && !isFilesProjectRelativePath(rel)` → `null`. Else register `{ files: [], dirs: [abs] }` same handle pattern. Root `'.'` → abs `projectKey`. |
| Overlapping adds | Two `addFile` same path → two RT-003 registrations; RT-003 ref-count + dedup on wire. Facade does not merge registrations. |
| `held()` | First-seen unique absolute paths among **currently unreleased** handles only (not RT-003 global set). Two live registrations of the same abs still appear once in the snapshot. |
| Cap 128 | **Not** enforced here; RT-003 `boundWatchInterests` drops overflow. Facade never reads/writes cap. |
| Ready / reconnect | Host runtime sends watches after ready and re-sends full desired set; facade does not replay. |
| Project change | Adapter disposes this facade and constructs a new one for the new `projectPath`. Facade does not call `selectProject`. |
| `dispose()` | Terminal and idempotent: release all handles; further `addFile`/`addDirectory` return `null` with zero host calls. |

Draft’s `remove` is **not** a separate path-keyed API: release is on the handle returned by add (matches RT-003 `WatchInterestRegistration`).
