## Objective

Client-runtime owns exact Files identities, non-optimistic write effects, typed file-change effects, and declarative file/directory interest semantics.

## Why this unit exists

Web `use-files.ts` and mobile `features/files/use-files.ts` each select cache strings, mutation invalidations, and raw watch sets; their effects diverge around content/search/Git freshness.

## Current behavior and evidence

- Current reads are `readDir`, `pinnedEntries`, `repoScope`, `readFile`, and `previewHtml`; writes are hide/unhide/pin/unpin/write/create/folder/rename/duplicate/trash.
- Web sends `watch:files` from open tabs and `watch:dirs` from expanded-tree state; mobile calls `useDaemonWatch` per directory/file.
- FIL-003 publishes `files.scope-changed`, `files.tree-changed`, and `files.content-changed`; RT-003 owns reconnect and bounded desired-interest state.

## Scope

Add `packages/client-runtime/src/files/{files-queries,files-mutations,files-notifications,files-interests,index}.ts`, colocated tests, and `./files` export.

## Non-goals

Do not implement filesystem operations, path safety, React hooks, search identities, Git identities, viewer UI, or a socket transport.

## Target ownership and public surface

- Export `filesTreeQuery(projectPath,path,showHidden)`, `filesPinsQuery(projectPath)`, `filesScopeQuery(projectPath)`, `fileContentQuery(projectPath,path)`, and `filePreviewQuery(projectPath,path)`; these are the only Files identities.
- Export `filesMutations` for `hide`, `unhide`, `pin`, `unpin`, `writeText`, `createFile`, `createFolder`, `rename`, `duplicate`, and `trash`. All set `optimistic: false` and `requiresAuthoritativeRefetch: true`.
- Scope mutations affect tree/pins/scope; structural writes affect tree/pins plus the exact affected content/preview identities; text write affects its content/preview identity. Cross-domain Git/Search effects are declared as typed dependency tokens for their owning later adapters, never raw names.
- Export `filesNotificationEffects`: scope changes affect scope/tree/pins; tree changes affect tree/pins; content changes affect the named content/preview identities. Export `createFilesInterest(projectPath)` with `addFile`, `addDirectory`, `remove`, and `desired`; it delegates merging/caps/ready gating to RT-003.

## Behavior to preserve

Daemon filesystem truth is never optimistic; file contents and directories refresh after agent/external changes; HTML preview is invalidated with its source; recovery requests authoritative reads rather than applying event payloads.

## Legacy behavior to delete

Delete no app hooks or raw listeners in this runtime-only unit; FIL-005 and FIL-006 own those deletions.

## Ordered implementation

1. Verify FIL-001 through FIL-003, RT-003 and TST-001 expose canonical contracts, change facts and interest runtime.
2. Implement identities and all non-optimistic effects from the stated table.
3. Implement notification mapping and interest facade without application imports; add the narrow package export.

## Tests

- Identity tests distinguish project/path/show-hidden dimensions.
- Mutation tests prove each exact affected identity, no optimistic data patch, and authoritative refetch requirement.
- Notification/interest tests prove scoped paths, other-project no-op, content/preview coupling, dedup/removal/cap and reconnect desired-set replay using RT-003 fakes.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../../packages/client-runtime/src/files`.
- Run `pnpm lint`.
- Run `rg -n "react|@trpc|QueryClient|zustand|AppEvent|watch:|readDir'|readDir\"" packages/client-runtime/src/files`; it returns no result.

## Forbidden shortcuts

Do not optimistic-paint host writes, use procedure-name invalidation strings, embed a socket, include Search/Git cache keys, or widen a path interest.

- [ ] Direct tests prove exact effects and recovery-interest behavior.
- [ ] Lint and the framework/legacy search pass; the unit is committed.
