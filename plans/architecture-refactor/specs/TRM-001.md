## Objective

Replace the remaining horizontal terminal frame vocabulary with strict Terminal stream commands/events carrying session epoch, sequence, correlation, and declared public failures.

## Why this unit exists

RT-001 preserved terminal's separate stream but only established framing; current `ws-protocol.ts` and `net/session.ts` still mix create/attach/write replies with old transport naming and no explicit recovery vocabulary.

## Current behavior and evidence

The authenticated session currently accepts `terminal:create`, `terminal:attach`, `terminal:detach`,
`terminal:write`, `terminal:resize`, `terminal:kill`, `terminal:paste-image`, and
`terminal:paste-file` through `apps/daemon/src/session/session-gateway.ts`; `live-session.ts`
still dispatches them to the legacy terminal manager. `terminal-manager.ts` fans out
`terminal:data` and `terminal:exit`, keeps a 64 KiB byte-capped scrollback and reattachment, and
`router/terminal.ts` serves roster/rename. Existing resource limits are 64 sessions, 10-minute
exited retention, 12-hour detached idle retention, 4 MiB decoded images, 8 MiB decoded files, and
64 Ki UTF-16-code-unit writes. `packages/client-runtime/src/session/client-runtime.ts`,
`apps/web/src/lib/daemon.ts`, and `apps/mobile/src/lib/daemon/terminal.ts` still consume the
RT-001 `reqId`/uncorrelated stream shapes and are intentionally TRM-002/TRM-003 consumers, not
TRM-001 edit targets.

## Scope

Refine the contract-only boundary in
`packages/contracts/src/terminal/{terminal.contract,terminal.errors,terminal.fixtures,terminal.procedures,terminal.stream}.ts`,
the terminal/error exports and exhaustive fixtures/tests under
`packages/contracts/src/{errors,terminal}`, and the package root export. Define the exact
command/event/correlation values required by TRM-002/003; do not alter daemon, client-runtime,
Web, mobile, renderer, PTY, or transport runtime code.

## Non-goals

Do not spawn PTYs, alter session/recovery behavior, wire Web/RN transports, change Ghostty/native views, or migrate roster/rename implementation.

## Target ownership and public surface

The exact client commands are strict `terminal:create`, `terminal:attach`, `terminal:detach`,
`terminal:write`, `terminal:resize`, `terminal:kill`, `terminal:paste-image`, and
`terminal:paste-file`; every command carries a non-empty `reqId`. The existing RT-001 wire spelling
`reqId` is deliberate for this contract-only unit and is not renamed to `requestId`; the common
`PorcelainError.requestId` remains the UUID diagnostics/correlation field for public failures.

The daemon replies/events are strict `terminal:created`, `terminal:attached`, `terminal:data`,
`terminal:exit`, `terminal:image-pasted`, `terminal:file-pasted`, and `terminal:error`. A successful
create has a non-empty id; capacity is a typed `terminal.capacity` error rather than the legacy
empty-id sentinel. An attach has bounded scrollback, status, and the attachment's `{ epoch,
sequence }` baseline; unknown ids use `terminal.not-found` rather than `found: false`. Data and exit
events carry non-empty `epoch` and nonnegative integer `sequence`, monotonic within one terminal
attachment. Paste successes retain the current bounded result/path shape; expected stream failures
are the strict common `PorcelainError` union narrowed to the five Terminal members. The
`terminalSessions`/`renameTerminal` tRPC records remain unchanged and continue to declare no
intentional errors in this unit.

Add exactly these no-details Terminal public errors to the composed `PorcelainError` union:

| Code | Category | Retryable |
| --- | --- | --- |
| `terminal.not-found` | `not-found` | no |
| `terminal.exited` | `conflict` | no |
| `terminal.capacity` | `unavailable` | yes |
| `terminal.invalid-size` | `invalid-request` | no |
| `terminal.paste-unavailable` | `unavailable` | yes |

## Behavior to preserve

Preserve byte data framing, terminal output ordering, attach scrollback replay, sessions surviving disconnect, roster fields, current size defaults, and all existing resource caps.

## Legacy behavior to delete

No runtime deletion occurs here. The old horizontal `ws-protocol.ts` was already deleted by RT-005;
the remaining uncorrelated consumers and local frame unions are temporary until TRM-002/TRM-003
switch them. This unit does not add aliases, optional epoch/sequence fallbacks, empty-id/found
sentinels, or a second error vocabulary.

## Ordered implementation

1. Add the five Terminal public-error members, compose/export them, and extend exhaustive public
   error fixtures/tests without changing the existing system/Git/Files/Review members.
2. Refine the Terminal stream schemas and fixtures: require `reqId` on all commands, require
   positive ids and bounded scrollback, add attachment/data/exit epoch+sequence, add the strict
   correlated `terminal:error` server frame, and remove the empty-id/`found` compatibility shapes.
3. Add tests for every command/event discriminator, all required correlation and epoch/sequence
   fields, ordering metadata, caps, strict public errors, malformed/unknown fields, and the
   unchanged roster/rename procedure records.
4. Leave all old runtime imports intact until TRM-002's atomic stream switch; this intentional
   contract/runtime handoff is the only intermediate type-surface change allowed by the recipe.

## Tests

Test every command/event discriminator, `reqId` correlation, epoch/sequence constraints,
scrollback/data shape, all current caps, malformed input, public error payloads, and the exact
absence of the old empty-id/`found` compatibility shapes. Use synthetic fixtures only; do not
instantiate a PTY, WebSocket, daemon, client runtime, or UI.

## Forbidden shortcuts

Do not encode terminal output as `session:change`, omit sequence/correlation, use `z.unknown`,
reintroduce an empty-id/`found` refusal sentinel, define a second non-Porcelain error envelope,
rename `reqId` in this contract-only unit, or change runtime transport early.
