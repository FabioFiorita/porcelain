# E2E-001 — Name and reduce the critical assembled wiring suite

- Status: Landed
- Batch: 7
- Domain: Cross-process end-to-end proof
- Depends on: SUP-002, SUP-003, TST-002
- Governing decisions: [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [014](../decisions/014-make-the-delivery-loop-always-on.md)
- Primary exemplar: yes

## Objective

Make the browser project run a named, small `critical-wiring.spec.ts` suite containing only assembled daemon, browser transport, watcher, CLI, Terminal-stream, and protocol-handshake risks, while every assertion removed from the twelve broad specs has an assertion-level ledger disposition and a passing lower-boundary owner.

## Why this unit exists

Decision 011 makes E2E the final wiring layer rather than the business-regression backbone. The current twelve browser specs mix assembled transport with ordinary UI branches, domain behavior, visual geometry, and native Electron proof, so the final launch gate cannot state what it proves.

The helper's `seedState()` currently writes `userData/config.json`, but `apps/daemon/src/server.ts` calls `initProjectsRecentsDir()` and `apps/daemon/src/features/projects/projects-recents-store.ts` reads the strict-v1 `projects-recents.json` envelope. The current browser baseline therefore lands on the Welcome surface instead of restoring the fixture repo; the helper must seed the current owner file.

## Scope

- Add `apps/desktop/e2e/critical-wiring.spec.ts` with exactly these browser tests:
  1. authenticated daemon-served startup restores the seeded repo and renders the dirty-file count;
  2. an authenticated raw `/session` connection receives the exact `session:mismatch` / `protocol.update-required` frame for `PROTOCOL_VERSION + 1` and closes;
  3. an open file refreshes after an external fixture-disk write;
  4. a built CLI `review set` write appears in the already-running browser Review surface through the companion watcher;
  5. one real Terminal flow creates a PTY, writes data, unmounts/remounts to detach and attach, emits more than 64 KiB, reloads the browser to force session reconnect, and proves the tail sentinel survives the daemon's 64-KiB attach replay cap.
- Add `apps/desktop/e2e/critical-wiring.md` with one row for every assertion in the twelve current specs. Each row must contain a stable ID, source file and line, exact assertion or assertion group, protected risk, disposition (`retained-critical`, `relocated`, `visual-lane`, `native-lane`, or `deleted-no-unique-risk`), exact destination test/path, deletion commit, and the focused command/result that proves a relocated assertion.
- Update `apps/desktop/e2e/helpers/app.ts:seedState()` to write the strict-v1 `projects-recents.json` envelope expected by `createProjectsRecentsStore`; keep all fixture paths under `tmpdir()` and keep the existing per-test daemon/token isolation.
- Move the Electron-only native clipboard/selection/drop test from `terminal.spec.ts` to `apps/desktop/e2e/terminal-native.spec.ts`; leave it out of the browser critical command while retaining the Mac-local native command.
- Move the sidebar clipping geometry test from `sidebar-frame.spec.ts` into the visual lane in `apps/desktop/e2e/visual.spec.ts`; retain all committed visual snapshot tests and `marketing.shots.ts` unchanged in purpose.
- Remove the obsolete broad functional specs after their ledger rows point to passing lower-boundary tests: `smoke.spec.ts`, `glance.spec.ts`, `theme.spec.ts`, `shortcuts.spec.ts`, `live-refresh.spec.ts`, `review-publish.spec.ts`, `companion-data.spec.ts`, `evidence.spec.ts`, `share.spec.ts`, and `terminal.spec.ts`.
- Change `apps/desktop/package.json` browser scripts so `test:e2e` and `test:e2e:prebuilt` run `critical-wiring.spec.ts`; retain the native scripts for the Electron project and retain `visual.spec.ts` for explicit visual runs.
- Add only the focused lower-boundary cases named by the completed ledger when an existing test does not already prove the removed assertion. The permitted lower-boundary files are `apps/web/src/components/shell/glance-home.test.tsx`, `apps/web/src/components/git/changes-list.test.tsx`, `apps/web/src/components/shell/general-section.test.tsx`, `apps/web/src/lib/keyboard.test.ts`, `apps/web/src/lib/theme.test.ts`, `apps/web/src/features/files/files-queries.test.tsx`, `apps/web/src/features/review/{active-review,evidence-panel,evidence-gallery,reading-surface}.test.tsx`, `apps/web/src/features/project-data/project-data-queries.test.tsx`, `apps/web/src/features/actions/action-run.test.tsx`, `apps/cli/src/{cli,evidence-file}.test.ts`, and the already-named Terminal/packaging tests. Do not add a second server mock or a second transport.

## Non-goals

- Do not change product behavior, daemon protocol, Terminal caps, watcher semantics, pairing, remote-daemon configuration, `shellRouter`, or `shell-api.ts`.
- Do not delete an assertion by spec/category name without a ledger row and a passing destination proof.
- Do not move visual snapshots into functional wiring, regenerate committed baselines, or run the Electron project on Linux.
- Do not use the production daemon, user projects, `~/.porcelain`, or a persistent shared fixture.
- Do not make E2E prove contract validation, operation branches, component layout, evidence sanitization, Git disposition, or ordinary shortcut behavior already owned below.

## Target ownership and public surface

- `critical-wiring.spec.ts` is the only normal browser functional E2E entrypoint and runs through `apps/desktop/package.json:test:e2e` against the built daemon-served renderer.
- The startup test owns only assembled static serving, browser authentication, tRPC project restoration, and the fixture's visible dirty-file fact.
- The mismatch test owns only the real authenticated WebSocket handshake response; exact frame shape is the contract/daemon test responsibility.
- The watcher test owns only external filesystem write → daemon watch → browser refresh.
- The CLI test owns only built CLI process → repo companion file → daemon watcher → already-open browser observation.
- The Terminal test owns only process-boundary create/write/attach/detach/reconnect and replayed tail data; stream ordering, request correlation, caps, and UI rendering remain in their named lower tests.
- `terminal-native.spec.ts` owns only Electron clipboard/selection/drop transport; it is run by `test:e2e:native*` on macOS.
- `visual.spec.ts` owns screenshot/layout evidence, including the sidebar clipping invariant; it is not part of the functional critical command.

## Behavior to preserve

- Browser tests use clean temporary fixture repos and isolated daemon/user-data/token state; no test reads or writes a human checkout.
- The browser project drives the same built renderer served by the daemon and uses the real HTTP/tRPC and `/session` WebSocket paths.
- Watch delivery remains best-effort and recovery remains query-authoritative; the test waits for observable file content, not a synthetic event.
- Terminal PTYs remain daemon-owned across socket loss; attach replay precedes live data, and the newest scrollback stays bounded by the existing 64-KiB cap.
- Protocol mismatch returns `session:mismatch` with `code: 'protocol.update-required'`, `expected: PROTOCOL_VERSION`, and `received: PROTOCOL_VERSION + 1`.
- Desktop native proof stays Mac-local and SUP-003's one-daemon/address-book ruling remains unchanged.

## Legacy behavior to delete

- Delete the broad functional assertions named in the ledger after each relocated row has a passing lower-boundary result.
- Delete the old duplicate CLI evidence journey and ordinary settings/shortcut/file-operation branches from functional E2E; retain their lower-boundary tests and retain visual/native lanes where the ledger says so.
- Delete the obsolete `config.json` recents seed from the E2E helper; the current strict-v1 `projects-recents.json` seed becomes the only fixture restore path.
