# E2E-001 — Name and reduce the critical assembled wiring suite

- Status: Draft
- Batch: 7
- Domain: Cross-process end-to-end proof
- Depends on: SUP-002, SUP-003, TST-002
- Governing decisions: 009, 011, 014
- Primary exemplar: yes

## Objective

Turn the broad browser suite into a named, small critical-wiring suite. Keep only risks that require assembled daemon, browser transport, filesystem/process, reconnect, Terminal, or packaging wiring; relocate ordinary behavior to the lowest complete boundary.

## Why this unit exists

Current E2E has 12 specs spanning smoke, UI branches, watcher/CLI flows, terminal, and visual proof. Decision 011 assigns E2E only final assembled risks; it must not become the first or sole proof of domain behavior.

## Current behavior and evidence

- Current groups are `apps/desktop/e2e/{smoke,glance,sidebar-frame,theme,shortcuts,live-refresh,review-publish,companion-data,evidence,share,terminal,visual}.spec.ts`.
- Browser project exercises the daemon-served built renderer; Electron is macOS-local native proof.
- The test inventory requires named current test, lowest owner, and explicit removal/relocation for every E2E assertion.

## Scope

- Create `apps/desktop/e2e/critical-wiring.spec.ts` and a per-assertion relocation ledger at `apps/desktop/e2e/critical-wiring.md`.
- Move non-wiring assertions into contract, operation, adapter, client-runtime, Web/mobile feature, or visual tests before deleting their E2E assertions.

## Non-goals

- Do not delete a current E2E spec before its exact assertion has a passing lower-boundary replacement.
- Do not use E2E to test a domain operation branch, contract validation, or component layout already owned below.

## Target ownership and public surface

The critical suite contains exactly: daemon-served browser startup/auth transport; protocol mismatch/update-required when REM-004 exists; Files watcher refresh/recovery; CLI companion write reflected through watcher; Terminal create/attach/data/detach/reconnect with 64KB scrollback; and Desktop packaging/one-daemon evidence supplied by SUP-003. Visual snapshots remain a separate visual lane.

## Behavior to preserve

Preserve browser-project execution against a dev daemon and clean fixtures; retain Terminal's real PTY/browser stream, watcher/reconnect failures, and cross-process CLI notification proof.

## Legacy behavior to delete

Delete redundant UI branch assertions from old E2E specs only after the ledger names their replacement test/path. Delete no resilience case and no visual snapshot merely because it is not functional E2E.

## Ordered implementation

1. List every assertion in the twelve current specs in `critical-wiring.md` with source line, risk, lowest complete owner, destination test, and deletion gate.
2. Create `critical-wiring.spec.ts` with only the exact target suite and fixture helpers using clean temporary daemon/project data.
3. For each ordinary assertion, first add/confirm its lower-boundary test, record command/result, then remove the E2E assertion and update its ledger row to removed.
4. Keep `terminal.spec.ts` only until all named Terminal wiring cases are transferred; then delete it in the same change that proves `critical-wiring.spec.ts` covers them.
5. Keep `visual.spec.ts` and `marketing.shots.ts` separate; label their screenshots visual evidence, not functional coverage.
6. Configure CI/main to run the named critical browser suite; retain Electron-native tests macOS-local and out of the normal CI lane.

## Tests

- `pnpm --dir apps/desktop test:e2e -- --project=browser apps/desktop/e2e/critical-wiring.spec.ts` passes from clean fixtures.
- Each ledger relocation runs its named lower-boundary test.
- `pnpm verify` and E2E typecheck pass.

## Validation and evidence

Attach the completed ledger, browser trace/screenshots for each retained assembled risk, and commands/results for every relocated assertion. Browser proof always targets dev daemon-served client.

## Forbidden shortcuts

- Do not delete a test by category name without an assertion-level replacement.
- Do not use production daemon, user projects, or a shared persistent fixture.
- Do not fold visual approval into functional assertions.

## Completion criteria

Every old E2E assertion has a ledger disposition, critical-wiring contains only the exact assembled risks, lower-boundary replacements pass, and named browser/verify gates pass.

## Handoff

LCH-003 consumes this named suite as launch evidence. Domain specs update the ledger whenever they relocate a test.
