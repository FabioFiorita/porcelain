## Architecture reviewer rulings

These bind the executor and supersede every conflicting sentence in the tracked
Draft. They are decisions already made; the executor does not reopen them.

1. **Lifecycle is two wire mutations, not three.** `archiveReview` is today's
   `clearFeatureReview` (archive the active review locally, clear the active
   slots). `publishReview` keeps its name and its semantics: archive, record the
   published review, and force-stage it in git — the deliberate no-auto-stage
   exception, preserved. `publishCost` (query) replaces `reviewPublishCost` as
   the pre-publish cost preview. There is **no** wire `completeReview`; that name
   stays an operation-layer concept only. This is 1:1 with REV-002's
   `createArchiveReview` / `createPublishReview` operations.

2. **Evidence is one aggregate plus on-demand bodies.** `reviewEvidence` (query)
   returns checks (today's `loopEvidence` payload), Results document
   **descriptors**, Assets **descriptors**, and explicit unavailable states —
   descriptors only, never raw filesystem paths and never inline bodies. Two body
   fetches exist: `reviewEvidenceDoc` (one Results document body selected by
   descriptor — new, mirroring the asset pattern) and `reviewEvidenceAsset`
   (unchanged, including its rationale: a procedure and not an HTTP route, so
   user files never transit the unauthenticated static server). `clearEvidence`
   replaces `clearLoopEvidence`. `reviewEvidenceDocs` and `reviewEvidenceAssets`
   fold into the aggregate. `loopEvidenceHtml` (the legacy root `index.html` /
   `hasReport` era) is **deleted at REV-009 with no target successor**.

3. **Reviewed marks collapse to one total mutation.** The target surface is
   `setReviewed` (mutation, carrying the desired boolean) and `reviewedPaths`
   (query). `markReviewed` and `unmarkReviewed` have no target names; they die at
   REV-009 and every client calls `setReviewed`. The target input carries a
   `paths` array so the existing bulk "mark all / unmark all" write stays one
   atomic call: `{ repoPath, paths, reviewed }` sets exactly those paths to the
   stated state and is idempotent.

4. **Target models get their own temporary file.**
   `packages/contracts/src/review/review.contract.ts` is 371 lines against the
   450-line ceiling, so the target models cannot fit in it. This unit is
   authorized to add `packages/contracts/src/review/review.target-contract.ts`.
   **REV-009 owns the deletion of both `review.target-contract.ts` and
   `review.target-procedures.ts` atomically**, folding their surviving names into
   `review.contract.ts` / `review.procedures.ts` in the same cutover commit.

5. **Reuse the existing notification file.**
   `packages/contracts/src/review/review.notifications.ts` already exists and
   already carries `review.changed`. RVC-001 forbids a second Review
   notification kind. This unit adds **no** kind, **no** field, and **no** file
   there; the only typed target notification fact it adds is the staleness map
   exported from `review.target-procedures.ts` (ruling 6). Do not write "add
   `review.notifications.ts`" into any commit message or packet.

6. **Errors are copied, not invented.** Each surviving target procedure declares
   exactly the error list its active twin declares today: the six Review-comment
   procedures keep RVC-001's lists; every other target entry declares
   `errors: []`. New public error codes belong to REV-002 / REV-004 when those
   units land the operations that can fail.

7. **Nothing activates here.** `packages/contracts/src/procedure-catalog.ts`,
   `review.procedures.ts`, `review.contract.ts`,
   `packages/contracts/src/review/index.ts`, and every daemon router stay
   **byte-identical**. The target files are imported only by their own tests
   until REV-009.

## Objective

Review owns one exhaustive, tested, strictly typed target-v1 contract and
23-procedure catalog — covering active review, archive, reading, Intent,
Evidence, reviewed marks, inbox, comments, and typed staleness — that no runtime
caller can reach, while the live 113-name catalog and every router stay unchanged.

## Why this unit exists

Review shapes live today in daemon store/router types, Feature-era wire names,
and per-client mirrors, so no client can validate one canonical public
vocabulary. REV-002 through REV-008 need a settled target surface to implement
against, and REV-009 needs an exact, reviewed inventory to cut over to in one
commit. Writing that inventory while the current wire still serves installed
clients is the only way to get both.

### `review.target-contract.ts`

Every export is prefixed `target` so nothing collides with the live
`review.contract.ts` names while both files exist. The file is **not** exported
from `packages/contracts/src/review/index.ts`. Zod objects are `.strict()`;
unions are discriminated. Reuse `diffHunkSchema` / `fileStatusSchema` from
`../git` exactly as `review.contract.ts` does. Caps are the current runtime
caps, restated as named constants in this file (12 documents, 2 MiB per
document, 60 assets, 8 MiB per asset, 32 checks, 120-char check label, 400-char
check detail, 4096-char thesis, 200-char section title, 32 KiB section prose,
256 KiB section diagram, 512 KiB section HTML).

Required exports:

```ts
// Reading primitives
targetFileSourceSchema          // 'changed' | 'context' | 'shipped'
targetSliceRangeSchema          // { startLine, lines, gapBefore }
targetReadingFileSchema         // path, source, note?, additions?, deletions?, status?, hunks?, ranges?, truncated?, whole?
targetReadingGroupSchema        // { layer, files }
targetReviewSectionSchema       // { title, prose, diagram?, html?, htmlHeight?, files }

// Active review (was featureView)
targetActiveReviewSchema        // { name, fromAgent, thesis?, sections: outline[], groups }
targetActiveReviewOutputSchema  // targetActiveReviewSchema.nullable()

// Reading (was featureReading, without the scene canvas and the `medium` marker)
targetReviewReadingEvidenceSchema // { title, updatedAt, checks }
targetReviewReadingSchema         // { name, thesis?, sections, groups, evidence: nullable }
targetReviewReadingOutputSchema   // targetReviewReadingSchema.nullable()

// Documents (Intent and Evidence Results share the primitive)
targetReviewDocSchema           // discriminated on medium: 'markdown' | 'html', { file, label, body }
targetReviewIntentOutputSchema  // array, max 12

// Evidence
targetEvidenceCheckSchema       // { label, status: 'pass'|'fail'|'skip', detail? }
```

Exact rules that leave no judgment:

- **Descriptors carry no path and no body.** `targetEvidenceDocDescriptorSchema`
  is `{ file, label, medium, bytes, state: 'available' }` or
  `{ file, label, medium, bytes, state: 'unavailable', reason: 'too-large', maxBytes }`,
  discriminated on `state`. `targetEvidenceAssetDescriptorSchema` is
  `{ file, label, kind: 'image', mime, bytes, state: 'available' }` or the same
  object with `state: 'unavailable', reason: 'too-large', maxBytes`. `file` is a
  plain file name (`min(1)`, no `/`, no `\`, no leading `.`) — the same
  containment rule `evidence-assets-list.ts` enforces today. No `dir`, no
  absolute path, and no `body`/`dataUrl` field appears on any descriptor.
- **`targetReviewEvidenceSchema` has no `medium`, no `hasReport`, no `dir`, and
  no HTML body.** A pack exists when any of checks/results/assets is non-empty;
  the output is `null` when there is no pack at all.
- **`targetReviewReadingSchema` has no `canvas`** and its `evidence` member has
  no `medium`.
- **`targetActiveReviewSchema` keeps `fromAgent`** — the empty-versus-no-active
  distinction the renderer's "No review yet" state depends on stays expressible
  (`null` = no active review; an object with empty `groups` = an empty one).
- `targetReviewDocSchema` keeps its `medium` discriminator; that field is not the
  legacy marker REV-009 deletes.
