# REV-001 — Define canonical active, archive, reading, intent, reviewed, and inbox contracts

- Status: Draft
- Batch: 5
- Domain: Review
- Depends on: CON-021, ERR-001, PDT-001
- Governing decisions: 003, 004, 005, 006, 015
- Primary exemplar: yes

## Objective

Prepare the strict target-v1 Review catalog for active/archived Review, Intent, Execution reading, reviewed marks, Review inbox, Results/Assets Evidence, public failures, and notifications without activating a second runtime wire.

## Why this unit exists

Review shapes currently live in daemon stores/router types, mobile local descriptors, Web daemon-derived hooks, and feature-era names; clients cannot validate one canonical public vocabulary.

## Current behavior and evidence

- Current sources include `review/review-set.ts`, `stores/{review-store,reviewed-store,evidence-store,comment-store}.ts`, `router/review.ts`, and `packages/contracts/src/router.ts` tombstone.
- Existing public procedures include `featureView`, `featureReading`, `clearFeatureReview`, `reviewIntent`, `reviewEvidenceDocs`, comments, reviewed paths, and review inbox behavior hidden in Git.
- Decision 015 requires canonical Review names and no Feature alias.

## Scope

- Extend the mechanically complete Review models created by `CON-007` in `packages/contracts/src/review/review.contract.ts`.
- Add the explicitly temporary, inactive `packages/contracts/src/review/review.target-procedures.ts` and the target `review.notifications.ts`.
- Define exact target-v1 procedure/error/notification inventory before moving daemon/client code; `REV-009` must replace the current catalog with this catalog and delete the temporary filename atomically.

## Non-goals

- Do not implement stores/operations/UI, accept old Feature names, or retain deprecated Evidence fields.
- Do not make contracts import daemon persistence or app models.

## Target ownership and public surface

Contract public names are `activeReview`, `archivedReviews`, `reviewReading`, `reviewIntent`, `reviewedPaths`, `reviewInbox`, `reviewEvidence`, `completeReview`, `archiveReview`, and verb-object procedures. `ReviewReading` contains Intent/Execution/Evidence models; Evidence exposes checks, Results descriptors, Assets descriptors, and explicit unavailable states, never raw paths.

## Behavior to preserve

Preserve containment-safe anchors, empty/no-active Review distinction, reviewed reconciliation semantics, checks-only Evidence packs, explicit failures, and typed notification facts.

## Legacy behavior to delete

Define Feature names, `reviewEvidenceDocs`, `medium`, `hasReport`, scene canvas, and root-index wire fields as deleted only in REV-009's atomic client/CLI/server cutover; expose none from target contracts.

## Ordered implementation

1. Inventory every router procedure/current client type and map it to one target contract name or a non-Review owner.
2. Extend `review.contract.ts` with strict target models without copying the current models under aliases.
3. Define the inactive target procedure catalog in `review.target-procedures.ts` and typed facts in `review.notifications.ts`.
4. Add contract fixture tests for valid/invalid wire values, containment-invalid anchors, Evidence unavailable state, and exhaustive target catalog keys.
5. Leave the active procedure catalog and router mapping unchanged; only `REV-009` may activate the target catalog and it must delete `review.target-procedures.ts` in that same commit.

## Tests

- Central Vitest contract fixtures under `../../packages/contracts/src/review/` from `apps/desktop`.
- Procedure-catalog lint and `pnpm lint` pass.

## Validation and evidence

Record a complete current-procedure-to-target-contract table and invalid-shape fixture results. `pnpm test` and lint pass.

## Forbidden shortcuts

- Do not type contracts from daemon router types or use handwritten unchecked interfaces.
- Do not add target aliases for Feature/root-index fields.

## Completion criteria

Review has one exhaustive, tested, inactive target-v1 catalog with no legacy field; the currently active catalog is unchanged and no runtime caller can select between two wires.

## Handoff

REV-002/003 implement operations behind the target catalog; REV-004 supplies Results/Assets storage; REV-009 is the sole activation/deletion owner.
