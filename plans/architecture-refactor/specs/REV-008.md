## Architecture reviewer rulings

These bind the executor and supersede every conflicting sentence in the tracked Draft.

1. **`apps/mobile/src/features/review/` already exists — nothing is created there.** REM-005-era
   feature work landed twenty files (3211 lines) under that directory. This unit changes what
   those files import and adds the adapter beside them; it never "relocates mobile Review
   presentation". The Draft's step 1 scope sentence is void.
2. **`lib/daemon/procedures/companion.ts` and `notes.ts` do not exist.** `apps/mobile/src/lib/daemon/`
   holds exactly `client.ts`, `errors.ts`, `poll.ts`, `procedure.ts`, `procedure-contract.test.ts`,
   `procedures/review.ts`, `provider.tsx`, `queries.ts`, `session.ts`, `session-native-adapter.ts`,
   `session-native-lifecycle.test.ts` and `watch.ts` plus four tests. PDT-003 already took Project
   Data's descriptors out. `procedures/review.ts` (313 lines) is the **last** file under
   `lib/daemon/procedures/`, so this unit deletes the directory, not one file in it.
3. **Mobile already depends on `@porcelain/client-runtime` and `@porcelain/contracts`.**
   `apps/mobile/package.json` lists both as `workspace:*`. There is no missing dependency edge:
   `features/git/workspace/git-queries.ts:7` already imports `worktreeInboxQuery` from
   `@porcelain/client-runtime/review`, and eight mobile files already bind
   `@porcelain/contracts/<domain>` descriptors through `namedContractProcedure`. The Draft's
   assumed dependency question is closed by landed precedent.
4. **The landed mobile exemplar is Git, not Remote.** `features/git/` is the only mobile feature
   that owns a typed key namespace (`git-query-key.ts`), a typed effect filter
   (`git-query-filter.ts`), a transport seam (`use-git-transport.ts`), contract-bound procedures
   and a notification bridge (`git-notifications.ts`) together. Review copies those five shapes
   file-for-file. `features/board/` supplies the notification-bridge component idiom
   (`board-notifications.ts` + `board-notification-bridge.tsx`); Review follows Git's simpler
   variant, whose `GitNotificationBridge(): null` lives in `git-notifications.ts` with no JSX.
5. **`reviewed-paths` is Changes-owned on mobile and is not re-keyed here.** Web could partition
   the effect list to Git (REV-007 ruling 3); mobile cannot, because `useReviewedPaths`
   (`features/changes/use-changes.ts:62-67`) reads through `useDaemonQuery`, so its cache entry is
   keyed `['daemon', envId, 'reviewedPaths', input]` by procedure **name**, not by a typed
   identity. `REV-006`'s `activeReviewEffects` includes `reviewedPathsQuery`, so the Review filter
   must still reach it. The minimal landing: `features/changes/use-changes.ts` gains one exported
   non-hook helper

   ```ts
   export function invalidateReviewedPaths(
     queryClient: QueryClient,
     environmentId: string,
   ): Promise<void>
   ```

   built from `daemonKeys.procedure(environmentId, 'reviewedPaths')`, and
   `features/review/review-query-filter.ts` forwards the `reviewed-paths` identity to it. The
   `'reviewedPaths'` string therefore stays in the one feature that owns that cache entry, and no
   procedure-name string enters `features/review/`. `features/changes/` has no `index.ts` and this
   unit does not create one; the import is `@/features/changes/use-changes`, matching how
   `features/shell/surface-slots.tsx:18-21` already deep-imports today.
6. **`worktreeInbox` leaves `provider.tsx` because REV-006 says it is not stale, and it was
   already inert.** `lib/daemon/provider.tsx:57-71` returns eight procedure-name strings for
   `review.changed`, `'worktreeInbox'` (:65) among them. The only mobile reader is
   `features/git/workspace/git-queries.ts:88`, whose key is `gitQueryKey(environmentId,
   worktreeInboxQuery(projectPath))` — a typed identity that the procedure-name predicate can
   never match. REV-006's `review-notifications.ts` excludes `worktree-inbox` deliberately ("a
   cross-worktree Git scan"), and `gitReviewNotificationEffects`
   (`packages/client-runtime/src/git/git-notifications.ts:50-61`) does not list it either. The arm
   loses the string; no reader loses a refresh it was actually getting.
7. **Contract parsing replaces mobile's tolerant `.catch` readers, under REM-005's strict-v1
   precedent.** `lib/daemon/procedures/review.ts:151` reads `canvas: canvasSchema.optional().catch(undefined)`
   and `:184-187` drops an unknown-medium document with `.catch(null)` + filter. Both exist for
   "a daemon older than the HTML + Markdown collapse". `packages/contracts/src/review/review.contract.ts`
   has neither: `featureReadingSchema:145` is a plain optional `reviewCanvasSchema` and
   `reviewIntentOutputSchema:174` / `reviewEvidenceDocsOutputSchema:175` are plain
   `.max()`-bounded arrays. REM-005 already made mobile strict against one daemon version by
   deleting version-3 and icon coercion, and decision 015 forbids pre-launch compatibility
   readers. The tolerant readers are deleted with the file; a document in a medium this build
   cannot render now surfaces as a Review error rather than silently vanishing, which is exactly
   what the Draft's own "do not hide protocol/schema failures as empty Review state" demands.
   This is the one deliberate behavior change in the unit and must be named in the packet.
8. **`hasReport` survives unchanged.** `packages/contracts/src/review/review.contract.ts:196`
   declares `hasReport: z.boolean().optional()` on `evidenceMetaSchema`, so
   `features/review/evidence-body.tsx:112` (`(meta.results ?? 0) + (meta.hasReport === true ? 1 : 0)`)
   keeps compiling and keeps counting the folded legacy report. REV-004 ruling 4 preserved that
   reader and REV-009 removes it later; this unit must not touch it.
9. **Six local exports are dead and go with the file.** `featureViewQuery`, `loopEvidenceQuery`,
   `loopEvidenceHtmlQuery`, `FeatureView`, `FeatureViewSummary` and `PublishResult` have zero
   importers outside `lib/daemon/procedures/review.ts`. Mobile Review reads seven procedures, not
   ten: `featureReading`, `reviewIntent`, `reviewEvidenceDocs`, `reviewEvidenceAssets`,
   `reviewEvidenceAsset`, `reviewPublishCost`, `archivedReviews`. Do not port a dead descriptor
   forward "for symmetry"; the identities that have no mobile reader get no mobile hook.
10. **`use-review.ts` splits into three files at its current responsibilities.** It is 279 lines
    today and gains a key, a transport and effect-driven invalidation. The split is mechanical and
    is named here so the executor makes no structural choice: `use-review-transport.ts` (transport
    + scope + one typed read binder), `use-review.ts` (the seven read hooks, same exported names),
    `use-review-actions.ts` (`useReviewActions`, `useArchivedReviewActions` — which is what the
    existing `use-review-actions.test.tsx` already tests). No file crosses 450 lines.
11. **Review identities reject an empty project path, so a disabled read needs a sentinel.**
    `reviewProjectKey` (`packages/client-runtime/src/review/review-queries.ts:24-30`) throws
    `ReviewIdentityError` on `''`, and today's hooks pass `project?.path ?? ''` with
    `enabled: project !== null`. Copy Git's answer exactly: export
    `REVIEW_DISABLED_PROJECT = '/__porcelain-disabled-review__'` from `use-review-transport.ts`,
    the way `use-git-transport.ts:28` exports `DISABLED_PROJECT`. Never build an identity from an
    empty string and never widen the schema.
12. **The mobile 450-line ledger stays empty.** `scripts/lint-mobile-file-size.mjs:23` declares
    `const ALLOWLIST = new Map()` and the guard reports `0 file(s) still over 450`. Adding an entry
    is never the fix and the script says so at :89. Every file this unit writes or edits stays
    under the ceiling on its own.
13. **`features/review/` gets its first `index.ts`.** `features/shell/surface-slots.tsx:18-21`
    deep-imports four Review files today. Board, Comments, Git and Remote each expose one
    `index.ts`; Review is the outlier. The entry exports the four shell-facing components plus
    `ReviewNotificationBridge`, and `surface-slots.tsx` and `app/_layout.tsx` import through it.
    No other cross-feature deep import into `features/review/` exists to repoint.

## Objective

Every mobile surface that reads or writes Review server state does so through
`apps/mobile/src/features/review`'s public entry over `@porcelain/client-runtime/review` and
`@porcelain/contracts/review`; `apps/mobile/src/lib/daemon/procedures/` no longer exists, and no
mobile file invalidates a Review read by procedure name.

## Why this unit exists

REV-006 landed the shared Review identities, mutation consequences and notification effects, and
REV-007 bound them on Web. Mobile still declares its own 313-line Zod mirror of the Review wire in
`lib/daemon/procedures/review.ts`, types thirteen feature files from it, invalidates Review by
twenty procedure-name strings across `use-review.ts` and `provider.tsx`, and carries tolerant
readers for a daemon version that no longer ships. REV-009's Feature-vocabulary cutover assumes
every client reaches Review through contracts; while mobile owns a second copy of the wire, that
rename is a two-schema edit with a silent drift window between them.
