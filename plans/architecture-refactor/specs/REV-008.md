# REV-008 — Move Mobile Review feature to contracts and delete local schemas

- Status: Draft
- Batch: 5
- Domain: Review
- Depends on: REV-001, REV-004, REV-005, REV-006, RT-005
- Governing decisions: 003, 005, 006, 011, 015
- Primary exemplar: no

## Objective

Relocate mobile Review presentation to the canonical Review feature boundary, consume contract-valid client-runtime semantics, and delete mobile local Review/Evidence procedure schemas.

## Why this unit exists

Mobile Review lives under `apps/mobile/src/features/review`, while Review-related procedures/descriptors are also in `apps/mobile/src/lib/daemon/procedures/review.ts` and `companion.ts`; local shapes diverge from daemon and Evidence evolution.

## Current behavior and evidence

- Exact mobile Review files include `features/review/{use-review,review-store,review-viewer,review-lifecycle,evidence-body,evidence-gallery,review-*.tsx}`.
- Mobile local procedure files include `lib/daemon/procedures/{review,companion,notes}.ts`.
- Inventory requires contract-valid daemon mocks and deletion of mobile local mirrors together with Evidence wire cutover.

## Scope

- Create `apps/mobile/src/features/review/` target public entry and convert its hooks/views to contracts/client-runtime.
- Delete local Review/Evidence schema mirrors after all imports move.

## Non-goals

- Do not move native navigation/sheet/platform behavior out of mobile.
- Do not retain Feature/root-index/medium/hasReport compatibility or change server behavior.

## Target ownership and public surface

Mobile Review feature imports only `@porcelain/contracts/review` and client-runtime Review query/mutation/notification APIs. It renders canonical active/archive/Intent/Execution/Evidence models, Results descriptors, Assets gallery, unavailable states, comments, and reviewed marks. Mobile owns native layout/accessibility only.

## Behavior to preserve

Preserve Review empty state, tabs, document ordering, Evidence checks/results/assets display, gallery gestures, unavailable messaging, comment/reviewed interactions, and native resilience for network/foreground.

## Legacy behavior to delete

Delete `apps/mobile/src/lib/daemon/procedures/review.ts` and Review/Evidence shapes in `companion.ts` only after imports use contracts. Delete Feature/root-index fields in REV-009, not as mobile-only coercions.

## Ordered implementation

1. Inventory every mobile local Review type/parser/procedure name and map to contract type.
2. Introduce contract-valid test mock harness shared with target client-runtime; it validates request/output schemas without daemon business logic.
3. Convert `use-review`, store, lifecycle, and views to canonical query identities/mutations/notification facts.
4. Move any Review behavior embedded in Settings/Shell/Changes to the Review public feature entry; retain only composition UI outside.
5. Delete local Review/Evidence schemas and tests that test the mirror; add feature tests for contract invalid/unavailable/mismatch states.
6. Perform Feature/root-index field deletion only with REV-009's all-client cutover.

## Tests

- Mobile focused feature tests using contract-valid mock daemon.
- Central `pnpm test`, mobile typecheck through `pnpm build`, and `pnpm lint` pass.

## Validation and evidence

Record every deleted local schema/import and contract replacement; capture empty/active/Evidence unavailable/gallery native feature tests.

## Forbidden shortcuts

- Do not import daemon router types or copy Zod schemas into mobile.
- Do not hide protocol/schema failures as empty Review state.

## Completion criteria

Mobile uses canonical contract/client-runtime Review surface, no local Review schema remains, and focused feature/type/lint tests pass.

## Handoff

REV-009 removes shared legacy vocabulary after Web and CLI reach the same target.
