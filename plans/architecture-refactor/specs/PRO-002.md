# PRO-002 — Version repository-owned HTTP and pairing client adapters

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: protocol / client HTTP adapters
- Depends on: `PRO-001`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Make every repository-owned tRPC and pairing HTTP adapter attach the exact protocol-version header
required by the daemon boundary.

## Why this unit exists

Version enforcement is only meaningful once every owned caller sends the same declared protocol
constant rather than an ad hoc literal or no version at all.

## Current behavior and evidence

Relevant fetch owners are `apps/web/src/lib/trpc.ts`, `apps/web/src/hooks/use-token-gate.ts`,
`apps/mobile/src/lib/daemon/client.ts`, `apps/mobile/src/lib/daemon/pairing.ts`, and
`apps/desktop/src/main/shell-api.ts`. They make daemon/pairing requests today without one shared
protocol-header adapter; no `x-porcelain-protocol-version` string exists anywhere in the tree.
`PRO-001` (Landed) exports `PROTOCOL_VERSION`, `protocolVersionSchema`, and `ProtocolVersion` from
the `@porcelain/contracts` root via `packages/contracts/src/protocol.ts`. Of the five focused test
files named under Validation, only the two mobile ones exist; the Web and desktop ones are created
by this recipe.

## Scope

Add the header-name constant to `packages/contracts/src/protocol.ts`, then update only those
repository-owned HTTP/pairing adapters and their focused tests to import the shared constants and
send `x-porcelain-protocol-version` on every applicable request.

## Non-goals

Do not change daemon routing, public error shapes, token-grant behavior, endpoint paths, session
WebSocket hello/ready, reconnect policy, or UI states.

## Target ownership and public surface

`packages/contracts/src/protocol.ts` exports
`PROTOCOL_VERSION_HEADER = 'x-porcelain-protocol-version'` (contracts own the wire vocabulary, and
`PRO-004` enforces this exact name at the daemon boundary). Expose a small per-runtime header helper
only where it prevents repeated literals. It must derive the header name from
`PROTOCOL_VERSION_HEADER` and the value from `String(PROTOCOL_VERSION)`; call sites retain their
current authentication headers and request options. Pairing requests use the identical header
name/value as tRPC requests.

## Behavior to preserve

Preserve credentials, authorization headers, retry/cancellation behavior, URL construction, success
parsing, and current user-visible pairing states.

## Legacy behavior to delete

Delete versionless owned tRPC/pairing fetch calls and any duplicated protocol-version literal in the
listed adapters. Do not retain a fallback retry without the header.

## Ordered implementation

1. Import the protocol constant into each listed owner.
2. Apply the header to every tRPC transport and pairing fetch, merging rather than replacing existing
   headers.
3. Add request-inspection tests for Web, mobile, and desktop-owned paths.

## Tests

Mock fetch/transport in each owner and assert the matching header, existing auth headers, URL, and
body are unchanged. Include a pairing request and a tRPC request per runtime.

## Validation and evidence

```text
rg -n "x-porcelain-protocol-version" apps packages --iglob '!*.test.*'
pnpm lint
pnpm verify
git diff --check
```

## Forbidden shortcuts

Do not put the version in a query string, generate it from package metadata, modify daemon tests, or
cover only the Web adapter.

## Completion criteria

- [ ] Every listed owned tRPC/pairing fetch carries the shared header.
- [ ] Header merges retain auth and existing request options.
- [ ] The header name/value literal exists only in `packages/contracts/src/protocol.ts` and tests.
- [ ] Focused adapter tests, repository lint, full verify, and diff check pass.
- [ ] One commit lands only `PRO-002`, marks recipe/catalog Landed, leaves a clean worktree, provides
      the README review packet, and finishes without pushing.

## Handoff

`PRO-003` applies the same shared version to the session handshake; `RT-004` and `RT-005` consume
that handshake through their runtime adapters.
