# REV-004 — Adopt Results and Assets-only Evidence contracts, containment, caps, and store

- Status: Draft
- Batch: 5
- Domain: Review
- Depends on: REV-001, DAT-001, PDT-002, TST-002
- Governing decisions: 004, 006, 009, 015
- Primary exemplar: yes

## Objective

Make Review Evidence a strict Results/Assets/checks model with containment, bounded reads/assets, explicit unavailable results, and canonical storage; root `index.html` is not a target representation.

## Why this unit exists

Current `evidence-store.ts` still recognizes root `index.html`, emits `medium`/`hasReport`, and bridges staggered clients, while CLI and docs carry matching legacy readers.

## Current behavior and evidence

- `stores/evidence-store.ts` scans meta/results/assets and root index, emits `medium`, `hasReport`, `htmlUnavailable`, and 4 MB cap behavior.
- `apps/cli/src/evidence-file.ts` documents legacy root index and duplicates check/assets caps.
- Inventory retains checks-only packs, containment, caps, unique labels, mtime freshness, and `htmlUnavailable`; it deletes root index/report fields.

## Scope

- Implement strict Evidence schemas/store/adapters under Review feature and contract.
- Use `active-review/evidence/{meta.json,results/,assets/}` only; Results documents and assets receive safe descriptors, not raw host paths.

## Non-goals

- Do not delete root-index readers/fields or clients in this unit; REV-009 performs atomic deletion.
- Do not remove checks-only pack, Results HTML support, image gallery, or oversized unavailable state.

## Target ownership and public surface

Evidence contract exposes `checks`, ordered `results`, bounded `assets`, `updatedAt`, and explicit `{ kind: 'unavailable', reason: 'too-large' }` result descriptor. `ReviewEvidenceStore` validates strict v1 meta, delegates safe path containment to Files capability, bounds document/asset counts/bytes, and never returns absolute filesystem paths.

## Behavior to preserve

Preserve checks-only presence, Results/Assets ordering, containment, inlined/sandboxed active content, size caps, mtime freshness, malformed-meta disposition, and no silent cleared state for oversized content.

## Legacy behavior to delete

Mark root `index.html`, `hasReport`, `medium`, `reviewEvidenceDocs`, root gallery/home readers, and report tests as REV-009 deletions. No target contract emits them.

## Ordered implementation

1. Define v1 Evidence meta/result/asset schemas and public error/unavailable variants.
2. Build adapter that reads only current directories, validates names/containment, enforces existing caps, and returns descriptors.
3. Move Evidence router/store calls to a bound Review operation and contract output parsing.
4. Add tests for checks-only, Results ordering, assets caps, traversal/symlink rejection, malformed meta, oversized result, and mtime refresh.
5. Update CLI target writer path to write only v1 meta/results/assets; leave old reader deletion to REV-009.
6. Add source gate rejecting root-index fields in target Review contract/feature paths.

## Tests

- Contract and temporary-directory adapter matrix for every retained resilience case.
- Central Vitest focus, `pnpm test`, and lint pass.

## Validation and evidence

Record a clean pack, checks-only pack, malicious path, oversized result, and malformed meta result. Prove descriptors contain no absolute path.

## Forbidden shortcuts

- Do not substitute missing/oversize with null/cleared.
- Do not accept root index or arbitrary asset/document extensions in target path.

## Completion criteria

Target Evidence is strict Results/Assets/checks only with retained containment/cap/freshness proof and no target legacy field.

## Handoff

REV-005 writes the target CLI documents; REV-009 deletes the old readers atomically.
