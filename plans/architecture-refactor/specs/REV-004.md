## Objective

`loopEvidence`, `reviewEvidenceDocs`, `reviewEvidenceAssets`,
`reviewEvidenceAsset`, and `clearLoopEvidence` are served by bound operations
under `apps/daemon/src/features/review/` over one `ReviewEvidenceStore`
capability that owns `.porcelain/active-review/evidence/` — its meta, its
`results/` document set, its `assets/` gallery, its containment, its caps, and
its freshness — with identical wire names, kinds, and schemas, and with no
router, operation, or capability value carrying an absolute filesystem path.

## Why this unit exists

Evidence is the only Review family still reading the filesystem from the wire:
`apps/daemon/src/router/review.ts` imports a path helper (line 2) and computes
the assets directory itself (lines 109 and 121), calls
`apps/daemon/src/stores/evidence-store.ts` directly (lines 11-17), and spreads
the pack's rules across three modules that each re-derive what a document, an
image, and a present pack are. Nothing between the wire and the disk can be
faked, so containment, caps, unique labels, mtime freshness, and checks-only
presence have no boundary that owns them. REV-005 (CLI writers) and REV-009 (the
cutover to the `reviewEvidence` aggregate) both need one storage owner already
bound to operations.

export type ReviewEvidenceDocDescriptor = {
  /** Plain file name — never a separator, never absolute. */
  file: string
  label: string
  medium: DocMedium
  bytes: number

  title: string
  updatedAt: string

  readAsset(repoPath: string, file: string): Promise<EvidenceAssetBody | null>
  /** Delete the pack directory; absent is success. */
  clear(repoPath: string): Promise<void>

## Behavior to preserve

- Every moving wire name, kind, input schema, and output schema is unchanged, and
  `procedureCatalog` still reports 113 names. The only payload change is the
  omitted `loopEvidence.dir` (ruling 7).
- Checks-only packs remain packs, and so do Results-only, Assets-only, and
  legacy-report-only packs. Presence keys off the meta **file**, not a successful
  parse, so a half-written `meta.json` shows an empty pack instead of vanishing.
- A malformed or over-cap `checks` list is dropped while the rest of the meta
  still parses.
- Freshness: an in-place edit (a dropped screenshot, a `sed`) moves `updatedAt`
  even when nothing re-bumped `meta.json`.
- Results ordering and unique labels: manifest order first, then name order,
  `MAX_DOCS` tabs, `MAX_DOC_BYTES` each, `MAX_TOTAL_BYTES` total, over-cap
  documents dropped rather than thrown, and no two tabs sharing a label.
- Containment: a client-supplied asset name is validated twice — name shape and
  resolved path — and a symlink is rejected by `lstat` before any read. A
  traversal, an absolute name, a dotfile, a non-image, or an over-cap image is
  `null`, never an error and never a body.
- Asset and document bytes travel over the authenticated procedure channel.
  **There is deliberately no HTTP route**: the daemon's static server is
  unauthenticated by design, and user files must never leave through it.
- Active-content posture: Results HTML stays self-contained (siblings inlined by
  the daemon, containment checked against the evidence root) and is destined only
  for the `<iframe sandbox="" srcdoc>` path — never a `src` URL, which would drop
  the parent CSP. Nothing here rewrites, sanitizes, or re-hosts it.
- Explicit unavailability stays distinct from cleared: `loopEvidenceHtml` keeps
  emitting `htmlUnavailable` for an oversized body, unchanged, and an over-cap
  image still lists as a tile with its size while its body reads `null`.
- Clearing deletes the directory and reports a real failure rather than silently
  succeeding on anything except an absent pack.
- Failure semantics on the wire: a filesystem failure that throws today still
  throws and still serializes as `internal.unexpected`; a check status that
  violates the contract still fails output parsing.
- `review-watch.ts` remains the only publisher of `review.changed`, and it still
