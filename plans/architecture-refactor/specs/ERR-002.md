# ERR-002 — Centralize tRPC request IDs, expected failures, and safe diagnostics

- Status: Queued
- Batch: 0 — architecture and contract foundations
- Domain: daemon composition
- Depends on: `ERR-001`
- Governing decisions: [003](../decisions/003-application-operations-own-orchestration.md), [006](../decisions/006-compose-explicit-capabilities.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

Every authenticated tRPC failure exposes one contract-valid `data.porcelain` value with a request
ID, while expected refusals and unexpected diagnostics follow one daemon-owned mapping.

## Why this unit exists

Routers currently throw raw `TRPCError`/`Error` values, tRPC has no formatter, and requests have no
correlation identity. This mapping must be proven separately from pre-tRPC HTTP response changes.

## Current behavior and evidence

- `apps/daemon/src/trpc.ts` creates the single tRPC builder with `{ auth }` context.
- `apps/daemon/src/net/daemon-http.ts` calls `fetchRequestHandler` with that context and no `onError`.
- `apps/daemon/src/router/daemon.ts` constructs three expected `TRPCError` values.
- `apps/daemon/src/router/files.ts` throws a destination-collision `Error` from `renamePath`.
- Other router/native exceptions have no accepted expected meaning and remain unexpected.

## Scope

Create `apps/daemon/src/daemon-composition/{request-id,expected-failure,public-error,error-log}.ts`,
wire request context/formatter/onError through `trpc.ts` and the tRPC branch of `daemon-http.ts`,
convert only the declared router refusals, and add focused mapper/formatter/router tests.

## Non-goals

Do not change pre-tRPC authentication/pairing/outer-500 bodies (`ERR-003`), WebSocket rejection,
protocol versions, clients, operations, router inputs/outputs, or native failures without a declared
code.

## Target ownership and public surface

- `createRequestId()` returns `randomUUID()`.
- `expectedFailure(code, details?)` returns a daemon-private immutable `ExpectedFailure`; callers
  throw `toTrpcError(expectedFailure(...))`. Safe fallback messages are selected centrally by code,
  never supplied by routers.
- `normalizePublicError(error, requestId)` returns
  `{ error: PorcelainError; unexpected: boolean }`. It recognizes only the private expected marker
  and tRPC input-validation failures; unknown exceptions become `internal.unexpected`.
- `toTrpcError` maps category to the stable tRPC status code and retains the marker as its cause.
- The tRPC formatter preserves the normal shape and adds exactly `data.porcelain`.

`DaemonTrpcContext` becomes `{ auth: AuthIdentity; requestId: string }`. The tRPC request branch
creates one ID before `fetchRequestHandler`, passes it through `createContext`, and uses the same ID
in formatter normalization. `onError` calls `logUnexpectedError` only when normalization says
unexpected.

`logUnexpectedError` logs one structured record containing only request ID, procedure path, and
error type/name. It must not pass the raw error, message, stack, cause, headers, input, host path,
environment, file/evidence content, or serialized object to `console`.

Convert:

- administrator middleware refusal → `auth.forbidden`;
- invalid pairing-link scheme/credentials/query/fragment → `request.invalid`;
- administrator calling `revokeCurrentClient` → `auth.forbidden`;
- existing destination in `renamePath` → `state.conflict`.

## Behavior to preserve

Preserve authentication decisions, tRPC HTTP statuses, safe user-facing meaning, router results,
single `initTRPC`, CORS/listeners, filesystem collision protection, and all unexpected throw paths.

## Legacy behavior to delete

Delete direct `new TRPCError` from `trpc.ts`/`router/daemon.ts` and the expected collision's raw
`Error`. Do not delete unrelated `throw new Error` sites representing defects/native failures.

## Ordered implementation

1. Implement request ID, expected marker, deterministic normalization/category mapping, and safe log.
2. Extend context and configure the one formatter without creating another tRPC builder.
3. Create one request ID for authenticated tRPC dispatch and attach `onError` logging once.
4. Convert the four declared refusal groups to the central helpers.
5. Add mapper/formatter/router tests, including injected unexpected errors containing fake secrets,
   paths, and content that must not appear in captured logs or responses.

## Tests

Add `apps/daemon/src/daemon-composition/{public-error,error-log}.test.ts`, extend tRPC/daemon/files
router tests, and prove expected failures are not error-logged, unexpected failures log once, request
IDs match their envelope, raw details never escape, and existing status meaning remains.

## Forbidden shortcuts

Do not log raw errors or redact by an incomplete secret blacklist; do not expose stacks/messages/
causes; do not infer business codes from native classes or text; do not create router-local mappers,
second builders, client fallbacks, or different request IDs for one tRPC request.

## Completion criteria

- [ ] Only the exact declared refusals are converted; unexpected failures remain unexpected.
- [ ] Diagnostics contain correlation/path/type only and occur exactly once.
- [ ] Focused tests, deletion search, repository lint, full verify, and diff check pass.
