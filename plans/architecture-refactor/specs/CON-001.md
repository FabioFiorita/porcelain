# CON-001 — Establish contract-domain scaffolding and the shrink-only procedure ledger

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: `support:contracts`
- Depends on: `ARC-001` (Landed), `ARC-002` (Landed)
- Governing decisions: [002](../decisions/002-organize-by-product-domain.md), [005](../decisions/005-contracts-own-the-wire.md), [012](../decisions/012-enforce-the-target-architecture.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

The contracts package has ten empty domain entry points, a query/mutation-aware `ProcedureContract`,
one exact initial ownership baseline for all 113 procedures, and a shrink-only ledger for the
procedures not yet migrated to domain modules.

## Why this unit exists

The current horizontal catalog has 113 names, 63 partial schemas and 50 unknown fallbacks. Domain
recipes need a mechanical migration baseline before they move one name without growing legacy debt.

## Current behavior and evidence

- `packages/contracts/src/procedures/{names,io,refined,index}.ts` is the horizontal catalog.
- `procedures/io.ts` supplies `unknownIo`; `scripts/lint-procedure-contracts.mjs` checks names only.
- The exact 113-name/domain map is in `../inventory/backend.md`.

## Scope

- Create the ten target domain directories and `index.ts` files under `packages/contracts/src/`.
- Register those ten contract roots as `migrating` in `scripts/architecture/domains.mjs` in the same
  change; `index.ts` is the ARC-002 activation marker and no target root may be unregistered.
- Create `packages/contracts/src/procedure-contract.ts` and `procedure-ledger.ts`.
- Create `packages/contracts/src/procedure-ledger-baseline.ts` as the temporary migration-only
  owner-of-record for all 113 exact domain/name/kind assignments.
- Extend the procedure lint to enforce that baseline for every ledger and completed domain record,
  while keeping the ledger/domain union exhaustive and shrink-only.

## Non-goals

- Do not move any runtime schema, router import, procedure name, client descriptor or output check.
- Do not delete `packages/contracts/src/procedures/*`; `CON-012` owns that deletion.

## Target ownership and public surface

Create `packages/contracts/src/{remote,projects,files,search,git,review,board,actions,terminal,project-data}/index.ts`.
Create `procedure-contract.ts` exporting:

```ts
export type ProcedureKind = 'query' | 'mutation'
export type ProcedureContract = {
  readonly kind: ProcedureKind
  readonly input: z.ZodType
  readonly output: z.ZodType
}
```

Create `procedure-ledger-baseline.ts` with one temporary, non-public
`initialProcedureOwnershipBaseline` containing all 113 exact `{ domain, name, kind }` assignments
from the backend inventory. It exists only to enforce migration ownership and is deleted with the
transitional ledger by `CON-012`; it is not a second public wire catalog.

Create `procedure-ledger.ts` exporting `unmigratedProcedureLedger`: a readonly object with the ten
domain keys. Each item is `{ name: ProcedureName; kind: ProcedureKind }`, contains every currently
unmigrated name exactly once, and uses the exact ownership/kinds from the baseline. It also exports
`unmigratedProcedureNames`. The lint compares router names/kinds against the union of this ledger
and completed domain module records, and compares every record to the baseline’s exact owner and
kind; a ledger entry may be deleted but cannot be added, renamed, moved, or have its kind changed.

## Behavior to preserve

The current horizontal catalog, all current wire schemas, procedure names and caller imports remain
unchanged. This is structural scaffolding only.

## Legacy behavior to delete

Delete no runtime legacy code. The baseline and ledger are temporary migration enforcement; `CON-012`
deletes both after every domain record is complete. This unit records that removal owner in both
file header comments.

## Ordered implementation

1. Create the ten domain directories/index files, register each contract root as `migrating`, and
   create `procedure-contract.ts`.
2. Transcribe all 113 current domain/name/kind assignments into the temporary ownership baseline
   using the exhaustive inventory.
3. Transcribe the currently unmigrated names into the shrink-only ledger and add tests for the
   baseline, sorted ledger names, uniqueness, domain keys and kinds.
4. Update `scripts/lint-procedure-contracts.mjs` to reject baseline growth, duplicate or unknown
   names, wrong domains, wrong kinds, and router names absent from both the ledger and a completed
   domain record.

## Tests

- Add `packages/contracts/src/procedure-ledger.test.ts` for 113 names, uniqueness, domain keys and kinds.
- Add lint-script fixtures for duplicate, growth outside the baseline, wrong-domain ledger records,
  wrong-domain completed records, wrong-kind records, and absent router procedure failure.

## Validation and evidence

```text
pnpm --dir apps/desktop test -- ../../packages/contracts/src/procedure-ledger.test.ts
node scripts/lint-procedure-contracts.mjs
rg -n "unknownIo|procedureIo|refinedProcedureIo" packages/contracts/src/procedure-ledger.ts packages/contracts/src/procedure-ledger-baseline.ts
git diff --check
```

The search returns zero: the new ledger has no fallback implementation reference.

## Forbidden shortcuts

- Do not make the ledger a second hand-maintained public catalog or use `z.unknown()` in its types.
- Do not add a generic Feature/Settings/Companion domain or a compatibility re-export.

## Completion criteria

- [ ] Ten domain entry points and a kind-aware contract type exist.
- [ ] All ten contract roots are registered as migrating target roots and pass the architecture gate.
- [ ] The temporary ownership baseline has exactly 113 unique current names with exact domains and kinds.
- [ ] The ledger has the exact currently unmigrated names and correct kinds.
- [ ] The lint rejects baseline growth, ownership/domain or kind drift, and router/record gaps.
- [ ] Contract test, lint script and diff check pass.

## Handoff

`CON-002` through `CON-011` each move only their listed domain entries from the ledger into the
corresponding domain procedure module; every moved record remains tied to the baseline’s original
domain and kind. `CON-012` owns deleting the completed baseline and empty-ledger migration scaffolding.
