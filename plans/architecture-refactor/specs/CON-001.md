# CON-001 — Establish contract-domain scaffolding and the shrink-only procedure ledger

- Status: Draft
- Batch: 0 — architecture and contract foundations
- Domain: `support:contracts`
- Depends on: `ARC-001` (Landed), `ARC-002` (Draft)
- Governing decisions: [002](../decisions/002-organize-by-product-domain.md), [005](../decisions/005-contracts-own-the-wire.md), [012](../decisions/012-enforce-the-target-architecture.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

The contracts package has ten empty domain entry points, a query/mutation-aware `ProcedureContract`,
and one exact shrink-only ledger for the 113 procedures not yet migrated to domain modules.

## Why this unit exists

The current horizontal catalog has 113 names, 63 partial schemas and 50 unknown fallbacks. Domain
recipes need a mechanical migration baseline before they move one name without growing legacy debt.

## Current behavior and evidence

- `packages/contracts/src/procedures/{names,io,refined,index}.ts` is the horizontal catalog.
- `procedures/io.ts` supplies `unknownIo`; `scripts/lint-procedure-contracts.mjs` checks names only.
- The exact 113-name/domain map is in `../inventory/backend.md`.

## Scope

- Create the ten target domain directories and `index.ts` files under `packages/contracts/src/`.
- Create `packages/contracts/src/procedure-contract.ts` and `procedure-ledger.ts`.
- Extend the procedure lint to enforce the ledger’s exact, shrink-only baseline.

## Non-goals

- Do not move any runtime schema, router import, procedure name, client descriptor or output check.
- Do not delete `packages/contracts/src/procedures/*`; `CON-012` owns that deletion.

## Target ownership and public surface

Create `packages/contracts/src/{remote,projects,files,search,git,review,board,actions,terminal,project-data}/index.ts`.
Create `procedure-contract.ts` exporting:

```ts
export type ProcedureKind = 'query' | 'mutation'
export type ProcedureContract = {
  readonly kind: ProcedureKind
  readonly input: z.ZodType
  readonly output: z.ZodType
}
```

Create `procedure-ledger.ts` exporting `unmigratedProcedureLedger`: a readonly object with the ten
domain keys. Each item is `{ name: ProcedureName; kind: ProcedureKind }`, contains every current
name exactly once, and uses the exact ownership/kinds from the backend inventory. It also exports
`unmigratedProcedureNames`. The lint compares router names/kinds against the union of this ledger
and completed domain module records; a ledger entry may be deleted but cannot be added or renamed.

## Behavior to preserve

The current horizontal catalog, all current wire schemas, procedure names and caller imports remain
unchanged. This is structural scaffolding only.

## Legacy behavior to delete

Delete no runtime legacy code. The ledger itself is temporary and `CON-012` deletes it after it is
empty; this unit records that removal owner in its header comment.

## Ordered implementation

1. Create the ten domain directories/index files and `procedure-contract.ts`.
2. Transcribe all 113 current names and their current query/mutation kinds into the ledger using the
   exhaustive inventory; add a test that sorted ledger names equal `PROCEDURE_NAMES`.
3. Update `scripts/lint-procedure-contracts.mjs` to reject a new ledger name, a duplicate, a wrong
   kind, or a router name absent from both the ledger and a completed domain record.

## Tests

- Add `packages/contracts/src/procedure-ledger.test.ts` for 113 names, uniqueness, domain keys and kinds.
- Add lint-script fixtures for duplicate, growth, kind drift and absent router procedure failure.

## Validation and evidence

```text
pnpm --dir apps/desktop test -- ../../packages/contracts/src/procedure-ledger.test.ts
node scripts/lint-procedure-contracts.mjs
rg -n "unknownIo|procedureIo|refinedProcedureIo" packages/contracts/src/procedure-ledger.ts
git diff --check
```

The search returns zero: the new ledger has no fallback implementation reference.

## Forbidden shortcuts

- Do not make the ledger a second hand-maintained public catalog or use `z.unknown()` in its types.
- Do not add a generic Feature/Settings/Companion domain or a compatibility re-export.

## Completion criteria

- [ ] Ten domain entry points and a kind-aware contract type exist.
- [ ] The ledger has exactly 113 unique current names and correct kinds.
- [ ] The lint rejects baseline growth and router/ledger kind drift.
- [ ] Contract test, lint script and diff check pass.

## Handoff

`CON-002` through `CON-011` each remove only their listed domain entries from the ledger while
creating the corresponding domain procedure module; `CON-012` owns the empty-ledger deletion.
