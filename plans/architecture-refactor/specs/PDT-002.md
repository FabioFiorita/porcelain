# PDT-002 — Move Notes, dispositions, layers, and visibility to Project Data boundaries

- Status: Draft
- Batch: 4
- Domain: Project Data
- Depends on: PDT-001, DAT-001, TST-002
- Governing decisions: 003, 004, 006, 009, 015
- Primary exemplar: yes

## Objective

Create canonical Project Data contracts, operations, adapters, and ownership for Notes, companion dispositions, Review layers, and visibility policy, leaving their product consumers narrow and transport-free.

## Why this unit exists

`notes-store.ts`, `layers-store.ts`, `companion-disposition.ts`, `git-exclude.ts`, and `project-channel.ts` currently mix record policy, filesystem writes, migration work, Git state, and caller-specific behavior.

## Current behavior and evidence

- `apps/daemon/src/stores/{notes-store,layers-store}.ts` use project channels.
- `apps/daemon/src/project/{companion-disposition,git-exclude}.ts` own gitignore/disposition behavior but are called by stores and Review publish paths.
- `net/project-channel.ts` currently starts migration, visibility, and Review-watch side effects during generic reads/writes.
- Existing CLI files are `apps/cli/src/{notes-file,layers-file}.ts`; Web/mobile consumers include `use-repo-notes`, `use-repo-layers`, and mobile Settings Review layers.

## Scope

- Add `packages/contracts/src/project-data/`, `apps/daemon/src/features/project-data/`, and the matching `index.ts` public entries under the registered migration roots.
- Move Notes, disposition, layers, and visibility behavior behind named Project Data operations/capabilities/adapters.
- Update direct CLI writers to strict v1 schemas only after their domain record has the target adapter.

## Non-goals

- Do not move Review reading ownership from Review, Git behavior from Git, or UI settings composition from Settings.
- Do not migrate/delete existing data, reset any root, or retain home-path compatibility.

## Target ownership and public surface

Project Data owns `readNotes`, `writeNotes`, `readLayers`, `writeLayers`, `readCompanionDispositions`, `setCompanionDisposition`, and `ensureCompanionVisibility` operations. Review owns the intention that consumes layers; Project Data owns their storage/format/disposition. Operations receive narrow `ProjectDocumentStore`, `ProjectGitVisibility`, and `Clock` capabilities. Router procedures call one bound operation.

## Behavior to preserve

Preserve empty Notes/layers defaults, managed `.porcelain/.gitignore` rendering, tracked-path discovery, explicit publication disposition, never-create-a-missing-repo safety, atomic writes, corruption disposition, and Git visibility semantics.

## Legacy behavior to delete

Delete direct calls from `stores/{notes-store,layers-store}.ts`, `project/companion-disposition.ts`, `project/git-exclude.ts`, and generic `project-channel.ts` only when all callers use the new operations. Do not delete `migrate-home` or active-layout migration here; PDT-005 owns them.

## Ordered implementation

1. Define strict v1 schemas/procedures in `packages/contracts/src/project-data/` for the four named record behaviors.
2. Register Project Data target roots as migrating and add a daemon feature public entry.
3. Build operations from injected narrow capabilities; move filesystem/gitignore implementation into adapters below the feature boundary.
4. Replace router/store callers with bound operations; Review publish calls its narrow Project Data capability rather than a store helper.
5. Make CLI Notes/Layers writers validate the same contract schema through dependency-light shared validation; reject unknown/version-incompatible documents.
6. Add architecture checks that Project Data operations do not import tRPC/routers and that generic project channel has no migration/watch/disposition imports.
7. Remove direct legacy callers only after contract, operation, adapter, and CLI integration tests pass.

## Tests

- Contract schema valid/invalid/version tests.
- Operation tests with capability fakes; real temporary-project adapter tests for atomic disposition and gitignore changes.
- Central Vitest focused paths plus `pnpm test` and `pnpm lint` pass.

## Validation and evidence

Record each old caller, replacement operation, target contract, and test. Prove a clean v1 Notes/layers/disposition fixture and preserve a corrupt/incompatible document without defaulting.

## Forbidden shortcuts

- Do not create a generic Companion domain/service or let Review own Project Data persistence.
- Do not make a read perform migration/watcher work.
- Do not rewrite existing user files as an implicit schema upgrade.

## Completion criteria

Project Data has public v1 contracts/operations/adapters; consumers use them; generic channel side effects are gone; named resilience tests and gates pass.

## Handoff

PDT-003 adopts client settings adapters. PDT-005 deletes old migration machinery only after authorized clean state.
