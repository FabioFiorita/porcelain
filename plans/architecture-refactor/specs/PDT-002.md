## Objective

Project Data owns Notes, Review-layer storage, companion dispositions, and
clone visibility through bound operations and adapters; settings and Review
publish call those operations; on-disk notes.md and layers.json stay on their
current unversioned payloads.

## Why this unit exists

`notes-store.ts`, `layers-store.ts`, and `companion-disposition.ts` still mix
record I/O with router and Review callers. Layers wire schemas sit in Review
contracts while PDT-001 already listed `layers.json` under the project-data
path catalog. Decision 003 requires one operation per public procedure.

## Behavior to preserve

- Missing notes → `''`. Empty notes write deletes `notes.md`.
- Missing / empty / all-invalid layers → store `null`; `repoLayers` returns
  `{ layers: DEFAULT_LAYERS, custom: false }`. Custom write round-trips in
  order. `setRepoLayers({ layers: null })` writes `[]` and reads back as
