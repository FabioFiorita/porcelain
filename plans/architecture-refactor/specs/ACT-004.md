## Objective

The Actions domain has one contract/daemon/client surface, with no Terminal-owned Action
descriptors, facades, or procedure definitions, and with the architecture registry marking
Actions complete.

## Why this unit exists

ACT-001 moved daemon ownership and stripped the Terminal router of Action procedures; ACT-002
landed shared client semantics; ACT-003 relocated Web and mobile adapters and deleted mobile
Terminal Action descriptors. Leaving Actions `migrating` in the registry means the domain can
re-absorb Terminal vocabulary without a completed-domain gate, and residual Terminal Action
ownership could re-enter procedure modules without a zero-result assertion set.

  errors (`actions.unavailable`, `actions.not-found`, `actions.untrusted`).

  Terminal create per successful run; never a second `terminal:write` for the command text.

  uses `LocalPathDialog` in run mode from ActionsGroup (or File Finder compose-intent).
- Mobile filters `where === 'local'`; no mobile CRUD UI.
- Saved action order and CRUD remain daemon-authoritative; refetch after mutation and after
  `actions.changed`.
- Terminal roster/rename/stream behavior unchanged.
- Unread still maps `actions.changed` → terminal companion; companion placement and
  `porcelain-terminal-*` testIDs remain.
