# GIT-002 — Implement checkout and add-worktree over hardened Git capabilities

- Status: Ready
- Batch: 2 — focused behavior exemplars

- Depends on: `GIT-001`, `DAE-001`, `TST-002`

## Objective

Checkout and add-worktree are bound daemon operations whose Git process adapter returns typed known failures and whose routers expose only the GIT-001 public error vocabulary.

## Why this unit exists

`apps/daemon/src/router/git.ts` currently calls process-backed helpers directly, exposing Git's implicit state and stderr where it cannot be tested or mapped intentionally. `DAE-001` and `TST-002` are Landed, and `GIT-001` now declares the exact five public Git failure codes consumed by this unit.

## Current behavior and evidence

- `apps/daemon/src/git/git.ts` exports `runGit`, `gitCheckout`, and `gitAddWorktree`. `runGit` owns `execFile('git', args)`, the caller `cwd`, a `64 * 1024 * 1024` `maxBuffer`, and `gitEnv(process.env, { GIT_OPTIONAL_LOCKS: '0' })`. `runGitChecked` and `gitErrorOutput` are also used by unmigrated Git mutations and remain in place.

The implementation must preserve this exact existing regex; it is not a new branch-validation policy.

- The Git contract procedures are already exact: `gitCheckout` declares `git.not-a-repository`, `git.branch-not-found`, and `git.working-tree-conflict`; `gitAddWorktree` declares `git.not-a-repository`, `git.branch-already-exists`, and `git.worktree-conflict`. ## Target ownership and public surface

### Port and result

`apps/daemon/src/features/git/git-ports.ts` defines the narrow capability used by the operations:

```ts
export type GitWorkspaceError =
  | { code: 'git.not-a-repository' }
  | { code: 'git.branch-not-found' }
  | { code: 'git.branch-already-exists' }
  | { code: 'git.worktree-conflict' }
  | { code: 'git.working-tree-conflict' }

export type GitWorkspaceResult<Value> =
  | { ok: true; value: Value }
  | { ok: false; error: GitWorkspaceError }

export type GitWorkspacePort = Readonly<{
  checkout(repoPath: string, branch: string): Promise<GitWorkspaceResult<void>>
  addWorktree(repoPath: string, branch: string): Promise<GitWorkspaceResult<Worktree>>
}>
```

Import `Worktree` from `@porcelain/contracts/git`. Do not add details to these capability errors; the router maps only their `code` values to the corresponding GIT-001 public errors.

### Git subprocess adapter

`createGitSubprocess()` in `git-subprocess.ts` returns a `GitWorkspacePort`. It is the only new owner of the two process-backed actions and must:

1. Construct exactly `['checkout', branch]` and `['worktree', 'add', '-b', branch, dir]`; no arbitrary argument or command parameter is exposed.
2. Run `git` with the repository path as `cwd`, `maxBuffer: 64 * 1024 * 1024`, and `gitEnv(sourceEnv, { GIT_OPTIONAL_LOCKS: '0' })`. The default source is `process.env`; tests may provide a source environment through the adapter host seam.
3. Preserve the current sibling directory and branch-leaf sanitization policy, create the parent recursively, and return `realpath(dir)` with the original branch. The linked worktree therefore continues to share the in-repo `.porcelain` companion data.
4. Normalize native stderr/stdout only inside the adapter, without returning raw output. Match these stable Git outcomes, in this order: repository discovery text containing `not a git repository` → `git.not-a-repository`; checkout pathspec text containing `did not match any file` → `git.branch-not-found`; branch-creation text containing `a branch named` and `already exists` → `git.branch-already-exists`; worktree text containing `already checked out` or a destination/path collision (`already exists` while the `worktree add` action is running) → `git.worktree-conflict`; checkout text containing `would be overwritten by checkout` → `git.working-tree-conflict`. Classification is action-aware so a branch-already-exists message is not treated as a destination conflict. Matching is case-insensitive and examines Git's stderr/stdout only at this adapter boundary; no path or message details cross it.
5. Re-throw an unmatched native process or filesystem error. The centralized daemon error boundary then exposes `internal.unexpected`; the operation and router must not catch or inspect such exceptions.

Use an explicit, narrow test host rather than a global singleton or module mock: `git-subprocess.ts` may accept optional `execute`, `mkdir`, `realpath`, and `sourceEnv` dependencies, where `execute` receives the fixed `git` argument list and `{ cwd, env, maxBuffer }` options and returns the subprocess stdout or throws the native error. Production defaults wrap `execFile`, `fs.mkdir`, `fs.realpath`, and `process.env`; the returned public port exposes only `checkout` and `addWorktree`.

### Operations

`git-operations.ts` exports:

```ts
export type GitOperations = Readonly<{
  checkoutGit(input: GitCheckoutInput): Promise<GitWorkspaceResult<void>>
  addGitWorktree(input: GitAddWorktreeInput): Promise<GitWorkspaceResult<Worktree>>
}>

export function createGitOperations(options?: {
  workspace?: GitWorkspacePort
}): GitOperations
```

The default constructs the subprocess adapter once. Each operation passes exactly `input.repoPath` and `input.branch` to its one port method and returns that result unchanged. It contains no stderr matching, transport code, cache invalidation, optimistic state, or calls to another application operation. The factory returns a frozen catalog.

### Feature router and composition

`git-router.ts` exports `createGitFeatureRouter(operations: GitOperations)` with exactly `gitCheckout` and `gitAddWorktree`. Each procedure uses the matching `procedureCatalog` input/output, calls exactly one bound operation, and translates every `GitWorkspaceError.code` exhaustively with `expectedFailure(code)` and `toTrpcError`. An unexpected thrown exception is allowed through for `internal.unexpected`; the feature router never reads stderr and never imports `apps/daemon/src/git/git.ts`.

`features/git/index.ts` exports the public feature router, operation factory/type, port/result types, and subprocess factory needed by the composition root and focused tests. `daemon-operations.ts` constructs the Git operation slice alongside the existing Board, Review-comment, and Files slices. `create-daemon-router.ts` merges the bound two-procedure feature router before the residual `createGitRouter()`; the residual router must no longer define either moved key, so the composed procedure set remains exactly `Object.keys(procedureCatalog)` with no duplicate names.

## Behavior to preserve

Preserve `GIT_OPTIONAL_LOCKS=0` for reads/background polling while required Git mutation locks remain enabled, the caller-selected repository `cwd`, exact fixed argv construction, current branch creation with `-b`, sibling linked-worktree location, branch-name sanitization only for the directory leaf, `realpath` normalization, and in-repo `.porcelain` sharing. Preserve centralized unexpected-error redaction through `ERR-001`; recognized native failures become stable public codes and unknown failures do not leak Git output.

## Legacy behavior to delete

Delete the two direct raw action exports from `apps/daemon/src/git/git.ts`, their direct router imports and procedure bodies, the moved legacy adapter test block, and the residual router contract fixtures that only prove those direct calls. Do not delete `runGit` or `runGitChecked`; they are still required by unmigrated actions and remain explicitly outside this cutover.
