# GIT-002 — Implement checkout and add-worktree over hardened Git capabilities

- Status: Draft
- Batch: 2 — focused behavior exemplars
- Domain: git
- Depends on: `GIT-001` (Draft), `DAE-001` (Draft), `TST-002` (Draft)
- Governing decisions: [003](../decisions/003-application-operations-own-orchestration.md), [006](../decisions/006-compose-explicit-capabilities.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Replace direct checkout/add-worktree router calls with two bound Git operations over a narrow subprocess capability that normalizes known Git outcomes.

## Why this unit exists

`router/git.ts` calls process-backed helpers directly, exposing Git's implicit state/error behavior where it cannot be tested or mapped intentionally.

## Current behavior and evidence

`git/git.ts` exports `runGit`, `gitCheckout`, and `gitAddWorktree`; `runGit` uses fixed arguments, daemon `cwd`, 64 MiB buffer, and scrubbed `gitEnv`. `gitAddWorktree` creates linked worktrees and relies on shared in-repo `.porcelain` data; router checkout has no cache/event consequence yet.

## Scope

Create `apps/daemon/src/features/git/{git-ports,git-operations,git-router,git-subprocess}.ts` and tests; move only checkout/add-worktree host calls from `git/git.ts` and `router/git.ts`; bind only these operations in daemon composition.

## Non-goals

Do not move status/branches/worktrees reads, commit/stage/push, Review inbox, client invalidation, watch facts, path storage, or change the Git executable policy.

## Target ownership and public surface

`GitWorkspacePort` exposes `checkout(repoPath, branch)` and `addWorktree(repoPath, branch)` with typed outcomes matching GIT-001. `GitSubprocess` owns fixed argument construction, `gitEnv` scrubbing, cwd, max buffer, and native stderr-to-outcome normalization. `checkoutGit` and `addGitWorktree` operations return success or expected failures; they never inspect stderr outside the adapter. Router procedures call one bound operation and `ERR-001` maps failures.

## Behavior to preserve

Preserve `GIT_OPTIONAL_LOCKS=0` read policy, required Git mutation locks, cwd repository selection, linked-worktree companion sharing, current branch creation behavior, and unexpected process failures as centralized internal errors.

## Legacy behavior to delete

Delete direct `gitCheckout`/`gitAddWorktree` router imports and direct raw process helper exports for these actions; retain `runGit` only for unmigrated Git actions until their owning recipes move them.

## Ordered implementation

1. Extract capability argument/outcome mapping without changing process behavior.
2. Add real temporary-Git-repository adapter proof for checkout, add worktree, conflicts, and scrubbed env.
3. Add focused operation tests with the Git port fake.
4. Bind operations and delete direct router action calls.

## Tests

Adapter tests create disposable initialized repositories and prove branch/worktree behavior and typed known failures; operation tests prove mappings; router tests prove one bound call and public error conversion.

## Validation and evidence

```text
pnpm --dir apps/desktop test -- ../daemon/src/features/git/git-subprocess.test.ts ../daemon/src/features/git/git-operations.test.ts ../daemon/src/features/git/git-router.test.ts
pnpm lint
rg -n "gitCheckout|gitAddWorktree" apps/daemon/src/router/git.ts
git diff --check
```

## Forbidden shortcuts

Do not pass arbitrary Git args, retain raw stderr matching in routers/operations, use a global Git singleton, perform client invalidation, or add optimistic checkout state.

## Completion criteria

- [ ] Only the Git adapter invokes checkout/add-worktree subprocess actions.
- [ ] Known outcomes are typed and public mapping is router-only.
- [ ] Real Git adapter, operation, router tests, lint, and diff check pass.

## Handoff

`GIT-003` may define distinct non-optimistic consequences for the two stable mutations.
