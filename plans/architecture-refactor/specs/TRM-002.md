# TRM-002 — Move PTY lifecycle and stream gateway behind Terminal capabilities

- Status: Draft
- Batch: 2 — focused behavior exemplars
- Domain: terminal
- Depends on: `TRM-001` (Draft), `DAE-001` (Draft), `TST-002` (Draft), `RT-005` (Draft)
- Governing decisions: [003](../decisions/003-application-operations-own-orchestration.md), [006](../decisions/006-compose-explicit-capabilities.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Replace Electron-shaped terminal sender management with a PTY capability, lifecycle operations, environment policy, and the target authenticated session stream gateway in one no-compatibility cutover.

## Why this unit exists

`terminal-manager.ts` currently owns process spawning, global session state, scrollback, old sender fan-out, lifecycle limits, and environment policy together; `net/session.ts` dispatches every old terminal frame directly.

## Current behavior and evidence

`apps/daemon/src/terminal/terminal-manager.ts` uses `node-pty`, `terminal-env.ts`, `initial-input.ts`, and `scrollback-buffer.ts`; it holds a process-global map, auto-attaches creators, keeps disconnected sessions, and sweeps limits. `net/session.ts` owns current frame dispatch. RT-005 already provides the only target session gateway and no legacy transport bridge.

## Scope

Create `apps/daemon/src/features/terminal/{terminal-ports,terminal-operations,terminal-stream-gateway,pty-adapter,terminal-environment}.ts` and tests; move runtime behavior from `terminal-manager.ts`, `terminal-env.ts`, `initial-input.ts`, and `scrollback-buffer.ts`; wire it to the RT target gateway and daemon composition; update `router/terminal.ts` roster/rename to bound operations.

## Non-goals

Do not implement client attach/recovery state machines (TRM-003), Web Ghostty or mobile native adapters, change shell UX, alter Actions workflows, or add a second socket/PTY transport.

## Target ownership and public surface

`PtyPort` creates/writes/resizes/kills a process and exposes data/exit callbacks; only `pty-adapter.ts` imports `node-pty`. `TerminalEnvironmentPort` derives login-shell environment by retaining user shell/PATH and removing daemon credentials, `RUN_AS_NODE`, and `PORCELAIN_*` secrets exactly as current `terminalEnv`. Operations own create/attach/detach/write/resize/kill/paste/rename/list, terminal map, bounded scrollback, epoch/sequence assignment, and typed expected failures. The stream gateway parses TRM-001 frames only after RT authenticated ready and sends terminal events only through target session transport.

## Behavior to preserve

Preserve login shell selection including `PORCELAIN_SHELL`, initial-input quiet-window behavior, 80×24 defaults, fan-out to attached clients, scrollback replay, disconnect survival, 64-session/retention/idle sweep policy, destroyed-client cleanup, safe capacity eviction order, image/file paste behavior, and one daemon-owned roster.

## Legacy behavior to delete

Delete `TerminalSender`, old `send(channel, ...args)` fan-out, terminal cases in old `net/session.ts`, and terminal exports from `ws-protocol.ts` in the same switch. Do not retain old/new frame conversion, a legacy attach path, or duplicate terminal session maps.

## Ordered implementation

1. Extract PTY/environment capability types and port existing platform behavior with adapter tests.
2. Move lifecycle/scrollback/initial-input logic into operations, retaining exact limits and clock seams.
3. Bind roster/rename and terminal stream operations through composition/target RT gateway.
4. Switch all daemon terminal dispatch to TRM-001 frames and delete old sender/frame paths atomically.

## Tests

Use a focused PTY fake for operation state, a real adapter construction test for environment/argument policy, and stream-gateway tests for auth-ready gating, correlation, epoch/sequence, attach replay, detach, exit, capacity, cleanup, and typed errors.

## Forbidden shortcuts

Do not import `node-pty` outside the adapter, kill attached sessions to satisfy a cap, let a session frame bypass RT auth/ready, retain compatibility parsing, or put browser/RN code in Terminal operations.

## Completion criteria

- [ ] One PTY adapter and one daemon terminal map own host state and lifecycle limits.
- [ ] Target gateway carries only strict correlated epoch/sequence Terminal frames after auth-ready.
- [ ] Old sender/frame dispatch has zero imports and no dual path remains.
- [ ] Adapter/operation/gateway tests, lint, and diff check pass.

## Handoff

`TRM-003` may implement transport-neutral client attach, recovery, and scrollback semantics over the stable gateway.
