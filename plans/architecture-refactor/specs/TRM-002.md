## Objective

Replace Electron-shaped Terminal sender management with one composition-injected PTY capability,
Terminal lifecycle operations, paste adapter, environment policy, and the authenticated session
stream gateway. Leave one daemon-owned Terminal map and one TRM-001 wire path.

## Why this unit exists

`apps/daemon/src/terminal/terminal-manager.ts` still combines native PTY spawning, process-global
session state, scrollback, sender fan-out, lifecycle limits, and environment policy. `image-paste.ts`
also reaches into the global manager and daemon home directly. `session-gateway.ts` validates local
frame unions, while `live-session.ts` converts manager callbacks and maps expected failures to the
old empty-id/`found`/paste-result sentinels. The Terminal roster router imports the manager
directly, and the DAE-001 catalog has no Terminal property.

## Current behavior and evidence

- `terminal-manager.ts` spawns `node-pty` login shells, auto-attaches the creator, retains PTYs
  across socket loss, fans out output to `TerminalSender`, stores a byte-capped scrollback, and
  sweeps exited/detached sessions. Its exact bounds are 64 sessions, 10-minute exited retention,
  and 12-hour detached-idle retention.
- `terminal-env.ts` preserves the user environment and forces `TERM=xterm-256color` and
  `COLORTERM=truecolor` while removing daemon credentials, `ELECTRON_RUN_AS_NODE`, and the listed
  `PORCELAIN_*` variables. `PORCELAIN_SHELL` is read for shell selection before sanitization.
- `initial-input.ts` owns the 300 ms prompt and 2,000 ms newline quiet windows. `scrollback-buffer.ts`
  retains newest chunks under a 64 KiB UTF-8 byte cap. `image-paste.ts` enforces 4 MiB images,
  8 MiB files, 24-hour paste retention, 0700 directories, 0600 files, and daemon-home storage.
- `session-gateway.ts` already gates terminal traffic behind authenticated `session:ready`, but it
  composes local client/server unions and `live-session.ts` still dispatches through the old
  manager. `ws-protocol.ts` and `net/session.ts` are already absent after RT-005 and are not
  execution targets.
- `router/terminal.ts` still reads `listTerminals` and `renameTerminal` directly; `server.ts`
  constructs the DAE-001 catalog without a Terminal capability and passes a global `createSession`
  callback.

## Target ownership and public surface

### Capability and operation contracts

`terminal-ports.ts` exports these concrete shapes:

```ts
type PtyProcess = {
  write(data: string): void
  resize(cols: number, rows: number): void
  kill(): void
  onData(listener: (data: string) => void): void
  onExit(listener: (exitCode: number) => void): void
}
type PtyPort = {
  spawn(input: { cwd: string; cols: number; rows: number }): PtyProcess
}
type TerminalEnvironmentPort = {
  shell: string
  environment: Readonly<Record<string, string>>
}
type TerminalPastePort = {
  save(input: { id: string; filename: string; dataBase64: string; maxBytes: number }): Promise<
    | { ok: true; value: { path: string } }
    | { ok: false; error: { code: 'terminal.paste-unavailable' } }
  >
  sweep(now: number): Promise<void>
}
type TerminalStreamSink = {
  isAlive(): boolean
  send(frame: TerminalServerFrame): void
}
```

`TerminalOperations` exposes exactly `create`, `attach`, `detach`, `write`, `resize`, `kill`,
`pasteImage`, `pasteFile`, `list`, `rename`, `detachSink`, and `sweep`. Each lifecycle operation
returns `{ ok: true, value }` or `{ ok: false, error }`; its failure union is limited to the
declared Terminal codes. `pasteImage` and `pasteFile` are asynchronous and return `{ result: 'ok',
path? }` on success. `list` returns contract-shaped `TerminalInfo[]`; `rename` preserves current
trim-and-ignore behavior and has no intentional public error. `detachSink` is teardown-only and
does not fabricate a reply.

The operations map owns one epoch supplied by `TerminalIds.epoch()` and one nonnegative sequence
counter per session. The counter starts at zero; attach returns the current `{ epoch, sequence }`
scrollback baseline; every data chunk and natural exit increments it once before fan-out. All
attached sinks receive the same ordered frame. A killed session is removed before `kill()` and
never emits an exit frame. Destroyed sinks are removed and start the detached-idle clock.

Create uses 80×24 when dimensions are omitted, rejects non-positive dimensions with
`terminal.invalid-size`, auto-attaches the creating sink, and returns `terminal.capacity` when all
64 entries are attached. Unknown ids return `terminal.not-found`; writes/resizes against exited
sessions return `terminal.exited`; kill removes an existing running or exited session. Eviction
keeps attached sessions, prefers expired exited entries, then the oldest detached running entry,
and refuses with `terminal.capacity` when no safe victim exists.

The operations layer owns the current 64 KiB UTF-8 byte scrollback cap, 10-minute exited retention,
12-hour detached-idle retention, and 2,000 ms/300 ms initial-input timers. It does not import
`node-pty`, read `process.env`, or access the filesystem.

### Environment, PTY, and paste adapters

`terminal-environment.ts` reads the injected source environment once, chooses `PORCELAIN_SHELL`
when nonblank otherwise `SHELL` then `/bin/zsh`, removes the exact daemon-only list currently
covered by `terminal-env.test.ts`, and adds `TERM`/`COLORTERM`. `pty-adapter.ts` is the sole
`node-pty` importer and receives the environment policy at construction. `terminal-paste.ts`
receives its daemon-home root from composition, never a Project path; it decodes and bounds bytes,
sanitizes only the client filename leaf, writes 0700/0600, preserves prompt-reference spacing, and
maps all expected filesystem/size failures to `terminal.paste-unavailable`.

### Stream gateway and composition

`terminal-stream-gateway.ts` owns the command-to-operation table. It emits:

- successful `terminal:created`, `terminal:attached`, `terminal:image-pasted`, and
  `terminal:file-pasted` frames with the original `reqId`;
- no success reply for detach, write, resize, or kill;
- strict `terminal:error` with the original `reqId`, optional target `id`, and a contract-owned
  `PorcelainError` generated with a fresh UUID `requestId` for every typed Terminal failure.

The gateway maps failures exhaustively to the five TRM-001 Terminal codes and never matches error
messages. `session-gateway.ts` imports the contract-owned `terminalClientFrameSchema` and
`terminalServerFrameSchema`; it validates/forwards Terminal frames only in the `open` state. The
Terminal gateway never receives a raw frame before the authenticated `session:ready` transition.
`live-session.ts` constructs one gateway per socket with the composition-injected operations and
the socket sink, while Terminal operations remain process-wide and socket-independent.

## Behavior to preserve

Preserve login-shell selection including `PORCELAIN_SHELL`, sanitized user environment, 80×24
defaults, initial-input quiet-window behavior, PTY output ordering, attach scrollback-before-live
ordering, disconnect survival, fan-out, destroyed-sink cleanup, 64-session/10-minute/12-hour
bounds, safe capacity eviction, paste path/permission/retention policy, and the unchanged roster
records and `terminalSessions`/`renameTerminal` procedure names.

## Legacy behavior to delete

Delete `TerminalSender`, the old `send(channel, ...args)` fan-out, manager/image-paste imports,
local session/server frame unions, empty-id create refusal, `found: false` attach replies, old
`too-large`/`no-session`/`write-failed` paste result values, and direct router imports. Do not add
compatibility conversion, optional epoch/sequence fields, a second error envelope, or a second
Terminal session map. The already-deleted `ws-protocol.ts` and `net/session.ts` are not recreated.

## Forbidden shortcuts

Do not import `node-pty` outside `pty-adapter.ts`, read environment/filesystem state from
operations, use `TerminalSender`, keep a module-global Terminal map, kill attached sessions for
capacity, silently ignore invalid resize dimensions, let a frame bypass authenticated ready,
retain local frame unions or compatibility parsing, return old paste failure result strings, or
put browser/RN code in daemon Terminal operations.
