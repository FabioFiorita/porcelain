# SEA-002 — Move Search semantics and presentation to the Search domain

- Status: Draft
- Batch: 3 — remaining domain cutovers
- Domain: search
- Depends on: SEA-001, FIL-004, GIT-005, TST-001, RT-005
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Search owns typed file/text/code identities, file-change consequences and both clients’ Search feature adapters rather than Files/Git/Shell hooks.

## Why this unit exists

Web `use-search.ts` is mixed with Git/Shell components and mobile Search lives in `features/files` over duplicate Files procedure schemas.

## Current behavior and evidence

Current reads are `searchFiles`, `searchText`, and `searchCode`; mobile calls them from `features/files/use-files.ts`; file-tree/content changes currently invalidate differing string sets.

## Scope

Add `packages/client-runtime/src/search/{search-queries,search-notifications,index}.ts`; create `features/search/` adapters in both apps; move Web `use-search.ts`, `components/git/search-list.tsx`, Shell search controls and mobile `features/files/search-*` callers.

## Non-goals

Do not change daemon search algorithms/caps, viewer rendering, Files tree reads, Git suggestions, keyboard shell mechanics, or persist query results in stores.

## Target ownership and public surface

Runtime exports `fileSearchQuery(projectPath,query)`, `textSearchQuery(projectPath,query)`, and `codeSearchQuery(projectPath,options)`; empty trimmed input is disabled in adapters. `searchNotificationEffects` maps `files.tree-changed` to file-search and `files.content-changed` to file/text/code identities for that project. Web/mobile feature indexes export their search read hooks and presentation components.

## Behavior to preserve

Keep debounce/keep-previous behavior, server caps/truncation, literal/regex/case/include/exclude semantics, file-result opening, highlight rendering and phone/shell search UX.

## Legacy behavior to delete

Delete Search descriptor/type imports from mobile Files, Web Git/Shell raw query hooks, and File event Search string invalidations; retain Files-only paths.

## Ordered implementation

1. Verify SEA-001 contracts/operations and RT-005 typed file facts.
2. Implement runtime identities/effects, then Web/mobile adapters over canonical descriptors.
3. Move presentation to Search features and delete misplaced hooks/imports.

## Tests

Test normalized disabled input, option-distinct identities, exact file notifications, valid mock responses/errors, and retained Search highlight/list/panel visible behavior.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../../packages/client-runtime/src/search ../web/src/features/search ../mobile/src/features/search`.
- Run `pnpm --dir apps/mobile typecheck` and `pnpm lint`.
- Run `rg -n "search(Files|Text|Code)|search-" apps/mobile/src/features/files apps/web/src/hooks/use-search.ts apps/web/src/components/git/search-list.tsx`; it returns no result after relocation.

## Forbidden shortcuts

Do not duplicate Files watch effects, use raw app events, or leave Search as a Files/Git subfeature.

## Completion criteria

- [ ] Search has shared identities/effects and two feature adapters.
- [ ] Misplaced schemas/hooks/components are removed and tests pass.
- [ ] Typecheck, lint and search pass; the unit is committed.
