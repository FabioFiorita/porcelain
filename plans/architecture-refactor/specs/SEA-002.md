## Objective

Search owns typed file-name, text, and code-search identities, the file-change freshness
consequences for those identities, and both clients' Search adapters and presentation. Files, Git,
and Shell retain only their own reads, mutations, navigation, and keyboard orchestration.

## Why this unit exists

Web Search is currently split between a raw tRPC hook, Git-named presentation, Shell controls, and a
global Search store. Mobile Search is under `features/files` and consumes duplicate Search
descriptors and result types declared by the Files daemon procedure module. Search freshness is also
applied through Files-owned raw procedure strings. The split makes the shared Search identity and
the owner of Search recovery invisible, and it permits the two clients to drift.

## Reviewer rulings

These rulings resolve the design choices required before implementation:

1. The client-runtime Search identity is a discriminated union with exactly these names and fields:

   ```ts
   type SearchQuery =
     | { domain: 'search'; name: 'files'; projectPath: string; query: string }
     | { domain: 'search'; name: 'text'; projectPath: string; query: string }
     | {
         domain: 'search'
         name: 'code'
         projectPath: string
         query: string
         regex: boolean
         caseSensitive: boolean
         include: string
         exclude: string
       }
   ```

   `searchProjectKey` requires a non-empty project path. `fileSearchQuery`, `textSearchQuery`, and
   `codeSearchQuery` trim only the query value; code flags and include/exclude strings remain
   option-distinct. The identity schema permits an empty normalized query so a disabled adapter can
   still construct a typed key without inventing a wire value, but adapters never call the daemon
   for an empty trimmed query.

2. Runtime effect variants are exactly `files`, `text`, and `code`, each carrying a normalized
   `projectPath`. `searchNotificationEffects` is exhaustive and returns these effects in first-seen
   order: `files.scope-changed` → `files`; `files.tree-changed` → `files`; and
   `files.content-changed` → `files`, `text`, and `code`. The last mapping follows the SEA-002
   target and preserves conservative file-index freshness while content facts refresh every Search
   read family. A Search foreign-dependency mapper uses the same project path and maps
   `search:path-index` → `files` and `search:content-index` → `text` plus `code`.

3. Search owns one typed invalidation filter in each client. A Search filter matches the daemon or
   environment identity plus the Search query domain and normalized project path; `files` effects
   invalidate every file-name Search identity for that project, while `text` and `code` effects
   invalidate only their exact family. Session recovery invalidates all Search keys; project
   recovery invalidates only the named project. Repeated effects are deduplicated.

4. Web Search adapters use the existing tRPC query transport and `keepPreviousData`, but their keys
   are `[daemon scope, SearchQuery]` and their input is converted from `projectPath` to the contract
   field `repoPath`. File, text, and code hooks preserve their current return shapes and error
   presentation. The code hook passes `regex`, `caseSensitive`, `include`, and `exclude` unchanged.
   Empty trimmed input is disabled and does not reach tRPC.

5. Mobile Search adapters use the canonical Search contract procedure descriptors with the landed
   `callDaemon`/`useQuery` adapter pattern used by Files. Their keys are
   `['daemon', environmentId, SearchQuery]`, include paired/environment/project gating, preserve
   `keepPreviousData` and the current 10-second stale window, and normalize the same query and code
   options before both key construction and wire conversion. Mobile adds the missing `useTextSearch`
   hook instead of leaving text Search in a Files seam.

6. Search gets one Web notification subscription and one Mobile notification bridge. Each listens to
   the existing session gateway's typed `files.scope-changed`, `files.tree-changed`, and
   `files.content-changed` facts plus typed freshness requirements. Neither creates a watch, parses a
   raw app event, or duplicates the Files watch. Files notification handling keeps Files effects and
   Git foreign invalidation; Search notification handling owns Search event and recovery
   invalidation. Files mutation success paths delegate their Search foreign tokens to the Search
   feature's typed mapper, so mutation freshness remains explicit without raw `searchFiles`,
   `searchText`, or `searchCode` strings in Files feature code.

7. Search presentation moves into the client feature roots. Web moves the four listed Search
   components and the Search store/tests; Shell keeps the File Finder latch and keyboard mounting,
   and imports the public Search index. Mobile moves all Search presentation/data/highlight modules
   from `features/files` to `features/search`; Files keeps file-tree navigation and open-file/open-
   directory callbacks. Mobile Search controls move from `files-store.ts` to a non-persisted
   `search-store.ts`; Files navigation state remains in `files-store.ts`. Search results never enter
   either store.

8. The shared runtime package gains the public `./search` export. The architecture registry gains
   `packages/client-runtime/src/search`, `apps/web/src/features/search`, and
   `apps/mobile/src/features/search` as Search target roots. Each root has a public `index.ts`; no
   app imports into client-runtime and no compatibility re-export remains at an old Search path.

## Target ownership and public surface

The runtime public surface is:

```ts
export type SearchQuery
export type SearchCodeOptions
export type SearchQueryEffect
export type SearchForeignDependency

export function searchProjectKey(projectPath: string): string
export function fileSearchQuery(projectPath: string, query: string): SearchQuery
export function textSearchQuery(projectPath: string, query: string): SearchQuery
export function codeSearchQuery(projectPath: string, options: SearchCodeOptions): SearchQuery
export function searchFilesEffect(projectPath: string): SearchQueryEffect
export function searchTextEffect(projectPath: string): SearchQueryEffect
export function searchCodeEffect(projectPath: string): SearchQueryEffect
export function searchNotificationEffects(notification: FilesChange): readonly SearchQueryEffect[]
export function searchForeignDependencyEffects(
  projectPath: string,
  dependencies: readonly SearchForeignDependency[],
): readonly SearchQueryEffect[]
```

The `SearchCodeOptions` type is derived from the Search contract input by omitting `repoPath`; no
second handwritten wire schema is permitted. The Web and Mobile indexes expose their three hooks,
typed Search contract result types, Search notification bridge/subscription, and Search presentation
components. Files imports only the narrow Search invalidation helper needed for its foreign token
handoff; Search does not import Files presentation or Shell state.
