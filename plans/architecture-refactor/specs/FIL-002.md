**FIL-002 is not executable without a coordinated product/architecture decision.** Architecture review at `eaeef63610b9b2a3b5066a84194758bbb636871d` (FIL-001 Landed) confirmed the Draft Target contradicts the landed wire and daemon identity model. ### Contradiction

The Draft Target requires:

```text
WorkspaceFiles(projectPath, relativePath)
  → realpath containment against project root
  → symlink escape → public files.path-outside-project
  → no absolute / escaped fallback targets
```

Landed FIL-001 wire for the **eight** host-fs procedures accepts only bare/embedded host `path` strings and **no** `projectPath` / `repoPath`:

| Procedure | Live input (contracts) |
| --- | --- |
| `readFile` | `z.string()` |
| `previewHtml` | `z.string()` |
| `writeTextFile` | `{ path: string, content: string }` |
| `createFile` | `{ path: string }` |
| `createFolder` | `{ path: string }` |
| `renamePath` | `{ from: string, to: string }` |
| `duplicatePath` | `{ path: string }` |
| `trashPath` | `z.string()` |

Web (`apps/web/src/hooks/use-files.ts`) and mobile (`apps/mobile/src/features/files/*` + `file-paths.ts`) send **daemon-host absolute paths**. Mobile UI is relative; conversion to absolute happens client-side before the wire.

`files.path-outside-project` is **not** a FIL-001 public error member. Procedure `errors` arrays list only:

- `createFile` / `createFolder` → `files.already-exists`
- `renamePath` → `state.conflict`
- the other six of the eight → `[]`

Using undeclared codes violates Decision 005 / ERR-001 / `lint-procedure-contracts`. Soft `FileView` / nullable preview outcomes must **not** be rebranded as public errors (FIL-001 ruling).

### tRPC / session / recents cannot supply authoritative project identity

Daemon tRPC context is **only** `{ auth, requestId }` (`apps/daemon/src/trpc.ts`, DAE-001). There is **no** per-request active project, no operations on context, and no authoritative project-identity capability bound into Files procedures.

Session `projectPath` in `live-session.ts` / session gateway is **watch/notification scope only**. Using it to authorize arbitrary tRPC Files mutations is **hidden ambient state**, rejected by Decision 006 (operations receive explicit inputs; no process-wide or accidental capture of request scope; no complete daemon context).

Inferring a project root from `config.recentRepos` (or any path-prefix scan) is also invention: non-authoritative, ambiguous for nested roots, and changes today’s “any host path the client names” product behavior without an accepted decision.

## Behavior to preserve

- 10 MiB read ceiling: `size > 10 * 1024 * 1024` → too-large (**strictly greater**).
- Image MIME table + binary NUL heuristic (first 8 KiB) via shared `image-mime`.
- `readFile` only: `expandUserPath` for `~/` and `file://`.
- `previewHtml`: null for missing/empty/over-cap/inlined-over-cap; `MAX_HTML_BYTES = 4_194_304`; sibling inlining via `inlineLocalAssets` (escape leaves remote/absolute alone — do not tighten without decision).
- UTF-8 write including empty; `wx` createFile; non-recursive createFolder; non-overwriting rename; Finder duplicate naming (` copy`, ` copy 2`, …); OS trash via `moveToTrash`.
- Void mutation outputs; duplicate returns new path string.
- No Files RT publish from these operations in this unit.
- Search procedure behavior unchanged in residual router.
