## Objective

Route Files reads and mutations through a project-contained filesystem capability and explicit operations, preserving current read/resource behavior.

## Why this unit exists

`router/files.ts` directly imports Node fs, trash, image, evidence, and read-limit helpers, so it owns host policy and native error interpretation.

## Current behavior and evidence

`router/files.ts` calls `stat/readFile/writeFile/mkdir/rename/cp`, `moveToTrash`, `inlineLocalAssets`, `imageMimeForPath`, and `uniqueDuplicatePath`; `fs-ops.ts` currently owns duplicate naming and `read-limits.ts` owns `MAX_READ_BYTES`. Inputs can be arbitrary daemon-host paths today.

## Scope

Create `apps/daemon/src/features/files/{files-ports,files-operations,files-router,workspace-files}.ts` and tests; move the named Node/filesystem behavior from `router/files.ts`, `fs/fs-ops.ts`, and `fs/read-limits.ts` into the Files adapter/operations; bind exactly `files` operations through daemon composition.

## Non-goals

Do not move `readDir`, pins, scope storage, Search, watch activation, client cache behavior, or change public procedure names.

## Target ownership and public surface

`WorkspaceFiles` accepts a `projectPath` plus project-relative path and resolves `realpath` containment before every read/write/rename/copy/trash/preview asset access; symlink escape is `files.path-outside-project`. It returns typed adapter outcomes for not-found, exists, unsupported file, too-large, and containment; unexpected Node failures throw. Operations are `readFile`, `previewHtml`, `writeTextFile`, `createFile`, `createFolder`, `renamePath`, `duplicatePath`, and `trashPath`; successful mutations return the current contract output and do not publish changes until FIL-003 activation.

## Behavior to preserve

Preserve 10 MiB limits, binary/image/text classification, `.html/.htm` preview cap and inlined relative assets, `wx` create semantics, no-recursive mkdir, collision-safe rename, Finder duplicate naming, and recoverable OS trash.

## Legacy behavior to delete

Delete direct Node fs/trash/read-limit/evidence imports and native `ENOENT`/existence logic from `router/files.ts`; delete old `fs-ops.ts` and `read-limits.ts` exports after their behavior is moved. No path fallback accepts an absolute or escaped target.

## Ordered implementation

1. Define capability outcomes and containment resolver; port duplicate/read-limit behavior.
2. Implement adapter integration tests in temporary project trees, including symlink escape.
3. Implement one operation per procedure with focused capability fakes.
4. Bind operations to the Files router and remove direct host imports.

## Tests

Adapter tests prove containment, symlink rejection, limits, binary/image/preview, collisions, and trash; operation tests prove outcome mapping; router tests prove one bound call and ERR mapping.

## Forbidden shortcuts

Do not use string-prefix containment, trust a symlink, parse native error messages outside the adapter, add a global filesystem singleton, or publish old app events.

## Completion criteria

- [ ] Every listed Files action reaches host fs only through `WorkspaceFiles`.
- [ ] Escapes and expected file outcomes are typed and tested at the adapter boundary.
- [ ] Router direct host access is gone; tests/lint pass.

## Handoff

`FIL-003` may attach successful Files facts to the prepared RT publisher without changing operation policy.
