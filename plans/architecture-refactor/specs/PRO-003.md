# PRO-003 — Define versioned session hello/ready mismatch handling

- Status: Draft
- Batch: 0 — architecture and contract foundations
- Domain: protocol / session handshake
- Depends on: `PRO-001` (Draft), `RT-001` (Draft), `ERR-001` (Draft)
- Governing decisions: [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Define strict session `hello`, `ready`, and version-mismatch frames, plus the daemon handshake
decision that blocks a non-matching session before it can publish or receive changes.

## Why this unit exists

HTTP version matching does not protect a later long-lived session. The session contract needs one
explicit capability/version exchange before RT transports and adapters are implemented.

## Current behavior and evidence

The current WebSocket protocol accepts its initial frames in `apps/daemon/src/net/session.ts`; protocol
types are horizontal today. `RT-001` establishes the target `packages/contracts/src/session/` frame
modules.

## Scope

Own handshake schemas in `packages/contracts/src/session/session.contract.ts`, a pure
`apps/daemon/src/session/session-handshake.ts` decision module, and focused tests. It accepts a
client hello containing protocol version and returns either a versioned ready frame or the structured
mismatch frame used by the future gateway.

## Non-goals

Do not create the session gateway, watches, publisher, reconnect/replay algorithm, Web adapter, or
mobile adapter. Those belong to `RT-002` through `RT-005`.

## Target ownership and public surface

`session:hello` carries literal `protocolVersion`; `session:ready` carries daemon protocol version and
the epoch needed by the RT contract; `session:mismatch` carries received/expected versions and a
stable public error code. The handshake function is transport-neutral and has no WebSocket imports.

## Behavior to preserve

Preserve the current session authorization boundary: a client still cannot receive repository changes
until its transport has been authenticated by the gateway. Matching-version behavior makes no extra
round trip beyond hello/ready.

## Legacy behavior to delete

Delete no legacy transport here. `RT-005` deletes the old frame/transport surface only after Web and
mobile adapters use the target handshake.

## Ordered implementation

1. Add strict discriminated frame schemas to the RT session contract.
2. Implement the pure version comparison using `protocolVersion` from `PRO-001`.
3. Add table-driven ready/mismatch tests without opening a socket.
4. Document the gateway integration point for `RT-002` and adapter obligations for `RT-004`/`RT-005`.

## Tests

Test valid hello, missing/malformed version rejection, equal version ready, and older/newer version
mismatch frames. Verify every produced frame parses against the session contract.

## Validation and evidence

```text
pnpm --dir apps/desktop test -- ../../packages/contracts/src/session/session.contract.test.ts ../daemon/src/session/session-handshake.test.ts
pnpm lint
git diff --check
```

## Forbidden shortcuts

Do not silently accept a mismatch, compare app releases, add a WebSocket dependency to the decision
module, or change client transport callers in this recipe.

## Completion criteria

- [ ] Hello, ready, and mismatch are strict shared frames.
- [ ] The daemon decision is transport-neutral and rejects every version mismatch.
- [ ] Contract/decision tests, lint, and diff check pass.

## Handoff

`RT-002` wires the pure decision into the daemon gateway. `RT-004` and `RT-005` must send hello and
handle ready/mismatch before legacy transport deletion.
