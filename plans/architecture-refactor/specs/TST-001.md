- Status: Draft
- Batch: 0 — architecture and contract foundations
- Domain: supporting test infrastructure
- Depends on: CON-021, ERR-001, RT-001
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Web and mobile feature adapters will test configured daemon outcomes through one transport-independent mock that validates every request, response, notification, and public error against the completed contracts.

## Why this unit exists

The current Web harness, `apps/web/src/hooks/trpc-test-harness.tsx`, is tied to `AppRouter`; mobile instead tests local descriptors under `apps/mobile/src/lib/daemon/`. Decision 011 requires one public-boundary mock rather than either app repeating daemon behavior.

## Current behavior and evidence

- `packages/contracts/src/procedures/{names,io,refined}.ts` currently owns a partial catalog;
  CON-001 through CON-021 replace it with domain-composed exhaustive contracts.
- `apps/web/src/hooks/trpc-test-harness.tsx` creates a typed tRPC terminating link and answers unvalidated `op.path`/`op.input` cases by hand.
- `apps/web/src/hooks/use-board.test.ts` demonstrates the current Web pattern with deferred board reads/writes.
- `apps/mobile/src/lib/daemon/{procedure,queries,provider}.ts(x)` and `procedures/{changes,workspace}.test.ts` use mobile-local descriptors and Zod output parsing.
- `apps/desktop/vitest.config.ts` is the one unit-test runner and already resolves `@porcelain/contracts` and `@porcelain/client-runtime` source aliases.

## Scope

- Add `packages/contracts/src/testing.ts` and `packages/contracts/src/testing.test.ts`.
- Add the `./testing` subpath to `packages/contracts/package.json`.
- Add `packages/client-runtime/src/testing/daemon-mock.ts` and `packages/client-runtime/src/testing/daemon-mock.test.ts`.
- Add the `./testing/daemon-mock` subpath to `packages/client-runtime/package.json`.
- Change only the test harness imports required to prove the new helpers in `apps/web/src/hooks/trpc-test-harness.tsx` and its direct tests; do not migrate any feature test in this unit.

## Non-goals

- Do not change daemon procedures, routers, client feature hooks, React Query adapters, WebSocket transport implementations, or E2E fixtures.
- Do not implement Board contracts; BRD-001 owns them.
- Do not model daemon domain rules in mock handlers, add an in-memory persistence store, or create a fake tRPC server.

## Target ownership and public surface

- `@porcelain/contracts/testing` will export `defineContractFixture`, `parseContractFixture`, and `ContractFixture`. A fixture is parsed by the supplied contract schema before it is returned; fixture builders never hand-author a parallel TypeScript shape.
- `@porcelain/client-runtime/testing/daemon-mock` will export `createValidatingDaemonMock`, `ValidatingDaemonMock`, `DaemonMockRequest`, `DaemonMockOutcome`, and `DaemonMockNotification`.
- `DaemonMockRequest` will contain `procedure`, `kind`, and `input`; `procedure` is the exact
  procedure identifier from CON-021 and `kind` is `query` or `mutation`.
- `createValidatingDaemonMock(catalog, handlers)` will parse request input with the catalog input schema, invoke the configured handler, parse a success value with the catalog output schema, parse an expected failure with the catalog public-error schema, record the request, and expose `emit(notification)` only after parsing that notification with the catalog notification schema.
- The mock will expose `dispatch(request)`, `subscribe(listener)`, `requests()`, and `clearRequests()`. It will not import React, tRPC, WebSocket, app source, or daemon source.
- Web and mobile transport test adapters will translate their framework request shape into `DaemonMockRequest`; the mock will not know either framework.

## Behavior to preserve

- Existing Web hook tests will remain deterministic and may use deferred promises to prove pending, rollback, and reconciliation.
- Mobile tests will continue to test endpoint, Secure Store, foreground and socket adapter behavior without requiring a Web runtime.
- Test mocks will reject malformed configured input, success output, notification, and public error rather than silently accepting drift.

## Legacy behavior to delete

- Delete no production path in this foundation unit.
- Delete only the duplicated validation logic moved from `apps/web/src/hooks/trpc-test-harness.tsx`; retain the file as a Web tRPC adapter until BRD-004 replaces its Board callers.
- Do not delete mobile local procedure descriptors here; BRD-005 and later domain cutovers own each exact deletion.

## Ordered implementation

1. Verify CON-021, ERR-001, and RT-001 are Landed and expose exhaustive procedure, public-error,
   and notification schemas. Stop if any catalog entry still uses `z.unknown()`.
2. Add the contracts testing subpath and implement schema-validating fixture helpers with no application imports.
3. Add the client-runtime daemon mock, using only the completed contract catalog and testing helpers; make malformed configured outcomes throw before a client adapter receives them.
4. Add direct tests for valid request/response, malformed input, malformed output, configured expected error, malformed error, valid notification, malformed notification, request recording, listener unsubscribe, and `clearRequests()`.
5. Refactor the Web tRPC harness to translate a tRPC operation into the mock request and translate a mock success/error back to the tRPC test link. Preserve deferred asynchronous behavior.
6. Run its existing direct tests and add one harness test proving a malformed Board fixture is rejected before the hook can render it. Do not update the Board feature tests.

## Tests

- `packages/contracts/src/testing.test.ts`: builder values are parsed at construction and invalid fixture values fail.
- `packages/client-runtime/src/testing/daemon-mock.test.ts`: all dispatch and notification validation, request recording, subscription, and expected-error cases listed above.

## Forbidden shortcuts

- Do not use `AppRouter`, `AnyTRPCRouter`, `z.unknown()`, raw procedure-name strings, or handwritten duplicate wire types in the contracts/client-runtime helpers.
- Do not make mock handlers call daemon routers, stores, operations, filesystem, Git, network, or process code.
- Do not add React, React Native, tRPC, WebSocket, or test-library dependencies to client-runtime.
