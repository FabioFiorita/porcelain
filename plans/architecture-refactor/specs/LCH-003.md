# LCH-003 — Run clean-checkout verify and named browser, Terminal, and packaging evidence

- Status: Draft
- Batch: 9
- Domain: Agent foundations and launch
- Depends on: SUP-003, E2E-001, LCH-002
- Governing decisions: 009, 011, 014, 015
- Primary exemplar: no

## Objective

Produce final launch evidence from a clean checkout: full verify, named critical browser wiring, Terminal stream/reconnect, and Desktop packaging/one-daemon proof.

## Why this unit exists

Passing unit tests do not prove the assembled client, daemon, CLI/watcher, Terminal, and packaged Desktop boundaries. Conversely, broad UI E2E is not launch evidence after E2E-001 relocation.

## Current behavior and evidence

- Root `pnpm verify` is lint, tests, build, and desktop E2E typecheck.
- E2E-001 defines the retained browser critical wiring suite.
- SUP-003 names Desktop lifecycle, URL, preload, package/native dependency, and one-daemon proof; native Electron evidence is macOS-local.

## Scope

- Use a fresh clean checkout and isolated dev fixture roots only.
- Run named commands and record artifacts/results; do not publish, sign, reset real data, or push.

## Non-goals

- Do not re-expand E2E with product/UI branches or substitute installed/prod daemon proof for the browser dev lane.
- Do not claim macOS-native evidence from Linux.

## Target ownership and public surface

Launch evidence contains: clean checkout revision; `pnpm verify`; critical browser suite artifacts; Terminal create/attach/data/detach/reconnect and scrollback assertion; Desktop one-daemon/safe-URL/packaging test results; and, on macOS, native Electron packaging proof. Browser is daemon-served dev client; Electron-native is supplementary.

## Behavior to preserve

Preserve clean fixture isolation, authentication/token safety, no production daemon use, Terminal recovery semantics, and packaging constraints.

## Legacy behavior to delete

Delete no code/data. Supersede only obsolete broad E2E launch claims after E2E-001's ledger has relocated them.

## Ordered implementation

1. Create a clean checkout/worktree and install dependencies without reusing user project/userData fixtures.
2. Run `pnpm verify` and save full output.
3. Run `pnpm --dir apps/desktop test:e2e -- --project=browser apps/desktop/e2e/critical-wiring.spec.ts`; save traces/screenshots/results.
4. Run SUP-003 focused Desktop tests and `pnpm build`; record one-daemon lifecycle, safe URL, preload boundary, renderer/daemon artifact, and native dependency assertions.
5. In a macOS environment, run `pnpm --dir apps/desktop test:e2e:native` and packaging smoke per Releasing/packaging procedure; otherwise record native proof as environment-not-run, never pass it by inference.
6. Confirm all evidence references isolated dev roots and contains no token/plain secret.

## Tests

- `pnpm verify`.
- Critical browser wiring command above.
- `pnpm --dir apps/desktop test src/main/remote-daemon.test.ts src/main/renderer-packaging.test.ts src/main/local-terminal-paths.test.ts`.
- macOS-only native command when that environment is available.

## Validation and evidence

Attach command transcripts, browser artifacts, test results, commit revision, fixture-root declaration, and macOS-native status. Record failures as failures; no waived launch claim.

## Forbidden shortcuts

- Do not run against production port/data, hand-edit a failing artifact, or omit the Terminal reconnect assertion.
- Do not claim packaging/native proof from a browser build.
- Do not publish or push as part of evidence.

## Completion criteria

Clean-checkout verify, named browser critical suite, Terminal wiring, and Desktop packaging/one-daemon proofs pass with artifacts; macOS native status is explicit. No production data/system changed.

## Handoff

Human release authorization remains separate and uses the Releasing procedure; LCH-003 only supplies evidence.
