# REM-004 — Move Web Remote settings to shared semantics

- Status: Draft
- Batch: 3 — remaining domain cutovers
- Domain: remote
- Depends on: REM-003, PRO-004, RT-005, TST-001
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Web local/remote/shell adapters consume canonical Remote contracts and REM-003 while Settings remains presentation only.

## Why this unit exists

Remote hooks mix shell RPC, daemon HTTP, token gate, listener settings and raw error/session interpretation.

## Current behavior and evidence

`hooks/use-{daemon-identity,remote-daemon,share,lan,tailnet,funnel,token-gate}.ts` feed `components/settings/{remotes-section,share-section}.tsx`; `lib/daemon.ts` owns browser session state.

## Scope

Create `apps/web/src/features/remote/{remote-data,remote-session,remote-settings,index}.ts`; move named hook callers; retain the Electron shell bridge as a narrow injected adapter.

## Non-goals

Do not alter daemon auth/listener operations, Electron APIs, pairing policy, setting copy or mobile storage.

## Target ownership and public surface

`remote-data.ts` exports canonical Remote queries/mutations; `remote-session.ts` binds browser/local session transport to REM-003/RT-005 and exposes health/update-required; `remote-settings.ts` maps typed values/failures to controls. `index.ts` is the sole settings import boundary. Shell RPC remains behind `WebLocalRemoteAdapter`, never a daemon type import.

## Behavior to preserve

Keep local-versus-remote selection, token gate, protocol header, listener controls, pairing/share feedback, reconnect recovery and safe error copy.

## Legacy behavior to delete

Delete direct remote tRPC/HTTP/error/session logic from Settings hooks and raw daemon-model imports after callers move.

## Ordered implementation

1. Verify REM-003, PRO-004 and RT-005.
2. Implement the Web adapters and Settings entry surface.
3. Move settings callers and delete raw hooks/imports.

## Tests

Test endpoint selection, header/update-required, retry health, typed failures and listener controls through contract-valid adapters; retain settings component accessibility/copy tests.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../web/src/features/remote ../web/src/components/settings`.
- Run `pnpm lint`.
- Run `rg -n "@backend|error\.message|use(RemoteDaemon|DaemonIdentity|TokenGate|Share|Lan|Tailnet|Funnel)" apps/web/src/hooks apps/web/src/components/settings`; it returns no result after relocation.

## Forbidden shortcuts

Do not embed endpoint ordering/retry in components, parse old error shapes, or add a second session.

## Completion criteria

- [ ] Web Remote behavior is behind one feature boundary over shared semantics.
- [ ] Settings retains presentation and safe recovery behavior.
- [ ] Tests, lint and search pass; the unit is committed.

## Handoff

REM-005 applies the same contract/runtime to mobile strict-v1 storage.
