## Objective

Web Remote settings, browser token gate, and session reconnect consume
REM-003 plus `remoteProcedures` behind `apps/web/src/features/remote`, while
Settings and shell chrome stay presentation and the Electron shell bridge
stays an injected adapter.

## Why this unit exists

Remote hooks mix shell RPC, daemon HTTP, token gate, listener toggles, and
raw `Error.message` / session interpretation. REM-003 owns order, retry,
health, and public-error parse; Web still has no feature boundary over them.

`createSessionBrowserAdapter` changes (file stays in `lib/`):

- Import `nextRemoteRetry`, `resetRemoteRetry`, `createSessionHealth`.
- Add required-capable `random: () => number` option; production default
  is `Math.random` **at this adapter** (platform RNG). Do not default
  `random` inside client-runtime.
- Optional `health: SessionHealth`; `createDaemonSession` always passes
  `createSessionHealth()`.
- On `opened`: `retryDelay = resetRemoteRetry()`; `health.apply({ type: 'connected' })`.
- On schedule: `const step = nextRemoteRetry(retryDelay, random)`; wait
  `step.waitMs`; then `retryDelay = step.delayMs`.
- On `start`: `health.apply({ type: 'start' })`.
- On socket `closed` while running: `health.apply({ type: 'disconnected' })`
  then reconnect (first-drop stays `connecting` via the health table;
  adapter `SessionConnectionStatus` still sets `connecting` when
  `everConnected === false` and `reconnecting` after a successful open —
  keep that RT-004 vocabulary).
- On `stop`: `health.apply({ type: 'stop' })`.
- On `updateRequired`: `health.apply({ type: 'update-required' })`.
