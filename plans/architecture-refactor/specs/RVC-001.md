# RVC-001 — Move Review comment wire behavior into explicit operations

- Status: Draft
- Batch: 2 — focused behavior exemplars
- Domain: review
- Depends on: `CON-021`, `ERR-001` (Draft), `RT-005` (Draft), `DAE-001` (Draft), `TST-002` (Draft), `DAT-001` (Draft)
- Governing decisions: [003](../decisions/003-application-operations-own-orchestration.md), [005](../decisions/005-contracts-own-the-wire.md), [006](../decisions/006-compose-explicit-capabilities.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Make the six existing Review comment procedures call typed Review operations over a narrow comment store capability and publish the canonical `review.changed` fact after successful mutations.

## Why this unit exists

Comments are the first optimistic client exemplar, so server operations must make their exact success/failure boundaries stable before `RVC-002` defines shared optimism.

## Current behavior and evidence

`apps/daemon/src/router/review.ts` directly invokes `readComments`, `addComment`, `editComment`, `deleteComment`, `setCommentResolved`, and `clearResolvedComments` from `apps/daemon/src/stores/comment-store.ts`. That store persists active-review comments through `net/project-channel.ts` at `ACTIVE_FILES.comments`; its local schema and no-op edits/deletes are current behavior. The procedures are `reviewComments`, `addReviewComment`, `editReviewComment`, `deleteReviewComment`, `clearResolvedReviewComments`, and `resolveReviewComment`.

## Scope

Create `apps/daemon/src/features/review/comments.{ts,ports.ts,router.ts}.ts` and focused tests; move comment Zod wire values to `packages/contracts/src/review/review.contract.ts`; add the Review operation to `daemon-operations.ts` and bind it only to the Review router factory. Adapt `comment-store.ts` to the `DAT-001` versioned adapter convention.

## Non-goals

Do not define client optimism/cache consequences, move other Review procedures, change archive/clear Review behavior, add comment replies, alter CLI semantics, or rename current public procedure names.

## Target ownership and public surface

`ReviewCommentsPort` exposes `read`, `append`, `replace`, and `removeResolved` for one repository; it never exposes a project channel. `createReviewCommentOperations(port, publish)` exports one operation per public intention. Add/edit/resolve return `ExpectedFailure` with exact `review.comment-not-found` for an unknown id; add rejects an end line below its start line as `request.invalid`. Successful mutations publish one `review.changed` for the same `projectPath` only after the version-1 write succeeds. Router procedures call exactly one bound operation and map expected failure through `ERR-001`.

## Behavior to preserve

Preserve UUID creation, descending `createdAt` read order, optional anchors/ranges, resolved default, active-review storage location, CLI-readable data, atomic writes/corruption handling, and silent clear-resolved when no resolved comment exists.

## Legacy behavior to delete

Delete `reviewCommentSchema` and direct comment-store imports from `router/review.ts`, direct router mutation logic, and the unversioned comments-array persistence shape. Do not retain a router fallback to the old store API.

## Ordered implementation

1. Transcribe strict comment input/output schemas and expected error declarations into Review contracts.
2. Define the narrow port and operations; test not-found/range validation before adapter wiring.
3. Make the comments adapter own the version-1 envelope under the DAT convention and normalize only declared corruption/native failures.
4. Bind the operation in daemon composition, replace six router bodies, and publish after success.
5. Delete direct router/store schema ownership and update focused router tests.

## Tests

Test contract valid/invalid comments; operation add/edit/delete/resolve/clear ordering and expected failures with a focused port fake; adapter ordering/atomic/corrupt-envelope behavior in a temporary directory; router output/error mapping and one `review.changed` emission.

## Forbidden shortcuts

Do not expose `ProjectChannel`, inspect native error text in an operation, publish before persistence, return a raw `Error` for a missing comment, or add client/cache behavior.

## Completion criteria

- [ ] Six procedures use one bound Review-comment operation each.
- [ ] Comment wire values/errors are contract-owned and outputs validate through CON-021.
- [ ] Successful mutations publish exactly one canonical Review change after the write.
- [ ] Direct router/store coupling and local schema ownership are absent; tests and lint pass.

## Handoff

`RVC-002` may define optimistic transitions against stable operation results and `review.changed`.
