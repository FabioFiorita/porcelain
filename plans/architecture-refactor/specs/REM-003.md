## Objective

Client-runtime owns contract-valid endpoint ordering, retry/session-health transitions and public-error classification without platform storage or sockets.

## Why this unit exists

Web `lib/daemon.ts`/remote hooks and mobile environment/client/errors/session modules duplicate endpoint fallback, reachability and message interpretation.

## Current behavior and evidence

Mobile persists version-3 environments and maps local `DaemonError`; Web mixes local shell routing with remote HTTP/session behavior.

## Scope

Add `packages/client-runtime/src/remote/{endpoints,retry,session-health,public-errors,index}.ts` with tests and `./remote` export.

## Non-goals

Do not access Secure Store/localStorage, open a socket, perform pairing, render settings, or retain legacy error shapes.

## Target ownership and public surface

Export `orderRemoteEndpoints`, `nextRemoteRetry`, `createSessionHealth`, `parsePublicError`, and `RemoteSessionHealth`. Inputs/outputs use REM-001 contracts and ERR-001 `PorcelainError`; retry distinguishes unreachable/retryable from terminal auth/protocol failure; matching protocol mismatch is terminal and never retried. Health exposes `idle`, `connecting`, `healthy`, `recovering`, `unavailable`, and `update-required` transitions without transport implementation.

## Behavior to preserve

Keep endpoint preference/order, bounded backoff, pairing authorization, no unsafe error text, reconnect recovery and explicit protocol-update state.

## Legacy behavior to delete

Delete no app module here; REM-004 and REM-005 replace their respective platform error/retry/environment paths.

## Ordered implementation

1. Verify REM-001/002, ERR-001, PRO-004 and RT-003 contracts.
2. Implement pure ordering/retry/health/error parsing with injected time/outcomes.
3. Add fixtures for all public errors and endpoint states.

## Tests

Test endpoint ordering/dedup, bounded retry, health transitions, retryable/nonretryable errors, redacted parsing, and update-required terminal behavior.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../../packages/client-runtime/src/remote`.
- Run `pnpm lint`.
- Run `rg -n "react|WebSocket|SecureStore|localStorage|error\.message|z\." packages/client-runtime/src/remote`; it returns no result.

## Forbidden shortcuts

Do not parse native messages, persist endpoint state, construct wire schemas, or use retry as compatibility fallback.

## Completion criteria

- [ ] Remote ordering, retry, health and public errors have one shared pure owner.
- [ ] Tests prove protocol/error safety and no platform dependency.
- [ ] Lint/search pass; the unit is committed.

## Handoff

REM-004 and REM-005 bind platform storage/transport/UI to this runtime.
