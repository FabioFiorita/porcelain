## Objective

Client-runtime owns contract-valid Remote endpoint ordering, injected retry
steps, session-health transitions, and public-error classification without
platform storage or sockets.

## Why this unit exists

Web `lib/daemon.ts` / remote hooks and mobile environment / client / errors /
session modules duplicate endpoint fallback, reachability, and message
interpretation. REM-004 and REM-005 cannot bind one policy until that policy
has a pure owner.

### Contracts and daemon (do not change)

- `packages/contracts/src/environment.ts` — `endpointKind` and
  `orderedEndpointUrls`. Kinds are `tailnet | lan | other`.
  `orderedEndpointUrls({ url, endpoints?, preferredEndpoint? })`:
  1. `all = endpoints` when that array is non-empty, else `[url]`.
  2. Preferred is prepended only when it is already in `all`.
  3. Order is `Set([preferred?, url, ...all])` then
     `.filter((candidate) => all.includes(candidate))`.
  4. Empties and duplicates follow that `Set` + filter. A preferred or
     last-known-good URL that is not in `all` is dropped.
  5. Comparison is exact-string. No lowercasing, trailing-slash strip, or
     kind sort lives here.
- `endpointKind(url)` is display-only: `localhost` / `*.local` / RFC1918 →
  `lan`; CGNAT `100.64–127` and `http://*.ts.net` → `tailnet`; everything
  else — including `127.0.0.1`, `https://*.ts.net` Funnel, named hosts, and
  unparseable strings — is `other`. **Kind never changes walk order.**
- `packages/contracts/src/errors/public-errors.ts` —
  `publicErrorSchema`, `PorcelainError`. System retryability:
  `request.invalid`, `auth.unauthenticated`, `auth.forbidden`,
  `internal.unexpected`, `protocol.update-required` are `retryable: false`;
  `resource.unavailable` is `retryable: true`. Domain members keep their
  declared flags. `protocol.update-required` details are
  `{ expected: number; received: number | null }`.
- `packages/contracts/src/errors/fixtures.ts` —
  `publicErrorFixtures['protocol.update-required']`.
- ERR-002 tRPC formatter (`apps/daemon/src/daemon-composition/public-error.ts`)
  attaches exactly `data.porcelain: PorcelainError`.
- ERR-003 / REM-002 HTTP (`createRemoteHttp` `writePublicError`) writes the
  bare `PorcelainError` JSON body. Protocol mismatch is HTTP 409 with
  `publicErrorFor('protocol.update-required', requestId, { expected, received })`.
- PRO-004 / RT-003 session mismatch
  (`packages/contracts/src/session/session.contract.ts`
  `sessionMismatchFrameSchema`):
  `{ t: 'session:mismatch', code: 'protocol.update-required', expected, received }`.
  `createSessionClientRuntime` sets `update-required` and does not send
  another hello (`packages/client-runtime/src/session/client-runtime.ts`).

### Shared session retry (both clients already agree)

- `packages/client-runtime/src/session/transport.ts` —
  `MIN_RETRY_MS = 500`, default `MAX_RETRY_MS = 8_000`,
  `nextRetryDelay(current, max)`, `reconnectDelayMs(base, random)` =
  `base + random() * base * 0.3`.
- `apps/web/src/lib/session-browser-adapter.ts` and
  `apps/mobile/src/lib/daemon/session-native-adapter.ts` both override the
  cap to `MAX_RETRY_MS = 10_000`, start at `MIN_RETRY_MS`, reset to `500` on
  `opened`, and schedule with `reconnectDelayMs`. Status vocabulary:
  `idle | connecting | open | reconnecting | update-required`.
- First close before any successful `opened` reports `connecting` on the
  next `connect()` (`everConnected === false`). After a successful open,
  close reports `reconnecting`.
- `updateRequired()` sets `running = false` and `update-required`. Web
  `stop()` returns immediately when `!running`, so it cannot leave
  `update-required`. Mobile `ensureOpen` refuses to `start()` while
  `update-required`.

Reuse landed helpers; do not fork the math:

```ts
export const REMOTE_MIN_RETRY_MS = 500
export const REMOTE_MAX_RETRY_MS = 10_000

export type RemoteRetryStep = {
  readonly delayMs: number
  readonly waitMs: number
}
```

- `resetRemoteRetry()` returns `REMOTE_MIN_RETRY_MS`.

### `public-errors.ts`

```ts
export type RemotePublicErrorParse =
  | { readonly kind: 'public'; readonly error: PorcelainError }
  | {
      readonly kind: 'update-required'
      readonly error: PorcelainError
    }
  | { readonly kind: 'unreachable' }

export function parsePublicError(value: unknown): RemotePublicErrorParse
export function isRemoteRetryable(parsed: RemotePublicErrorParse): boolean
```

`parsePublicError` algorithm (order is required):

1. If `value` is a non-null object with `t === 'session:mismatch'`,
   `sessionMismatchFrameSchema.safeParse(value)`. On success return
   `{ kind: 'update-required', error }` where `error` is
   `publicErrorSchema.parse({ ...publicErrorFixtures['protocol.update-required'], details: { expected, received } })`
   with the fixture `requestId` and `message` (this unit does not mint IDs).
   On mismatch-frame parse failure, fall through.
2. Let `candidate` be `value.porcelain` when that own property exists,
   else `value.data.porcelain` when `data` is a non-null object with that
   own property, else `value`.
3. `publicErrorSchema.safeParse(candidate)`. On success:
   - `code === 'protocol.update-required'` → `{ kind: 'update-required', error }`
   - otherwise → `{ kind: 'public', error }`
4. Otherwise `{ kind: 'unreachable' }`.

`isRemoteRetryable`:

- `unreachable` → `true`
- `update-required` → `false`
- `public` → `error.retryable`

So `auth.unauthenticated`, `auth.forbidden`, `request.invalid`, and
`internal.unexpected` are terminal; `resource.unavailable` and other
`retryable: true` members retry; a missing / malformed envelope is
unreachable (the walk continues). Do not branch on HTTP status or tRPC
code strings.

### `session-health.ts`

```ts
export type RemoteSessionHealth =
  | 'idle'
  | 'connecting'
  | 'healthy'
  | 'recovering'
  | 'unavailable'
  | 'update-required'

export type RemoteSessionOutcome =
  | { readonly type: 'start' }
  | { readonly type: 'stop' }
  | { readonly type: 'connected' }
  | { readonly type: 'disconnected' }
  | { readonly type: 'walk-exhausted' }
  | { readonly type: 'update-required' }

export type SessionHealth = {
  readonly apply: (outcome: RemoteSessionOutcome) => RemoteSessionHealth
  readonly status: () => RemoteSessionHealth
  readonly everConnected: () => boolean
}

export function createSessionHealth(): SessionHealth
```

Transition table (authoritative):

| From | Outcome | To | Notes |
| --- | --- | --- | --- |
| `idle` | `start` | `connecting` | |
| `unavailable` | `start` | `connecting` | mobile `retryConnection` |
| `connecting` | `connected` | `healthy` | sets `everConnected` |
| `recovering` | `connected` | `healthy` | resets retry in the adapter |
| `unavailable` | `connected` | `healthy` | |
| `connecting` | `disconnected` | `connecting` | first-attempt drop (`everConnected === false`) |
| `healthy` | `disconnected` | `recovering` | adapter `reconnecting` |
| `recovering` | `disconnected` | `recovering` | |
| any except `update-required` | `walk-exhausted` | `unavailable` | finished preference walk |
| any | `update-required` | `update-required` | terminal |
| `update-required` | `start` / `stop` / `connected` / `disconnected` / `walk-exhausted` | `update-required` | no-op |
| `idle` | `stop` | `idle` | |
| `connecting` / `healthy` / `recovering` / `unavailable` | `stop` | `idle` | |
| `healthy` / `recovering` / `connecting` | `start` | unchanged | adapter `start` is idempotent while running |
| `idle` | `disconnected` / `walk-exhausted` / `connected` | unchanged | outcomes without `start` do not invent a session |

No clock, timer, or socket. Adapters inject outcomes after they classify
errors and finish or abandon a walk.

## Behavior to preserve

- Preferred exact URL first, then last-known-good `url`, then remaining
  stored endpoints, deduped, never yielding an address the group no longer
  knows.
- Preference is not updated when a fallback answers.
- Bounded reconnect: 500 ms, double, cap 10 s, 0–30% injected jitter.
- Pairing / auth refusals are terminal (`auth.*`); they do not walk the
  next URL and do not schedule backoff.
- Protocol mismatch is one `update-required` outcome on HTTP, tRPC
  `data.porcelain`, and `session:mismatch`. No retry into a daemon that
  already refused this build.
- Unreachable and `retryable: true` public errors remain the only retry
  classes.
- Safe public `message` is copy, never a parse key.
