## Objective

Move `searchFiles`, `searchText`, and `searchCode` from Files router wiring to Search operations over narrow Git-list/grep and Files-scope capabilities.

## Why this unit exists

`router/files.ts` directly combines Git listing/grep, hidden paths, candidate construction, and fuzzy search, obscuring Search as the owning intention.

## Current behavior and evidence

`router/files.ts` calls `gitGrep`, `gitSearchCode`, `gitListSearchFiles`, `hiddenPathsForRepo`, `searchCandidates`, and `fuzzySearch`; the exact inputs/results live in `CON-005` contracts.

## Scope

Create `apps/daemon/src/features/search/{search-ports,search-operations,search-router}.ts` and tests; move three router procedures and existing `search/{fuzzy,search-candidates,suggestions}.ts` ownership into Search without moving Git process adapters or Files scope storage.

## Non-goals

Do not alter Search UI, Git list cache implementation, Files watch facts, procedure names, fuzzy ranking/50-result cap, or cross-domain storage.

## Target ownership and public surface

`SearchGit` reads searchable files/text/code; `SearchScope` reads hidden project paths. Operations normalize blank file-name query to `[]`, preserve code flags, filter hidden candidates, and return contract values. Known unavailable/non-project outcomes map through declared Search/Git public failures; native process parsing remains in Git capability adapters.

## Behavior to preserve

Preserve loose ignored-file inclusion, ignored-directory exclusion, `.DS_Store` filtering, stale-while-revalidate list behavior, fuzzy ordering/cap, current grep/code result parsing, and hidden-path filtering.

## Legacy behavior to delete

Delete Search imports and three procedure bodies from `router/files.ts`; no `features/files` Search re-export or direct foreign store import remains.

## Ordered implementation

1. Define narrow ports from existing Git/Files functions.
2. Move pure candidate/fuzzy functions under Search and test unchanged fixtures.
3. Bind three operations to a Search router via composition.
4. Delete router/files Search code and prove route names remain flat.

## Tests

Test blank query, hidden filtering, ignored-file policy, ranking/cap, code flags, typed failures, and router mapping with narrow fakes plus existing parser tests.

## Forbidden shortcuts

Do not call Git/Files operations, duplicate their adapters, change ranking, or leave a Files-owned Search alias.

## Completion criteria

- [ ] Search router/operations own exactly three intentions over narrow ports.
- [ ] Existing result semantics and caps remain proved.
- [ ] Files router has no Search code; tests/lint pass.
