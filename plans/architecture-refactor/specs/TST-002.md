# TST-002 — Establish operation fakes and controlled adapter fixtures

- Status: Draft
- Batch: 0
- Domain: Test foundations
- Depends on: DAE-001, TST-001
- Governing decisions: 001, 004, 006, 014
- Primary exemplar: yes

## Objective

Provide one deferred bound-operation stub for narrow router mapping tests and one controlled
filesystem fixture for real adapter tests. Operation tests use domain-capability fakes, prove
outputs/state/failures without daemon globals, and adapters use real isolated filesystem behavior.

## Why this unit exists

DAE-001 supplies a composition seam, but there is no shared fake or isolated adapter fixture. Later
migrations would otherwise use module mocks, production home directories, or daemon-wide tests.

## Current behavior and evidence

- Current routers import stores directly; no bound operation has a standard fake shape.
- `net/home-channel.ts` and `net/project-channel.ts` retain atomic rename, serialized mutation,
  limits, and corrupt-file handling that must be exercised on a real filesystem.
- `*.tmp` and `*.corrupt-*` are retained resilience artifacts, not compatibility behavior.

## Scope

- Add `apps/daemon/src/testing/operation-stub.ts`, `temporary-directory.ts`, and `test-clock.ts`.
- Add a same-name `.test.ts` file for each helper.
- Add one construction-seam example to the DAE-001 composition test.

## Non-goals

- Do not rewrite an existing store/router/domain test, add a dependency, mock Node/timers/modules
  globally, or use user/home/check-out companion data or a live daemon port.

## Target ownership and public surface

`operation-stub.ts` exports:

```ts
export interface RecordedCall<Input> { input: Input }
export interface DeferredOperationStub<Input, Output> {
  readonly calls: readonly RecordedCall<Input>[]
  readonly operation: (input: Input) => Promise<Output>
  resolve(value: Output): void
  reject(error: Error): void
}
export function createDeferredOperationStub<Input, Output>(): DeferredOperationStub<Input, Output>
```

It starts unresolved. `operation` records a `structuredClone` deep-frozen input and waits for the
next settlement. A second outstanding call throws `OperationFake may serve one pending call at a
time`; resolve/reject without a pending call throws.

`temporary-directory.ts` exports
`withTemporaryDirectory<T>(prefix: string, run: (path: string) => Promise<T> | T): Promise<T>`;
it creates a unique directory under `os.tmpdir()` and removes only that exact directory in `finally`.
`test-clock.ts` exports `createTestClock(initial: Date)` with `now(): Date` and
`advance(milliseconds: number): void`; it rejects non-finite and negative advances.

## Behavior to preserve

- Existing runner and tests remain unchanged.
- Adapter tests use actual Node filesystem semantics.
- A fake rejection is the exact supplied `Error`, never a swallowed/default result.

## Legacy behavior to delete

Delete no production behavior. New migrated operation tests stop adding ad-hoc unresolved promises
or module-level mocks.

## Ordered implementation

1. Implement `createDeferredOperationStub` with a single internal deferred; consume it on settlement and
   deep-freeze only the cloned recorded input.
2. Test snapshot isolation, resolution, exact rejection identity, invalid settlement, and overlapping
   call failure in `operation-stub.test.ts`.
3. Implement `withTemporaryDirectory`; test nested write, absolute unique path, cleanup after
   success, and cleanup after throw.
4. Implement and test `createTestClock`: distinct returned dates, exact advance, invalid advance.
5. Add an executable convention comment in `operation-stub.ts`: router tests stub only the one bound
   operation; operation tests construct domain-specific capability fakes and primarily assert
   results/state; adapter tests construct real adapters inside `withTemporaryDirectory`.
6. Extend the DAE-001 composition test to prove the operation catalog is supplied at construction,
   not replaced through a module mock.

## Tests

- The three focused helper tests cover their entire public state/failure contracts.
- `create-daemon-router.test.ts` demonstrates the no-global-mock construction seam.
- `pnpm --dir apps/desktop test ../daemon/src/testing/operation-stub.test.ts ../daemon/src/testing/temporary-directory.test.ts ../daemon/src/testing/test-clock.test.ts`, `pnpm test`, and `pnpm lint` pass.

## Validation and evidence

Run the three focused central-Vitest paths, `pnpm test`, and lint. Record the temporary-path cleanup
and exact-error identity assertions as proof that adapter and operation failure behavior remains
observable.

## Forbidden shortcuts

- Do not return `undefined` as a fake default or use `vi.mock`, fake timers, monkey-patching, or a
  mutable global queue.
- Do not put production adapter constructors in `apps/daemon/src/testing`.
- Do not delete temporary directories by glob or parent directory.

## Completion criteria

- Every helper has focused tests and an explicit failure contract.
- A domain can test its operation with narrow fakes and its adapter on isolated real storage.
- Focused central-Vitest tests, `pnpm test`, and lint pass.

## Handoff

BRD-002 is the first consumer: its router test uses `createDeferredOperationStub`, its operation
tests use a focused BoardStore fake, and its adapter test uses `withTemporaryDirectory`.
