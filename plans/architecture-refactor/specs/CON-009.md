## Objective

Actions owns six exact procedure records and reduces the ledger from 14 to 8 names.

## Why this unit exists

Actions currently resides in `router/terminal.ts`, despite separate command/trust ownership.

## Current behavior and evidence

`apps/daemon/src/router/terminal.ts` declares all six names and their authoritative inputs and
outputs. `apps/daemon/src/stores/actions-store.ts` owns the stored `Action`, derived `ActionView`,
defaults, and return types. The temporary wire schema is `actionSchema` in
`packages/contracts/src/procedures/refined.ts`; the mobile duplicate in
`apps/mobile/src/lib/daemon/procedures/terminal.ts` is evidence only and is not changed here.

## Scope

Create `packages/contracts/src/actions/{actions.contract,actions.fixtures,actions.procedures,index}.ts`,
its contract tests, and remove exactly the six Actions entries from `procedure-ledger.ts`. Update
the ledger tests to compose `actionsProcedures` and assert 8 unmigrated names. Do not edit daemon,
Web, mobile, storage, or the horizontal `procedures/` files in this unit.

## Non-goals

Do not run Actions, change trust persistence, move Terminal streams or add a notification.

## Target ownership and public surface

`actionsProcedures` makes `actions` a query and the other five names mutations. The exact records are:

- `actions`: input `string`; output `ActionView[]`.
- `trustActions`: strict input `{ repoPath: string; ids: string[] }` with at least one ID; output
  `void`.
- `addAction`: strict input `{ repoPath; title; command; where? }`, with trimmed non-empty title and
  command and `where` in `primary | local`; output stored `Action` without `trusted`.
- `updateAction`: strict input `{ repoPath; id; title?; command?; where? }` with the same optional
  field constraints; output `void`.
- `moveAction`: strict input `{ repoPath; id; direction: up | down }`; output `void`.
- `deleteAction`: strict input `{ repoPath; id }`; output `void`.

Stored `Action` is strict `{ id; title; command; where?; order; createdAt }`. `ActionView` extends
that exact wire shape with required boolean `trusted`. Export schemas and inferred types through the
Actions public entry point, following the landed Board module's procedure-record convention.

## Behavior to preserve

Preserve unbounded path/ID strings, trimmed non-empty create/update title and command inputs, optional
`where`, and numeric `order`/`createdAt`. Parsing persisted actions supplies `order = 0` and
`createdAt = 0`; the wire view supplies `trusted = false` when absent. `addAction` returns the stored
shape and therefore must reject `trusted`; only the list result contains the required derived flag.
The store omits `where` for primary actions, but the wire accepts both explicit `primary` and
`local` because the current router does.

## Legacy behavior to delete

Delete only six Actions ledger entries; `CON-012` owns horizontal-file deletion.

## Ordered implementation

1. Read the router, store, refined schema, ledger baseline, and the landed Board contract module.
2. Define strict stored Action and ActionView schemas plus exact inputs and outputs without importing
   Terminal or daemon code.
3. Add representative synthetic fixtures for every record; do not use machine names, user names,
   real repository paths, tokens, or real commands containing personal context.
4. Export the six kind-aware records and inferred names/types through `packages/contracts/src/actions`.
5. Remove exactly the Actions ledger entries and update ledger composition/count assertions from 14
   to 8 (4 queries and 4 mutations remain).

## Tests

Add `actions.procedures.test.ts` covering exact names/kinds, valid and invalid input/output for every
record, strict unknown-field rejection, all `where`/direction values, trimmed-empty rejection,
non-empty trust IDs, stored Action versus ActionView `trusted` separation, defaulted numeric fields
and derived trust, and the four `void` mutation outputs. Extend `procedure-ledger.test.ts` to prove
only the six baseline-owned Actions names were removed.
