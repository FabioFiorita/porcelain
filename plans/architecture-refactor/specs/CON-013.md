# CON-013 — Bind Remote routers to canonical procedure contracts

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: Remote contract boundary
- Depends on: `CON-012`
- Governing decisions: [005](../decisions/005-contracts-own-the-wire.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

All twelve Remote procedures validate input and successful output through their exact canonical
catalog entries without changing authorization, networking, pairing, or configuration behavior.

## Why this unit exists

Remote ownership is split across `router/daemon.ts` and `router/network.ts`; migrating both together
keeps one domain contract exemplar while remaining bounded to twelve procedures and two files.

## Current behavior and evidence

`daemon.ts` owns `daemonInfo`, `accessStatus`, `issuePairingLink`, `revokePairingLink`,
`revokeAuthorizedClient`, and `revokeCurrentClient`. `network.ts` owns `tailnetStatus`,
`setTailnetBind`, `lanStatus`, `setLanBind`, `funnelStatus`, and `setFunnelBind`. They use
`publicProcedure`/`adminProcedure`, local Zod inputs, no output middleware, and ERR-002 expected
failures. `remoteProcedures` owns their landed schemas, kinds, and errors.

## Scope

Edit only `apps/daemon/src/router/{daemon,network}.ts`, focused tests for those routers, and the
CON-012 lint remaining-file set. Remove `daemon.ts` and `network.ts` from that set only after all
twelve procedures pass the canonical usage check.

## Non-goals

Do not change HTTP/pairing/session boundaries, administrator middleware, grants, URLs, bind/config
semantics, public errors, handler implementations, procedure names, or other router files.

## Target ownership and public surface

Import `procedureCatalog` from `@porcelain/contracts`. Each named procedure uses exactly:

```text
<existing publicProcedure or adminProcedure>
  .input(procedureCatalog.<name>.input)
  .output(procedureCatalog.<name>.output)
  .query(...) or .mutation(...)
```

Retain the existing public/admin builder and declared kind for every name. Remove `zod` imports only
when no non-contract use remains. Do not wrap or copy handler results; tRPC's existing output
middleware is the single validation boundary.

## Behavior to preserve

Preserve canonical daemon-info/access shapes, constant authorization decisions, pairing-link URL rules,
grant/revocation side effects, listener/config status semantics, safe ERR formatting, and all
current HTTP statuses. A valid current handler result must serialize unchanged.

This is the intentional pre-launch acceptance cutover: strict object inputs reject unknown keys, and
the six no-input procedures reject supplied values through ERR-002 `request.invalid`. Do not retain
the former strip/ignore behavior or add a compatibility parser.

## Legacy behavior to delete

Delete the six existing local inputs, add the six missing canonical void inputs, and delete absence
of output validation in these files. Delete only `daemon.ts` and `network.ts` from the temporary
lint ledger; no waiver remains.

## Ordered implementation

1. Replace every local/missing input with the same-name catalog input in `daemon.ts`.
2. Attach the same-name catalog output before each existing query/mutation and keep ERR helpers.
3. Repeat for all six `network.ts` procedures without moving listener/config logic.
4. Extend focused tests for representative valid query/mutation outputs, unknown-key and supplied-
   void rejection, and contract-invalid mocked output rejection; retain expected-failure tests.
5. Remove the two filenames from lint's remaining set and run its exact checks.

## Tests

Extend `apps/daemon/src/router/daemon.test.ts` and add
`apps/daemon/src/router/network.contract.test.ts`. Use injected/test-owned config/network seams; no
real Funnel, LAN, or Tailnet mutation. Lint is the exhaustive proof for all twelve bindings.

## Validation and evidence

```text
pnpm --dir apps/desktop exec vitest run ../daemon/src/router/daemon.test.ts ../daemon/src/router/network.contract.test.ts ../daemon/src/net/daemon-http.test.ts
node scripts/lint-procedure-contracts.mjs
rg -n "\.input\(z\.|from 'zod'" apps/daemon/src/router/daemon.ts apps/daemon/src/router/network.ts
pnpm lint
pnpm verify
git diff --check
```

## Forbidden shortcuts

Do not call `.parse` inside handlers, create a second tRPC builder, weaken strict schemas, retain a
local Zod input, mock external commands by running them, or remove a filename before all its
procedures validate.

## Completion criteria

- [ ] Twelve Remote procedures use exact same-name catalog input/output schemas and existing kinds.
- [ ] Authorization, expected failures, listener/config behavior, and serialization are unchanged.
- [ ] Both router files are absent from the ledger and lint proves their exhaustive bindings.
- [ ] Focused tests, deletion search, repository lint, full verify, and diff check pass.
- [ ] One commit lands only `CON-013`, marks recipe/catalog Landed, leaves a clean worktree, provides
      the README review packet, and finishes without pushing.

## Handoff

Remote routers are the landed exemplar for every later router-file contract cutover.
