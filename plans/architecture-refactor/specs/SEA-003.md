## Objective

The Search domain has one contract/daemon/client surface, with no Files router or mobile Files
procedure mirror and with the architecture registry marking Search complete.

## Why this unit exists

SEA-001 moved the daemon Search procedures into `apps/daemon/src/features/search`, and SEA-002
moved client semantics and presentation into the Search feature roots, but SEA-002 intentionally
left the mobile Files procedure mirror for this bounded deletion. Leaving that mirror means a
second executable descriptor source can be imported again and the Search domain cannot be marked
complete.

## Current behavior and evidence

The current tree was checked at the SEA-002 implementation commit:

- `apps/daemon/src/features/files/files-router.ts` is the canonical eight-procedure Files router;
  its `createFilesFeatureRouter` surface contains only `readFile`, `previewHtml`,
  `writeTextFile`, `createFile`, `createFolder`, `renamePath`, `duplicatePath`, and
  `trashPath`. It contains no Search procedure. The former
  `apps/daemon/src/router/files.ts` path is already absent after SEA-001.
- `apps/daemon/src/features/search/search-router.ts` is the direct Search router for
  `searchText`, `searchCode`, and `searchFiles`, and
  `apps/daemon/src/features/search/search-operations.ts` is its only operation dependency.
  `packages/contracts/src/search` owns the corresponding schemas and flat procedure names.
- `apps/mobile/src/lib/daemon/procedures/files.ts` contains only the local Search mirror:
  `FileSearchResult`, `GrepMatch`, `CodeSearchLine`, `CodeSearchFile`,
  `CodeSearchResult`, `CodeSearchOptions`, and the three `search*Query` descriptors. Its
  only consumer is `apps/mobile/src/lib/daemon/procedures/files.test.ts`.
- No production module imports that mobile Files procedure mirror. Mobile Search imports
  `searchProcedures` from `@porcelain/contracts/search` and `namedContractProcedure` in
  `apps/mobile/src/features/search/use-search-data.ts`; its adapter test proves the canonical
  `searchFiles`, `searchText`, and `searchCode` descriptors and wire inputs.
- `apps/mobile/src/features/files/test-support.tsx` has validating mock handler keys for the
  public procedure names. They are contract-backed test transport defaults, not schemas or
  descriptors; they remain because Files harnesses still validate the complete public catalog.
- `scripts/architecture/domains.mjs` currently registers Search target roots as migrating with
  empty legacy paths. All five Search target roots have their public `index.ts`:
  contracts, daemon, client-runtime, Web, and Mobile. This unit changes only the Search record to
  `status: 'complete'` after the mirror is deleted.

## Scope

Change only the final Search ownership seam:

- Delete `apps/mobile/src/lib/daemon/procedures/files.ts` and its mirror-only test
  `apps/mobile/src/lib/daemon/procedures/files.test.ts`.
- Change the Search record in `scripts/architecture/domains.mjs` from `migrating` to
  `complete`, retaining its existing target roots and empty `legacyPaths`.
- Update this recipe and `plans/architecture-refactor/specs/catalog.md` to `Landed` in the
  implementation commit.

No canonical Search source, Files test-support handler, public procedure name, or unrelated
architecture record changes.

## Non-goals

- Do not change Search contracts, schemas, procedure names, operations, router mapping, result
  shapes, caps, errors, or Git/Files capabilities.
- Do not change Web/Mobile Search adapters, stores, UI, notification ownership, query identities, or
  invalidation behavior established by SEA-002.
- Do not edit the canonical Files router or reintroduce Search procedures there.
- Do not delete `apps/mobile/src/features/files/test-support.tsx` defaults; they are validating
  harness data for the public catalog, not a local Search descriptor.
- Do not remove canonical Search names from contract fixtures, daemon Search tests, or client adapter
  tests.
- Do not add aliases, compatibility re-exports, a replacement mobile procedure barrel, or E2E.
