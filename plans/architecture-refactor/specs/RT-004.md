# RT-004 — Bind the Web client to the shared real-time runtime

- Status: Draft
- Batch: 0 — architecture and contract foundations
- Domain: real-time Web adapter
- Depends on: `RT-003` (Draft), `PRO-002` (Draft)
- Governing decisions: [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Prepare Web's browser transport and cache binding around the shared client real-time runtime without
activating it against the still-legacy daemon.

## Why this unit exists

Web must receive the same conservative recovery and versioned handshake behavior as mobile without
making browser sockets or React Query part of the reusable runtime. Activation waits for `RT-005` so
no intermediate needs compatibility parsing.

## Current behavior and evidence

Web daemon/session code is under `apps/web/src/lib/` and Web hooks. It currently owns connection and
invalidation choices separately from future mobile behavior.

## Scope

Own unactivated Web-only transport, runtime lifecycle hook/provider, and query invalidation mapping
under `apps/web/src/lib/` and `apps/web/src/hooks/`. Use `RT-003` for all session state and `PRO-002`
for the shared protocol constant/header conventions. Do not replace the current mounted session path.

## Non-goals

Do not alter daemon publication, shared runtime logic, mobile files, terminal protocol, current mounted
Web session behavior, or delete the legacy transport. Final activation/removal belongs to `RT-005`.

## Target ownership and public surface

The browser adapter supplies connection/auth to the runtime, maps categories to existing authoritative
query invalidations, installs/removes file interests with the active Viewer context, and surfaces a
recoverable connection state. It must refetch on runtime recovery signals rather than applying push
payloads as cached data. It is only exercised through tests until `RT-005` mounts it.

## Behavior to preserve

Preserve Web navigation, cache keys, authorization flow, terminal rendering behavior, and no-op
invalidation for contiguous irrelevant project signals.

## Legacy behavior to delete

Delete nothing here. `RT-005` removes Web-only duplicate reconnect/invalidation logic together with
the daemon/mobile legacy surface after the atomic switch.

## Ordered implementation

1. Add a browser transport adapter and lifecycle binding around `RT-003`.
2. Map each category to current query invalidations and Viewer-derived file interests.
3. Keep current mounted handlers unchanged and add browser-focused tests with a fake runtime transport.

## Tests

Cover hello/ready lifecycle, category invalidation, recovery refetch, interest updates when Viewer
files/directories change, mismatch state, cleanup, and terminal frame forwarding.

## Validation and evidence

```text
pnpm --dir apps/desktop test -- ../web/src/lib/session-browser-adapter.test.ts ../web/src/hooks/use-session-runtime.test.ts
pnpm lint
git diff --check
```

## Forbidden shortcuts

Do not bypass `RT-003`, mutate React Query data from notification payloads, embed protocol literals,
or delete mobile/daemon legacy code.

## Completion criteria

- [ ] The unactivated Web binding uses the shared runtime for handshake, recovery, and interests in tests.
- [ ] Category signals trigger only authoritative existing queries to refetch.
- [ ] Web adapter tests, lint, and diff check pass.

## Handoff

`RT-005` mounts this binding, migrates mobile, switches daemon publication, then removes the legacy
surface atomically.
