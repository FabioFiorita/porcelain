# BRD-004 — Move Web Board to the shared client boundary

- Status: Landed
- Batch: 1 — Board primary exemplar
- Domain: board
- Depends on: BRD-002, BRD-003, TST-001
- Governing decisions: [002](../decisions/002-organize-by-product-domain.md), [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [013](../decisions/013-use-ten-canonical-product-domains.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: yes

## Objective

The Web Board feature will consume canonical Board contracts and `@porcelain/client-runtime/board` through one React Query/tRPC adapter, retain its Board presentation workflows, and remove all Web Board daemon-model, raw event, and hook-local mutation semantics.

## Why this unit exists

Board is the first complete client-domain exemplar. It proves that the browser/Electron client can keep its UI and platform adapter while client-runtime owns query identity, mutation consequences, optimism and notification meaning.

## Current behavior and evidence

- `apps/web/src/hooks/use-board.ts` imports `BoardCard`/`CardStatus` from `@backend/stores/board-store`, calls `trpc.boardCards` and all five mutations, owns temporary-id/rollback code, and exports `BOARD_COLUMNS`/`STATUS_LABEL`.
- Board UI is in `apps/web/src/components/board/{board-list,board-quick-access,board-view,card-composer,card-item,clear-column-button}.tsx`.
- Web Board presentation state is split across `apps/web/src/stores/{board-selection,card-draft}.ts`; their tests are `board-selection.test.ts` and `commit-draft.test.ts` is unrelated.
- `apps/web/src/components/shell/{glance-home,use-app-shortcuts}.tsx` import Board hook/store behavior. `hooks/use-app-events.ts` owns raw `case 'board'` invalidation.
- `apps/web/src/hooks/use-board.test.ts` uses the raw tRPC test harness and tests optimistic behavior; no Board component test currently exists.

## Target ownership and public surface

- `apps/web/src/features/board/board-columns.ts` will export `BOARD_COLUMNS` and `boardStatusLabel`; `CardStatus` comes from `@porcelain/contracts/board`, never `@backend`.
- `board-queries.ts` will export `useBoardCards`. It reads the selected Project from `useRepoStore`, maps BRD-003 `boardCardsQuery(projectPath)` to a React Query key containing the active daemon identity, and invokes the BRD-001 `listBoardCards` descriptor through the Web transport adapter.
- `board-mutations.ts` will export `useBoardCardActions`. It binds all five BRD-003 mutation definitions to Web tRPC/React Query, cancels/snapshots/applies/rolls back/reconciles the cards query, then invalidates exactly the declared cards identity. It supplies temporary ids and timestamps at the adapter boundary.
- `board-notifications.ts` will export `applyBoardNotification`. It receives a validated BRD-001 notification and maps BRD-003 effects to the Web QueryClient. It does not inspect raw `AppEvent` strings.
- `board-selection-store.ts` will export `useBoardSelectionStore` and `resolveBoardFocus`; `card-draft-store.ts` will export `useCardDraftStore` and `draftFromCard`. These stores hold only Board focus and a composer draft; cards remain Query data.
- `index.ts` is the only Web Board public entry point. It exports components needed by Shell, the two feature hooks, columns/labels, and presentation stores. Other Web regions import it, never a Board implementation file.
- `apps/web/src/components/shell/app-shell.tsx` will subscribe to the validated Board notification through the feature notification adapter; `hooks/use-app-events.ts` will no longer contain Board behavior.

## Behavior to preserve

- An unloaded Board, a loaded empty Board, and a failed Board read remain distinguishable.
- Every create, update, move, delete and clear presents immediate reversible feedback, restores the exact previous list on a failure, shows the current mutation failure at the triggering Web surface, and refetches authoritative cards after settlement.
- Board remains refreshed by agent/CLI changes through the single app-level notification subscription.
- Focus remains scoped by Project path and falls back Doing → To do → Done when a focused card disappears; drafts remain unpersisted and the current keyboard shortcut opens a To do draft.
- Board list, wide Board, Focus rail, Glance, composer, clear confirmation, Start Review handoff and all current accessibility labels remain rendered by Web components.
