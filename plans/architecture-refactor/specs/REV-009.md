## Objective

Perform the single canonical Review cutover: remove Feature vocabulary, scene canvas, root-index Evidence, deprecated wire fields/readers, local schema mirrors, and their compatibility tests after all target contract/daemon/CLI/Web/mobile callers are live.

## Why this unit exists

Keeping aliases allows a half-migrated product to silently use old layout/representation. The inventory explicitly requires these names/fields/readers to disappear atomically, while real containment/caps/corruption/recovery stays.

## Current behavior and evidence

- Feature names span `router/review.ts`, `review/feature-*`, `stores/feature-snapshot-store.ts`, CLI `feature-view-file.ts`, Web Git components/hooks, mobile Review procedures/features, contracts, events, and tests.
- Evidence legacy paths/fields span CLI `evidence-file.ts`, daemon `evidence-store.ts`, `review/doc-set.ts`, `fs/evidence-paths.ts`, Companion/worktree scripts, and E2E fixtures.
- Exact deletions include `index.html`, `hasReport`, `medium`, `reviewEvidenceDocs`, scene canvas, `reviewSetsPath`, and home/root gallery readers.

## Scope

- Replace all callers with canonical Review contracts/operations/client features, then delete the exact source/test/fixture aliases in one commit.
- Add a Review completion lint for forbidden names/fields/paths.

## Non-goals

- Do not delete Results/Assets/checks, containment, caps, mtime freshness, malformed external-content disposition, reviewed reconciliation, or active archive resilience.
- Do not delete real user files or perform reset.

## Target ownership and public surface

Only canonical Review public names/paths exist. Evidence is strict `meta.json`, `results/`, and `assets/`; malformed bounded optional external content has explicit safe disposition, not scene-to-HTML coercion. No runtime fallback reads an old representation.

## Behavior to preserve

Preserve canonical Review data, empty/default current behavior, archive, results/assets/checks, assets containment, unavailable states, watcher refresh, and all real failure/recovery tests.

## Legacy behavior to delete

Delete `feature*`, `feature-view`, `featureReading`, `clearFeatureReview`, scene canvas acceptance/test, root `index.html` reader/test, `hasReport`, `medium`, `reviewEvidenceDocs`, `loopEvidenceRoot`, home/root gallery readers, `reviewSetsPath`, deprecated client fields, local mobile schemas, worktree/Companion/E2E legacy fixtures.

## Ordered implementation

1. Build a complete caller ledger by exact `rg` searches; classify every hit as canonical low-level English, target replacement, or deletion.
2. Land all target contract/operation/CLI/Web/mobile imports and run their focused tests before deletion.
3. Delete old router procedures/types, Feature modules, CLI noun/helper, legacy Evidence readers/fields, mobile mirrors, fixtures, and compatibility tests in one atomic commit.
4. Add `scripts/lint-review-cutover.mjs` to reject forbidden identifiers/paths in active source and target contracts; fixture-test it and add to root lint.
5. Run clean v1 Review/Results/Assets fixtures, contract runtime parsing, client feature tests, and no-hit searches.
6. Remove Review legacy entries from architecture registry only after these gates pass.

## Tests

- Contract/operation/adapter/client/CLI matrices plus source-lint fixtures.
- `pnpm test`, `pnpm lint`, and `pnpm verify` pass; named browser wiring remains only where E2E-001 owns it.

## Validation and evidence

## Forbidden shortcuts

- Do not retain alias/export/shim or translate scene/root index at runtime.
- Do not delete a resilience test because its file contains a legacy word.
- Do not spread this cutover across partial compatibility commits.

## Completion criteria

All active source/client/CLI/contracts use canonical Review Results/Assets vocabulary; forbidden compatibility has zero hits; retained resilience proof and full gates pass.
