## Objective

Mobile comments consume the same `@porcelain/contracts/review` + `@porcelain/client-runtime/review` semantics as Web (RVC-003) through one React Query feature adapter on the existing mobile daemon transport: typed comments query identity + environment identity, five reversible optimistic mutations with cancel → snapshot → load-gated apply → mutate → rollback/reconcile → exact refetch, per-identity serial concurrency, validated `review.changed` notification effects via one bridge, and deletion of Review-local comment descriptors and `COMMENT_INVALIDATIONS`.

## Why this unit exists

`apps/mobile/src/features/comments/use-comments.ts` is an invalidate-only adapter over duplicate comment descriptors in `lib/daemon/procedures/review.ts` (`COMMENT_INVALIDATIONS = ['reviewComments']`), while RVC-002 shared optimism and RVC-003 Web already land the canonical client semantics. BRD-005 proved the mobile adapter + bridge pattern. Completing this cutover removes the last comments semantic divergence and the Review-local wire ownership for comments.

#### Lifecycle for each of the five `reviewCommentMutations` keys

For each key (`add` | `edit` | `delete` | `setResolved` | `clearResolved`):

1. **Cancel** in-flight queries for `reviewCommentsQueryKey(environment.id, identity.projectPath)` with `exact: true`.
2. **Snapshot** current cache: `getQueryData<readonly ReviewComment[]>(queryKey)`.
3. **Load gate:** if snapshot data is `undefined`, do **not** `setQueryData`. Return context `{ queryKey, snapshot: undefined, temporaryId? }` so rollback is a no-op; settle still refetches.
4. If data is defined: `applyReviewCommentOptimisticTransition(current, key, wireInput, { temporaryId, now })` then `setQueryData(queryKey, comments)`.
5. **Mutate** via `callDaemon(getDaemonClient(environment), namedContractProcedure(procedureName, reviewProcedures.<proc>), wireInput)` — **not** `useDaemonMutation`.
6. **onError:** if `context.snapshot` is defined, `setQueryData(queryKey, rollbackReviewCommentOptimisticTransition(context.snapshot))`. Re-throw / leave mutation error so composer `catch` still surfaces `cause.message` (no new toast product). Public failures: `review.unavailable`, `review.comment-not-found`, `request.invalid` through existing `DaemonError` / message path.
7. **onSuccess (add only):** `reconcileReviewCommentMutation(current, 'add', { temporaryId, result })` when both present.
8. **onSettled:** if `reviewCommentMutations.<key>.requiresAuthoritativeRefetch`, `invalidateQueries({ queryKey: reviewCommentsQueryKey(environment.id, identity.projectPath), exact: true })` for each `affectedQueries(wireInput)` — **never** string/`useDaemonInvalidate(['reviewComments'])`.
