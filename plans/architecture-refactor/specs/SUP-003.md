# SUP-003 — Prove thin Desktop, one daemon, safe URLs, and packaging boundaries

- Status: Draft
- Batch: 7
- Domain: Desktop integration and packaging
- Depends on: ARC-002, DAE-001, CLI-001
- Governing decisions: 003, 006, 009, 014
- Primary exemplar: yes

## Objective

Make Desktop a thin Electron integration layer and preserve its earned one-daemon, safe-URL, preload/IPC, native dependency, and packaging guarantees with source gates and integration proof.

## Why this unit exists

Desktop currently owns utilityProcess lifecycle, daemon bootstrap, shell API/events, renderer packaging, and CLI install integration. Those are legitimate integration concerns; product policy or a second daemon is not.

## Current behavior and evidence

- Exact main paths: `apps/desktop/src/main/{daemon,index,ipc,shell-api,shell-events,window,remote-daemon,renderer-packaging,cli-install}.ts`.
- Existing focused tests are `local-terminal-paths.test.ts`, `remote-daemon.test.ts`, and `renderer-packaging.test.ts`.
- Audit assigns utilityProcess lifecycle to Daemon/Desktop and native deps/signing/asar to Desktop packaging plus Releasing.

## Scope

- Add Desktop boundary tests/gates for package imports, renderer URL validation, one-daemon lifecycle, preload-only IPC, and packaging inputs.
- Relocate product mutations from Desktop main/preload into daemon contract calls or domain clients before deleting the old main-process code.

## Non-goals

- Do not change listener/auth policy, sign/release an artifact, remove native dependencies, or add renderer access to Node.
- Do not replace real recovery/restart behavior with a process-global singleton.

## Target ownership and public surface

Desktop owns Electron windows, preload bridge, utilityProcess lifecycle, local terminal integration, packaging, and update/native packaging setup. Daemon owns product operations and transport. Renderer reaches Desktop only through typed preload APIs; all external navigation goes through the existing safe-URL guard.

## Behavior to preserve

Preserve one managed daemon per Desktop instance, restart/teardown behavior, token secrecy, safe external navigation, packaged renderer discovery, `node-pty`/`trash` packaging, and local Terminal path mapping.

## Legacy behavior to delete

Delete only product business logic, raw data IPC, duplicate daemon start paths, and obsolete compatibility proxies after their daemon/client owner proves replacement. Retain lifecycle and packaging resilience.

## Ordered implementation

1. Inventory every export in `main/{ipc,shell-api,shell-events}.ts` as Desktop integration, daemon transport, or product behavior; assign product behavior to its canonical domain spec.
2. Add `scripts/lint-desktop-boundary.mjs`: reject imports from Web/mobile/daemon source except contracts/shared, reject product-domain store imports in main/preload, and reject raw `ipcMain` payload forwarding outside typed bridge modules.
3. Add source tests for `daemon.ts`: one utilityProcess launch path, one shutdown path, no renderer-supplied daemon command/port, and no duplicate listener creation.
4. Extend `remote-daemon.test.ts` and `renderer-packaging.test.ts` for safe URL disposition, packaged renderer path, daemon artifact path, and native dependency inclusion.
5. Add preload bridge tests proving only declared typed APIs are exposed and no Node/Electron object leaks to renderer.
6. Build Desktop and execute the existing browser E2E against the daemon-served renderer; run native Electron proof only on macOS.
7. Remove each inventoried product bridge only after its domain's contract/client test and the Desktop boundary gate pass.

## Tests

- `pnpm --dir apps/desktop test src/main/remote-daemon.test.ts src/main/renderer-packaging.test.ts src/main/local-terminal-paths.test.ts`.
- `pnpm build`, `pnpm lint`, and browser E2E pass; macOS additionally runs `pnpm --dir apps/desktop test:e2e:native`.

## Validation and evidence

Record one daemon launch/restart proof, rejected unsafe navigation, packaging artifact assertion, and preload API-surface assertion. Do not use production state for any proof.

## Forbidden shortcuts

- Do not import daemon implementation into preload/renderer, create a second product daemon, or expose a generic IPC/send channel.
- Do not disable asar/native packaging checks or weaken URL validation.

## Completion criteria

Desktop has no product ownership or raw data IPC, the named lifecycle/URL/packaging invariants have tests/gates, and all retained integration proof passes.

## Handoff

Remote, Terminal, and domain cutovers consume the inventory. Releasing retains signing/notarization ownership; SUP-003 does not publish.
