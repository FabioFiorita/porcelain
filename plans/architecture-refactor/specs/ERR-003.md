# ERR-003 — Return public errors from daemon authentication and pairing HTTP failures

- Status: Landed
- Batch: 0 — architecture and contract foundations
- Domain: daemon HTTP boundary
- Depends on: `ERR-002`
- Governing decisions: [010](../decisions/010-type-expected-failures-and-validate-boundaries.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md), [012](../decisions/012-enforce-the-target-architecture.md), [015](../decisions/015-make-a-clean-pre-launch-cutover.md)
- Primary exemplar: no

## Objective

Every failed daemon tRPC authentication or pairing HTTP request returns one contract-valid public
error with correlation, while the token gate, caps, rate limits, CORS, and static routes stay exact.

## Why this unit exists

`daemon-http.ts` currently returns empty 400/401/413/429/500 bodies outside tRPC. These hostile-input
paths need the same safe envelope without mixing their security-sensitive behavior into ERR-002.

## Current behavior and evidence

`apps/daemon/src/net/daemon-http.ts` owns Bearer authentication, pairing body/rate/grant handling,
CORS, tRPC dispatch, static routing, WebSocket upgrade, and the outer catch. Audit invariants are in
`docs/internals/audit/{network-boundary,data-ipc}.md`; `daemon-http.test.ts` exercises the live
ephemeral listener.

## Scope

Add/reuse `writePublicError` under daemon composition, update only HTTP request failures in
`daemon-http.ts`, and extend its live-boundary tests. Keep the ERR-002 tRPC formatter unchanged.

## Non-goals

Do not change WS upgrade responses, protocol-version acceptance (`PRO-004`), successful pairing,
credentials/grants, bind interfaces, CORS policy, static routing/cache policy, client parsing, or
router behavior.

## Target ownership and public surface

Create one request ID at the start of a dynamic `/trpc` or POST `/pair` request and preserve it
through the response. `writePublicError(res, status, corsHeaders, porcelainError, extraHeaders?)`
validates with `publicErrorSchema`, emits UTF-8 JSON with correct content length/type and
`cache-control: no-store`, and never serializes a native error.

Map exactly:

- missing/invalid Bearer and consumed/invalid pairing grant → `auth.unauthenticated`, 401;
- malformed pairing JSON/body shape → `request.invalid`, 400;
- declared or streamed pairing body above 8 KiB → `request.invalid`, 413;
- pairing rate limit → `resource.unavailable`, 429, preserving `retry-after: 60`;
- unexpected request-pipeline exception → `internal.unexpected`, 500 and one safe ERR-002 log.

OPTIONS remains 204 with no body. GET `/pair` remains static app-shell navigation. Successful pair
responses remain `no-store`. tRPC-generated failures remain owned by ERR-002.

## Behavior to preserve

Preserve constant-time admin comparison, individual client validation/revocation, the sole
unauthenticated mutation, 8 KiB cap before retained allocation, 12-attempt window, exact CORS echo,
loopback/private-listener sharing, public GET/HEAD static serving, and WS subprotocol authentication.

## Legacy behavior to delete

Delete only empty 400/401/413/429/500 bodies for the named HTTP paths and raw error logging in the
request pipeline. Keep empty/non-public responses for unrelated static/OPTIONS/WS behavior.

## Ordered implementation

1. Add the validating response writer and fixtures for each status/code mapping.
2. Thread one request ID through tRPC auth and pairing handling without changing authentication order.
3. Replace named empty failures and preserve CORS, retry-after, no-store, content type/length.
4. Consolidate request-pipeline unexpected handling so one failure logs once and writes once when
   headers are still available; never double-log tRPC errors already handled by ERR-002.
5. Extend live HTTP tests for bodies, headers, IDs, caps, rate limits, handler non-invocation, CORS,
   and secret/stack/path absence.

## Tests

Extend `apps/daemon/src/net/daemon-http.test.ts` with table-driven missing/wrong auth, malformed,
oversized, exhausted grant, rate-limited, and injected unexpected cases. Parse every error through
`publicErrorSchema`; assert UUID request IDs, exact status/code/header mapping, and unchanged success,
OPTIONS, static, CORS, and WebSocket gates.

## Forbidden shortcuts

Do not make auth optional, widen CORS/binds, move pairing secrets into URLs/logs, read beyond the
body cap, expose raw input/errors, return HTML/plain text for named failures, alter WS behavior, or
add compatibility bodies.

## Completion criteria

- [ ] Named tRPC-auth/pairing/pipeline failures return strict public errors with one request ID.
- [ ] Authentication, rate/body limits, CORS, static, and WS invariants remain exact.
- [ ] Unexpected paths log safely and exactly once; raw request/error logging is gone.
- [ ] Live HTTP tests, deletion search, repository lint, full verify, and diff check pass.
- [ ] One commit lands only `ERR-003`, marks recipe/catalog Landed, leaves a clean worktree, provides
      the README review packet, and finishes without pushing.
