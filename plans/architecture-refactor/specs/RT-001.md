- Status: Landed

- Depends on: `CON-010`

- Primary exemplar: no

## Objective

Define strict domain-owned notification, session, watch-interest, and terminal-stream contracts
without changing any daemon or client transport.

## Why this unit exists

The current WebSocket frames and app events are horizontal and untyped at the product-domain boundary.
The daemon publisher and runtime adapters need a shared vocabulary before either can migrate safely.

## Current behavior and evidence

Current frame types live in `packages/contracts/src/ws-protocol.ts`; daemon sources include
`apps/daemon/src/app-events.ts`, `net/session.ts`, file-watch, review-watch, and terminal session
code. The current event and terminal behavior is inventoried in [`backend.md`](../inventory/backend.md).

## Scope

Create only these contract modules and their tests:

- `packages/contracts/src/files/files.notifications.ts`
- `packages/contracts/src/git/git.notifications.ts`
- `packages/contracts/src/review/review.notifications.ts`
- `packages/contracts/src/board/board.notifications.ts`
- `packages/contracts/src/actions/actions.notifications.ts`
- `packages/contracts/src/session/{session.contract,files-watches}.ts`
- `packages/contracts/src/terminal/terminal.stream.ts`

Update domain/root contract exports. Do not change a runtime source or delete a legacy frame.

## Non-goals

Do not create a gateway, publisher, watch manager, reconnect/replay code, Web/mobile adapter, or
transport migration. `RT-002` through `RT-005` own those changes.

## Target ownership and public surface

Each notification is strict and includes `projectPath`. The exact change union is:

`files.scope-changed`, `files.tree-changed` (`paths`), `files.content-changed` (`paths`),
`git.working-tree-changed`, `review.changed`, `board.changed`, and `actions.changed`.

`session:change` is `{ t: 'session:change', epoch: string, sequence: number, change }` where
`change` is that discriminated domain union. `session:watches` owns `projectPath`, `files`, and
`dirs`; the daemon later caps combined interests at 128. Session `hello`, `ready`, and `mismatch`
schemas reserve the exact handshake surface implemented by `PRO-003`.

`terminal.stream.ts` owns strict terminal lifecycle/output/input schemas and preserves current byte,
line, and buffered-frame caps; it does not route terminal output through the change union.

## Behavior to preserve

Preserve project scoping, all current file-path detail, terminal ordering/framing and limits, and the
distinction between coarse recoverable change signals and terminal's ordered stream.

## Legacy behavior to delete

Delete nothing in this recipe. `ws-protocol.ts`, app events, existing watches, and old client frames
remain until `RT-005` performs the coordinated legacy deletion after both runtime adapters migrate.

## Ordered implementation

1. Transcribe current notification and terminal frame values into strict domain/session modules.
2. Add the cross-domain session envelope and watch-interest schemas.
3. Add handshake frames needed by `PRO-003`, without daemon integration.
4. Export only from canonical domain/session entry points and test parsing/caps.

## Tests

Add contract fixtures for every change category, invalid/missing `projectPath`, paths-required file
changes, session envelope parsing, watch-interest shape, terminal lifecycle/output/input frames, and
all existing terminal caps.

## Forbidden shortcuts

Do not use a generic `changed` event, omit `projectPath`, encode terminal output as a change signal,
or change runtime imports/legacy files in this contract-only recipe.

- [x] Terminal stream contracts preserve its distinct ordering and resource limits.
- [x] No daemon/client runtime source or legacy transport file is changed.
