- Primary exemplar: no

## Objective

Move authenticated pairing HTTP, CORS, LAN/Tailnet/Funnel configuration and listener lifecycle into explicit Remote operations/adapters.

## Why this unit exists

`daemon-http.ts`, `router/network.ts`, and listener modules distribute public boundary/security policy and mixed config mutations.

## Current behavior and evidence

`net/daemon-http.ts` authenticates/pairs/serves CORS; `router/network.ts` calls `net/{lan,tailnet,funnel}.ts`; `stores/config-store.ts` mixes listener flags with Projects recents; Funnel/LAN/Tailnet start/stop real listeners.

## Scope

Create `apps/daemon/src/features/remote/{remote-http,remote-listeners,remote-network-operations,remote-config-store}.ts`; move network router/listener/config and HTTP boundary collaborators, leaving generic server/static wiring in daemon composition.

## Non-goals

Do not change protocol header semantics, frontend forms, identity/pairing grant data, static assets, or invent listener retries/fallbacks.

## Target ownership and public surface

`RemoteListeners` owns status/start/stop for LAN/Tailnet/Funnel; `RemoteNetworkConfig` owns a strict version-1 Remote-only flag record. Operations serialize start/stop/state changes, publish Remote state only after successful effects, and return typed unavailable/conflict outcomes. `remote-http` uses REM-001 auth/pairing capability and ERR safe output, preserving exact CORS/body/rate limits.

## Behavior to preserve

Preserve loopback/default bind behavior, admin authorization, CORS scoping, body caps, pairing rates, listener shutdown/start order, Funnel availability handling, and HTTP safe error/request IDs.

## Legacy behavior to delete

Delete Remote fields from `config-store.ts`, network router direct listener/config calls, and daemon-http direct access policy imports; no mixed config compatibility read remains.

## Ordered implementation

1. Extract Remote config and listener capability adapters with real lifecycle fakes.
2. Implement bound status/set operations and exact ordering.
3. Delegate HTTP auth/pairing boundary to Remote feature collaborators.
4. Delete mixed config/network router direct paths.

## Tests

Test config atomicity/corruption, listener start/stop failures/order, CORS/auth/pairing HTTP boundaries, version enforcement regression, and router mapping.

## Forbidden shortcuts

Do not mix Projects config, weaken CORS/auth/header enforcement, add retries, or call listeners from routers.
