# ACT-002 — Define shared Actions semantics and run preparation

- Status: Draft
- Batch: 3 — remaining domain cutovers
- Domain: actions
- Depends on: ACT-001, TRM-003, TST-001, RT-001
- Governing decisions: [004](../decisions/004-keep-cross-domain-workflows-shallow.md), [005](../decisions/005-contracts-own-the-wire.md), [007](../decisions/007-share-nonvisual-client-behavior.md), [008](../decisions/008-give-each-client-state-one-owner.md), [009](../decisions/009-treat-realtime-as-recoverable-signals-and-streams.md), [011](../decisions/011-test-the-boundary-that-owns-the-risk.md)
- Primary exemplar: no

## Objective

Client-runtime owns Actions list/trust/CRUD identities, exact effects and pure explicit terminal-run preparation.

## Why this unit exists

Web `use-actions.ts` imports daemon action types; mobile exposes actions/trust under Terminal descriptors and has no CRUD seam.

## Current behavior and evidence

Actions UI is in Web `components/terminal/*` and mobile Changes/Terminal components; terminal execution is socket behavior and must not become an Actions cache mutation.

## Scope

Add `packages/client-runtime/src/actions/{actions-queries,actions-mutations,actions-notifications,prepare-action-run,index}.ts`, tests and `./actions` export.

## Non-goals

Do not spawn a terminal, create UI, persist run state, or implement terminal transport.

## Target ownership and public surface

Export `actionsQuery(projectPath)`, `actionTrustQuery(projectPath)`, `actionsMutations` for trust/add/update/move/delete, `actionsNotificationEffects`, and `prepareActionRun(action, context)`. All persisted writes are non-optimistic and authoritative; `actions.changed` affects both list/trust identities. `prepareActionRun` returns either a validated command/cwd/name/initial input for TRM-003 or a typed refusal; it performs no I/O.

## Behavior to preserve

Keep trust-by-command behavior, action ordering, local-only action restrictions, visible refusal and the explicit human Actions → Terminal transition.

## Legacy behavior to delete

Delete no app implementation here; ACT-003 removes terminal-owned action descriptors and UI facades.

## Ordered implementation

1. Verify ACT-001 contracts/operations and terminal run input contract.
2. Implement identities/effects and pure preparation.
3. Test all outcomes with fixtures and no terminal mock behavior.

## Tests

Test project identity isolation, each mutation consequence, notification mapping, trust/refusal preparation and malformed contract outcomes.

## Validation and evidence

- Run `pnpm --dir apps/desktop test -- ../../packages/client-runtime/src/actions`.
- Run `pnpm lint`.
- Run `rg -n "react|WebSocket|QueryClient|terminal:create|AppEvent" packages/client-runtime/src/actions`; it returns no result.

## Forbidden shortcuts

Do not launch terminals, hide required run preparation in a notification, use local action schemas, or optimistic-paint trust/CRUD.

## Completion criteria

- [ ] Shared Actions query/mutation/notification/run-preparation semantics exist.
- [ ] Tests prove exact effects and no terminal/platform dependency.
- [ ] Lint/search pass; the unit is committed.

## Handoff

ACT-003 binds Actions presentation to this explicit terminal workflow.
