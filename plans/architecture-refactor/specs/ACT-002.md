## Architecture reviewer rulings (bind the executor; supersede the tracked Draft)

1. **Dependencies.** Catalog is the source of status. Depend only on `ACT-001`, `TRM-003`,
   `TST-001`, and `RT-001` (all Landed). Do not repeat mutable status beside IDs.

2. **Copy the Board/Files client-runtime vocabulary, not a third pattern.** Physical shape and
   tests follow `BRD-003` / `packages/client-runtime/src/board/` and the non-optimistic mutation
   style of `FIL-004` / `packages/client-runtime/src/files/` (no reconciliation module, no
   decorative `optimistic: false` field). TRM-003 supplies the Terminal create field alphabet
   (`name`, `cwd`, `initialInput`) that pure preparation must produce; do **not** import
   `@porcelain/client-runtime/terminal` or any Terminal type into Actions runtime (Decision 004 —
   shallow cross-domain: return plain fields; ACT-003 maps them onto `terminal:create`).

3. **Two semantic query identities, one wire list procedure.** Machine trust is product-distinct
   from the saved-action roster (ACT-001: trust is home-local; list is project-local), but the
   only Actions **read** procedure remains flat `actions` (bare project-path string in, 
   `ActionView[]` out with derived `trusted`). Export both identities so notification and mutation
   consequences name both slots; ACT-003 adapters may collapse both onto one tRPC/React Query key
   until a separate trust read exists. Exact shapes:

   ```ts
   type ActionsQuery = {
     readonly domain: 'actions'
     readonly name: 'list'
     readonly projectPath: string
   }
   type ActionTrustQuery = {
     readonly domain: 'actions'
     readonly name: 'trust'
     readonly projectPath: string
   }
   type ActionsIdentity = ActionsQuery | ActionTrustQuery
   ```

   Constructors: `actionsQuery(projectPath)`, `actionTrustQuery(projectPath)`. Shared
   `actionsProjectKey(projectPath)` requires a non-empty string (`z.string().min(1)`); empty
   throws `ActionsIdentityError` (programmer error — not a public Actions error code). No
   absolute-path, host, or trailing-slash policy (Actions wire has none). Strict Zod schemas
   `actionsQuerySchema`, `actionTrustQuerySchema`, and `actionsIdentitySchema`
   (discriminated on `name`) are the executable descriptions adapters parse generic cache keys
   against.

4. **Five non-optimistic mutation definitions.** `actionsMutations` binds exactly the five
   ACT-001 mutation procedures. No create-from-list optimism, no snapshot/rollback module, no
   `optimistic` field. Every definition declares `requiresAuthoritativeRefetch: true` and
   `affectedQueries(input)` returning **both** identities for `input.repoPath` in this order:
   `[actionsQuery(key), actionTrustQuery(key)]` where `key = actionsProjectKey(input.repoPath)`.

   | Key | `procedure` / `procedureName` | Wire input type |
   | --- | --- | --- |
   | `trust` | `actionsProcedures.trustActions` / `'trustActions'` | `TrustActionsInput` |
   | `add` | `actionsProcedures.addAction` / `'addAction'` | `AddActionInput` |
   | `update` | `actionsProcedures.updateAction` / `'updateAction'` | `UpdateActionInput` |
   | `move` | `actionsProcedures.moveAction` / `'moveAction'` | `MoveActionInput` |
   | `delete` | `actionsProcedures.deleteAction` / `'deleteAction'` | `DeleteActionInput` |

   Bind `procedure` objects from `@porcelain/contracts/actions` (`actionsProcedures`). Do not
   invent local procedure descriptors or raw procedure-name invalidation strings. The list query
   procedure `actions` is **not** a mutation definition (adapters call it as a query).

5. **Notification mapping is exhaustive over `ActionsChange`.**
   `actionsNotificationEffects(notification: ActionsChanged)` accepts only the RT-001/CON-009
   `actions.changed` fact (`{ kind: 'actions.changed', projectPath }`) and returns
   `[actionsQuery(key), actionTrustQuery(key)]` for `key = actionsProjectKey(notification.projectPath)`.
   No default branch, no raw `AppEvent` string, no entity payload merge. Trust is not a separate
   wire notification — list refetch re-derives `trusted` (contract comment on
   `actions.notifications.ts`).

6. **Pure client `prepareActionRun` (no I/O, no Terminal).** Distinct from the daemon internal
   operation of the same name (ACT-001: store+trust re-check by `actionId`). Client preparation
   runs against an already-fetched `ActionView` plus adapter-supplied context:

   ```ts
   type PrepareActionRunContext = {
     readonly projectPath: string
     readonly localPath?: string | null
   }

   type PreparedActionRun = {
     readonly id: string
     readonly title: string
     readonly command: string
     readonly where: 'primary' | 'local'
     readonly projectPath: string
     /** Absolute cwd for `terminal:create` (project root or This-device path). */
     readonly cwd: string
     /** Terminal session name — always the action title. */
     readonly name: string
     /** Shell initial input — always the action command text (not auto-executed). */
     readonly initialInput: string
   }

   type PrepareActionRunRefusal =
     | { readonly code: 'actions.untrusted'; readonly actionId: string }
     | { readonly code: 'actions.needs-local-path'; readonly actionId: string }

   type PrepareActionRunResult =
     | { readonly ok: true; readonly value: PreparedActionRun }
     | { readonly ok: false; readonly error: PrepareActionRunRefusal }

   function prepareActionRun(
     action: ActionView,
     context: PrepareActionRunContext,
   ): PrepareActionRunResult
   ```

   Exact rules (preserve Web `useRunAction` + `actions-group` gate):

   | Condition | Outcome |
   | --- | --- |
   | `action.trusted !== true` | `{ ok: false, error: { code: 'actions.untrusted', actionId: action.id } }` |
   | `action.where === 'local'` and (`context.localPath == null` or `context.localPath === ''`) | `{ ok: false, error: { code: 'actions.needs-local-path', actionId: action.id } }` |
   | `action.where === 'local'` and non-empty `localPath` | success; `cwd = localPath`; `where = 'local'` |
   | `action.where` is `'primary'` or omitted/undefined | success; `cwd = actionsProjectKey(context.projectPath)`; `where = 'primary'` |

   Success always sets `id = action.id`, `title = action.title`, `command = action.command`,
   `name = action.title`, `initialInput = action.command`,
   `projectPath = actionsProjectKey(context.projectPath)`. Empty `context.projectPath` throws
   `ActionsIdentityError` (even for local runs — project identity is always required). No
   `actions.not-found` path (caller already holds the view). No call to daemon `prepareActionRun`,
   no trust write, no spawn, no `reqId`/`cols`/`rows`.  
   `actions.needs-local-path` is a **client-prepare-only** refusal code — it is **not** a member of
   `publicErrorSchema` and must not be added to contracts in this unit. `actions.untrusted` reuses
   the public code string for vocabulary alignment but is returned as a plain object, not a
   transport-mapped public error.

## Objective

Client-runtime owns typed Actions list and trust query identities, five non-optimistic
mutation consequence definitions bound to ACT-001 procedures, exhaustive `actions.changed`
→ identity mapping, and pure explicit `prepareActionRun` that yields Terminal-create fields or a
typed refusal without I/O.

## Why this unit exists

beside tRPC; mobile exposes only list/trust under Terminal descriptors
(`apps/mobile/src/lib/daemon/procedures/terminal.ts`) with no CRUD seam. Shared semantics must land
before ACT-003 relocates UI and binds the Actions → Terminal workflow.

## Behavior to preserve

- Trust is by command fingerprint on this machine; UI continues to gate untrusted runs with a
  visible accept step (preparation refuses untrusted so adapters cannot skip the gate).
- Saved action order and CRUD remain daemon-authoritative; clients refetch after every successful
  mutation and after `actions.changed` (including CLI/agent disk writes).
- Local-only actions require an explicit This-device path before any terminal create; missing path
  is a typed refusal, not a silent primary fallback.
- Running a command remains an explicit human Actions → Terminal transition: preparation yields
  create fields; it never auto-executes from a notification and never hides spawn inside a mutation.
- `where: 'primary'` (or omitted) runs in the project root; `where: 'local'` runs on the mapped
  local path with the action title as the session name and the command as initial input.

## Legacy behavior to delete

- Delete no app hook, descriptor, invalidation array, session-runtime case, or UI module in this
  unit. ACT-003 relocates presentation and binds adapters; ACT-004 deletes Terminal-owned
  descriptors/facades.
- Do not export procedure-name strings, `AppEvent`, local Action Zod schemas, or a generic
  invalidation helper from client-runtime.
