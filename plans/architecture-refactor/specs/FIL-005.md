3. **Five identity → Web query mappings (ruling 2).** Leave **tRPC procedure-name React Query keys**. Board/RVC-003 pattern is mandatory: vanilla `trpc.useUtils().client.<procedure>` + custom key.

### Key construction (exact; live Board parity)

```ts
// files-query-key.ts — mirror board-query-key.ts
export type FilesDaemonScope = {
  readonly host: string | null
  readonly version: string | null
}

/** React Query key: FIL-004 identity + active daemon scope. Never procedure-name strings. */
export function filesQueryKey(
  daemon: FilesDaemonScope,
  query: FilesQuery,
): readonly [FilesQuery, FilesDaemonScope] {
  return [query, { host: daemon.host, version: daemon.version }] as const
}
```

Daemon scope comes from `useDaemonIdentity()` (`host`, `version`) exactly as Board.

| FIL-004 identity | Wire procedure | Wire input | UI path conversion | `enabled` |
| --- | --- | --- | --- | --- |
| `filesTreeQuery(projectKey, path, showHidden)` | `readDir` | `{ repoPath: projectKey, path: wireAbs, showHidden }` where `wireAbs = path === '.' ? projectKey : projectAbsoluteFromRelative(projectKey, path)` | UI absolute dir → `treePathFromAbsolute` → `'.'` or relative | `repo !== null && identityPath !== null && enabledArg` |
| `filesPinsQuery(projectKey)` | `pinnedEntries` | `projectKey` (string) | n/a | `repo !== null` |
| `filesScopeQuery(projectKey)` | `repoScope` | `projectKey` (string) | n/a | `repo !== null` |
| `fileContentQuery(projectKey, rel)` | `readFile` | `{ projectPath: projectKey, path: rel }` | UI abs → `projectRelativeFromAbsolute`; null → disabled | `repo && rel && abs !== '' && enabledArg` |
| `filePreviewQuery(projectKey, rel)` | `previewHtml` | same as content | same | same + caller `enabled` (HTML preview mode) |

- `projectKey = filesProjectKey(repo.path)` (same trailing-slash rules as live `normalizeProjectRoot` / FIL-004).
- `showHidden` from `useRepoStore((s) => s.showHidden)` — both false/true identities are distinct cache rows.
- **Root:** UI absolute project root ↔ identity `path: '.'` ↔ wire `readDir.path = projectKey` (absolute). Never identity `''`.
- **Disabled identity:** when repo/path conversion is unavailable, build a private, contract-valid
  sentinel identity with project `/` and path `__disabled__` (tree uses `'.'`). Set
  `enabled: false`; the `queryFn` must defensively throw an invariant error if invoked rather than
  call the daemon (React Query must never invoke it while disabled). This is a
  cache-key implementation detail, not a wire input or public export.
- **Prefetch:** `usePrefetchFileContent()` builds content identity key and `queryClient.prefetchQuery` / or `client.readFile.query` into that key — must populate the **same** `filesQueryKey` as `useFileContent`, not tRPC’s internal key.
- Result types: `DirEntry[]`, `FileView`, `RepoScope` / `{ hiddenPaths; pinnedPaths }` from **`@porcelain/contracts/files`** only.
- Isolation: distinct `projectPath` or daemon `{host,version}` → distinct keys (prove in tests).

4. **Exhaustive `FilesQueryEffect` binding (ruling 3).** Feature-owned pure mapper in `files-query-filter.ts` + `invalidateFilesEffects` in the same module (or thin wrapper). **Must be pure/testable** without React.

```ts
/** Segment-safe: self or descendant. Never bare string prefix (rejects 'a' matching 'ab'). */
export function filesPathIsSelfOrDescendant(candidate: string, root: string): boolean {
  return candidate === root || candidate.startsWith(`${root}/`)
}

export function filesQueryMatchesEffect(
  queryKey: readonly unknown[],
  effect: FilesQueryEffect,
  daemon: FilesDaemonScope,
): boolean
```

| Effect | Match rule on `queryKey = [FilesQuery, FilesDaemonScope]` |
| --- | --- |
| `exact` | `queryKey` deeply equals `filesQueryKey(daemon, effect.query)` (invalidate with `exact: true`) |
| `tree-family` | head is tree identity (`domain:'files'`, `name:'tree'`) AND `head.projectPath === effect.projectPath` AND daemon scope equals |
| `tree-subtree` | tree identity + same projectPath + daemon + `filesPathIsSelfOrDescendant(head.path, effect.path)` — **`'.'` root is only self** (`candidate === '.'`); descendants use relative paths only, never treat `'.'` as prefix of all trees |
| `content-subtree` | content **or** preview identity + same projectPath + daemon + `filesPathIsSelfOrDescendant(head.path, effect.path)` |

- Exhaustive `switch (effect.type)` with `never` default — forgetting a variant is a compile failure.
- `invalidateFilesEffects(queryClient, daemon, effects)`: always iterate
  `dedupeFilesQueryEffects(effects)`; exact → `invalidateQueries({ queryKey, exact: true })`;
  family/subtree → `invalidateQueries({ predicate })`.
- Tests **must** prove: `a` does not match `ab`; `src` matches `src` and `src/x` not `src2`; rename/trash content-subtree invalidates nested content+preview; tree-family hits all showHidden rows; mandatory adapter knowledge is not left untested.

5. **Ten mutation adapters (ruling 4).**

### Public hooks

```ts
export function useFilesActions(): {
  createFile: (absolutePath: string) => Promise<void>
  createFolder: (absolutePath: string) => Promise<void>
  rename: (fromAbsolute: string, toAbsolute: string) => Promise<void>
  /** Relative daemon output converted to absolute UI path; null if no repo / invalid conversion. */
  duplicate: (absolutePath: string) => Promise<string | null>
  /** True only when the daemon mutation and its success effects completed. */
  trash: (absolutePath: string) => Promise<boolean>
  // create/folder/rename/duplicate throw; trash toasts via onMutationError('Delete')
  // and returns false on missing repo, invalid conversion, or mutation failure
}

export function useWriteTextFile(absolutePath: string): {
  save: (content: string, onSaved?: () => void) => void
  isSaving: boolean
  error: { message: string } | null
}

export function useFilesScopeActions(): {
  hide: (absolutePaths: readonly string[]) => Promise<void>
  unhide: (absolutePaths: readonly string[]) => Promise<void>
  pin: (absolutePaths: readonly string[]) => Promise<void>
  unpin: (absolutePaths: readonly string[]) => Promise<void>
}
```

Scope batches run sequentially in caller order. After each successful daemon mutation, apply that
mutation's Files effects before attempting the next path. If a later path fails, throw immediately:
already-completed paths remain freshly invalidated and the caller does not clear selection because
the whole batch did not resolve. Never postpone all invalidation until the end of a batch.

### Success-only call order (FIL-004)

1. `client.<procedureName>.mutate(wireInput)` via vanilla tRPC client.
2. On throw/failure: **no** Files effect invalidation; no foreign invalidation; surface error (toast or throw).
3. On success (non-duplicate): `invalidateFilesEffects(..., filesMutations[k].affectedEffects(input))` then `applyFilesForeignDependencies(..., foreignDependencies(input))`.
4. On success **duplicate only:** `affectedEffectsForResult(input, output)` where `output` is the relative destination string — **never** settle on base `affectedEffects` alone; return `projectAbsoluteFromRelative(projectKey, output)`.
5. `requiresAuthoritativeRefetch: true` → invalidation only; **never** `setQueryData` from filesystem mutation results (non-optimism).

| Action | Wire | Notes |
| --- | --- | --- |
| write/create/folder/rename/duplicate/trash | host-fs: `{ projectPath: projectKey, path \| from/to }` relative | UI abs → relative; skip if null |
| hide/unhide/pin/unpin | `{ repoPath: repo.path, path: absolutePath }` | **absolute path wire unchanged** (FIL-004 non-goal) |

### Caller-owned UI

- Tab close after trash: **callers** (`tree-node`, `file-commands`) call `useTabsStore.getState().closeTabEverywhere(tabId('file', path))` after `await trash(...)` resolves successfully.
- `trash` returning `true` is the sole success signal: callers close that path's tab only on
  `true`. `tree-node` otherwise does nothing. `file-commands` attempts each target, closes only
  successful targets, then clears the selection after the batch exactly as today; a failed target
  remains on disk and its tab remains open. The mutation owns the failure toast and never leaks a
  rejected floating promise from a click/keyboard handler.
- Selection clear after hide/pin batch: **callers**.
- File prompt dialog close: remains in `file-prompt-dialog` on success.

7. **Interest ownership (ruling 6).**

- Single `useFilesInterestBridge()` mounted in `AppShell`.
- Lifecycle:
  1. Read `repoPath` from repo store; if null, dispose any prior facade and register nothing.
  2. Production constructs `createFilesInterest(repoPath, { registerWatchInterest: primary.runtime.registerWatchInterest })`. Tests mock the `primary` module boundary, matching Board notification tests; do not widen the public hook with a second production session/runtime path.
