## Architecture reviewer rulings (bind the executor; supersede the tracked Draft)

1. **Dependencies and target roots.** The catalog is the source of dependency status. GIT-003,
   TST-001, and RT-005 are Landed at the review HEAD. Register
   `apps/web/src/features/git` and `apps/mobile/src/features/git` as Git target roots in
   `scripts/architecture/domains.mjs`; each root has an `index.ts`, and its `workspace/` child
   has its own public `index.ts`. No caller outside either root deep-imports a workspace module.

2. **Semantic cache keys.** Web keys are exactly
   `[GitWorkspaceQuery, DaemonScope]`, with `DaemonScope` from `@renderer/lib/daemon-scope`;
   mobile keys are exactly `['daemon', environmentId, GitWorkspaceQuery]`. Both adapters parse
   their full keys with `gitWorkspaceQuerySchema` plus the platform scope schema before matching
   an effect. The only disabled identity is an adapter-local, non-empty sentinel project path;
   it is never sent to a daemon and is not exported as product state. Project paths otherwise
   pass through unchanged; no host canonicalization or second project key is introduced.

3. **Canonical transport binding.** Web reads invoke the existing tRPC vanilla client through
   `trpc.useUtils().client` and use the canonical `gitHead`, `gitBranches`, `gitWorktrees`, and
   `worktreeInbox` contract procedures. Mobile binds the same Git/Review contract descriptors
   with `namedContractProcedure` and calls them through `callDaemon(getDaemonClient(...))`.
   Neither adapter declares a Zod schema, wire type, procedure descriptor, or invalidation array.
   Head polling remains 5 seconds; worktree and inbox polling remain 15 seconds; branch refresh
   remains an explicit sheet-open refetch.

4. **Mutation ownership and refusal behavior.** `useGitCheckout`, `useGitCreateBranch`, and
   `useGitAddWorktree` bind `gitWorkspaceMutations` directly. Each mutation sends the exact
   canonical input, never writes optimistic data, and applies
   `affectedQueries(input)` only after a successful authoritative response. A pending or refused
   mutation leaves the semantic cache untouched and rejects to the initiating surface, where the
   existing typed public-failure copy remains responsible for display. Checkout and create-branch
   retain the fourteen-effect set; add-worktree retains only branches, worktrees, and inbox.

5. **Legacy cache bridge during the bounded cutover.** Changes, Diff, History, Commit, and Review
   reads are explicitly out of GIT-004, so their existing raw tRPC/mobile Query keys remain until
   GIT-006. The Web/mobile Git workspace adapters therefore apply each GIT-003 semantic effect to
   both the new semantic workspace key and the matching legacy cache entries, using an explicit
   project-scoped procedure mapping (including the per-file `gitDiffFile` family). This is a
   temporary transport/cache binding, not a second semantic definition, and it must not use a
   broad client flush or an unscoped procedure prefix. GIT-006 owns its deletion.

6. **One notification and recovery owner per client.** Add one Web subscription under
   `apps/web/src/features/git` and one mobile `GitNotificationBridge` mounted from
   `apps/mobile/src/app/_layout.tsx`. Each converts only the validated
   `git.working-tree-changed` SessionChange into the contract `GitChange`, runs
   `gitNotificationEffects`, and applies the exact project/environment effects through ruling 5.
   Each bridge also handles project freshness requirements with the same typed effect and session
   recovery by invalidating only its semantic Git workspace keys; the existing session/provider
   code must remove its duplicate Git working-tree branch. Review/Files/Board recovery remains in
   its owning boundary. Working-tree notifications never add branches, worktrees, or inbox.

7. **Mobile shell split.** Move the Git reads and writes out of
   `apps/mobile/src/features/shell/use-workspace.ts` into the Git workspace feature. Leave the
   Project sheet there and keep `useWorkspaceHeader` as the shell presentation adapter over the
   public Git workspace hook. Branch/worktree sheets import Git hooks and `BranchRef`/`Worktree`
   through the Git feature boundary; `workspace-lists.ts` imports the canonical contract types.
   `workspace-create-form.tsx` and all copy, destination-preview, selection, and error behavior
   remain unchanged.

8. **Exact deletion boundary.** Delete the Web legacy hook and test, the mobile
   `procedures/workspace.ts` descriptor/test, both string invalidation arrays, and every direct
   caller/import of those paths. Remove only the Web/mobile global Git working-tree invalidation
   branch now owned by the new bridge. Do not delete or relocate Changes/History/Diff/Commit
   hooks, their legacy descriptors, or their later migration tests.

9. **Owning tests.** Add adapter tests under both `features/git/workspace/` using TST-001's
   validating mock and contract Git fixtures. They must prove semantic key scope, exact
   checkout/create versus add-worktree effects, pending state, refusal without post-failure
   invalidation, project/environment isolation, and typed notification/recovery mapping. Update
   the retained Web switcher/inbox/Glance tests and mobile workspace-list/form tests only for the
   public import boundary; do not mock the new adapter in presentation tests.

## Objective

Web and mobile workspace adapters bind GIT-003’s non-optimistic checkout/create/add-worktree effects and delete broad/string invalidation logic.

## Why this unit exists

The two clients expose the same intent but one broad-flushes every Web cache and the other maintains local arrays under a mobile daemon descriptor module.

## Current behavior and evidence

- Web `hooks/use-worktrees.ts` owns `useCheckout`/`useCreateBranch` and `utils.invalidate()`.
- Mobile `features/shell/use-workspace.ts` imports descriptors/types and `WORKSPACE_CHECKOUT_INVALIDATIONS`/`WORKSPACE_ADD_WORKTREE_INVALIDATIONS` from `lib/daemon/procedures/workspace.ts`.
- Web branch/worktree/inbox/Glance callers consume the legacy hook; mobile shell headers and branch/worktree sheets consume the Git portions of `use-workspace.ts`; Web and mobile global session/provider maps still own duplicate raw Git notification invalidation.
- RT-005 supplies validated `SessionChange` delivery; GIT-003 supplies the fourteen project-scoped identities, exact mutation consequences, and eleven-effect working-tree mapping.

## Scope

Create Web and mobile `features/git/workspace/` adapters with public indexes, strict platform
semantic-key/filter helpers, mutation bindings, legacy-cache bridges, and one notification/recovery
subscription each; register both Git feature roots; move current hook callers; remove the listed
Web hook and mobile workspace descriptors/arrays after all callers move.

## Non-goals

Do not relocate Changes/History/Diff, change branch-sheet copy/forms, persist Git Query data in stores, or add optimistic UI.

## Target ownership and public surface

- Web exports `useGitWorkspace`, `useGitCheckout`, `useGitCreateBranch`, and `useGitAddWorktree`; mobile exports the same behavior from its Git workspace feature boundary.
- Each uses canonical Git contract types/descriptors, maps GIT-003 identities to its current Project/environment key, invokes exactly the named mutation consequence, and displays typed public failures.
- Each public index also exports its notification bridge and the minimum canonical `BranchRef`, `Worktree`, and inbox-row types needed by its presentation callers.
- Both install the GIT-003 notification adapter once at their domain/session boundary; the typed working-tree fact invalidates only declared identities and the bridge owns project/session recovery for its semantic keys.

## Behavior to preserve

Keep branch label/refetch behavior, 15-second worktree/inbox polling, destination preview, dirty-tree refusal, current worktree selection, and the strict narrower add-worktree refresh.

## Legacy behavior to delete

Delete `apps/web/src/hooks/use-worktrees.{ts,test.ts}`, its broad `utils.invalidate()` workspace
calls, `apps/mobile/src/lib/daemon/procedures/workspace.{ts,test.ts}`, both
`WORKSPACE_*_INVALIDATIONS`, the Git portions of the mobile shell hook, and direct callers of
those paths. Delete the Web `git.working-tree-changed` invalidation branch from
`hooks/use-session-runtime.ts` and the mobile equivalent from `lib/daemon/provider.tsx`; retain
all unrelated session/provider mappings for later units.

## Ordered implementation

1. Verify GIT-003, TST-001, and RT-005 are landed and the ruling anchors match.
2. Register both Git app roots; add each platform's semantic workspace keys, exact effect filter,
   canonical reads, mutation bindings, legacy cache bridge, and notification/recovery bridge.
3. Move Web switcher/inbox/Glance callers and mobile shell header/sheet callers through public Git
   indexes; keep Project sheet and presentation copy in their existing shell files.
4. Remove raw hooks/descriptors/arrays and the duplicate global Git working-tree notification
   branches, then prove no broad flush or direct legacy path remains.
