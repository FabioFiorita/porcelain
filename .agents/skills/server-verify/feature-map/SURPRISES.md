# Surprises

Behaviour the net observed that looks wrong or inconsistent. Each case still asserts what the server does today, so the net stays green; fixing one means changing the server, its case and this entry together. Nothing here has been decided.

| Feature                   | Request                                                               | Observed                                                            | Why it looks wrong                                                                                                 |
| ------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| reviews.reviewed-files    | `PUT …/reviewed` for a path that is not a change                      | 409 `…based on a version that has changed`                          | The bulk route reports the same case as `missing`; the single-mark message is misleading.                          |
| reviews.publish-review    | a step pointer to a file that does not exist                          | 200, pointer fingerprinted as empty text, location `changed`        | A pointer to nothing is accepted as explaining a change.                                                           |
| access.live-updates       | send `subscribe`, then change something at once                       | the change's notice can be lost                                     | The protocol never acknowledges a subscription, so a client cannot know when notices start; the cases wait 300 ms. |
| projects.browse-folders   | `GET /api/projects/folders?path=/opt/porcelain`                       | 200, lists it                                                       | Any absolute path is browsable, not only the project home. May be intended.                                        |
| projects.file-preferences | a preference for a path that does not exist                           | 200, stored                                                         | May be intended (preferences outlive files); not decided.                                                          |
| changes.list-commits      | `tip` without `after`                                                 | ignored, no `restarted`                                             | The parameter only matters when continuing; alone it is silently dropped.                                          |
| (transport)               | any request after a rejected WebSocket upgrade on the same connection | the server answers `Connection: keep-alive`, then closes the socket | A client reusing the connection gets `socket hang up`; the verifier opens a connection per request.                |
| access.live-updates       | any change to a subscribed project                                    | project notices only ever carry `change: 'preferences'`             | The contract also allows `change: 'files'`, which the server never sends.                                          |
