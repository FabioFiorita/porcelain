# Surprises

Behaviour the net observed that looks wrong or inconsistent. Each case still asserts what the server does today, so the net stays green; fixing one means changing the server, its case and this entry together. Nothing here has been decided.

| Feature                               | Request                                                                                                                                    | Observed                                                                         | Why it looks wrong                                                                                                                          |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| changes.read-change-lines             | `GET …/changes/lines?path=missing.md&at=head`                                                                                              | 422 `Repository could not be inspected`                                          | The same path with `at=worktree` answers 404 `Path not found`; a missing path is not a repository failure.                                  |
| changes.read-change-lines             | `…/changes/lines?from=5&to=1`                                                                                                              | 200 with `from: 5, to: 4, lines: []`                                             | A reversed range is accepted and echoed as a different range; comment anchors and review pointers reject end before start.                  |
| changes.read-commit-files             | `GET …/commits/<unknown oid>/files`                                                                                                        | 422 `History snapshot is unavailable; start a new listing`                       | The commit does not exist; the message sends the client to relist history, and 404 would say what happened.                                 |
| changes.read-commit-diffs             | `POST …/commits/<unknown oid>/diffs`, and `parent: 2` on a one-parent commit                                                               | 422 `Repository could not be inspected` for both                                 | Its sibling read-commit-files answers the same inputs with a different 422 and with 400 `Invalid history request`.                          |
| changes.read-commit-diffs             | a path the commit did not touch                                                                                                            | 200, `metadata-only` with an empty patch                                         | An untouched path is indistinguishable from a mode-only change.                                                                             |
| changes.read-change-diffs             | a selection that is not one of `expectedFiles`                                                                                             | 409 `Refresh status and retry inspection`                                        | It is a client input error; refreshing and retrying cannot succeed.                                                                         |
| git-actions.run-action                | `POST /api/projects/:p/worktrees/<unknown>/git/actions`                                                                                    | 202, a running receipt for the unknown worktree, later `rejected`/`GIT_REJECTED` | list-branches answers 404 for the same scope; the action should be refused before it is accepted.                                           |
| git-actions.dismiss-interrupted       | `DELETE …/git/interrupted/<unknown request>`                                                                                               | 409 `Git action request does not match its receipt`                              | read-receipt answers 404 `Git action receipt not found` for the same ID.                                                                    |
| git-actions.list-branches             | an unknown project with a real worktree                                                                                                    | 404 `Worktree not found`                                                         | Names the wrong resource.                                                                                                                   |
| reviews.reviewed-layers               | `PUT …/reviewed-layers` with a layer the review does not have, or a fingerprint that matches nothing (also before any review is published) | 200, stored with `stale: false`                                                  | Reviewed files refuse the equivalent with 409; a mark nothing backs is reported fresh.                                                      |
| reviews.reviewed-files                | `PUT …/reviewed` for a path that is not a change                                                                                           | 409 `…based on a version of the file that has changed`                           | The bulk route reports the same case as `missing`; the single-mark message is misleading.                                                   |
| reviews.publish-review                | a step pointer to a file that does not exist                                                                                               | 200, pointer fingerprinted as empty text, location `changed`                     | A pointer to nothing is accepted as explaining a change.                                                                                    |
| reviews.comment-threads               | any create, reply or resolve                                                                                                               | the body is a list holding only the written thread                               | The contract reuses the list schema (`createCommentThreadResponseSchema = listCommentThreadsResponseSchema`), which reads as "all threads". |
| access.live-updates                   | send `subscribe`, then change something at once                                                                                            | the change's notice can be lost                                                  | The protocol never acknowledges a subscription, so a client cannot know when notices start; the cases wait 300 ms.                          |
| files.read-asset                      | `GET …/asset?path=README.md`                                                                                                               | 422 `Path could not be read`                                                     | The file is readable; it is just not an image. The message suggests an I/O failure.                                                         |
| files.list-directory, files.edit-file | a path inside `.git`                                                                                                                       | 422 `Path could not be read`                                                     | Routes that use the shared relative-path schema reject `.git` as invalid input (400); these use a looser path schema and fail later.        |
| projects.browse-folders               | `GET /api/projects/folders?path=/usr`                                                                                                      | 200, lists it                                                                    | Any absolute path is browsable, not only the project home. May be intended.                                                                 |
| projects.file-preferences             | a preference for a path that does not exist                                                                                                | 200, stored                                                                      | May be intended (preferences outlive files); not decided.                                                                                   |
| changes.list-commits                  | `tip` without `after`                                                                                                                      | ignored, no `restarted`                                                          | The parameter only matters when continuing; alone it is silently dropped.                                                                   |
| (transport)                           | any request after a rejected WebSocket upgrade on the same connection                                                                      | the server answers `Connection: keep-alive`, then closes the socket              | A client reusing the connection gets `socket hang up`; the verifier opens a connection per request.                                         |
