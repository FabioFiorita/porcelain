# Push notifications

A paired device sets its own push registration with `PUT /api/push-registration` (`token`, `platform`, `kinds` from `review-ready` and `agent-reply`; an empty `kinds` clears it; registering a token another device holds moves it to this device) and removes it with `DELETE /api/push-registration` (204). The owner and the desktop session are refused with 403. Revoking the device deletes its registration. After `publish_review`, and after an agent's `reply_to_comment` on a thread the developer started (not a developer's reply, not the agent's own thread), the server sends one Expo push message per registered device that asked for that kind, best-effort and in the background, and drops a registration whose ticket says `DeviceNotRegistered`.

The disposable server points its push endpoint at a fake push service inside the sandbox. `$C server push-requests` prints every request it received with the messages: `to`, `title` (the project), `body` (`Review ready: …` or `Agent replied: …` without code blocks), `data.kind`, `data.url` (the review's app link), `sound` and `channelId`. A token containing `Unregistered` is answered with `DeviceNotRegistered`.

1. Read the fixture bearer and Origin from the card. `PUT /api/push-registration` with `{ "token": "ExponentPushToken[check]", "platform": "android", "kinds": ["review-ready", "agent-reply"] }`: 200 `{ "kinds": ["review-ready", "agent-reply"] }`.
2. `$C agent publish-review`, then `$C server push-requests`: one new request whose message has `Review ready:` and the review link. Post a developer comment with `POST /api/worktrees/<worktreeId>/comments` (`threadId`, `anchor` `{ "kind": "file", "filePath": "README.md" }`, `body`), then `$C agent reply <threadId> "…"`: one more request with `Agent replied:` and the project as title. An agent reply on a thread made with `$C agent comment` sends nothing.
3. `DELETE /api/push-registration`, publish again and wait a second: no new request.

[The integration test](../../../../apps/server/spec/integration/access-push-notifications.integration.ts) proves registration, the publish and reply messages, developer replies and agent-started threads sending nothing, unregistering, the dropped `DeviceNotRegistered` token and a publish that returns while the push service hangs, against the built server; [the domain rules spec](../../../../packages/access/src/rules/push-notifications.spec.ts) covers recipients and message text. Run them by name.
