# Worktree review navigation

Review documents and plain Files, Changes and History share the selected worktree. Published layers
explain behavior; the changed-file list remains reachable because an explanation can omit changes.
Comments attach to code rather than to a step, so republishing an explanation does not relocate the
discussion. Layer marks and plain file marks represent different review choices.

Environment, project and worktree scope identify cached reads. Disconnect aborts outstanding work
and clears private client state. Live notices invalidate mutable surfaces; immutable commit reads
need no polling. In-memory fixtures exercise rendering, while disposable real-server browser tests
verify Git and publication integration.

Git execution retains a request ID for receipt checks. An uncertain outcome must not offer blind
resubmission. Client-side identity survives navigation within the current connection; the server
owns durable receipts across reloads and disconnects.

The sidebar reply indicator clears only when the discussion is shown, using the highest revision
actually displayed. Prefetching a comment is not reading it, and a newer reply must remain unread.
